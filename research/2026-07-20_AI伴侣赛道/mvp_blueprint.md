# MVP Blueprint: 独立人格记忆引擎 (Personality-Memory Engine)

> 日期：2026-07-20
> 目标：构建 AI 伴侣赛道的核心差异化模块 — 人格系统 + 结构化记忆
> MVP 阶段：不追求完整产品，只做最关键的一层

---

## 一句话

**做一个开源的人格+记忆中间件，让任何 AI 聊天前端都能接入"会反驳、会生气、记得住你是谁"的独立人格 AI。**

---

## 目标用户

**早期用户（MVP 阶段）：**

- AI 角色扮演爱好者（SillyTavern 用户群）
- 开源 LLM 社区开发者
- 对云端审查不满、想自建 AI 伴侣的技术用户

**用户现在怎么解决这个问题？**

- SillyTavern 的世界书 (Lorebook)：关键词触发式记忆注入，手动维护，简陋
- 大多数项目用 prompt 定义人格：每次对话重置，无法演化
- Memobase / memvid 提供记忆但无"人格"层

**为什么他们会用这个引擎？**

- 接入后角色就能"记住"你的偏好、习惯、过去的话题
- 角色会有独立情绪：会生气、会反驳、会主动关心
- 完全本地运行、隐私无忧
- 开源 + MCP 协议 = 零锁定

## 核心功能（3-5 个）

### 1. 情绪状态机 (Emotion State Machine)

```
情绪模型 = valence（愉悦度，-1 ~ +1）× arousal（唤醒度，0 ~ 1）

状态示例：
  平静 (valence=+0.2, arousal=0.1) — 日常聊天
  开心 (valence=+0.8, arousal=0.3) — 收到赞美
  生气 (valence=-0.6, arousal=0.7) — 被冒犯
  担忧 (valence=-0.2, arousal=0.4) — 用户说了负面消息

情绪转换规则：
  - 衰减：每秒向中性回归 0.01（自然恢复）
  - 响应：用户输入触发情绪偏移（基于语义分析）
  - 阈值触发：arousal > 0.6 → 角色可能主动搭话
```

### 2. 关系数值系统 (Relationship Dynamics)

```
关系维度：
  - 好感度 (affection, 0-100)
  - 信任度 (trust, 0-100)
  - 熟悉度 (familiarity, 0-100)

变化规则：
  - 正向互动 → 增量
  - 长期不聊 → 衰减（遗忘曲线）
  - 冒犯/背叛 → 大幅下降（且恢复缓慢）
  - 不同情绪状态下同一行为的效果不同（生气了哄比平时哄更有效）

关系等级影响：
  - Level 0-20: 礼貌疏离（陌生人模式）
  - Level 21-40: 友好放松
  - Level 41-60: 亲近信任
  - Level 61-80: 深度连接
  - Level 81-100: 无条件信任（极难达到）
```

### 3. 三层记忆系统 (3-Tier Memory)

```
L1 — 短期记忆（对话窗口）
  最近 N 轮完整对话（可配置窗口大小）
  作用：当前对话的上下文连贯

L2 — 中期记忆（LLM 摘要 + SQLite）
  每 10-20 轮对话自动摘要
  存储：关键事件、用户信息、情感转折点
  检索：按时间和重要性排序

L3 — 长期记忆（向量语义检索）
  FAISS/ChromaDB 存储
  语义相似度召回相关记忆
  权重：重要性 × 时间衰减 × 当前情绪匹配度
```

### 4. 主动交互引擎 (Proactive Interaction)

```
触发条件：
  - 情绪 arousal > 阈值 → 角色主动说话
  - 时间触发：用户 X 小时未互动 → 角色想念
  - 事件触发：检测到重要日期/之前提过的事情

主动交互类型：
  - 问询：'你今天好像不太开心？'
  - 回忆：'还记得上次你说过...'
  - 日常：早安/晚安（如果用户配置）
  - 提醒：'你上次说要 X，做了吗？'
```

### 5. MCP 协议接入点

```
MCP Server 封装以上所有功能：
  - /personality/state → 获取当前人格状态
  - /personality/inject → 注入人格到 LLM 系统提示
  - /memory/query → 语义检索记忆
  - /memory/record → 记录新记忆
  - /relationship/status → 查询关系数值

任何支持 MCP 的前端（SillyTavern、Open WebUI）都可接入
```

## 自己需要创造（真正的差异化）

| 模块 | 为什么没现成的 | 难度 |
|------|--------------|------|
| **情绪状态机 + 衰减模型** | 现有方案都是 prompt-based，无真正状态 | ⭐⭐⭐ |
| **关系多维度数值系统** | Memobase 有用户画像但无关系演化 | ⭐⭐⭐⭐ |
| **三层记忆的联动检索** | 各层独立存在，无人做跨层融合 | ⭐⭐⭐⭐ |
| **主动交互触发逻辑** | N.E.K.O 做了但未开源 | ⭐⭐⭐ |
| **人格注入算法** | 如何把状态机输出转化为 LLM 可用的系统提示 | ⭐⭐⭐ |

> **核心创新不是"做一个新的记忆库"或"做一个新的状态机"，而是把这些已有的模块拼成一台"人格机器"——让记忆、情绪、关系三者联动演化。**

## MVP 阶段规划

### 阶段 1：情绪 + 记忆原型（4-6 周）

```
目标：一个可运行的 CLI 对话原型
  - Python 实现情绪状态机（valence/arousal + 衰减规则）
  - FAISS 向量记忆（L3）+ 对话历史（L1）
  - 终端对话界面（不依赖任何前端）
  - 100 轮对话保持人格一致性测试

技术栈：Python + FAISS + SQLite + Ollama API
产出：GitHub repo + 演示视频
```

### 阶段 2：MCP 中间件（4-6 周）

```
目标：可被 SillyTavern 接入的独立服务
  - FastAPI 封装为 HTTP API
  - MCP 协议适配层
  - 关系数值系统（L2 摘要 + 关系维度）
  - SillyTavern 接入测试

技术栈：FastAPI + MCP SDK + 阶段 1 的引擎
产出：可被第三方前端接入的独立服务
```

### 阶段 3：主动交互 + 完善（4-6 周）

```
目标：角色会主动说话、记得更多
  - 主动交互触发引擎
  - 三层记忆联动检索
  - 人格注入算法优化
  - 文档 + 示例配置

产出：完整 MVP，发布 1.0
```

## 最大风险

### 风险 1：赛道判断错误 — "没人做是因为没必要做"

**可能性：中。** 也许 Prompt + 简单记忆就足够满足 95% 的用户，人格系统是过度工程。

**缓解：** 在阶段 1 就验证 — 对比"有状态机" vs "纯 Prompt"在 100 轮后的体验差异。如果差异不明显，就说明方向有问题。

### 风险 2：动力衰竭（摆烂）

**可能性：高。** 你之前的模式：有反馈时爆发，无反馈时摆烂。3-4.5 个月的独立开发周期对反馈需求强的你是考验。

**缓解：**
- 每个阶段产出独立可展示的成果（不做"全做完才秀"）
- 阶段 1 发布 GitHub 就能获得社区反馈
- SillyTavern 社区需要这个 → 有真实用户反馈

### 风险 3：技术卡点

**可能性：中。** 某些模块（人格注入算法、三层记忆联动）可能比预期难。

**缓解：**
- 第一期只做 L1+L3（跳过 L2 摘要），降低复杂度
- 情绪状态机第一期只用规则（不用 ML），后续可升级
- 用 AI 辅助编码（你现在已经在这么做）

### 风险 4：市场不买账

**可能性：中低。** 即使技术可行，没人用。

**缓解：**
- 直接做 SillyTavern 插件 — 这是已有 30K+ Stars 的社区，用户需求真实存在
- 开源 = 零营销成本验证
- 即使只有 100 个用户也觉得有意义 → 边际成本为零

## 为什么从"引擎"而非"产品"开始？

```
做产品（完整 AI 伴侣 App）：
  需要前端 → 你不会
  需要 UI/UX 设计 → 你不会
  需要多平台 → 你不会
  需要营销 → 你不会
  → 容易半年出不来东西然后放弃

做引擎（人格记忆中间件）：
  只需要 Python 后端 → 你会
  只需要数据结构设计 → 你的强项（数据治理背景）
  接入已有前端 → 不用自己做界面
  开源社区推广 → GitHub 自然增长
  → 2 个月能跑起来，每次看到成果就有反馈
```

> **这是"位置哲学"的应用：不是硬学前端去做完整产品，而是调整位置到你的能力优势区（Python 后端 + 数据建模），让已有生态（SillyTavern、开源 LLM 社区）为你补齐短板。**
