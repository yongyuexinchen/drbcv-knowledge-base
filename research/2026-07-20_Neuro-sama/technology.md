## 一、LLM 选型与演进

### 1.1 早期阶段 (2022年底 — 2023年初)

Vedal987 最早在 2022 年底开始开发 Neuro-sama，最初使用 **OpenAI GPT 系列模型**（推测为 GPT-3.5-Turbo）。
- 早期直播中对用户提问的响应风格和延迟（~1-3秒）与 GPT-3.5 高度吻合
- Vedal 曾在 Discord 提到使用 "OpenAI API" 作为起步方案 📚
- 早期 Neuro-sama 有明显的 GPT "助手语气"痕迹，回答谨慎、回避争议话题

### 1.2 自训练阶段 (2023年中期至今)

大约在 2023 年中期，Vedal 开始暗示使用 **自训练/微调模型** 📚 ⚠️ 待验证：
- 社区广泛推测使用了 **LLaMA 系列开源模型**进行微调（LLaMA 2 发布后时间点吻合）
- 模型响应速度明显提升（从 ~2-3秒 降至 <1秒），暗示从云端 API 切换到本地推理
- 语调和用词风格变得更随意、更"直播化"，不再是标准 GPT 的 formal 语气
- 出现了角色一致性的显著提升——Neuro 开始"记住"过往的 meme 和内部梗

**社区推测的技术路线** ⚠️ 以下为社区分析，未经 Vedal 官方确认：
| 推测 | 证据 | 可信度 |
|------|------|--------|
| 使用 LLaMA 2/3 微调 | 响应速度、部署成本合理性 | 中 |
| 自定义指令微调 | 角色一致性明显提升 | 高 |
| 混合模型（不同场景不同模型） | 游戏评论 vs 聊天 vs 角色扮演风格不同 | 中 |
| 本地 GPU 推理 | 延迟低、Vedal 展示过的硬件 | 高 |

### 1.3 Evil Neuro 的模型策略

Evil Neuro 于 2023 年底/2024年初登场，其人格与主 Neuro 形成鲜明对比。
- 社区推测使用了 **同一基座模型 + 不同 system prompt/微调数据** 📚
- Evil Neuro 的"毒舌"风格需要特定的训练数据来避免触发内容安全过滤
- 两人格可能共享同一个推理实例，通过 prompt switching 切换 ⚠️ 待验证

## 二、TTS 方案

### 2.1 技术选型

Neuro-sama 使用 **自定义训练/微调的 TTS 模型**，而非现成的商业 TTS 服务 📚：
- 声音特征：年轻女性声线，略带电子感但自然度高于传统 TTS
- 推测基座：可能基于 **VITS**（Variational Inference with adversarial learning for end-to-end Text-to-Speech）或 **Tortoise-TTS** 微调
- 早期版本声音更机械，后来经过优化变得更加自然

### 2.2 实时性实现

TTS 在直播场景的核心挑战是 **低延迟**：
- 从 LLM 输出文字 → TTS 合成 → 音频输出 的总延迟需要控制在 **< 2 秒**
- Vedal 可能采用了 **流式 TTS**（streaming TTS），边生成边播放 📚 ⚠️
- 社区观察到 Neuro 说话时有"思考停顿"，这个停顿恰好被用作 TTS 合成的缓冲时间
- 推测使用了 **GPU 加速的本地 TTS 推理**，避免网络 API 延迟

### 2.3 情感表达

TTS 不仅传递文字，还需要传递情感 📚：
- Neuro-sama 的语音有明显的情绪变化（开心时音调升高、困惑时拉长音）
- 推测通过 LLM 输出的 **情感标签** 来控制 TTS 的韵律参数（音调、速度、重音）
- Evil Neuro 的 TTS 略低、更有攻击性，可能是同一模型的不同参数配置

## 三、动画栈

### 3.1 Live2D

Neuro-sama 使用 **Live2D** 作为虚拟形象渲染方案 📚：
- Live2D Cubism：将 2D 插画分层建模，实现伪 3D 的动态效果
- 角色模型由画师 Anny（@annytf）设计绘制
- 推测运行在 **VTube Studio** 或自定义 Live2D 渲染器上

**技术细节推测** ⚠️：
- Live2D 参数（面部朝向、表情、身体动作）可以通过 API 实时控制
- Vedal 可能编写了将 LLM 输出的情绪/动作映射到 Live2D 参数的中间层
- 例如：LLM 输出 "happy" → Live2D 参数 `ParamMouthSmile=1.0, ParamEyeOpen=1.2`

### 3.2 为什么不选 3D？

- Live2D 相比 3D（VRM/VRoid）在直播中计算开销更小
- 渲染帧率可以保持在 30-60fps 而不占用过多 GPU
- Live2D 的"2.5D"效果在 VTuber 圈接受度更高，更接近传统动漫风格
- 3D 模型需要更复杂的骨骼动画、物理模拟，增加开发成本

### 3.3 动作同步

Neuro-sama 的"说话动作"（口型同步、身体微动）需要与 TTS 输出同步 📚 ⚠️：
- 推测通过提取 TTS 音频的 **音量包络**来控制口型开合参数
- 随机或基于情感参数的 **身体微动**（眨眼、歪头、手势）增加自然感
- 游戏直播场景下还有额外的动作层（紧张时身体前倾 etc）

## 四、实时系统架构

### 4.1 整体架构推测

```
┌─────────────────────────────────────────────────────┐
│                    Twitch Chat                        │
│  (观众消息流, ~10-100 msg/sec 高峰期)                 │
└────────────────┬────────────────────────────────────┘
                 │ IRC/WebSocket
                 ▼
┌─────────────────────────────────┐
│   消息过滤 & 优先级队列          │
│   - 过滤垃圾/敏感消息            │
│   - 按优先级排序                 │
│   - @Neuro 消息优先              │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   LLM 推理引擎                   │
│   - 上下文组装 (历史+当前消息)    │
│   - System Prompt 注入           │
│   - 模型推理 (GPU)               │
│   - 输出: 文本 + 情感标签 + 动作  │
└────────────────┬────────────────┘
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
   ┌─────────┐ ┌──────┐ ┌──────────┐
   │  TTS    │ │Live2D│ │ 游戏交互  │
   │ 合成    │ │控制  │ │ (osu!等)  │
   └────┬────┘ └──┬───┘ └────┬─────┘
        │         │          │
        ▼         ▼          ▼
   ┌──────────────────────────────────┐
   │      OBS / 推流合成              │
   │      将 TTS 音频 + Live2D 画面    │
   │      + 游戏画面合成直播流         │
   └────────────────┬─────────────────┘
                    │ RTMP
                    ▼
              Twitch 直播
```

### 4.2 延迟分析

直播系统中的关键延迟源 📚：
| 环节 | 估计延迟 | 说明 |
|------|----------|------|
| Chat → 消息队列 | 0.1-0.5s | Twitch IRC 固有延迟 |
| 消息过滤/选择 | <0.1s | 轻量级处理 |
| LLM 推理 | 0.5-2s | 本地 GPU 推理，主要瓶颈 |
| TTS 合成 | 0.2-1s | 流式合成可隐藏部分延迟 |
| 推流延迟 | 2-5s | Twitch 低延迟模式 |
| **总端到端延迟** | **3-8s** | 从用户发消息到听到 Neuro 回复 |

### 4.3 多模态输入

Neuro-sama 的输入不仅限于聊天文字 📚：
- **Twitch Chat**：主要交互通道，通过 IRC 协议读取
- **游戏状态**：通过屏幕捕获/游戏 API 获取（如 osu! 的谱面信息、Minecraft 的玩家状态）
- **语音输入**：Vedal 本人有时通过语音与 Neuro 交流（推测使用 STT 转文字后再输入 LLM）
- **视觉输入**：在某些场景下可能有屏幕内容理解（如读聊天框、识别游戏元素）

### 4.4 Twitch 集成

- Twitch Chat 通过 **IRC 协议** 连接（twitch IRC 服务器 irc.chat.twitch.tv:6667）
- 消息过滤层：去除表情符号纯文本、过滤重复消息、识别 @Neuro-sama 的定向消息
- 使用 Twitch API 获取频道状态、订阅者列表等元数据

## 六、技术栈总结

| 模块 | 推测方案 | 可信度 |
|------|----------|--------|
| LLM 基座 | OpenAI GPT → 自训练 LLaMA 微调 | 中高 |
| LLM 推理 | 本地 GPU (推测 NVIDIA RTX 4090 或 A系列) | 中 |
| TTS | VITS/Tortoise-TTS 微调，本地推理 | 中 |
| 动画 | Live2D Cubism + VTube Studio 或自定义渲染 | 高 |
| 消息接入 | Twitch IRC | 高 |
| 游戏交互 | 屏幕捕获 + 游戏 API | 中 |
| 推流 | OBS Studio | 高 |
| 开发语言 | Python (LLM/TTS) + C# (Live2D?) | 低 |
| 部署 | 单机 Windows/Linux，本地 GPU | 中 |
