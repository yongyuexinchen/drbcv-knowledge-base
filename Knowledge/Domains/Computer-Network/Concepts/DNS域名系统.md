# DNS域名系统

## 类型判定
连接模型 — 回答"域名如何一步步解析为IP地址"

## 是什么
DNS（域名系统）是一种将层次结构的域名转换为对应IP地址的分布式系统。它由四类域名服务器协同工作，通过递归查询或迭代查询完成域名解析。DNS基于UDP传输，端口53，采用C/S模型。

## 输入-输出空间
- **输入**: 一个域名（如 www.qq.com）
- **输出**: 对应的IP地址
- **映射关系**: 映射关系（域名 → IP地址）

## 正例（至少2个）
1. **访问网站**: 用户在浏览器输入 www.qq.com，DNS通过层次化查询最终返回该域名对应的服务器IP地址
2. **本地缓存命中**: 本地域名服务器缓存中有 www.bilibili.com 的记录，直接返回IP，无需逐级查询根域名服务器

## 反例/边界（至少1个）
1. **常见误解**: DNS查询每次都要从根域名服务器开始？不，本地域名服务器有缓存，大多数查询可直接由缓存命中返回，无需打扰根域名服务器

## 详细解释
### 四类域名服务器
1. **根域名服务器**: 全球13组，存储所有顶级域名服务器的IP地址，仅支持迭代查询；通过**任播技术**（Anycast）实现就近访问和冗余容灾——多台主机共享同一IP，报文由路由器就近投递，一台损坏自动切换到最近的其他节点
2. **顶级域名服务器**: 管理.com、.cn等顶级域名下的权限域名服务器信息
3. **权限域名服务器**: 存储具体域名与IP地址的映射关系（最终答案所在）
4. **本地域名服务器**: 用户侧默认DNS入口（通过DHCP配置）；内部有DNS缓存，减少向根服务器的查询频率

### 两种查询方式
**递归查询** — "你问我问题，即便我不知道最终答案，也会想方设法的帮你找到最终答案"
- 流程：本地域名服务器问根 → 根问顶级 → 顶级问权限 → 权限返回结果逐层回传
- 终端主机只需发1次查询，本地域名服务器对外也只发1次
- 类比：像函数递归调用，A→B→C→D→E，结果E→D→C→B→A传回

**迭代查询** — "你问我问题，如果我不知道最终答案，就告诉你下一个该问谁"
- 流程：本地域名服务器问根 → 根告诉"去问顶级"→ 本地问顶级 → 顶级告诉"去问权限"→ 本地问权限 → 获得答案
- 本地域名服务器需发多次查询（最多3次：根→顶级→权限）
- <b>注意</b>：根域名服务器通常只提供迭代查询服务

### 缓存机制
- **本地域名服务器缓存**: 降低对根域名服务器的查询频率（大量热点域名命中缓存）
- **主机解析器缓存**: 降低对本地域名服务器的查询频率
- 缓存设置TTL（生存时间），过期后需重新查询

### 解析器（Resolver）
操作系统内的一段程序，负责发出DNS查询报文和解析DNS响应报文。浏览器等高频DNS应用可能自行实现解析器，不调用操作系统级的解析器。

### 为什么不用集中式系统
集中式方案（一台超级域名服务器存所有域名）不可行的原因：
1. 域名数量巨大（数亿），单服务器存储和检索压力大
2. 单点故障：服务器损坏则全球DNS瘫痪
3. 每秒数千万次查询请求，单服务器无法承受

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 传输层协议 | 基于UDP（端口53） |
| 应用层模型 | C/S模型 |
| 任播技术 | 同一组根域名服务器的多台主机共享一个IP，报文就近投递 |
| 解析器 | 主机内部负责发出DNS查询和解析响应的程序 |
| 13组根服务器 | 每组背后可能有多台主机，物理上分散部署全球 |

### 历年真题要点
- **2010年40题**: 递归方法下，用户主机和本地域名服务器各只发1次DNS查询请求
- **2016年40题改编**: 迭代查询下，本地域名服务器对外最少发0次（缓存命中），最多发3次（根→顶级→权限）
