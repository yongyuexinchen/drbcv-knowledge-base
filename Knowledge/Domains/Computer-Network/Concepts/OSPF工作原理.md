# OSPF工作原理

## 类型判定
连接型 — 回答"OSPF如何从零开始构建路由表"的问题，核心是路由器的路由表生成流程：探测邻居→构建LSA→洪泛→构建LSDB→运行Dijkstra→生成路由表。

## 是什么
OSPF的路由表生成是一个"先收集再计算"的过程。每个路由器先独立探测与自己直连的邻居和链路代价，然后通过洪泛法（Flooding）把自己的LSA（链路状态通告）**一传十、十传百**地通知给全网所有路由器。所有路由器都发布完自己的LSA后，每台路由器就拥有了一张完整的**链路状态数据库（LSDB）**——本质是图的邻接表。最后每台路由器独立对LSDB运行Dijkstra算法，计算出到每个目的网络的最短路径，并据此生成路由表。

## 输入-输出空间
- **输入**：本地探测到的直连链路状态信息，全网其他路由器洪泛来的LSA
- **输出**：路由表（目的网络→下一跳→距离）
- **映射关系**：映射关系 — 所有LSA集合→LSDB（图的邻接表）→Dijkstra算法→最短路径树→路由表

## 正例（至少2个）
1. **典型企业OSPF部署**：一个企业AS内有6台路由器、6个网络。各路由器启动后自动探测邻居并洪泛LSA，不到几秒内所有路由器都拥有完整的网络拓扑图。R1运行Dijkstra后知道到net6有两条等价路径（R1→R3→R5→R6→net6 和 R1→R3→R4→R6→net6），都写入路由表实现负载均衡。
2. **链路变化快速响应**：某段光纤故障断开，相邻路由器立即探测到变化，马上洪泛更新后的LSA。全网路由器收到后立即重新运行Dijkstra、更新路由表。整个过程在数秒内完成，远快于RIP。

## 反例/边界（至少1个）
1. **OSPF ≠ RIP**：两台路由器刚建立连接时，OSPF不像RIP那样直接交换完整路由表，而是先通过Hello分组打招呼，再通过DD/LSR/LSU/LSACK实现LSDB同步（类似"对作业答案、抄不会的题"的过程）。

## 详细解释

### 核心流程总览

```
路由器启动/探测变化
       ↓
① 探测直连链路状态（邻居+代价）
       ↓
② 封装为LSA
       ↓
③ 洪泛LSA给全网（Flooding）
       ↓
④ 收集所有LSA → 构建LSDB（邻接表）
       ↓
⑤ 运行Dijkstra算法 → 最短路径树
       ↓
⑥ 生成路由表（只记录下一跳，不记录完整路径）
```

### 步骤详解

#### ① 探测直连链路状态
每台路由器开机后独立探测：
- "我是谁"（本路由器ID）
- "我的邻居有哪些"（相邻的路由器/网络）
- "到每个邻居的代价是多少"（基于带宽计算或管理员配置）

例如R1探测到：→R2(代价3)、→R3(代价1)、→R4(代价3)、→net1(代价1)、→net0(代价2)

#### ② 构建LSA
将探测到的信息封装为LSA（Link State Advertisement）——本质是一个单链表：
- 头节点：路由器ID + 序号（标识版本新旧）
- 链表节点：相邻节点ID + 指向该节点的有向边代价

#### ③ 洪泛（Flooding）
- R1将自己的LSA封装到OSPF分组中，发送给所有直连邻居
- 每个邻居收到后，**从除收到接口外的所有其他接口**转发出去
- 特点：**不回流**（不从收到接口发回去），**不重复转发**（重复收到的LSA直接丢弃）
- 效果：一传十、十传百，全网所有路由器很快收到R1的LSA

同理，R2、R3、R4、R5、R6都会洪泛自己的LSA。

#### ④ 构建LSDB
每台路由器收集到所有LSA后，组合成完整的链路状态数据库（LSDB）：
- LSDB ≈ 图的**邻接表**存储
- 包含全网所有节点和带权有向边的信息
- 每台路由器的LSDB都**完全一致**（因为洪泛保证了全网一致性）

#### ⑤ 运行Dijkstra算法
基于LSDB，每台路由器独立运行Dijkstra算法：
- 以自己为源点，计算到每个其他节点/网络的最短路径
- 改进版的Dijkstra算法支持找到多条**等价路径**
- 计算结果是**最短路径树**（从源点到所有节点的最短路径集合）

#### ⑥ 生成路由表
虽然Dijkstra计算结果包含完整路径，但路由表**只记录下一跳**：
| 目的网络 | 距离（总代价） | 下一跳路由器 |
|---------|-------------|------------|
| net1 | 1 | 直接交付 |
| net2 | 4 | R2 |
| net3 | 2 | R3 |
| net4 | 5 | R3 |
| net6 | 9 | R3（有两条等价路径） |

注意：net6有两条等价路径（R1→R3→R5→R6 或 R1→R3→R4→R6），但路由表只记录下一跳为R3。

### 拓扑变化时的处理
1. 变化被直连路由器探测到
2. 该路由器立即更新自己的LSA（序号+1）
3. 立即洪泛新的LSA给全网
4. 全网路由器收到后立即更新LSDB
5. 重新运行Dijkstra，更新路由表

**这与RIP的本质区别**：RIP等180秒超时+30秒周期迭代才慢慢发现变化；OSPF在探测到变化后立即洪泛，**好消息和坏消息一样快**。

### OSPF中的关键术语

| 术语 | 全称 | 类比 | 说明 |
|------|------|------|------|
| **LSA** | Link State Advertisement | 书的一个章节 | 每台路由器对自己的直连链路状态的描述 |
| **LSDB** | Link State Database | 整本书 | 所有LSA的集合，即全网拓扑的邻接表 |
| **LSI** | Link State Information | 书里的内容 | 广义概念，可以指LSA、LSDB或某条链路信息 |

### 区域划分的意义
- **问题**：大型AS中洪泛全网开销大、LSDB过于庞大
- **解决方案**：将AS划分为多个区域，洪泛局限在各自区域内
- **好处**：
  - 区域内部路由器的LSDB更小（只需本区拓扑），Dijkstra计算更快
  - 洪泛只在区域内传播，大大减少网络通信量
- **结构**：一个主干区域（Area 0）+ 多个非主干区域
  - 非主干区域必须通过ABR直连主干区域
  - ABR（区域边界路由器）同时维护两个区域的LSDB

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 正向链路代价 | 路由器→网络：由OSPF计算或配置，基于带宽 |
| 反向链路代价 | 网络→路由器：OSPF规定为0 |
| 有向边 | 两条相邻路由器之间，两个方向的有向边代价可不同 |
| 网络到路由器的链路 | 代价通常视为0 |
