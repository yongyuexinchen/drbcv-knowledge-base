# 地址解析协议 ARP

## 类型判定
连接型 — 回答"ARP如何根据已知IP地址查找同一网络内的MAC地址"，涉及ARP请求（广播）→ ARP响应（单播）的完整工作流程。

## 是什么
ARP（地址解析协议）用于在同一个局域网内，根据已知的IP地址查询对应的**MAC地址**（数据链路层地址）。ARP维护一张**ARP表**（存储在ARP缓存中），记录IP地址与MAC地址的映射关系，每台主机和路由器都有自己的ARP表，并定期更新表项。ARP请求分组封装在**广播帧**中发送，ARP响应分组封装在**单播帧**中返回。

## 输入-输出空间
- **输入**：目标节点的IP地址（已知）
- **输出**：目标节点的MAC地址（查询得到）
- **映射关系**：映射关系 — 通过ARP请求/响应交互，建立IP→MAC的映射并缓存

## 正例（至少2个）
1. **H3查询默认网关MAC**：H3（166.1.128.2，MAC=33）需要向互联网==发数据==，已知默认网关IP=166.1.128.1但不知其MAC。H3广播ARP请求"我是166.1.128.2（MAC=33），谁是166.1.128.1？"。网关B2接口收到后单播回复"我是166.1.128.1，我的MAC=B2"。H3将结果写入ARP表并开始转发数据。
2. **ARP表加速后续通信**：在步骤1中网关B2同时将H3的(IP,MAC)记录到自己的ARP表中。之后有发往H3的数据报时，B2直接查表得到MAC地址，无需再发ARP请求。

## 反例/边界（至少1个）
1. **ARP只工作在同一个局域网内**：ARP无法跨网络查询MAC地址。如果主机A要查询不在同一子网的主机B的MAC地址，A会将IP数据报先发给默认网关，由网关处理后续转发。A只会查询网关的MAC地址，不会直接查询B的MAC地址。

## 详细解释

### ARP协议在协议栈中的位置
- ARP分组属于网络层PDU，封装在MAC帧中传输
- MAC帧的**类型字段**：0800（IPv4数据报）vs 0806（ARP分组）
- 数据链路层通过类型字段区分上层协议

### ARP工作流程（广播请求 + 单播回复）

```
步骤1：发送方构造ARP请求分组
  ├─ 填写：发送方IP、发送方MAC
  ├─ 填写：目标IP（待查询的IP）
  └─ 封装为广播MAC帧（目的MAC=全1）

步骤2：网络内所有节点接收广播帧
  ├─ 非目标节点：链路层接收→网络层拆包→传输层检查端口号不一致→丢弃
  └─ 目标节点：拆包发现ARP请求中的目标IP与自己一致

步骤3：目标节点返回ARP响应分组
  ├─ 填写自己的MAC地址
  └─ 封装为单播MAC帧（目的MAC=请求方的MAC）
      → 交换机精准投递请求方

步骤4：请求方收到响应，将(IP,MAC)写入ARP表
```

### ARP表与缓存
- 初始为空，通过ARP交互动态学习
- 每个表项有一定**生存周期**，需定期更新以保证正确性
- 当一台主机刚接入网络时，其ARP表为空

### ARP分组格式（28字节）
| 字段 | 长度 | 说明 |
|------|------|------|
| 硬件类型 | 2B | 如以太网=1 |
| 协议类型 | 2B | 如IPv4=0x0800 |
| 硬件地址长度 | 1B | MAC地址=6 |
| 协议地址长度 | 1B | IP地址=4 |
| Operation | 2B | 1=请求，2=响应 |
| 发送方MAC | 6B | — |
| 发送方IP | 4B | — |
| 目标MAC | 6B | 请求时填0，响应时填写 |
| 目标IP | 4B | — |

### 注意点
- ARP分组28字节，封装到以太网MAC帧时需填充到46字节（因为以太网数据部分最短46字节）
- 交换机收到广播ARP帧会转发到所有其他接口；收到单播ARP响应会精准转发

## 生活类比
- **ARP工作流程**：就像你在一个大会议室里找人（知道名字=IP，不知道面孔=MAC）。你站起来大喊"三年二班的咸鱼同学请回答！"（广播请求）。所有人都听到了但只有咸鱼回应你："我就是，我穿红衣服戴眼镜"（单播回复）。然后你把他的特征记在小本本上（ARP表），以后直接找他。
- **ARP表**：相当于你的手机通讯录——存着朋友们的名字（IP）和电话号码（MAC）。第一次需要打电话时先问"你号码多少？"（ARP请求），之后直接查通讯录拨号（查ARP表），不用再问。
