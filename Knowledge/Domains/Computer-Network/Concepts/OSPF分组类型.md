# OSPF分组类型

## 类型判定
连接型 — 回答"OSPF的五种分组分别有什么作用、如何配合工作"的问题，核心是路由器之间通过这五种分组完成"打招呼→对答案→抄作业→确认"的完整协作流程。

## 是什么
OSPF协议定义了5种分组类型（由OSPF首部的Type字段标识），两台路由器建立邻居关系并同步LSDB的过程，就像两个新同桌**互借作业**的过程：先Hello打招呼认识 → DD互报"我会做哪些题"（LSDB摘要）→ LSR请求"借我抄不会的题" → LSU把具体答案发过去 → LSACK确认"已收到"。

## 输入-输出空间
- **输入**：不同场景下触发的OSPF分组交换
- **输出**：邻居关系建立 → LSDB同步完成 → 全网LSDB一致性
- **映射关系**：映射关系 — 五种分组类型构成一个完整的状态机，从NULL→2-Way→ExStart→Exchange→Loading→Full

## 正例（至少2个）
1. **新路由器加入OSPF域**：新路由器R2接入R1的网络上电启动。R1和R2通过Hello分组打招呼建立邻居关系 → DD分组交换各自的LSDB摘要 → R2发现缺少net1/3/4/5/6的LSA，发送LSR请求 → R1回复LSU把完整的LSA发给R2 → R2回复LSACK确认。R2的LSDB同步完成。
2. **周期性邻居保活**：R1每隔10秒向直连邻居R3发送Hello分组（签到打卡）。如果超过40秒没有收到R3的Hello回应，R1判定R3不可达，更新LSA并洪泛全网。

## 反例/边界（至少1个）
1. **DD分组 ≠ LSU分组**：DD分组是"摘要信息"（告诉对方自己有哪些LSA的头部/序号），不携带LSA的完整内容；而LSU分组携带完整的LSA数据。类比：DD是"我会做第一题、第二题、第五题"（只报题号），LSU是"第一题的完整答案是X=..."（给出具体内容）。

## 详细解释

### OSPF五种分组类型一览

| Type值 | 分组类型 | 英文缩写 | 作用 |
|--------|---------|---------|------|
| 1 | 问候分组 | Hello | 建立和维护邻居关系 |
| 2 | 数据库描述分组 | DD/DDP | 向邻居给出自己的LSDB摘要 |
| 3 | 链路状态请求分组 | LSR | 请求对方发送本路由器缺少的LSA |
| 4 | 链路状态更新分组 | LSU | 核心分组，携带完整的LSA数据 |
| 5 | 链路状态确认分组 | LSACK | 对收到的LSU进行确认，保证可靠性 |

### 分组交互完整流程

以新路由器R2加入OSPF域为例：

#### 第1步：Hello分组（建立邻居关系）
- R1和R2每**10秒**向直连邻居发送Hello分组（签到打卡）
- 超过**40秒**未收到Hello→认为邻居不可达
- 收到对方的Hello后，确认邻居关系和链路可达性

**关键效果**：
- 发现新邻居（如R1检测到R2新加入）
- 可确定新链路的代价
- 触发LSA更新（增加新邻居信息）+ 序号+1

#### 第2步：DD分组（交换LSDB摘要）
- 新邻居关系建立后，双方互相发送DD分组
- DD分组包含的**不是完整的LSA**，而是**LSA头部摘要**（LSA ID、序号等）
- 类比：告诉对方"我会做的题目编号"——"我有LSA #1, #3, #4, #5, #6"
- 如果摘要信息太多（超过IP分组数据部分容量），可拆分为多个DD分组发送

#### 第3步：LSR分组（请求缺少的LSA）
- 收到对方的DD后，对比自己的LSDB，发现缺少哪些LSA
- 通过LSR分组向对方请求："我没有LSA #2，请把#2的完整内容发给我"

#### 第4步：LSU分组（发送完整的LSA）
- 收到LSR后，将对方请求的LSA完整数据通过LSU分组发送
- LSU分组中直接携带完整的LSA数据结构（单链表）
- **LSU是OSPF最核心的分组类型**，承载实际的链路状态数据

#### 第5步：LSACK分组（确认收到）
- 收到LSU后，回复LSACK确认
- LSACK只包含已收到的LSA头部信息（简洁确认）
- 如果超时未收到LSACK，发送方可重传LSU，**保证可靠传输**

### Hello分组的更多细节

Hello分组除了建立和维护邻居关系外，还承担以下角色：

1. **周期保活**：每10秒发送一次，邻居长期（40秒）未收到则认为链路断开
2. **触发更新**：一旦检测到邻居关系变化（新邻居加入/邻居断开），触发LSA更新洪泛

### LSU的洪泛传播

当一个路由器从邻居收到含有**新信息**的LSU分组时：
1. 更新本地的LSDB
2. 将这个LSU**继续洪泛**给其他邻居（从非接收接口转发）
3. 即使**重复收到**同一个LSU，也需要给发来LSU的邻居回复LSACK

> 重复收到 ≠ 不处理：虽然LSU内容已知道，但发送方需要LSACK确认，否则发送方会重传。

### 信息交换的"抄作业"类比

| 阶段 | OSPF分组 | 抄作业流程 |
|------|---------|-----------|
| 互相认识 | Hello | 新同桌：你好！我叫R2 |
| 报题号 | DD | 我：我会做1,3,4,5,6题；同桌：我会做第2题 |
| 请求答案 | LSR | 我：请把第2题答案发我；同桌：1,3,4,5,6题答案也发我 |
| 给答案 | LSU | 把对方要的完整答案发过去 |
| 确认收到 | LSACK | 我已收到你发的答案，谢谢！ |

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| Hello周期 | 默认10秒 |
| 邻居超时 | 40秒（4倍Hello周期）未收到则判定邻居不可达 |
| DD分组可能多个 | 因IP分组长度限制，DD摘要可能需拆为多个分组 |
| LSU的洪泛 | 收到新LSU→继续转发给其他邻居（一传十、十传百） |
| 可靠机制 | LSACK保证LSU的可靠传输，未确认则重传 |
## 一句话
10告知存活，40秒挂。有更新立马洪泛
