# MIME（多用途互联网邮件扩展）

## 类型判定
判别模型 — 回答"MIME是一个协议还是一种格式规范"

## 是什么
MIME（多用途互联网邮件扩展）**不是通信协议**，而是一种**格式规范**。它解决了SMTP只能传输7位ASCII码（纯英文+符号）的限制，通过编码将中文、图片、视频等非ASCII数据转换为7位ASCII码，使得SMTP可以传输丰富多媒体内容的邮件。

## 输入-输出空间
- **输入**: 非ASCII数据（中文、图片、视频等二进制数据）
- **输出**: 编码后的7位ASCII码文本
- **映射关系**: 映射关系（非ASCII数据 → ASCII编码数据，解码时逆向还原）

## 正例（至少2个）
1. **中文邮件**: 中文文本通过base64编码转换为纯ASCII字符串，SMTP传输后在接收端解码还原为中文
2. **图片附件**: JPEG图片的二进制数据通过base64编码为ASCII字符串，SMTP传输后解码还原为图片

## 反例/边界（至少1个）
1. **常见误解**: MIME是一个通信协议？不，MIME不是协议，它只是对邮件格式的扩展规范。它定义了邮件内容的格式和编码方式，不负责通信本身

## 详细解释
MIME主要包括三部分内容：

### 1. 五个新的邮件首部字段
在SMTP原有to/from/subject基础上新增，如MIME-Version（版本号，确保编解码规则一致）等

### 2. 多种邮件主体格式
定义不同类型内容的格式规范：
- Content-Type: text（文本）/ image（图片）/ video（视频）等
- Content-Transfer-Encoding: 指明编码方式
- 用分界线（boundary）分隔不同的内容部分（如文本正文和图片附件之间的分界）

### 3. 传送编码 — base64
最著名的编码方式，原理简单：
- 将二进制数据每6比特为一组（2^6=64种状态）
- 映射为64个不同的ASCII字符（每个ASCII字符占7比特）
- **类比**: 就像16进制把4比特映射为1个16进制字符（0-9, A-F），base64是"64进制"

### MIME工作流程
```
非ASCII数据（中文/图片/视频）
    ↓ MIME编码（base64等）
7位ASCII码文本
    ↓ SMTP传输
接收端
    ↓ MIME解码
还原为非ASCII原始数据
```

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 本质 | 格式规范，非通信协议 |
| 核心编码 | base64（6比特→1个ASCII字符） |
| 解决的根本问题 | SMTP仅能传输7位ASCII码 |
| 角色类比 | 翻译官：把非ASCII数据"翻译"成ASCII，让SMTP能传输 |

### 使用原则
- MIME版本在发送方和接收方之间要对齐，确保编解码规则一致
- 不违背SMTP的原始规定，仅在其基础上扩展格式
