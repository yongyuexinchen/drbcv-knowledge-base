# 软件定义网络 (SDN)

## 类型判定
判别型 — 回答"SDN 是什么，和传统网络有何本质区别"，核心是区分**控制平面与数据平面分离**这一关键特征。

## 类比
**一句话比喻：** SDN 就是把每个路口的交警撤走，换成一个中央交通指挥大厅——所有路口的红绿灯不再自己独立判断，而是由大厅统一远程遥控。

| 维度 | 生活映射 |
|------|---------|
| 传统网络（分布式控制） | 每个十字路口站一个交警，各自根据自己看到的情况决定红绿灯——A 路口不知道 B 路口堵了 |
| SDN（集中式控制） | 交通指挥大厅通过摄像头看全城路况，统一给每个路口下发红绿灯指令——全局最优 |
| 南向接口（OpenFlow） | 指挥大厅到每个红绿灯控制器的专用电话线——"把东西方向调成绿灯 30 秒" |
| 北向接口 | 指挥大厅给市长看的仪表盘——"现在全城平均通行时间比昨天快 12%" |

## 是什么
SDN（Software-Defined Networking，软件定义网络）是一种新型网络架构，核心思想是将传统路由器中**紧耦合的「控制平面」和「数据平面」解耦**：控制平面集中到逻辑上的**SDN 控制器**（大脑），数据平面保留在**交换机/路由器**中（四肢），通过标准化的**南向接口（如 OpenFlow 协议）** 实现远程集中控制。

**一句话定义**：把「怎么转发」的决策权和「实际转发」的执行力分开，决策集中做，执行分布做。

## 输入-输出空间
- **输入**：网络管理员通过北向接口编写的全局网络策略（如"视频流量优先级最高"）
- **输出**：控制器通过南向接口向各交换机下发的流表规则（匹配域 + 动作）
- **映射关系**：从属关系 — SDN 是一种网络体系结构范式，不是单一协议

## 传统网络 vs SDN（考研核心对比）

| 维度 | 传统网络 | SDN |
|------|---------|-----|
| **控制平面位置** | **分布式**——每台路由器独立运行路由协议（RIP/OSPF），各自计算路由表 | **集中式**——SDN 控制器掌握全局拓扑，统一计算并下发流表 |
| **数据平面功能** | 根据本地路由表转发分组 | 根据控制器下发的流表进行**匹配+动作** |
| **控制与转发关系** | 紧耦合——每台设备既是"大脑"也是"四肢" | **解耦**——控制器是大脑，交换机是四肢 |
| **可编程性** | 低——每台设备独立配置，难以全局调整 | **高**——通过软件编程即可改变全网转发行为 |
| **开放接口** | 各厂商私有 CLI/API | **OpenFlow**（南向标准化接口） |
| **类比** | 每个路由器是一个独立交警 | 控制器是交通指挥大厅，交换机是红绿灯执行器 |

## 详细解释

### SDN 三层架构

```
┌──────────────────────────────┐
│       应用层（应用平面）         │  ← 流量工程、防火墙、负载均衡等网络应用
│      北向接口（REST API）       │
├──────────────────────────────┤
│       控制层（控制平面）         │  ← SDN 控制器（ODL / ONOS / Ryu / Floodlight）
│      南向接口（OpenFlow）       │
├──────────────────────────────┤
│    基础设施层（数据平面）         │  ← OpenFlow 交换机（仅执行流表转发）
└──────────────────────────────┘
```

### 三大平面 + 两大接口

| 组件 | 说明 |
|------|------|
| **数据平面（基础设施层）** | 由 OpenFlow 交换机组成，只做一件事：收到分组 → 查流表匹配 → 执行动作（转发/丢弃/修改）。**不做路由决策** |
| **控制平面（控制层）** | SDN 控制器，掌握全局网络拓扑，运行路由算法，**生成流表**下发到各交换机 |
| **应用平面（应用层）** | 运行在控制器之上的网络应用（流量监控、负载均衡、安全策略等） |
| **南向接口（控制器→交换机）** | **OpenFlow 协议**——标准化通信协议，控制器通过它下发/查询流表 |
| **北向接口（应用→控制器）** | REST API 等——网络应用通过它调用控制器功能 |

### OpenFlow 流表（南向接口核心）

流表是 SDN 交换机中的匹配-动作规则表：

| 匹配域（Match Fields） | 动作（Action） | 优先级 | 计数器 |
|------------------------|---------------|--------|--------|
| 入端口 + 源/目的 MAC + 源/目的 IP + 源/目的端口 + ... | 转发到端口 X / 丢弃 / 修改字段 / 送交控制器 | 多条匹配时优先用高优先级规则 | 匹配次数统计 |

**Table-Miss 表项**：流表中优先级最低的默认规则——不匹配任何规则时，将分组送交控制器处理。

### SDN 控制器

| 控制器 | 特点 |
|--------|------|
| **OpenDaylight (ODL)** | Java 开源，工业级，Linux 基金会项目 |
| **ONOS** | Java 开源，面向运营商 |
| **Ryu** | Python 开源，教学友好 |
| **Floodlight** | Java 开源，ODL 的前身 |

## 正例（≥2个）

1. **全局流量工程**：传统网络中，RIP 只看跳数选路可能导致某条链路拥塞而其他链路空闲。SDN 控制器能看到全网链路利用率 → 动态调整流表 → 将部分流量引导到空闲链路 → 实现全局负载均衡。
2. **数据中心网络**：Google 的 B4 WAN 使用 SDN 控制器全局调度数据中心之间的流量，链路利用率从传统网络的 ~30% 提升到 **~95%**——因为控制器能实时看到全网的链路状态，做全局最优的流量分配。

## 反例/边界（≥1个）

1. **SDN 不等于 OpenFlow**：OpenFlow 只是 SDN 最流行的南向接口协议——但 SDN 是一种**架构思想**（控制与转发分离），即使不用 OpenFlow（如用 NETCONF、P4 等），只要满足"集中控制+可编程"仍是 SDN。同样，用了 OpenFlow 也不一定是完整意义上的 SDN。

## 细节备注

### 考研常见题型

| 题型 | 要点 |
|------|------|
| **辨析：SDN 控制平面在哪？** | 集中式的 SDN 控制器中，而非分布式在各路由器上 |
| **辨析：SDN 向数据平面下发什么？** | 流表（flow table），而非路由表 |
| **辨析：OpenFlow 是什么？** | SDN 的**南向接口协议**，用于控制器与交换机之间的通信 |
| **SDN 是否改变传统网络分层？** | 否，SDN 不改变 OSI/TCP-IP 分层模型，它改变的是**控制逻辑的部署方式**（从分布式→集中式） |

### SDN 的优点

1. **全局优化**：控制器掌握全局视图，能做传统分布式路由协议做不到的最优决策
2. **灵活可编程**：改变转发行为不需要逐台登录设备，写一段程序下发即可
3. **简化设备**：交换机不再需要运行复杂的路由协议，硬件成本降低
4. **快速创新**：新协议/新功能可以在控制器软件层面快速实现和部署
