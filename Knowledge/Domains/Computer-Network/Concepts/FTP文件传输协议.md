# FTP文件传输协议

## 类型判定
连接模型 — 回答"FTP客户端和服务器之间如何一步步完成文件传输"

## 是什么
FTP（文件传输协议）是一种基于TCP的应用层协议，采用C/S模型，通过控制连接和数据连接两条独立的TCP连接实现文件上传和下载。控制信息与数据信息分离传输，称为**带外传输**。

## 输入-输出空间
- **输入**: 用户想要上传或下载的文件请求
- **输出**: 文件在客户端和服务器之间的成功传输
- **映射关系**: 映射关系（文件传输请求 → 文件传输结果）

## 正例（至少2个）
1. **下载文件**: 客户端通过控制连接（21端口）登录服务器，请求下载文件；服务器通过数据连接（主动模式20端口，或被动模式随机端口）传输文件数据
2. **上传文件**: 客户端通过控制连接登录并请求上传，通过数据连接将本地文件传输到服务器指定目录

## 反例/边界（至少1个）
1. **常见误解**: FTP可以直接修改远程文件的某一部分？不，FTP只能整体下载修改后再整体上传，无法局部修改文件

## 详细解释
### 两次连接
**控制连接**（TCP，21端口）
- 持久连接，整个FTP会话期间保持不断
- 用于传输控制信息（登录命令、用户名密码、操作指令等）
- 不传输文件数据

**数据连接**（TCP，20端口或随机端口）
- 非持久连接，每次文件传输前建立，传输完成后立即关闭
- 用于传输文件数据以及文件列表信息
- 数据传送进程随数据连接的建立而创建，随关闭而销毁
- 每个已登录用户：始终有1个控制进程，0或1个数据传送进程

### 两种传输模式
**主动模式**（官方默认，考研默认）：
1. 客户端通过控制连接告知服务器自己的IP+随机端口
2. 服务器通过固定20端口主动连接客户端指定的端口
3. 现实问题：无法穿透NAT（内网环境服务器无法主动连接客户端）

**被动模式**（现实默认）：
1. 客户端发送PASV命令，告知希望采用被动模式
2. 服务器开放随机端口并告知客户端
3. 客户端主动连接服务器的随机端口
4. 更适应NAT环境，现实中使用更广泛

### 三个工作阶段
1. **登录阶段**: 客户端控制进程连接服务器21端口 → 主进程建立TCP连接后继承给控制进程 → 客户端发送用户名密码 → 服务器验证
2. **数据传输阶段**: 客户端指定主动/被动模式 → 发送上传/下载请求 → 建立数据连接 → 传输文件 → 数据传输完毕后由发送方主动断开数据连接
3. **登出阶段**: 客户端发送quit命令 → 服务器响应 → 服务器主动发起第一次挥手 → 四次挥手断开控制连接

### 带外传输
控制信息与数据信息通过不同连接传输，称为"带外传输"。优点：控制命令不会因大数据传输而阻塞——即使正在下载大文件，也可通过控制连接随时发送停止命令。

### 功能特点
- 支持不同主机系统之间的文件传输（如DOS的FAT ↔ Unix的UFS）
- 支持用户权限管理（读/写权限控制）
- 支持匿名FTP，提供公用文件共享

### 补充细节
- 查看文件列表（list命令）：请求通过控制连接发送，但文件列表数据通过数据连接传输
- 断开数据连接由谁发起：取决于数据传输方向。上传时客户端知道文件传完，由客户端发起；下载时服务器知道文件传完，由服务器发起
- 主动模式无法穿透NAT，因为内网客户端没有公网IP供服务器主动连接

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 传输层协议 | 基于TCP |
| 应用层模型 | C/S模型 |
| 控制连接端口 | 21（固定） |
| 数据连接端口（主动） | 20（固定） |
| 数据连接端口（被动） | 随机端口 |
| 控制连接特性 | 持久 |
| 数据连接特性 | 非持久（一次性） |
| 通信方式 | 带外传输（控制与数据分离） |

### 使用原则
- 默认模式（考研）：主动模式
- 现实默认：被动模式（可穿透NAT）
- 在一次FTP会话中，用户可以多次切换主动/被动模式
