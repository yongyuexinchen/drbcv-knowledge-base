# TCP拥塞控制

## 类型判定
连接型 — 回答"TCP如何根据网络拥塞程度动态调整发送速率"，涉及拥塞窗口（cwnd）的动态变化算法（慢开始→拥塞避免→快恢复），以及拥塞窗口变化曲线的分析和计算。

## 是什么
TCP拥塞控制通过维护一个**拥塞窗口（cwnd）** 来限制发送方的数据发送量，以缓解网络拥塞。发送方实际的发送窗口大小 = min(拥塞窗口, 接收窗口)。拥塞控制算法由慢开始、拥塞避免和快恢复三种算法组成，根据网络状态（是否超时/是否收到冗余ACK）动态调整拥塞窗口大小。拥塞窗口反映**网络的传输能力**，与反映**接收方处理能力**的接收窗口不同。

## 输入-输出空间
- **输入**：当前拥塞窗口大小 + 阈值 + 网络反馈（超时事件/冗余ACK事件）
- **输出**：调整后的拥塞窗口大小 + 调整后的阈值（ssthresh）
- **映射关系**：映射关系 — 网络事件决定拥塞窗口的增减规则和幅度

## 正例（至少2个）
1. **慢开始阶段**：新连接开始时cwnd=1（MSS倍数），每收到1个ACK cwnd+1。第1个RTT后cwnd=2，第2个RTT后cwnd=4，第3个RTT后cwnd=8——指数增长，快速探测网络容量。
2. **超时后拥塞控制**：cwnd增长到24时发生超时→ssthresh=12（当前cwnd一半），cwnd=1重启慢开始→到达ssthresh后切换为拥塞避免（每RTT加1）→逐步恢复。

## 反例/边界（1个）
1. **拥塞控制 ≠ 流量控制**：流量控制由**接收方**控制（通过接收窗口限制发送速率），解决"接收方来不及处理"的问题；拥塞控制由**发送方**自己控制（通过拥塞窗口），解决"网络来不及传输"的问题。发送窗口 = min(拥塞窗口, 接收窗口)。

## 详细解释

### 核心概念

| 概念 | 含义 | 受谁影响 |
|------|------|---------|
| **拥塞窗口（cwnd）** | 反映网络传输能力的变量 | 拥塞控制算法 |
| **接收窗口（RWND）** | 反映接收方处理能力的变量 | 接收方反馈 |
| **发送窗口（SendWnd）** | 实际可发送的最大数据量 | = min(cwnd, RWND) |
| **阈值（ssthresh）** | 慢开始和拥塞避免的分界线 | 超时/快重传时调整 |

### 网络拥塞的判断
| 事件 | 拥塞程度 | 处理方式 |
|------|---------|---------|
| 所有段都正常收到ACK | 无拥塞 | 窗口可继续增长 |
| 收到**3个冗余ACK**（快重传触发） | **轻度拥塞** | 快恢复（适度降窗口） |
| **超时重传** | **严重拥塞** | 慢开始（窗口降为1） |

### 三种算法详解

#### 1. 慢开始算法（Slow Start）
**适用场景**：连接刚建立 或 发生超时重传后

| 规则 | 说明 |
|------|------|
| 初始cwnd | **1**（1倍MSS） |
| 增长方式 | **每收到1个ACK，cwnd + 1** |
| 增长效果 | **每经过1个RTT，cwnd翻倍**（指数增长） |
| 结束条件 | cwnd ≥ ssthresh → 切换为**拥塞避免** |

**慢开始不是真的"慢"，增长很快**——指数增长，目的是快速探测网络容量。

#### 2. 拥塞避免算法（Congestion Avoidance）
**适用场景**：cwnd ≥ ssthresh 时

| 规则 | 说明 |
|------|------|
| 增长方式 | **每经过1个RTT，cwnd + 1**（无论收到多少个ACK） |
| 增长效果 | **线性增长** |
| 结束条件 | 发生超时 或 收到3个冗余ACK |

**慢开始用指数跑，拥塞避免用线性跑**——超过阈值后谨慎增长。

#### 3. 快恢复算法（Fast Recovery）
**适用场景**：收到3个冗余ACK（快重传触发），判定为轻度拥塞

| 调整 | 规则 |
|------|------|
| 拥塞窗口 | cwnd = **当前cwnd的一半** |
| 阈值 | ssthresh = **当前cwnd的一半** |
| 后续 | 立即切换为**拥塞避免**（因cwnd = ssthresh） |
| 注意 | 快重传不再配合慢开始（旧版本TCP才用慢开始） |

**快恢复的特点**：只降一半，不归零；快速恢复后线性增长。

### 拥塞窗口变化曲线（核心图示）

```
cwnd（MSS倍数）

    │                  ╱  ╲     ↓
 16─┼───阈值(ssthresh)──── ╲    ↓
    │    ╱╲                ╲    ↓
 12─┼──╱──╲───新阈值───────╲────┼───快恢复后阈值
    │ ╱    ╲                ╲   │
  8─┼╱      ╲                ╲  │
    │        ╲                ╲ │
  4─┼         ╲───拥塞避免──────╲│
    │          ╲  线性增长       ╲
  2─┼           ╲                ╲
    │慢开始       ╲                ╲
  1─┼─────────────┼────────────────┼──→ RTT
    0  1  2  3  4  ...         12 13 14 15 16 17
      ←指数增长→ ← 线性增长 →  ↑    ←慢开始→←拥塞避免→
                                超时后
                                cwnd=1
                                ssthresh=12
```

#### 两种拥塞事件的对比

| 事件 | 严重拥塞（超时） | 轻度拥塞（3冗余ACK） |
|------|----------------|-------------------|
| **算法** | 慢开始 | 快恢复 |
| **cwnd** | **= 1**（归零） | **= cwnd / 2**（只减半） |
| **ssthresh** | **= cwnd / 2** | **= cwnd / 2** |
| **恢复速度** | 慢（从1开始指数增长） | 快（从中间值线性增长） |
| **ssthresh下限** | ≥2 | ≥2 |

### 例题分析

#### 例题1（纯拥塞控制）
MSS=1KB，cwnd=16KB时发生超时。之后4个RTT内所有传输都成功，第4个RTT结束时cwnd=？

1. 超时：ssthresh=16/2=8，cwnd=1
2. 1RTT后：cwnd=2（慢开始）
3. 2RTT后：cwnd=4（慢开始）
4. 3RTT后：cwnd=8（慢开始，到达ssthresh）
5. 4RTT后：cwnd=9（拥塞避免，只+1）
→ 答案：9KB

#### 例题2（拥塞控制 + 流量控制综合）
MSS=1KB，初始ssthresh=32KB，接收缓存=16KB且数据不被取走

| RTT | cwnd | RWND | 发送窗口 = min(cwnd, RWND) |
|-----|------|------|--------------------------|
| 0 | 1 | 16 | 1 |
| 1 | 2 | 15 | 2 |
| 2 | 4 | 13 | 4 |
| 3 | 8 | 9 | 8 |
| 4 | 16 | 1 | **1** |

→ 注意发送窗口受接收窗口限制，不能只看拥塞窗口

### 生活类比
**像健身循序渐进的运动量**：
- 慢开始 = 刚开始锻炼每天运动量很小（1公里），但第二天翻倍（2公里），第三天再翻倍（4公里）——指数增长
- 阈值 = 给自己设的"运动量安全上限"（如16公里）
- 拥塞避免 = 超过上限后不能翻倍了，每天只增加1公里——线性增长
- 超重传 = 运动过量累倒了（严重问题）→ 从1公里重新开始
- 快恢复 = 有点累但没倒（小问题）→ 运动量减半后继续

## 细节备注

### 🚨 易错点
- **发送窗口 = min(cwnd, RWND)**：综合题必须同时考虑两个窗口
- **超时 vs 快重传**：超时→严重拥塞（cwnd=1）；3冗余ACK→轻度拥塞（cwnd/2）
- **ssthresh最小为2**（不能设为1）
- **计数单位是MSS倍数**：如cwnd=16表示16倍MSS，实际值 = 数字×MSS

### 子特性
| 特性 | 说明 |
|------|------|
| 慢开始 | 初始cwnd=1，指数增长 |
| 拥塞避免 | 超过阈值后线性增长 |
| 快恢复 | 3冗余ACK后cwnd减半 |
| 超时处理 | cwnd归1，ssthresh减半 |
| 阈值下限 | ssthresh ≥ 2 |

### 真题特点
- 每个TCP段都满载MSS发送
- 只考虑单向传输（一方只发数据，一方只返ACK）
- 接收方采用立即确认
- 拥塞窗口可能和接收窗口同时限制发送窗口
