# 证书与自签名证书（SSL/TLS Certificate）

## 类型判定
判别 — TLS 加密的"身份证"。由受信任的证书颁发机构（CA）签发的证书被浏览器和操作系统自动信任；自己签发的证书（自签名）不被信任，会触发安全警告。

## 类比 ★
### 一句话比喻
正规证书 = 公安局签发的身份证——银行、机场、酒店都认。自签名证书 = 你自己手写一张"我是郭于稔"的纸片——没人信，因为没法验证是不是你自己编的。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| CA（证书颁发机构） | 公安局——有公信力的第三方 |
| 正规证书（Let's Encrypt/Cloudflare） | 公安局发的身份证 |
| 自签名证书（openssl 生成） | 自己手写的姓名纸条 |
| 证书链验证 | 银行扫描身份证——联网验证真伪 |

## 是什么
数字证书包含：域名、公钥、有效期、签发者（CA）的签名。浏览器/操作系统内置了受信任的 CA 列表。访问 HTTPS 网站时：①验证证书由受信任 CA 签发 ②验证证书未过期 ③验证域名匹配。三项全通过才显示🔒。

## 正例
1. **Cloudflare 的正规证书**：Cloudflare 自动为 `yongyuexinchen.xin` 签发 Let's Encrypt/Google Trust Services 证书，全球浏览器都信任——V2RayN 连 `vps.yongyuexinchen.xin:443` 不报错。
2. **Let's Encrypt 免费证书**：自动化签发，90 天有效期，被所有主流浏览器信任——个人项目首选。

## 反例/边界
1. **Xray 自签名证书报错**：V2RayN 直连 `192.255.128.175:443` 时，Xray 用的是 3X-UI 自动生成的自签名证书 → 报 `x509: certificate signed by unknown authority`。
2. **Xray 26.x 废弃 allowInsecure**：旧版可通过 `allowInsecure=true` 跳过验证——26.x 版删除此选项，必须用正规证书或 `pinnedPeerCertSha256`（钉住特定自签名证书的指纹）。
3. **自签名 ≠ 不安全**：自签名证书同样加密通信，只是身份无法由第三方验证——适合内网或只有你自己知道的场景。

## 详细解释
本项目中证书相关的两次关键决策：
```
决策 1: Hysteria2 用 insecure=1
  跳过证书验证——因为 VPS 上没有正规证书，只有 Hysteria2 自己的密钥
  风险：中间人攻击？没有，因为自建 VPS 只有自己用

决策 2: Shadowsocks 走 Cloudflare Tunnel
  Cloudflare 提供正规证书（客户端→CF 的 TLS 有🔒）
  CF→VPS 是 Tunnel 内部连接，不需要证书
  避开了 Xray 26.x 的 allowInsecure 问题——釜底抽薪
```
