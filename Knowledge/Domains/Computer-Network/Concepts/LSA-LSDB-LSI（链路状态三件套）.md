# LSA / LSDB / LSI（链路状态三件套）

## 类型判定
连接型 — 回答"LSA、LSDB、LSI 分别是什么、三者什么关系"的问题。它们是 OSPF 的数据基础——LSA 是原材料，LSDB 是仓库，LSI 是统称。

## 类比
**一句话比喻：** LSA 是每个人写的自我介绍卡片，LSDB 是把所有人的卡片收齐装订成册，LSI 是"个人信息"这个统称。

| 术语 | 类比 | 一句话 |
|------|------|--------|
| **LSA** | 一本书的一个章节 | "我是 R1，我的邻居有 R2(代价3)、R3(代价5)" |
| **LSDB** | 所有章节装订成的整本书 | 全网拓扑的邻接表，每台路由器内容一致 |
| **LSI** | "书里的内容"这个说法 | 广义统称，可以指 LSA、LSDB 或某条链路信息 |

## 是什么

```
LSI (Link State Information) — 统称，链路状态信息的广义概念
  │
  ├── LSA (Link State Advertisement) — 具体的数据包
  │     每台路由器发布一份，描述"我是谁 + 直连邻居 + 代价"
  │
  └── LSDB (Link State Database) — 所有 LSA 的集合
        本质 = 图的邻接表，运行 Dijkstra 的输入
```

### LSA（链路状态通告）

路由器把自己的直连链路信息封装成的数据包。结构本质是一个**单链表**：

```
[头节点] 路由器ID + 序号(标识版本新旧)
  ├── [节点1] 邻居R2, 代价3
  ├── [节点2] 邻居R3, 代价5
  └── [节点3] 网络net1, 代价1
```

每次链路状态变化（邻居断开/恢复、代价改变），路由器更新自己的 LSA（序号+1），立即洪泛给全网。

### LSDB（链路状态数据库）

全网所有 LSA 的集合。每台路由器通过洪泛收集所有路由器的 LSA 后，构建出一个**完全一致的 LSDB**。

LSDB ≈ 图的邻接表：
```
R1: →R2(3), →R3(5), →net1(1)
R2: →R1(3), →R4(2)
R3: →R1(5), →R4(4), →R5(6)
...
```

每台路由器对自己的 LSDB 运行 Dijkstra 算法，以自己为源点计算最短路径树。

### LSI（链路状态信息）

广义统称，不是具体的数据结构。教材中说"路由器需要知道 LSI"时，可能指：
- 某条具体链路的状态（R1-R2 的代价）
- 一个 LSA 的内容
- LSDB 中的某条记录

**考试中看到 LSI = 泛指链路状态相关信息，不用纠结具体指哪个。**

## 正例（≥2 个）

1. **洪泛 LSA → 全网 LSDB 一致**：R1 的 LSA 被洪泛后，R2 收到→转发给 R3/R4→它们继续转发。最终全网 6 台路由器的 LSDB 都包含 R1 的 LSA。每台路由器的 LSDB 完全一致——这是 OSPF 能独立计算而不冲突的前提。

2. **链路断开时 LSA 更新**：R2-R4 之间的光纤断了。R2 和 R4 各自探测到邻居丢失→各自更新 LSA（序号+1）→各自洪泛→全网 LSDB 同步更新→所有路由器重新运行 Dijkstra。整个过程在数秒内完成。

## 反例/边界（≥1 个）

1. **LSA 序号冲突**：如果同一台路由器因网络抖动连续发出多个 LSA，其他路由器通过**序号**判断哪个最新。序号大的 LSA 覆盖旧的。这是 OSPF 的版本控制机制——不是所有 LSA 都会被保留，只保留最新的。

2. **LSDB ≠ 路由表**：LSDB 是原始拓扑数据（谁连谁、代价多少），路由表是 Dijkstra 处理后的转发指令（去 X 走 Y）。初学者常把两者搞混。

## 详细解释

### 三件套在 OSPF 流程中的位置

```
① 路由器探测直连邻居 + 代价
         │
         ▼
② 封装为 LSA ─────────────────────┐
         │                        │
         ▼                        │
③ 洪泛 LSA 给全网                  │
         │                        │
         ▼                        │
④ 收集所有 LSA → 构建 LSDB        │ ← 同一台路由器的
   （图的邻接表，全网一致）         │   更新版 LSA 覆盖旧版
         │                        │
         ▼                        │
⑤ 对 LSDB 运行 Dijkstra ──────────┘
         │
         ▼
⑥ 生成路由表
```

### LSA 的内容（以 R1 为例）

| 字段 | 值 | 说明 |
|------|-----|------|
| 路由器 ID | R1 | 谁发的 |
| 序号 | 3 | 第几次更新（越大越新） |
| 邻居列表 | R2(代价3), R3(代价5), net1(代价1) | 直连的都有谁 |

### LSDB 的一致性

洪泛机制保证了**最终一致性**——不是"一瞬间所有路由器同时更新"，而是"在很短时间内（几秒）所有路由器都收到了新 LSA"。在此期间可能出现短暂的不一致（某台路由器还没收到更新），但不影响最终结果。
