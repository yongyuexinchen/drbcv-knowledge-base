# ChatGLM3-6B 微调：部署与数据格式

## 类型判定
[程序] — 在 AutoDL 云平台上部署 ChatGLM3-6B 并进行微调的完整流程，涵盖环境搭建、两种官方数据集格式（多轮对话/输入输出）的结构解析、微调执行与模型测试。

## 类比 ★
### 一句话比喻
你要把一位通用翻译官（ChatGLM3）培训成服装行业的专业导购。先租一间配有超级电脑的培训室（AutoDL 4090），然后编写培训教材——要么是"顾客问、导购答"的问答本（输入输出格式），要么是完整对话记录含工具调用（多轮对话格式），培训 4 小时后翻译官就成了能精准推荐阔腿裤的服装专家。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| ChatGLM3-6B 基座模型 | 通用翻译官（什么领域都能翻，但不够专） |
| 微调数据集 | 行业培训教材（服装问答 / 对话记录） |
| 多轮对话格式 | 完整培训录像：导师示范 + 学员练习 + 工具使用 |
| 输入输出格式 | 速查问答手册：一个问题一个标准答案 |
| System 角色提示词 | 贴在桌上的便签："你是服装导购，帮顾客选衣服" |
| 微调 4 小时 | 封闭培训 4 小时，学完全套教材 |

## 是什么
ChatGLM3-6B 是智谱/清华续 ChatGLM2 之后发布的第三代开源大模型，支持在云端 GPU 上使用官方提供的微调脚本进行领域适配。官方支持两种数据集格式：多轮对话格式（含工具调用能力）和输入输出格式（简单问答对）。微调在 AutoDL 的 RTX 4090 上约需 3-4 小时，训练完成后可导出微调模型并通过 Web UI 或终端测试效果。

## 输入-输出空间（程序型必填）
- **输入**: AutoDL 4090 实例、ChatGLM3-6B 模型权重、符合格式的数据集 JSON
- **输出**: 微调后的模型权重文件（含 pytorch_model.bin 等）+ Web UI 对话服务
- **前置条件**: conda 虚拟环境已激活、所有依赖已安装、模型权重已下载

## 数据集格式详解

### 格式一：多轮对话（含工具调用）
最完整的格式，数据外层用 `[]` 包裹，每条数据是一个独立对象，包含两个核心字段：

```
{
  "tools": [...],        // 工具定义（名称、参数、描述）
  "conversations": [...] // 对话记录
}
```

**conversations 中的四种角色**：
| 角色 | 含义 | 示例 |
|------|------|------|
| `system` | 系统级提示词，持续提醒模型的定位 | "你是一个程序员" |
| `user` | 用户说的话 | "帮我检索悉尼的卫星图像" |
| `assistant` | AI 返回给用户的话 | "我需要使用 get_satellite_image 工具" |
| `tool` | 工具调用与返回（非原生角色） | 工具名称 + 参数 + 返回值 |

**设计意图**：system 提示词在每次 AI 输出时都会被"重复提醒"——就像有人在 AI 耳边不停说"你是程序员、你是程序员"。多轮对话格式专门训练模型的对话能力和工具使用能力。

### 格式二：输入输出（简单问答对）
最简格式，`[{"prompt": "问题", "response": "回答"}, ...]`：
- 每条数据只有一个 prompt 和一个 response
- 没有工具字段，没有角色区分
- 适合场景：客服标准问答、产品介绍、FAQ 应答
- 示例：`{"prompt": "宽松的阔腿裤怎么搭配", "response": "宽松的阔腿裤能够修饰腿型，搭配修身的上衣..."}`

### 两种格式对比
| 维度 | 多轮对话格式 | 输入输出格式 |
|------|-------------|-------------|
| 复杂度 | 高，含工具调用和角色 | 低，纯问答对 |
| 适用场景 | Agent、工具调用、复杂对话 | 标准问答、FAQ、客服 |
| 训练难度 | 高 | 低 |
| 数据标注成本 | 高 | 低 |

## 正例（≥2 个）
1. **多轮对话微调**：用含工具调用的对话数据训练模型，用户问"帮我查悉尼卫星图像，我的生日是 X 日"→ 模型自动调用 get_satellite_image 工具 → 返回图像 URL。训练约 3 小时 41 分钟，4090 上完成。
2. **输入输出微调**：用服装问答数据集微调，测试时输入"宽松的阔腿裤能修饰腿型吗"→ 模型回答"宽松的阔腿裤能够修饰腿型，搭配..."与数据集中的 response 高度吻合。可通过增加数据集条数或训练轮次进一步提升效果。

## 反例/边界（≥1 个）
1. **模型下载失败**：从 Hugging Face 拉取 ChatGLM3 权重时卡住——三种解决方案：①多执行几次 + 关闭学术加速（国内访问 Hugging Face 不稳定）；②换机器重试；③最慢方案：百度网盘下载 → 上传阿里云盘 → 服务器拉取（不推荐，容易出错）。
2. **训练后的模型文件定位**：微调完成后在 `output/` 目录下生成多个文件夹，要找"包含很多文件的文件夹"（含 pytorch_model.bin、tokenizer 等），而不是只有单个文件的文件夹。加载时路径必须带 `/root/` 前缀。

## 详细解释

### 微调完整流程
| 步骤 | 命令/操作 | 注意 |
|------|----------|------|
| 1. 创建实例 | AutoDL 选 4090（或 3090 24G） | 4090 微调速度最快 |
| 2. 环境准备 | conda create → conda activate → pip install -r requirements | 必须看到 `(env_name)` 前缀 |
| 3. 克隆项目 | git clone 官方微调仓库 | 失败则开启学术加速，加速用完立即关 |
| 4. 拉取模型 | git lfs install → git clone 模型仓库 | 约 200MB/s，完成后验证文件完整性（带 `*`=完整） |
| 5. 测试基座模型 | 运行 cli_demo.py + web_demo.py | 替换模型路径 → 终端/Web UI 对话测试 |
| 6. 准备数据集 | 按两种格式之一准备 JSON | 数据条数越多效果越好 |
| 7. 修改参数 | 修改 config 中的 base_model 和 data_path | 指向正确的模型路径和数据集位置 |
| 8. 执行微调 | 运行微调脚本 | 终端显示预估时间，4090 约 3-4 小时 |
| 9. 测试微调模型 | 加载 output 目录的模型 → Web UI 测试 | SSH 端口 8501，密码手打不显示 |

### 关键注意事项
- conda 虚拟环境激活后前缀必须变为环境名，否则重开终端
- 学术加速：访问 Hugging Face 时开启，用完必须关闭（国内访问反而更快）
- 密码输入：终端不显示任何字符，必须逐字母手动输入，区分大小写
- 端口映射：注意 SSH 指令中的端口号需与 Web UI 端口（8501）对应
