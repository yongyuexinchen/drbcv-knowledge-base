# 提示词结构

## 类型判定
提示词结构是工程化编写提示词的四段式模板——按"上下文 → 指令 → 输入 → 输出"的顺序组织内容，使提示词清晰、可复用、可维护。

## 类比 ★
### 一句话比喻
写一封正式的商务邮件你不会把所有内容堆成一段——你会分"称呼→背景说明→具体要求→期望回复格式"。提示词结构就是 AI 对话里的"邮件模板"。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 上下文（角色+任务+知识） | 邮件开头："我是XX项目负责人" |
| 指令（步骤+示例） | 邮件正文："请在本周五前完成以下三项工作……" |
| 输入数据 | 邮件附件或引用的数据 |
| 输出要求 | 邮件结尾："请以 Excel 表格回复" |
| 四段式结构 | 完整的商务邮件模板 |

## 是什么
提示词四段式结构：①上下文——定义角色（"你是XX"）、任务（"你的任务是XX"）、背景知识；②指令——明确命令、操作步骤（思维链）、少量示例（Few-shot）；③输入数据——用户的具体问题或待处理文本，常留空让系统填充；④输出要求——格式（JSON/纯文本/表格）、风格、禁止事项。其中"指令"是必选的，其他三部分视场景可选。

## 正例（≥2 个）
1. 实体抽取：上下文（你是文本提取器）→ 指令（提取品牌中文名、英文名、创立时间、主打商品）→ 输入（给定内容：___）→ 输出（格式：字段冒号字段值，只输出字段和值）。
2. 智能音箱：上下文（你是智能助理）→ 指令（从用户输入提取结构化信息为 JSON）→ 输入（用户说的话）→ 输出（JSON 格式，方便后端解析）。

## 反例/边界（≥1 个）
1. 把角色、任务、格式要求全混在一段话里——模型可能理解混乱。结构化分段后，模型能清晰区分"我是谁、要我干什么、给我什么数据、我要输出什么"。
2. 简单的一句话提问（"今天天气怎么样"）不需要四段式结构——过度结构化对简单任务没有增益。

## 详细解释
提示词结构对应两大编写原则：①"清晰明确的指令"——通过分隔符（引号、尖括号）区分任务要求和用户输入，使用标号 1234 列出要求；②"给模型思考时间"——提供上下文和分步骤指令。企业级提示词通常会在结构中留出"用户输入占位符"，运行时动态拼接完整提示词再发给大模型。强制输出 JSON 等结构化格式是为了方便后端代码解析。
