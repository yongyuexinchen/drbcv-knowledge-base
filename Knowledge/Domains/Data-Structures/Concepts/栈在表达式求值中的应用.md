# 栈在表达式求值中的应用

## 类型判定
程序型 — 栈的两个经典应用组合：**① 中缀转后缀**（用运算符栈）+ **② 后缀表达式求值**（用操作数栈）。合并两者即为**中缀表达式直接求值**（双栈协同）。

## 是什么
三种算术表达式：中缀（运算符在中间）、后缀/逆波兰（运算符在后）、前缀/波兰（运算符在前）。核心在于后缀表达式**无需括号即可无歧义地表达运算次序**，计算机用栈可高效计算。

## 输入-输出空间
- **中缀 → 后缀**：输入中缀表达式字符串 → 输出后缀表达式
- **后缀求值**：输入后缀表达式 → 返回计算结果
- **中缀直接求值**：输入中缀表达式 → 双栈协同，直接返回结果

## 正例（≥2 个）
1. **中缀 `A+B*(C-D)-E/F` → 后缀 `ABCD-*+EF/-`**：按左优先原则确定运算符生效次序
2. **后缀 `15 7 1 1 + - / 3 * 2 1 1 + + -` 求值**：从左往右，遇操作数入栈，遇运算符弹出两个栈顶运算后压回

## 反例/边界（≥1 个）
1. **后缀求值时操作数左右顺序颠倒**：先弹出的是**右操作数**，后弹出的是左操作数。如 `AB/`，B 先出栈 → 是除数，A 后出栈 → 是被除数。顺序错则除法/减法结果错误
2. **前缀求值时则相反**：先弹出的是**左操作数**，后弹出的是右操作数

## 详细解释

### 三种表达式

| 类型 | 格式 | 示例 |
|------|------|------|
| 中缀（Infix） | 操作数 运算符 操作数 | `A + B` |
| 后缀/逆波兰（Postfix） | 操作数 操作数 运算符 | `AB+` |
| 前缀/波兰（Prefix） | 运算符 操作数 操作数 | `+AB` |

### 中缀 → 后缀（用运算符栈）

**左优先原则**：当左右两个运算符都可以先算时，优先让左边的先生效。

```
从左往右扫描：
  遇到操作数 → 直接输出
  遇到运算符 → 弹出栈中所有优先级 ≥ 当前运算符的运算符（出栈即输出），然后当前入栈
  遇到 '(' → 直接入栈
  遇到 ')' → 依次弹出栈中运算符直到 '('（括号不输出）
扫描完后 → 弹出栈中剩余运算符
```

**运算符优先级**：`* / > + -`，同级从左到右。

### 后缀表达式求值（用操作数栈）

```
从左往右扫描：
  遇到操作数 → 入栈
  遇到运算符 → 弹出两个栈顶，先弹出的是右操作数！
              执行运算，结果压回栈
扫描完后 → 栈顶即最终结果
```

### 中缀直接求值（双栈协同）

结合上面两个算法，用一个**运算符栈**和一个**操作数栈**：
- 扫描到操作数 → 压入操作数栈
- 扫描到运算符/界限符 → 按「中缀转后缀」的规则处理运算符栈
- 每弹出一个运算符，就从操作数栈弹出两个操作数执行运算，结果压回

### 核心代码（后缀表达式求值）

```c
// 假设后缀表达式以字符串数组 tokens 给出，如 {"15","7","1","1","+","-","/",...}
int EvalPostfix(char *tokens[], int n) {
    int stack[MAXSIZE];
    int top = -1;

    for (int i = 0; i < n; i++) {
        if (isNumber(tokens[i])) {
            stack[++top] = atoi(tokens[i]);      // 操作数入栈
        } else {
            int b = stack[top--];                 // ⚠️ 先弹出的是右操作数
            int a = stack[top--];                 //    后弹出的是左操作数
            int result;
            switch (tokens[i][0]) {
                case '+': result = a + b; break;
                case '-': result = a - b; break;
                case '*': result = a * b; break;
                case '/': result = a / b; break;
            }
            stack[++top] = result;                // 结果压回
        }
    }
    return stack[top];
}
```

### 中缀转后缀时运算符优先级的判断

当前扫描到运算符 `op`，与栈顶 `top` 比较：
- 若 `priority(top) >= priority(op)`：弹出 top（因为左优先原则，左边的先算）
- 若栈顶是 `(`：op 直接入栈（括号内的优先级暂时未知）

### 时间复杂度

| 操作 | 复杂度 |
|------|--------|
| 中缀 → 后缀 | $O(n)$ |
| 后缀求值 | $O(n)$ |
| 中缀直接求值 | $O(n)$ |

空间复杂度：$O(n)$（栈的深度）

## 类比

### 一句话比喻
**表达式求值就像吃一道需要严格按顺序做的菜。中缀表达式 = 人类菜谱（"先炒鸡蛋再放番茄"——人类懂），后缀表达式 = 机器人指令（"鸡蛋拿、番茄拿、炒"——没有歧义，按顺序来就行）。中缀转后缀 = 把人类菜谱翻译成机器人能执行的 step-by-step，而栈就是这个翻译官手里的记事本。**

### 生活映射

| 数据结构世界 | 现实世界 |
|---|---|
| 中缀表达式 | 人类菜谱："先腌制鸡肉(20分钟)，然后炒到变色，最后加青椒" |
| 后缀表达式 | 机器人指令："鸡肉拿、腌20分、青椒拿、炒"——不用括号 |
| 运算符栈（中缀转后缀） | 翻译官的小抄——记下"这个菜要炒，但得等括号里的先做完" |
| 操作数栈（后缀求值） | 厨房台面——暂放食材，需要时才取用 |
| 左优先原则 | 两个师傅都能开工时，左边的先动手 |
| `(` 入栈 | 翻译官看到菜谱上写了"此处开始一个子任务" |
| `)` 触发弹栈 | 翻译官说"子任务结束了，括号里的先全部执行！" |
| 先弹出右操作数 | 灶台上的调味料——最近的先被拿到（LIFO） |
| 前缀表达式求值先弹出左操作数 | 从右往左看菜谱，最右边的最先被处理 |
