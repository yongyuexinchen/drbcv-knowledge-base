# KMP 算法（Knuth-Morris-Pratt）

## 类型判定
程序型 — 字符串模式匹配的高效算法。核心创新：利用模式串自身的结构信息（next 数组），使主串指针 `i` 绝不回溯，时间复杂度从 $O(nm)$ 降至 $O(n+m)$。`derives` [[朴素模式匹配算法]]。

## 是什么
KMP 算法是朴素模式匹配的优化：当某字符失配时，不把主串指针 `i` 回退，而是根据模式串已成功匹配的部分，将模式串指针 `j` 跳到一个合适的位置继续匹配。这个「跳到哪」的信息预先计算为 **next 数组**，只依赖模式串本身。

## 输入-输出空间
- **输入**：主串 S（长度 n），模式串 T（长度 m），next 数组（长度 m+1）
- **输出**：int — T 在 S 中首次出现的位序，找不到返回 0
- **前置条件**：已预计算出 next 数组；$1 \le m \le n$

## 正例（≥2 个）
1. **S="GOOGLEGOOGLEGOOGLE", T="GOOGLE"**：朴素匹配需多次回溯；KMP 利用 next 数组跳过不可能匹配的位置，`i` 只进不退
2. **S="ABAABAABAABC", T="ABAABC"**：当 T 的第 6 个字符 'C' 失配时，`j = next[6] = 3`，直接从 T 的第 3 个字符 'A' 继续匹配，跳过中间两个无效子串

## 反例/边界（≥1 个）
1. **next[1] = 0**：第一个字符就失配 → `j = 0`，然后 `i++` 和 `j++`（同时前移，相当于换下个子串）
2. **主串虽长但模式串没有任何重复结构**（如 `T="ABCDEF"`）：next 数组全为 0/1，KMP 退化得和朴素匹配差不多——但 `i` 仍不回溯

## 详细解释

### 核心思想：为什么 i 可以不回溯？
当匹配到第 j 个字符失配时，**前面 j-1 个字符一定和模式串的前 j-1 个字符完全相同**。这就意味着：
- 我们**已经知道**主串中这 j-1 个字符是什么
- 如果模式串的前缀和后缀有重叠，就可以「滑动」模式串，让前缀对齐到已匹配的后缀位置
- 中间那些肯定不匹配的子串直接跳过

### KMP 匹配代码

```c
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {  // j==0 或 匹配
            i++; j++;                          // 继续比较
        } else {
            j = next[j];                       // i 不动，j 回跳！
        }
    }
    if (j > T.length)
        return i - T.length;                   // 匹配成功
    else
        return 0;
}
```

**与朴素匹配的关键区别**（仅两处）：
| | 朴素匹配 | KMP |
|---|---|---|
| 失配时 `i` | `i = i - j + 2`（回溯） | `i` 不变（好马不吃回头草） |
| 失配时 `j` | `j = 1` | `j = next[j]` |

### next 数组的含义
`next[j]` = 当模式串的第 `j` 个字符失配时，`j` 应该跳到哪个位置继续匹配。

**手算 next 数组的方法**：
1. `next[1] = 0`（任何模式串！第一个字符失配 → 换下个子串）
2. `next[2] = 1`（任何模式串！第二个失配 → 只能和第一个比）
3. 对 $j \ge 3$：在失配位置画一条分界线，将模式串逐步右移，找到**分界线左边上下完全匹配**的位置 → 此时 j 应指向匹配部分的**下一位置**

### 手算示例：T = "ABAABC"

```
j:   1  2  3  4  5  6
T:   A  B  A  A  B  C
next:0  1  ?  ?  ?  ?
```

- **next[3]**：失配位置前为 "AB"，右移1格→对不上，右移2格→全部跨过 → `next[3]=1`
- **next[4]**：失配位置前为 "ABA"，右移1→B≠A；右移2→A=A（对上了！）→ 下一位置是2 → `next[4]=2`
- **next[5]**：失配位置前为 "ABAA"，右移2→"AB"匹配→下一位置是3 → `next[5]=3`
- **next[6]**：失配位置前为 "ABAAB"，右移3→"ABA"匹配→下一位置是4 → `next[6]=4`

**最终**：`next = [0, 1, 1, 2, 3, 4]`

### 经典练习：T = "GOOGLE"
```
j:   1  2  3  4  5  6
T:   G  O  O  G  L  E
next:0  1  1  1  2  1
```
> 特点：模式串几乎没有重复前缀，next 数组值很小 → KMP 优势不明显。

### 时间复杂度
| 步骤 | 复杂度 |
|------|--------|
| 预处理（求 next 数组） | $O(m)$ |
| 模式匹配 | $O(n)$（i 只增不减，最多 n 步） |
| **总计** | $\mathbf{O(n+m)}$ |

vs 朴素匹配最坏 $O(nm)$。

## 类比

### 一句话比喻
**KMP 算法就像你看一段已经看过的视频——点击进度条往前跳 10 秒时，你不会从第 0 秒重新看，而是直接跳到已经看过的那个位置继续。朴素匹配每次失配都「倒回起点+1 格重来」——像金鱼一样只有 7 秒记忆；KMP 拿着 next 数组这张「小抄」，记住「这部分我已经知道长什么样了，直接跳到下一个值得查的位置」。**

### 生活映射
| 代码世界 | 视频跳看现场 |
|---|---|
| 主串 S | 整部电影的全部帧 |
| 模式串 T | 你要找的一段画面（比如一个特定的镜头） |
| `i` 指针（主串） | 你现在看到电影的哪一帧 |
| `j` 指针（模式串） | 你在对比目标画面的第几帧 |
| 失配 | 「这段画面不对，不是我要找的」 |
| `i = i - j + 2`（朴素回溯） | 「好，我倒回到刚才起点的下一帧，从头比」→ 浪费时间 |
| `j = next[j]`（KMP 跳转） | 「前面 5 帧我已经确认过了，直接从第 3 帧开始比对就行」 |
| next 数组 | 一张「跳过指南」小抄：「如果在第 j 帧失配，跳到第 k 帧继续」 |
| `next[1]=0` | 「第一帧就不对？那这段肯定不是，换下一个片段吧」 |
| 前 j-1 个字符已匹配 | 你已经确认前 j-1 帧和目标画面一模一样 |
| $O(n+m)$ | 你全程不倒退，电影放完一遍就找完了 |
