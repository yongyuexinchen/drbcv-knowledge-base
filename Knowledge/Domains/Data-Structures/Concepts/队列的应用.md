# 队列的应用

## 类型判定
判别型 — 队列（FIFO）在树/图遍历和操作系统中的三个典型应用场景，体现"先来先服务"思想。

## 是什么
队列的 FIFO 特性使其天然适合**按到达顺序依次处理**的场景。三大应用：① 树的**层次遍历**；② 图的**广度优先搜索**（BFS）；③ 操作系统中的**先来先服务调度**（打印队列、就绪队列、缓冲区管理）。

## 输入-输出空间
- **层次遍历**：逐层访问树节点，每访问一个节点，将其左右孩子入队
- **BFS**：从起点出发，逐层扩散访问图中所有可达节点
- **缓冲区**：生产者（快）→ 队列缓冲 → 消费者（慢），缓解速度不匹配

## 正例（≥2 个）
1. **树的层次遍历**：根节点入队 → 循环：出队并访问 → 将其左右孩子入队 → 直到队空。输出顺序就是从上到下、从左到右的层次序
2. **打印机缓冲区**：多人同时提交打印 → 系统按提交顺序放入队列 → 打印机逐个取出打印（FIFO）

## 反例/边界（≥1 个）
1. **深度优先遍历（DFS）不用队列**：DFS 是一路走到底再回溯 → 使用栈（显式或隐式递归栈），不能用队列
2. **优先级调度不用普通队列**：操作系统中并非所有调度都是"先来先服务"，高优先级进程可能需要插队 → 优先队列

## 详细解释

### 树的层次遍历算法

```
初始化：根节点入队
while (队列非空) {
    取出队头节点 p 并访问
    if (p 有左孩子)  左孩子入队
    if (p 有右孩子)  右孩子入队
}
```

**为什么是队列？** 先入队的父节点先被处理，其孩子后入队排在后面。这样保证了**同层节点按入队顺序依次访问**，且上层全部访问完才轮到下层。

### 图的广度优先搜索（BFS）

```
初始化：起点入队，标记已访问
while (队列非空) {
    取出队头节点 v
    for (v 的每个未访问邻接点 w) {
        标记 w 已访问
        w 入队
    }
}
```

与层次遍历思想相同——逐层扩散，先到的先探索。

### 操作系统中的应用

| 场景 | 队列的作用 |
|------|-----------|
| **就绪队列** | 多个进程争 CPU，按先来后到排队 |
| **打印队列** | 多台电脑连一台打印机，打印任务排队 |
| **缓冲区** | 快速主机 vs 慢速 I/O 设备，数据暂存于队列 |

### 队列 vs 栈在遍历中的选择

| 场景 | 用栈 | 用队列 |
|------|------|------|
| 树的遍历 | DFS（深度优先） | 层次遍历 |
| 图的遍历 | DFS | BFS |
| 特征 | 一路走到底 | 逐层扩散 |

### 时间复杂度
层次遍历和 BFS 的时间复杂度均为 $O(n)$（n 为节点数），空间复杂度 $O(n)$（队列最坏存整层节点）。

## 类比

### 一句话比喻
**队列的应用就像医院的叫号系统——挂号（入队）时拿一个号，大屏幕按挂号顺序叫号（出队）。不管你病情轻重（优先级），先来先看。树的层次遍历 = 按楼层叫号（一楼所有人看完再看二楼）；BFS = 以你为中心一圈圈往外扩散找人。打印队列 = 全科室共享一台打印机，谁的病历先送来就先打。**

### 生活映射

| 数据结构世界 | 现实世界 |
|---|---|
| 层次遍历 | 公司按职级从上到下一级级通知——先通知 CEO，再通知 VP，最后一线员工 |
| BFS | 朋友圈扩散——先问你最熟的 5 个人，再让他们各自问 5 个人…… |
| 就绪队列 | 银行叫号——所有人在大厅等着，叫到谁谁去柜台（CPU） |
| 打印缓冲区 | 打印机肚子里的排队——电脑早就发完指令了，打印机吭哧吭哧慢慢打 |
| 速度不匹配 | 每秒能下单 100 份奶茶券，但店员 10 秒才做一杯——中间靠小票排队 |
| DFS（对比） | 不是叫号，是"一人把所有科室全看完再轮到下一个" |
