# 散列表（Hash Table）

## 类型判定
判别型 — 定义散列表、散列函数、冲突、同义词等核心概念。理想情况下查找 $O(1)$。

## 是什么
通过**散列函数** $H(key)$ 将关键字直接映射到存储地址的数据结构。理想情况：给定 key → $O(1)$ 算出地址 → $O(1)$ 存取。冲突不可避免时用拉链法或开放定址法解决。

## 正例（≥2 个）
1. **学生信息按学号散列**：$H(key) = key \bmod 13$，学号 19→地址 6，14→地址 1，23→地址 10
2. **缓存/字典（Python dict）**：键→散列值→槽位，平均 $O(1)$ 查找

## 反例/边界（≥1 个）
1. **冲突**：1 和 14 都对 13 取余得 1 → 两个不同 key 映射到同一地址 → 必须处理冲突
2. **散列函数设计太差**：$H(key) = key \times 13 \bmod 13 = 0$ → 所有 key 映射到地址 0

## 详细解释

### 核心概念
| 概念 | 含义 |
|---|---|
| **散列函数** $H(key)$ | 将关键字映射为地址的函数 |
| **散列表** | 存储数据的数组（表长 M） |
| **冲突** | $H(key_1) = H(key_2)$ 但 $key_1 \neq key_2$ |
| **同义词** | 发生冲突的不同关键字 |
| **装填因子** $\alpha = n/M$ | 表中记录数 / 表长，反映"满"的程度 |

### 处理冲突的两种思路
| 方法 | 思路 | 别称 |
|---|---|---|
| **拉链法** | 同义词用链表串起来 | 链地址法、链接法 |
| **开放定址法** | 另找一个空闲位置 | 线性探测、平方探测、双散列等 |

### 理想查找过程
1. 计算 $H(key)$ → 得到地址
2. 检查该地址：匹配 → 成功 / 为空 → 失败 / 不匹配且非空 → 按冲突处理策略继续找

### 复杂度
- **理想情况**（无冲突）：$O(1)$
- **实际**：取决于装填因子和冲突处理方法

## 类比 ★

### 一句话比喻
**散列表就像一个快递柜矩阵——给你一个取件码（散列函数）"手机尾号 3821 → 去 21 号柜"，你直奔 21 号柜取件。如果两个人尾号一样（冲突）→ 要么在 21 号柜旁边加挂一个小箱子（拉链法），要么你被分到 21 号、发现有人了、去 22 号、22 也有、去 23……（开放定址法）。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 散列函数 | 取件码规则："手机尾号后两位" |
| 散列地址 | 柜子编号 |
| 关键字 | 你的手机号 |
| 冲突 | 尾号一样 → 两个人被分到同一个柜子 |
| 同义词 | 尾号相同的两个手机号 |
| 拉链法 | 在 21 号柜旁边加挂一个扩展箱 |
| 开放定址法 | "21 号有人了 → 去 22 号 → 22 号也有人 → 23 号……" |
| 装填因子 | 快递柜使用率——越满越容易冲突 |
