# 顺序表（Sequential List / Sequence List）

## 类型判定
判别型 — 顺序表是线性表的顺序存储实现，核心特征是「逻辑相邻 = 物理相邻」，与链式存储（单链表、双链表等）形成根本性区别。

## 是什么
顺序表是用**顺序存储**方式实现的线性表。所谓顺序存储，就是把逻辑上相邻的数据元素存储在物理上也相邻的存储单元中。由于线性表中各元素数据类型相同（占用空间相等），知道起始地址后，第 $i$ 个元素的地址可以直接算出：$\text{loc}(a_i) = \text{loc}(a_1) + (i-1) \times \text{sizeof}(\text{ElemType})$。

两种实现方式：
- **静态分配**：用定长数组 `data[MaxSize]`，容量初始化后不可改变
- **动态分配**：用指针 `*data` + `malloc/free`，容量可动态扩展（但需复制数据，时间代价高）

## 输入-输出空间
- **输入**：无（逻辑结构的物理实现方式，不涉及输入输出）
- **输出**：无
- **核心字段**：`data`（数据区）、`length`（当前长度）、`MaxSize`（最大容量，动态分配时）

## 正例（≥2 个）
1. **学生成绩表（静态分配）**：一个班里 50 个学生，声明 `int scores[50]` 存放成绩，学生按学号排列，成绩在内存中连续存放。
2. **动态订单列表（动态分配）**：不确定订单量，初始 `malloc(10 * sizeof(Order))`，满后用 `malloc` 申请更大空间 + 复制数据实现扩容。

## 反例/边界（≥1 个）
1. **脏数据**：静态分配时，声明数组后不初始化 `length=0`，且不用 `length` 限制访问范围，会读到内存中遗留的脏数据——用 `length` 限定有效范围即可避免。
2. **静态数组满后无法插入**：静态分配的数组一旦存满就无法再插入新元素，不是顺序表本身的缺陷，而是静态分配方式的局限。

## 详细解释

### 两种实现方式对比

| 方面 | 静态分配 | 动态分配 |
|------|---------|---------|
| 定义 | `int data[MaxSize]` | `ElemType *data` |
| 空间 | 编译时确定，不可变 | 运行时用 `malloc` 申请，可扩容 |
| 扩容 | 不可扩容，满了直接放弃 | `malloc` 新空间 → 复制数据 → `free` 旧空间 |
| 回收 | 系统自动回收（栈/静态区） | 必须手动 `free`（堆区） |
| 适用 | 表长已知且固定 | 表长未知或可能变化 |

### 顺序表的四个特性
1. **随机访问**：$O(1)$ 找到第 $i$ 个元素（核心优势）
2. **存储密度高**：每个结点只存数据，无指针开销
3. **扩容不方便**：静态不可扩，动态扩需复制全表
4. **插入删除不便**：需移动大量元素（$O(n)$）

### 随机访问的数学基础
```c
// data[i-1] 等价于 *(data + i - 1)
// 编译器的地址计算：起始地址 + (i-1) × sizeof(ElemType)
ElemType e = L.data[i - 1];  // O(1)
```

### 初始化关键操作
```c
// 静态分配初始化
void InitList(SqList &L) {
    for (int i = 0; i < MaxSize; i++)
        L.data[i] = 0;       // 清除脏数据（可省略，因为用 length 限制访问）
    L.length = 0;            // 必须设置！否则无法知道有效数据范围
}

// 动态分配初始化
void InitList(SqList &L) {
    L.data = (ElemType *)malloc(InitSize * sizeof(ElemType));
    L.length = 0;
    L.MaxSize = InitSize;
}
```

## 类比

### 一句话比喻
**顺序表就像一排画好格子的停车位——每辆车（数据元素）必须停在相邻的格子里。你想找第 5 辆车？从第一家开始数 5 格就到了（$O(1)$）。但要在第 3 个位置停一辆新车？对不起，后面所有车都得依次往后挪一格（$O(n)$）。如果车位满了还想加车（静态分配），只能换一个更大的停车场。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| `data` 数组 | 停车位编号 0 到 MaxSize-1 |
| `length` | 当前实际停了几辆车 |
| `MaxSize` | 停车场总车位数 |
| `sizeof(ElemType)` | 每个车位宽度（全部相同） |
| 随机访问 `L.data[i-1]` | 直接走到第 i 号车位 |
| `malloc` 扩容 | 换到另一个更大的停车场，把车全部开过去 |
| 脏数据 | 新停车场里之前遗留的垃圾 |
