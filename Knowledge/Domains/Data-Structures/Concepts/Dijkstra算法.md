# Dijkstra算法（迪杰斯特拉）

## 类型判定
程序型 — 带权图**单源最短路径**算法，贪心策略。`generalizes` BFS（无权→有权）。与 Prim 算法实现结构惊人相似。

## 是什么
求从**一个源点 $v_0$ 出发到其余所有顶点**的最短路径（带权路径长度）。核心：三个辅助数组 + $n-1$ 轮贪心选择。

**发明人**：Edsger Dijkstra（1972 年图灵奖得主），还发明了信号量/PV 原语、银行家算法等。

## 输入-输出空间
- **输入**：带权图 $G$（有向或无向），源点 $v_0$
- **输出**：`dist[i]` = 从 $v_0$ 到 $v_i$ 的最短路径长度；`path[i]` = 最短路径上 $v_i$ 的直接前驱
- **限制**：❌ 不能处理负权值边

## 正例（≥2 个）
1. **导航软件**：从当前位置到目的地的最短路线 → 典型的单源最短路径
2. **物流配送**：从中心仓库出发，计算到各配送点的最短路线和时间

## 反例/边界（≥1 个）
1. **负权值边**：图中有负权边时 Dijkstra 可能失效。例：源点→A=10, 源点→B=7, B→A=-5 → 实际最短路径是 源→B→A=2，但 Dijkstra 会错误地先确定 B 的最短路径为 7

## 详细解释

### 三个辅助数组
| 数组 | 含义 |
|------|------|
| `final[v]` | `true` = 已确定从源点到 $v$ 的最短路径 |
| `dist[v]` | 当前找到的从源点到 $v$ 的最短路径长度 |
| `path[v]` | 最短路径上 $v$ 的直接前驱顶点编号 |

### 手动模拟步骤
1. **初始化**：`final[源点]=true, dist[源点]=0`；其余顶点 `final=false`，`dist` = 源点到该顶点的弧长度（无边则 $\infty$）
2. **循环 $n-1$ 轮**，每轮：
   - 从 `final=false` 的顶点中选 `dist` 最小的顶点 $v_k$
   - `final[v_k] = true`（确定 $v_k$ 的最短路径）
   - 检查所有 $v_k$ 的邻接点 $v_j$：若 `dist[k] + w(k,j) < dist[j]`，则更新 `dist[j]` 和 `path[j]`

### 代码框架
```c
// 初始化
for (int i = 0; i < n; i++) {
    final[i] = false;
    dist[i] = G.Edge[v0][i];  // 邻接矩阵直接取
    path[i] = (dist[i] < INFINITY) ? v0 : -1;
}
final[v0] = true;
dist[v0] = 0;

// n-1 轮
for (int i = 1; i < n; i++) {
    // 找 dist 最小的未确定顶点
    int min = INFINITY, k;
    for (int j = 0; j < n; j++)
        if (!final[j] && dist[j] < min) { min = dist[j]; k = j; }

    final[k] = true;  // 确定 k 的最短路径

    // 更新邻接点的 dist
    for (int j = 0; j < n; j++)
        if (!final[j] && dist[k] + G.Edge[k][j] < dist[j]) {
            dist[j] = dist[k] + G.Edge[k][j];
            path[j] = k;
        }
}
```

### 回溯最短路径
从目标顶点沿 `path[]` 倒推：`v → path[v] → path[path[v]] → ... → v0`（直到 -1），再反转序列。

### 复杂度
- **时间复杂度**：$O(|V|^2)$（邻接矩阵）；邻接表也是 $O(|V|^2)$（因为找 min dist 仍需扫描所有顶点）
- 与 Prim 算法复杂度完全相同，实现结构也几乎一样（`lowCost` ↔ `dist`）

### 负权值为何失效？
Dijkstra 基于贪心：一旦 `final[v] = true` 就认为该路径最短且不可再更新。但负权边可能让后续顶点绕远路反而更短，打破贪心的正确性。

## 类比

### 一句话比喻
**Dijkstra 就像导航软件计算最短路线——你从家出发，导航说：「离你最近的是便利店（1km），我们先确定去便利店最短是 1km。然后从便利店出发去超市（3km），比直接去超市（5km）更近，更新！再去下一个最近的地方……」一步步把整张地图上所有目的地的最短路线都算出来。但如果存在一条「倒给钱的高速公路」（负权值），Dijkstra 可能就算错了——因为它一旦确定「到 A 城最短是 10km」，就不会再考虑「先绕远路到 B 再走倒给钱的路去 A 实际更短」这种反直觉情况。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 源点 $v_0$ | 你的家——所有路线从这里出发 |
| `final[v] = true` | 「到这里的路线已经是最优的了，盖章确认」 |
| `dist[v]` | 目前找到的去 v 的最短距离 |
| 每轮选 min `dist` | 每次都先处理离你最近的未确认地点 |
| `path[v] = k` | 「去 v 的最短路线中，v 的上一个是 k」 |
| 更新 `dist` | 「经过刚确认的地点绕一下，会不会更近？」 |
| 负权边失效 | 有「倒给钱」的路 → 绕远路反而更便宜 → 算法傻了 |
| 与 Prim 相似 | Prim 也是每轮选最小代价加入（只是语义不同） |

## 应用：OSPF 链路状态路由

Dijkstra 是 OSPF 协议的核心引擎。在计算机网络中：

1. 每台路由器收集全网 LSA → 构建 LSDB（图的邻接表）
2. 以自己为源点运行 Dijkstra → 算出到每个网络的最短路径
3. 路由表只记录**下一跳**，不记录完整路径
4. 支持等价多路径（ECMP）：代价相同的两条路径都写入路由表

**与 RIP（Bellman-Ford）的区别：**

| 维度 | Dijkstra（OSPF） | Bellman-Ford（RIP） |
|------|-----------------|-------------------|
| 信息基础 | 全网 LSDB | 邻居距离向量 |
| 收敛 | 洪泛后立即算完 | 好消息快、坏消息慢 |
| 典型应用 | 企业内网 | 小型网络 |

> 详细路由场景见计算机网络课程中 [[OSPF工作原理]] 卡片。
