# 顺序查找（线性查找）

## 类型判定
程序型 — 最基础的查找算法，含代码实现、哨兵优化、有序表优化和 ASL 分析。

## 是什么
**从头到尾（或从尾到头）逐个对比关键字**的查找方法。适用于顺序表和链表，无论元素是否有序都能用。时间复杂度 $O(n)$。

## 输入-输出空间
- **输入**：查找表 L（顺序表或链表），目标关键字 key
- **输出**：找到返回下标（位序），未找到返回 -1（或 0）
- **无前置条件**——不要求有序，不要求随机存取

## 正例（≥2 个）
1. **普通数组查找**：`for (i=0; i<n; i++) if (a[i]==key) return i;` → 最直观的实现
2. **链表查找**：从头结点开始，`p = p->next` 逐个对比 → 链表不支持随机存取，只能用顺序查找

## 反例/边界（≥1 个）
1. **大规模有序数据**：如果有 100 万条排序数据，顺序查找平均要对比 50 万次 → 傻大个做法，应该用折半查找 $O(\log n)$
2. **查找失败时也扫完全表**：无序表的顺序查找必须扫到最后一个元素才能说"没找到"

## 详细解释

### 哨兵实现（从后往前扫，0 号位放哨兵）
```c
int SeqSearch(int a[], int n, int key) {
    a[0] = key;           // 哨兵：把 key 放到 0 号位
    int i;
    for (i = n; a[i] != key; i--);  // 从尾部往前扫，不需要判断越界！
    return i;             // i=0 表示查找失败
}
```
**哨兵的好处**：每轮循环只需判断 `a[i] != key`，省去了 `i >= 0` 的越界判断。数量级没变（还是 $O(n)$），但常数更优。

### 有序表优化
如果查找表是**有序的**（递增/递减），查找失败时可以提前终止：
- 找 21，扫到 29 发现 29 > 21 → 后面肯定更大 → 直接失败
- ASL(失败) = $\frac{1+2+3+\cdots+n+n}{n+1} = \frac{n}{2} + \frac{n}{n+1}$

### 概率降序优化
如果各关键字被查概率不同，把**高频元素放前面**可以减少 ASL(成功)。代价是 ASL(失败) 回到 $O(n)$（因为无序了必须扫到底）。

### 复杂度
| 情况 | 查找成功 ASL | 查找失败 ASL |
|---|---|---|
| 一般 | $\frac{n+1}{2}$ | $n+1$（哨兵） |
| 有序表 | $\frac{n+1}{2}$ | $\frac{n}{2} + \frac{n}{n+1}$ |
| 数量级 | $O(n)$ | $O(n)$ |

## 类比 ★

### 一句话比喻
**顺序查找就像在一排快递柜前挨个扫码——从第一个柜子开始，滴滴、滴滴、滴滴……一直扫到你的那个。运气好第一个就是（$O(1)$），运气差扫到最后一个是（$O(n)$），如果根本没有你的快递，你得把所有柜子全扫一遍才能死心。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 顺序查找 | 逐个快递柜扫码找你的包裹 |
| 哨兵（0 号位放 key） | 在第一个柜子上贴个标签"你的快递号"，扫到它就停——不用记扫了多少个 |
| 越界判断 | 心里默数"还剩几个柜子没扫"（哨兵帮你省了这一步） |
| 有序表提前终止 | 快递按手机尾号排序——扫到尾号比你大的，后面肯定没有了 |
| 概率降序排列 | 把常收快递的人放前排柜子——多数人一开柜就有 |
| 最坏情况 | 你的快递在最后一排最后一个柜子 😭 |
