# 计数排序（Counting Sort）

## 类型判定
程序型 — 一种**不基于比较**的排序算法，用"统计出现次数"的方式确定每个元素的最终位置。408大纲未明确要求，但真题中多次用到其思想（空间换时间）。

## 是什么
计数排序的核心：统计每个关键字值出现了多少次，然后通过累加确定"小于等于该值的元素总数"，由此直接推算出每个元素应排在第几位。适用条件：关键字为整数，取值范围 $[0, K]$ 且 K 较小。

## 输入-输出空间
- **输入**：数组 A[0..n-1]，元素值 ∈ [0, K)
- **输出**：数组 B[0..n-1]（有序结果）
- **前置条件**：需辅助数组 C[0..K)（计数数组）

## 正例（≥2 个）
1. **成绩排名（0~100分）**：K=101 → 统计每个分数的人数 → 直接定位 → $O(n)$，比快排还快
2. **408真题应用**：13年"找主元素"和18年"找未出现最小正整数"——都用到了计数统计的思想

## 反例/边界（≥1 个）
1. **K 远大于 n**：取值范围太大（如身份证号 0~10^17），辅助数组 C 开不下 → 空间不可接受
2. **K 的数量级 ≥ $n \log n$**：时间复杂度退化为 $O(n + K) \geq O(n \log n)$，不如快排/堆排
3. **元素不是整数**：无法映射为数组下标

## 详细解释

### 算法三步走
**Step 1**：遍历 A，统计各值的出现次数 → `C[A[i]]++`
**Step 2**：对 C 累加 → `C[i] += C[i-1]`，此时 `C[i]` = 值 ≤ i 的元素总数
**Step 3**：**从后往前**遍历 A，对每个 `A[i]`：
- `C[A[i]]--` 得到该元素在 B 中的下标
- `B[C[A[i]]] = A[i]`

### 核心代码
```c
void CountingSort(int A[], int B[], int n, int K) {
    int *C = (int *)calloc(K, sizeof(int));   // 辅助数组，全0
    int i;

    for (i = 0; i < n; i++)                   // Step 1: 统计次数
        C[A[i]]++;

    for (i = 1; i < K; i++)                   // Step 2: 累加
        C[i] += C[i - 1];

    for (i = n - 1; i >= 0; i--) {            // Step 3: 从后往前放置
        B[--C[A[i]]] = A[i];                  // 减1后作为下标
    }
}
```

### 关键注意事项
- **从后往前遍历**：保证稳定性（相同关键字，靠后的元素先处理，但放在更靠后的位置）
- `--C[A[i]]` 而非 `C[A[i]] - 1`：先减再取——保证下标从0开始
- 实战扩展：查找 min/max 再做偏移，可处理非零起始的序列

### 时间复杂度
- 时间复杂度：**$O(n + K)$**
- 当 $K = O(n)$ 时 → $O(n)$（优于所有比较类排序！）
- 当 $K > O(n \log n)$ 时 → 不如快排

- 空间复杂度：**$O(n + K)$**（B 数组 + C 数组）
- 稳定性：**稳定**
- 适用存储：顺序表

## 类比 ★

### 一句话比喻
**计数排序就像选举计票——每个候选人的名字写在黑板上（C数组每个下标对应一个分数），每唱一票就在对应名字下画"正"字（统计次数）。全部唱完后，"正"字累加就知道"这个分数及以上共多少人"，于是每个人该排第几一目了然。不需要"你分高还是我分高"地比来比去——全凭统计。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 统计数组 C | 黑板上的候选人和"正"字 |
| Step1: C[A[i]]++ | 唱票，画一笔 |
| Step2: C[i] += C[i-1] | 算"≤此票数的总人数" |
| Step3: 从后往前放 | 名单从后往前填——保证同票的人按原顺序排 |
| K = O(n) 时 O(n) | 候选人不多（100个），选民很多（10000人） |
| K 太大不适用 | 候选人太多（几万个），黑板写不下 |
