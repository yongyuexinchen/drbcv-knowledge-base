# 邻接表（Adjacency List）

## 类型判定
判别型 — 图的**顺序+链式**混合存储实现，`is_a` 图的存储结构，用一维数组存顶点 + 链表存边，是邻接矩阵的空间优化方案。

## 是什么
- **顶点表**：一维数组，每个元素含「数据域 + 指向第一条边/弧的指针」
- **边表**：链表结点，每个结点含「邻接点编号 + 指向下一条边的指针」（带权图再加权值域）

本质上和树的「孩子表示法」是同一思想。

## 输入-输出空间
- **输入**：顶点集 $V$ + 边集 $E$
- **输出**：顶点数组 + 边链表
- **空间复杂度**：无向图 $O(|V| + 2|E|)$；有向图 $O(|V| + |E|)$

## 正例（≥2 个）
1. **稀疏无向图**（$|E| \ll |V|^2$）：如社交网络中大多数人只有几十个好友 → 邻接表比邻接矩阵省空间
2. **有向图找所有出边**：遍历顶点 $v$ 的边链表即可 → $O(1) \sim O(|V|)$，远好于邻接矩阵的固定 $O(|V|)$

## 反例/边界（≥1 个）
1. **有向图找入边**：要统计有多少条弧指向 $v$，必须遍历**整个邻接表的所有边结点** → $O(|E|)$，效率极低
2. **稠密图用邻接表**：边接近 $|V|^2$ 时链表指针开销反而比矩阵大，且查找边不如 $O(1)$ 的矩阵

## 详细解释

### 代码定义
```c
// 边结点
typedef struct ArcNode {
    int adjvex;              // 邻接点编号
    // int weight;           // 权值（带权图时使用）
    struct ArcNode *next;    // 下一条边
} ArcNode;

// 顶点结点
typedef struct VNode {
    VertexType data;         // 顶点数据
    ArcNode *first;          // 第一条边
} VNode;

// 图
typedef struct {
    VNode vertices[MaxVertexNum];
    int vexnum, arcnum;
} ALGraph;
```

### 空间复杂度对比
| 存储结构 | 无向图 | 有向图 |
|----------|--------|--------|
| 邻接矩阵 | $O(|V|^2)$ | $O(|V|^2)$ |
| 邻接表 | $O(|V| + 2|E|)$ | $O(|V| + |E|)$ |

无向图每条边对应 2 个边结点（冗余），有向图每条弧对应 1 个边结点。

### 求度操作
| 操作 | 无向图 | 有向图 |
|------|--------|--------|
| 度 | 遍历边链表，数结点数 → $O(1) \sim O(|V|)$ | — |
| 出度 | — | 遍历边链表 → $O(1) \sim O(|V|)$ |
| 入度 | — | 遍历整个邻接表 → $O(|E|)$ ❌ |

### 关键特性
- **表示不唯一**：边链表中各边结点的顺序可任意排列 → 同一个图可对应多个不同的邻接表 → 遍历序列也不唯一
- **邻接矩阵表示唯一**（给定顶点编号后）
- **适合稀疏图**

## 类比

### 一句话比喻
**邻接表就像每个人的微信通讯录——每个联系人（顶点）下面挂着 ta 的好友列表（链表）。找「张三」的好友：打开张三的通讯录，一个一个滑过去看就行（出边）。但想知道「谁加了张三为好友」（入边）？对不起，你得把所有人的通讯录都翻一遍——这就是邻接表的阿喀琉斯之踵。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 顶点数组 | 每个人的名片盒（按编号排） |
| 边链表 | 名片下面挂的便利贴：写了和谁有联系 |
| 无向图每条边两份冗余 | 加好友是双向的 → 张三的通讯录里有李四，李四的通讯录里也有张三 |
| 出边（找好友） | 打开通讯录，一个一个看 → 快！ |
| 入边（找谁加了我） | 翻所有人的通讯录 → 慢！ |
| 表示不唯一 | 通讯录排序 → 按姓名排、按添加时间排都行 |
| 邻接矩阵 $O(1)$ 判边 | 矩阵像航空公司系统 → 直接查航班号 |
