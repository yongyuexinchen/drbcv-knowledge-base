# 顺序表 vs 链表

## 类型判定
比较型 — 顺序表和链表是线性表两种对立的存储实现，用数据结构三要素（逻辑结构、物理结构、数据运算）框架进行系统对比。

## 是什么
顺序表和链表是实现线性表的两种根本策略：
- **顺序表**：连续空间，物理相邻反映逻辑相邻 → 随机存取，但插入删除需移动
- **链表**：离散空间，指针/游标串联逻辑关系 → 插入删除只需改指针，但不可随机存取

## 输入-输出空间
（比较型卡片无输入输出）

## 正例（≥2 个）
1. **奶茶店叫号系统**：顾客数量不可预估（表长难估计），频繁新增（顾客取号）和删除（取餐完成）→ 用链表
2. **课堂点名系统**：班级人数基本固定（表长可预估），主要操作是按位查找（按学号点名）→ 用顺序表

## 反例/边界（≥1 个）
1. **只用时间复杂度选型**：顺序表插入 $O(n)$ vs 链表插入 $O(n)$（看起来一样），但 $n$ 的含义不同：顺序表的 $O(n)$ 来自移动**大体积数据元素**（可能 1MB/个），链表的 $O(n)$ 来自遍历**指针**（8 字节/次）→ 链表擦入删除实际远快于顺序表

## 详细解释

### 数据结构三要素框架对比

#### 1. 逻辑结构：相同
两者都是线性结构（一对一的前驱后继关系）。

#### 2. 物理结构（存储结构）：根本区别

| 维度 | 顺序表 | 链表 |
|------|--------|------|
| 存储方式 | 连续空间（数组） | 离散空间 + 指针串联 |
| 空间分配 | 预分配大片连续空间 | 动态按需分配小块 |
| 存储密度 | 高（只存数据） | 低（额外存指针） |
| 空间灵活性 | 差（静态不可扩，动态扩代价高） | 好（随时 malloc 即可） |
| 随机存取 | ✅ $O(1)$ | ❌ $O(n)$ |

#### 3. 基本操作：各有胜负

| 操作 | 顺序表 | 链表 |
|------|--------|------|
| **创建（初始化）** | 需预分配大片连续空间，空间过大浪费/过小扩容困难 | 只需分配头结点，按需扩展 |
| **销毁** | 静态：系统自动回收；动态：需 `free` | 逐个 `free` 每个结点 |
| **按位查找** | $O(1)$ ✅ | $O(n)$ ❌ |
| **按值查找（无序）** | $O(n)$ | $O(n)$ |
| **按值查找（有序）** | $O(\log n)$（折半） | $O(n)$（不能折半） |
| **插入** | $O(n)$（移动元素，开销大） | $O(n)$（查找位置）+ $O(1)$（改指针） |
| **删除** | $O(n)$（移动元素，开销大） | $O(n)$（查找位置）+ $O(1)$（改指针） |
| **增删实际开销** | ⚠️ 移动大元素（可能 1MB/个） | ✅ 只遍历指针（8B/次） |

### 为什么链表插入删除实际上比顺序表快？

假设每个数据元素 1MB：
- 顺序表插入：遍历到位置 $O(n)$ + 移动 $n/2$ 个 1MB 元素 → 巨大时间开销
- 链表插入：遍历到位置 $O(n)$（每次跳 8 字节指针）+ 修改 2 个指针 → 小得多

> **大 O 相同不代表实际性能相同！** 常数因子和操作粒度天差地别。

### 选型决策树

```
需要频繁按位查找？ ──是──→ 顺序表
    │
   否
    │
表长不可预估或频繁变化？ ──是──→ 链表
    │
   否
    │
频繁插入/删除？ ──是──→ 链表
    │
   否
    │
数据元素体积大？ ──是──→ 链表（避免移动大元素）
    │
   否
    │
需要有序查找（折半）？ ──是──→ 顺序表
    │
   否
    │
   顺序表（默认，更简单）
```

## 类比

### 一句话比喻
**顺序表是豪华电影院——座位编号清清楚楚（随机存取），但你想在第 3 排加一排座位？对不起，整个电影院所有排都得拆了往后挪（$O(n)$ 移动），而且电影院建多大一开始就得定好（预分配）。链表是户外音乐节——观众席地而坐，位置随便加一个人很简单（malloc 一个新位子，让他坐哪儿都行），但你要找到"第 5 排坐的是谁"就必须从第一排开始数过去（$O(n)$ 遍历）。**

### 生活映射
| 数据结构世界 | 电影院 vs 音乐节 |
|---|---|
| 随机存取 $O(1)$ | 电影院：门票上印着"5 排 3 座"，直接走过去 |
| 遍历查找 $O(n)$ | 音乐节：第 5 排？从头一排一排数 |
| 插入 $O(n)$ 移动 | 电影院加排：所有观众站起来挪位 |
| 插入 $O(1)$ 改指针 | 音乐节加人：两观众之间挤一个，旁边人挪挪就行 |
| 预分配空间 | 电影院：盖楼时就定好了能坐多少人 |
| malloc 按需分配 | 音乐节：场地多大无所谓，来多少人坐多少人 |
| 存储密度低（额外指针） | 音乐节：每人得配一个小板凳标记位置 |
| 数据元素大 | 电影院：每人是 200 斤的相扑手，移动成本极高 |
