# 空间复杂度（Space Complexity）

## 类型判定
判别型 — 算法效率度量的另一维度。考研中考察频率低于时间复杂度，但递归程序的空复分析是常见考点。

## 是什么
**空间复杂度是用于衡量一个算法内存开销的指标，描述算法所需存储空间 $S(n)$ 随问题规模 $n$ 的增长趋势——同样用大O表示法，只关心数量级。** 如果算法所需内存空间不随 $n$ 增长（常数），则称该算法**可以原地工作**。

## 输入-输出空间
- **输入**：算法代码 + 问题规模 $n$
- **输出**：一个 $O(f(n))$ 表达式表示空间复杂度的数量级
- **核心规则**：只需关注所占空间大小与 $n$ 相关的变量，与 $n$ 无关的变量最多贡献常数项 $O(1)$，被大O吃掉

## 正例（≥2 个）
1. **原地工作的算法（$O(1)$）**：函数内只定义了几个普通变量 `int i, j; float x;` → 无论 n 多大，所需空间是固定的常数 → $S(n) = O(1)$，该算法可以**原地工作**
2. **一维数组（$O(n)$）**：函数内定义了 `int arr[n]` → 数组大小随 n 线性增长 → $S(n) = O(n)$
3. **二维数组（$O(n^2)$）**：定义了 `int flag[n][n]` → $S(n) = O(n^2)$

## 反例/边界（≥1 个）
1. **把 int 占几个字节算进去** ❌：`int arr[n]` 需要 $4n$ 字节 → 但大O会把系数4干掉 → 直接写 $O(n)$ 就够了。考研分析时**不用关心类型占几个字节**，只看数量级。
2. **混淆「程序代码占的空间」和「算法运行需要的数据空间」**：编译后的程序代码存入内存的空间是固定的（与 n 无关），这部分在分析空间复杂度时忽略不计。

## 详细解释

### 程序运行时三类内存开销
| 内存区域 | 内容 | 是否受 n 影响 |
|---------|------|-------------|
| 程序代码区 | 编译后的机器指令 | ❌ 固定（忽略） |
| 静态/全局变量区 | 全局变量、static 变量 | 看情况 |
| **动态数据区** | 局部变量、数组、递归调用栈 | ✅ **分析重点** |

### 空间复杂度分析要点

1. **普通程序**：找所有「大小随 n 变化」的变量/数组，看它们所占空间与 n 的数量关系
2. **递归程序**：空间复杂度一般 = **递归调用深度 × 每层所需空间**
   - 大多数考研题：每层空间是常数 $O(1)$ → 空间复杂度 = 递归深度
   - 特殊情况：每层递归还定义了与 n 相关的数组 → 需要把各层空间加起来求数量级

### 递归空间复杂度示例

**例1：普通递归（每层常数空间）**
```c
void loveYou(int n) {
    int a, b, c;          // 每层 3 个 int，固定大小
    if (n > 1) loveYou(n-1);
    printf("%d\n", n);
}
```
- 每层空间 = $O(1)$
- 递归深度 = $n$
- 总空间 = $n \times O(1) = O(n)$

**例2：每层变长数组（少见但考点）**
```c
void loveYou(int n) {
    int flag[n];          // 第 k 层数组长度为 n=k
    if (n > 1) loveYou(n-1);
    printf("%d\n", n);
}
```
- 第 n 层数组长度 n，第 n-1 层长度 n-1，…第 1 层长度 1
- 总空间 = $1 + 2 + \cdots + n = n(n+1)/2$
- $S(n) = O(n^2)$

### 口诀
> **普通程序找数组，递归程序看深度。**

### 空间复杂度 vs 时间复杂度
| 维度 | 符号 | 关注 | 考研地位 |
|------|------|------|---------|
| 时间复杂度 | $T(n)$ | 运行时间的增长趋势 | ⭐⭐⭐ 每年必考 |
| 空间复杂度 | $S(n)$ | 内存占用的增长趋势 | ⭐ 考察频率低，但递归必会 |

两者使用**完全相同的大O运算法则**（加法规则、乘法规则、常对幂指阶口诀）。

## 类比

### 一句话比喻
**空间复杂度就像你搬家时租的货车——$O(1)$ 是你两手空空揣个U盘就过去了，$O(n)$ 是你租了一辆小面包车（东西越多车越大），$O(n^2)$ 是你租了一整列火车皮，递归就像你每搬一个房间就要再叫一辆新车来拉——搬10层楼你就叫了10辆车（递归深度 = 10），如果每层的东西还越往上越多（每层开个新数组），那你的搬家车队就是个等差数列求和，破产预定。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| $O(1)$（常数阶）/ 原地工作 | 口袋里装个U盘——不管数据多大，我只占一个口袋 |
| $O(n)$（线性阶） | 租了一辆容量和行李数成正比的货车 |
| $O(n^2)$（平方阶） | 租了一个 $n \times n$ 的仓库——东西翻倍，面积翻四倍 |
| 递归空间复杂度 = 深度 | 搬家上楼——每层都要在楼道里暂放一批箱子，层数越多楼道堆得越满 |
| 普通程序只看数组大小 | 搬家只看那些会随着「你东西多」而变大的家具，马桶刷那种固定体积的忽略 |
| 大O干掉系数 | 一个 int 占 4 字节还是 8 字节不重要——反正数量级是一样的 |
| 顺序存储（连续空间） | 租一整排连号车位——车大一点就不够停 |
| 链式存储（离散空间） | 每个车随便停哪个角落，用对讲机（指针）告诉后车你在哪 |
