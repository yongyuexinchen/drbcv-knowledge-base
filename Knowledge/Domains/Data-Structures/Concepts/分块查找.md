# 分块查找（索引顺序查找）

## 类型判定
程序型 — 含算法思想、索引表查找策略（顺序/折半）、ASL 分析、最优分块推导。

## 是什么
将数据分成若干块，**块间有序、块内无序**。先查索引表定位块，再在块内顺序查找。是顺序查找和折半查找的折中方案。

## 输入-输出空间
- **输入**：数组（块间有序）+ 索引表，目标关键字 key
- **输出**：找到返回位置，未找到返回失败
- **数据结构**：索引表（每块的最大关键字 + 起止位置）+ 数据数组

## 正例（≥2 个）
1. **技术书籍分柜**：第 1 柜放编号 ≤10 的书，第 2 柜放 ≤20 的书……先看柜门标签（索引表）确定柜子，再在柜内一本本找（块内顺序）
2. **学生档案按班级分块**：每班一个文件柜，柜门写最大学号，找学生先定位班级再翻档案

## 反例/边界（≥1 个）
1. **纯有序数据**：用折半查找 $O(\log n)$ 更快，不需要分块查找的折中
2. **纯无序且不分区**：没法建索引表 → 只能用顺序查找

## 详细解释

### 查找步骤
1. **查索引表**确定目标属于哪一块（顺序查找或折半查找索引表）
2. **块内顺序查找**（块内无序，只能顺序找）

### 折半查找索引表的重要细节
如果目标关键字**不在索引表中**（如找 19，索引表有 10、20、30…），折半最终停在 `low > high`。此时：**一定在 `low` 所指的分块中查找！**
- 原理：low 所指索引值必定 > key，而 key 只可能在"索引值 > key"的那个块

### ASL 分析（顺序查索引表 + 均匀分块）
设 $n$ 个元素，分 $b$ 块，每块 $s$ 个元素（$n = bs$）：

$$\text{ASL} = \text{ASL}_{\text{索引}} + \text{ASL}_{\text{块内}} = \frac{b+1}{2} + \frac{s+1}{2} = \frac{s}{2} + \frac{n}{2s} + 1$$

### 最优分块
令导数 $\frac{d}{ds}\text{ASL} = \frac{1}{2} - \frac{n}{2s^2} = 0$，得 **$s = \sqrt{n}$**。

**$n = 10000$ 时**：分 $\sqrt{10000} = 100$ 块，每块 100 个 → ASL ≈ 101。而顺序查找平均 5000 次，提升约 50 倍。

### 动态查找表版本
用链表存储各块（而非数组），插入删除无需移动大量元素——只需修改指针。

### 复杂度
| 索引表查找方式 | ASL(成功) |
|---|---|
| 顺序 | $\approx \sqrt{n} + 1$（最优分块时） |
| 折半 | $\approx \log_2(\sqrt{n}+1) + \frac{\sqrt{n}+1}{2}$ |

## 类比 ★

### 一句话比喻
**分块查找就像逛宜家——入口有个大地图（索引表）告诉你"灯具在 2 楼 C 区"，你直奔 C 区再一个货架一个货架找（块内顺序）。索引表告诉你大方向，块内再慢慢扫。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 索引表 | 商场楼层导览牌（每层有什么品类） |
| 每个分块 | 一个品类的货架区域 |
| 块间有序 | 1 楼鞋包 < 2 楼女装 < 3 楼男装 |
| 块内无序 | 女装区里衣服不按尺码排 |
| 查索引表 | 看导览牌："鞋在 1 楼" |
| 块内顺序查找 | 在 1 楼鞋区一双双翻 |
| 最优分块 $s=\sqrt{n}$ | 商场分 $\sqrt{\text{总面积}}$ 个区最合理 |
| 链式分块 | 可以随时增加/撤掉一个货架 |
