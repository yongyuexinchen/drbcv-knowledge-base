# 关键路径（Critical Path）

## 类型判定
程序型 — AOE 网中求关键路径和关键活动，决定工程最短完成时间。依赖拓扑排序 + 逆拓扑排序作为前置步骤。

## 是什么
在 **AOE 网**（Activity On Edge，边表示活动、权值表示耗时）中：
- **关键路径**：从源点到汇点**路径长度最长**的路径
- **关键活动**：关键路径上的活动——时间余量为 0，拖延就会推迟整个工程
- **关键路径长度** = 整个工程完成的**最短时间**

**AOE 网性质**：
- 仅一个入度为 0 的顶点（源点/开始顶点）和一个出度为 0 的顶点（汇点/结束顶点）
- 事件（顶点）是瞬间的，活动（边）是有持续时间的
- 只有进入某顶点的所有活动都结束，该顶点代表的事件才发生
- 只有某事件发生后，从该顶点出发的活动才能开始

## 输入-输出空间
- **输入**：AOE 网（带权 DAG，权 = 活动耗时）
- **输出**：关键路径（边序列）、关键活动、工程最短完成时间
- **复杂度**：基于拓扑排序 → $O(|V| + |E|)$

## 正例（≥2 个）
1. **装修房子**：打地基→砌墙→水电→贴砖→刷墙→装门……关键路径告诉你哪些工序绝对不能拖延
2. **软件开发**：需求分析→设计→编码→测试→部署，某些任务可以并行（前后端同时开发），关键路径上的任务必须按时完成

## 反例/边界（≥1 个）
1. **压缩非关键活动**：把时间余量大的活动缩短没有意义，不会让整体工期提前
2. **多条关键路径**：只压缩某一条关键路径上的活动可能无效——必须压缩**所有关键路径的公共活动**或同时压缩多条路径

## 详细解释

### 五个核心参数

| 参数 | 符号 | 含义 |
|------|------|------|
| 事件最早发生时间 | $ve(k)$ | 从源点开始，事件 $k$ 最早何时能发生 |
| 事件最迟发生时间 | $vl(k)$ | 不推迟工期前提下，事件 $k$ 最晚何时必须发生 |
| 活动最早开始时间 | $e(i)$ | 活动 $a_i$ 最早何时能开工 = $ve$(弧尾) |
| 活动最迟开始时间 | $l(i)$ | 活动 $a_i$ 最晚何时必须开工 = $vl$(弧头) - 权值 |
| 时间余量 | $d(i) = l(i) - e(i)$ | 活动可以拖延的时间；$d=0$ → 关键活动 |

### 算法步骤

**1. 求 $ve(k)$ — 从源点出发，按拓扑序列递推**
- $ve(源点) = 0$
- $ve(k) = \max\{ve(j) + w(j, k)\}$，其中 $\langle j, k \rangle$ 是所有指向 $k$ 的边
- 取最大值原因：必须等所有前驱活动都完成

**2. 求 $vl(k)$ — 从汇点出发，按逆拓扑序列递推**
- $vl(汇点) = ve(汇点)$（最早 = 最迟）
- $vl(k) = \min\{vl(j) - w(k, j)\}$，其中 $\langle k, j \rangle$ 是所有从 $k$ 出发的边
- 取最小值原因：不能耽误任何一个后继

**3. 求 $e(i)$ 和 $l(i)$**
- $e(a_i) = ve(弧尾顶点)$
- $l(a_i) = vl(弧头顶) - w(a_i)$

**4. 求 $d(i) = l(i) - e(i)$**，$d(i)=0$ 的活动即为关键活动

**5. 关键活动构成的路径 = 关键路径**

### 关键路径的性质（选择题高频！）
1. ✅ 关键活动耗时增加 → 工期延长
2. ✅ 缩短关键活动 → 可以缩短工期
3. ⚠️ 关键活动缩短到一定程度 → 可能变成非关键活动（关键路径转移）
4. ⚠️ 多条关键路径时：只缩短一条路径上的活动 → 工期不变（另一条仍是瓶颈）
5. ⚠️ 缩短被所有关键路径共享的活动 → 可以有效缩短工期

## 类比

### 一句话比喻
**关键路径 = 装修房子的「最慢流水线」。你发现所有工序中，贴瓷砖要 5 天、刷墙要 3 天、装门要 2 天——贴瓷砖就是关键路径上的活。泥瓦工哪怕多拖一天，整个装修就推迟一天。而装门这个活有 3 天的「懒散空间」（时间余量），拖两天也无所谓。但如果你把贴瓷砖从 5 天压缩到 2 天（比刷墙还快），关键路径就转移到了刷墙上——你再压缩贴瓷砖也没用了，除非同时把刷墙也加速。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| AOE 网 | 装修施工流程图 |
| 顶点（事件） | 某个工序完成的瞬间（「墙砌好了！」） |
| 边（活动）+ 权值 | 某个工序 + 需要几天 |
| 源点 | 开工！ |
| 汇点 | 完工！交房！ |
| $ve(k)$ | 工序 k 最早哪天能干完 |
| $vl(k)$ | 工序 k 最晚哪天必须干完（否则拖工期） |
| $e(i)$ | 活 i 最早哪天能开始干 |
| $l(i)$ | 活 i 最晚哪天必须开始干 |
| 时间余量 $d(i)$ | 这个活可以摸鱼几天 |
| 关键活动 | 绝对不能摸鱼的活 |
| 关键路径 | 决定总工期的那条瓶颈流水线 |
| 多条关键路径 | 几组活都卡在同一个时间点 → 得同时加速 |
| 关键活动变非关键 | 瓶颈被你打通了 → 新瓶颈出现 |
