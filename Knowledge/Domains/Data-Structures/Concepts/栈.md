# 栈（Stack）

## 类型判定
判别型 — 栈是**操作受限的线性表**，`is_a` [[线性表]]，核心区别是插入/删除只能在一端进行。

## 是什么
栈是一种只允许在**一端**进行插入和删除的线性表。允许操作的一端叫**栈顶**（top），另一端叫**栈底**（bottom）。

核心特性：**后进先出**（LIFO, Last In First Out）——最后进来的元素最先出去。

## 输入-输出空间
- **Push(S, x)**：输入元素 x → 放入栈顶
- **Pop(S, &x)**：弹出栈顶元素 → 输出到 x
- **GetTop(S, &x)**：读取栈顶元素（不删除）→ 输出到 x

## 正例（≥2 个）
1. **洗碗叠盘子**：洗好的盘子从顶部摞上去，用的时候从顶部取——后洗的先用到
2. **浏览器后退按钮**：访问 A→B→C，点后退先回到 B → LIFO
3. **函数调用栈**：main() → f1() → f2()，f2 先返回，f1 后返回，main 最后返回

## 反例/边界（≥1 个）
1. **排队买票**：先来的先买到 → 这是 FIFO（队列），不是栈
2. **任意位置的插入删除**：普通线性表可以在中间位置插入 → 栈不允许，只在栈顶

## 详细解释

### 基本操作（5 个）
| 操作 | 含义 |
|------|------|
| `InitStack(&S)` | 初始化空栈 |
| `DestroyStack(&S)` | 销毁释放 |
| `Push(&S, x)` | 进栈（压栈）|
| `Pop(&S, &x)` | 出栈（弹栈），返回栈顶值 |
| `GetTop(S, &x)` | 读栈顶（不弹出）|
| `StackEmpty(S)` | 判空 |

### 进栈顺序 vs 出栈顺序
若进栈顺序为 $a_1 \to a_2 \to a_3 \to a_4 \to a_5$（依次压入），则出栈顺序为 $a_5 \to a_4 \to a_3 \to a_2 \to a_1$（逆序）。

⚠️ 但如果中途允许出栈后再进栈（如 push a1, push a2, pop a2, push a3…），则出栈序列可能有多种合法组合——**合法出栈序列数是 Catalan 数问题**。

### 与线性表的区别
| | 线性表 | 栈 |
|---|---|---|
| 插入位置 | 任意 | 仅栈顶 |
| 删除位置 | 任意 | 仅栈顶 |
| 特性 | 无特殊约束 | LIFO |
| 逻辑结构 | 线性 | 线性（相同！） |

**栈只是加了操作限制的线性表。**

## 类比

### 一句话比喻
**栈就像手枪弹夹——子弹只能从顶部一颗一颗压进去（push），射击时也只能从顶部一颗一颗弹出来（pop）。最后压进去的那颗子弹，最先被打出去。你想拿中间那颗子弹？不好意思，先把上面的全卸了再说。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| Push（压栈） | 往弹夹顶部塞一颗子弹 |
| Pop（弹栈） | 射击，弹出一颗子弹 |
| 栈顶（top） | 弹夹口——唯一能进出的口 |
| 栈底（bottom） | 弹簧底座——永远拿不到，除非全部清空 |
| LIFO | 最后压入的子弹最先射出 |
| 栈满（overflow） | 弹夹塞满了，再塞就炸 |
| 栈空（underflow） | 弹夹打空了，扣扳机只有"咔" |
| `GetTop`（读栈顶） | 摸一摸弹夹口那颗子弹还在不在，但没扣扳机 |
| 中间元素 | 卡在弹夹中间的子弹——不把上面的全退出来，你碰不到它 |
