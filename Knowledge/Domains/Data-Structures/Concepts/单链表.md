# 单链表（Singly Linked List）

## 类型判定
判别型 — 单链表是线性表最基础的链式存储实现，核心特征是每个结点只有一个后继指针（next），与双链表（两个指针）和循环链表（尾指针指回头）形成区分。

## 是什么
单链表是用**链式存储**方式实现的线性表。每个结点包含**数据域**（data）和**指针域**（next，指向下一个结点）。各个结点在物理上可以离散存放，通过 next 指针串联起逻辑上的先后关系。

两种实现方式：
- **不带头结点**：头指针 L 直接指向第一个数据结点，空表时 `L == NULL`
- **带头结点**：头指针 L 指向一个不存数据的头结点，空表时 `L->next == NULL`（**推荐方式**，代码更统一）

## 输入-输出空间
- **输入**：无（物理结构定义）
- **输出**：无
- **核心字段**：`data`（数据域）、`next`（指针域，指向下一结点）

## 正例（≥2 个）
1. **带头结点的学生链表**：头结点不存数据，之后每个结点存一个学生信息，next 指针指向下一个学生 → 空表判断：`L->next == NULL`
2. **不带头结点的简单链表**：L 直接指向第一个结点，空表判断：`L == NULL` → 插入/删除 i=1 时需要特殊处理

## 反例/边界（≥1 个）
1. **混淆 LinkList 和 LNode***：`LinkList L` 和 `LNode *L` 本质上等价，前者强调"这是一个链表"，后者强调"这是一个结点指针"。课本代码中两者混用，不理解会看得一头雾水。
2. **空表判断混淆**：带头结点 `L->next == NULL`，不带头结点 `L == NULL`，搞混会导致程序崩溃。

## 详细解释

### 结点定义与类型重命名

```c
typedef struct LNode {      // 定义结点类型
    ElemType data;          // 数据域
    struct LNode *next;     // 指针域，指向下一个结点
} LNode, *LinkList;         // LNode = struct LNode, LinkList = struct LNode*
```

**typedef 的作用**：
- `LNode` = `struct LNode`（少写 struct）
- `LinkList` = `struct LNode *` = `LNode *`（强调"这是一个链表"）

```c
// 以下两种声明等价：
LNode *p;       // 强调 p 是一个结点指针
LinkList L;     // 强调 L 是一个链表
```

### 初始化（带头结点 vs 不带头结点）

```c
// 不带头结点
bool InitList(LinkList &L) {
    L = NULL;            // 空表
    return true;
}
bool Empty(LinkList L) {
    return (L == NULL);
}

// 带头结点（推荐）
bool InitList(LinkList &L) {
    L = (LNode *)malloc(sizeof(LNode));  // 分配头结点
    if (L == NULL) return false;         // 内存不足
    L->next = NULL;                      // 头结点后继为空
    return true;
}
bool Empty(LinkList L) {
    return (L->next == NULL);
}
```

### 为什么要带头结点？

| 场景 | 不带头结点 | 带头结点 |
|------|-----------|---------|
| 在 i=1 插入 | 需修改头指针 L 本身，特殊处理 | 统一逻辑，头结点可看作"第 0 个结点" |
| 删除 i=1 | 需修改头指针 L 本身 | 统一逻辑 |
| 空表插入 | 特殊处理 | 统一逻辑 |
| 代码分支 | 3 种情况（空表/表头/其他） | 1 种情况 |

### 单链表的核心特性
1. **不支持随机存取**：找第 i 个结点须从头遍历，$O(n)$
2. **存储密度较低**：每个结点除了数据还要存指针
3. **容量灵活**：每次 `malloc` 一个结点即可扩展，无需预分配大片空间
4. **插入删除方便**：只需修改指针，不需移动元素

## 类比

### 一句话比喻
**单链表就像一串用钩子连起来的火车车厢——每节车厢（结点）只知道自己后面钩着谁（next），不知道前面是谁。你要找到第 5 节车厢？必须从火车头（头指针）一节一节往后数。想在第 3 和第 4 节之间加一节新车厢？只需要把第 3 节的钩子挂到新车上，新车的钩子挂到第 4 节——不用搬动任何一节车厢。带头结点就像在火车头前面再加一节不载客的引导车厢——这样不管在哪儿加车厢，操作规则都一样。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| `LNode`（结点） | 一节火车车厢 |
| `data`（数据域） | 车厢里的乘客/货物 |
| `next`（指针域） | 车厢尾部的挂钩 |
| 头指针 `L` | 火车头（知道第一节在哪） |
| 头结点 | 引导车厢（不载客，方便编组） |
| `L->next == NULL`（空表） | 火车头后面啥都没有 |
| 按位查找 $O(n)$ | 必须从车头走到目标车厢 |
| `malloc` 新结点 | 从仓库调一节新车厢 |
