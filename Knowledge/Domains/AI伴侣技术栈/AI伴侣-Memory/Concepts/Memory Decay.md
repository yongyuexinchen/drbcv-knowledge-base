# Memory Decay（记忆衰减）

## 类型判定
判别型 — 模拟人脑遗忘曲线，按时间和重要性降低非活跃记忆的权重，防止记忆库膨胀失控。

## 类比 ★
### 一句话比喻
记忆衰减像你的手机相册自动清理——一个月前拍的午餐照片被压到「建议删除」列表底端，但去年生日那几张被标了「精彩瞬间」的永远挂在最上面。不是所有照片都值得永久保存，手机空间有限，AI 的检索精度也有限。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 记忆衰减曲线 | 手机相册的智能清理建议——越久远、越不重要的照片越先被建议删除 |
| 重要性权重保护 | 「精彩瞬间」标记的照片——重要记忆被锁定，衰减极慢或不衰减 |
| 重新激活（Rehearsal） | 翻到一张旧照片——被回看后重新获得「热度」，延迟衰减 |

## 是什么
Memory Decay 是 AI 伴侣记忆系统的**信息生命周期管理机制**。它赋予每条记忆一个随时间递减的权重（检索分数），模拟艾宾浩斯遗忘曲线。核心目的是防止记忆库无限膨胀——没有衰减的系统会变成垃圾场，检索时噪声淹没信号。同时它体现了 AI 对人类记忆的模拟：重要的事记很久，琐事很快忘。

## 输入-输出空间
- **输入**: Memory Entry（包含重要性评分和创建时间戳）
- **输出**: 修正后的检索权重（decayed_score）
- **衰减公式（简化）**: `score = importance × e^(-λ × days_since_last_access)`
- **关键参数**: λ（衰减速率）、importance（初始重要性，来自 Consolidation）

## 正例（≥2 个）
1. **Mem0 的记忆衰减**: Mem0 内置衰减机制，低重要性记忆随时间降低检索优先级，长期未被访问的记忆可能被归档或删除
2. **Notion AI 的上下文窗口管理**: 近期对话优先、久远对话降权——本质是一种时间衰减策略
3. **人脑模拟**: 你记得去年生日怎么过的但不记得去年今天午饭吃的什么——这正是 Decay 在根据重要性差异化处理

## 反例/边界（≥1 个）
1. **无衰减的全量记忆库**: 每条记忆权重永远不变——5000 条记忆后检索噪声完全淹没相关记忆，AI 表现「记忆力差」其实是检索精度崩溃
2. **边界 — 过度衰减**: λ 设太大导致一周前的记忆全部归零——AI 伴侣变得像金鱼一样只有 7 秒记忆

## 详细解释
衰减策略的几种常见模式：

| 策略 | 描述 | 适用场景 |
|-----|------|---------|
| 时间线性衰减 | 权重随天数线性下降 | 通用场景 |
| 指数衰减 | 权重按 e^(-λt) 快速下降 | 对时效性要求高的场景 |
| 重要性加权衰减 | `score = importance × decay(t)` — 重要记忆衰减更慢 | AI 伴侣（推荐） |
| 访问频率保护 | 经常被检索的记忆衰减减速（Rehearsal 效应） | 活跃话题保护 |
| 硬删除 | 低于阈值的记忆直接删除 | 存储成本敏感场景 |

AI 伴侣推荐「重要性加权衰减 + 访问频率保护」——既模拟人脑的遗忘机制，又保留对关系重要的信息。
