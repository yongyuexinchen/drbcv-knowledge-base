# Working Memory（工作记忆）

## 类型判定
判别型 — 模型「当下正在处理」的信息空间，是 LLM 推理的即时操作台。

## 类比 ★
### 一句话比喻
工作记忆像厨师面前的砧板——短期记忆是冰箱里的食材（整段对话历史），厨师从冰箱取出当前要用的几样（当前消息 + 相关记忆），放在砧板上切配翻炒（LLM 推理），出锅上菜（生成回复）。砧板就这么大，放不下的只能先搁冰箱。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Working Memory（Context Window） | 厨师的砧板——只能同时处理有限食材，多了就掉地上 |
| Attention（注意力机制） | 厨师的目光——盯着正在切的这根葱，但余光还能扫到旁边的姜 |
| Memory Retrieval（检索注入） | 从冰箱拿食材——把长期记忆中相关的记忆片断放到砧板上 |

## 是什么
工作记忆是 LLM 在一次推理中实际「看到」和「处理」的信息集合，等价于当前 Prompt 的全部内容：System Prompt + 短期记忆（对话历史）+ 长期记忆检索结果 + 工具调用结果。它是三层记忆体系中的「处理层」——短期记忆提供上下文，长期记忆提供背景，工作记忆负责综合两者执行推理。

## 输入-输出空间
- **输入**: 短期记忆（当前对话） + 长期记忆检索结果 + 工具调用返回 + System Prompt
- **输出**: LLM 生成的文本（下一个 token → 完整 response）
- **容量**: = Context Window 大小（如 128K tokens），是所有输入的总和上限
- **动态特性**: 每次 LLM 调用时重新组装——不保留上一次调用的内部状态

## 正例（≥2 个）
1. **多步推理**: 用户问「把我上次提到的餐厅和今天说的新偏好结合起来推荐」，工作记忆同时持有「上次的餐厅名」+「今天的新偏好」+「推荐逻辑」三条信息进行综合推理
2. **工具调用链**: Agent 调用搜索 API → 结果注入工作记忆 → 基于结果调用计算 API → 再注入 → 生成最终答案——每一步结果都暂存在工作记忆中

## 反例/边界（≥1 个）
1. **仅靠 Context Window 的「伪工作记忆」**: 把整段对话塞进 Prompt 不叫工作记忆——这只是把所有食材堆在砧板旁边，工作记忆需要「选择性注意」和「信息整合」
2. **边界 — 信息过载**: 当 Prompt 塞入过多信息（超长对话 + 大量检索结果 + 复杂 System Prompt），工作记忆超载导致 LLM 忽略关键信息或产生幻觉

## 详细解释
工作记忆在三层记忆体系中的位置是「枢纽」：

```
                    ┌──────────────────┐
Short-term Memory →│                  │
                    │  Working Memory  │→ LLM 推理 → 生成回复
Long-term Memory  →│  (Context Window) │
                    │                  │→ Memory Consolidation（重要信息写回长期）
Tool Results      →│                  │
                    └──────────────────┘
```

工作记忆的关键特性是 **组装式（assembly-based）**而非**持久式（persistent）**：
- 每次 LLM 调用时从各输入源组装 Prompt
- 推理完成后工作记忆清空（模型本身无状态）
- 需要跨轮次保持的信息必须写回短期记忆或长期记忆
