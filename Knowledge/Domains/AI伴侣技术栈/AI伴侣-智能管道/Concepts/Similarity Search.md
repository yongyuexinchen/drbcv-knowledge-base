# Similarity Search

## 类型判定
判别型 — 通过向量距离度量「有多像」的算法，语义检索的「评分员」。

## 类比 ★
### 一句话比喻
相似度搜索像相亲平台的匹配算法——不是按身高、收入精确匹配（精确搜索），而是把每个人变成一个多维坐标（Embedding），然后算「你们俩在多维空间里离得有多近」。离得越近，越可能是灵魂伴侣。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Cosine Similarity | 相亲匹配度——看你俩的「方向」是否一致，不在乎绝对值（你存款多少不重要，重要的是价值观同向） |
| Euclidean Distance | 直线距离——在所有维度上算你俩差了多少，身高体重收入兴趣都算 |
| Top-K 检索 | 不只要一个匹配，要「最匹配的前 5 个人」——给你选择余地 |

## 是什么
Similarity Search 是通过计算向量之间的距离来判断数据之间相似程度的技术。在 RAG 和 AI 伴侣记忆检索中，用户查询被 Embedding 成一个向量，然后与向量库中的海量向量逐一计算距离，返回距离最近的 K 个结果。这不是精确匹配——「你喜欢猫吗」和「家里养了只橘猫」向量距离很近，即使没有一个词相同。

## 输入-输出空间
- **输入**: 查询向量 Q + 候选向量集合 + top-k 参数
- **输出**: 与 Q 距离最小的 K 个向量 + 对应数据 + 距离分数
- **距离度量**: Cosine Similarity（-1~1）、Euclidean Distance（0~∞）、Dot Product（-∞~∞）

## 正例（≥2 个）
1. **AI 伴侣记忆匹配**: 用户说「今天心情不好」→ Embedding → 与记忆库中所有记忆算余弦相似度 → 找到「上次心情不好时用户去散步了」「用户喜欢看搞笑视频治愈」→ LLM 回复带共情+建议
2. **推荐系统**: 「喜欢这本书的人也喜欢...」→ 用户读过的书的 Embedding → 相似度搜索 → 推荐距离最近但用户没读过的书

## 反例/边界（≥1 个）
1. **精确匹配（BM25/关键词）**: 搜「Python 教程」返回所有标题含「Python 教程」的文档——不是相似度搜索，不关心语义
2. **边界 — 距离 ≠ 语义**: 在高维空间中，「距离近」不一定等于「人觉得相似」——Embedding 模型的质量决定了距离的语义可信度

## 详细解释
三种核心距离度量：

**余弦相似度（Cosine Similarity）**：
$$\cos(\theta) = \frac{A \cdot B}{||A|| \times ||B||}$$
- 衡量方向相似性，忽略向量长度
- 值域 [-1, 1]，1=完全相同方向，-1=完全相反
- **最常用于文本 Embedding**

**欧几里得距离（Euclidean Distance）**：
$$d(A,B) = \sqrt{\sum (A_i - B_i)^2}$$
- 衡量绝对距离，考虑所有维度的差异
- 值越小越相似
- 对向量长度敏感（长文本 vs 短文本）

**点积（Dot Product）**：
$$A \cdot B = \sum A_i \times B_i$$
- 同时考虑方向和长度
- 归一化后等价于余弦相似度

在 RAG 中的实际应用：
```
查询 "AI 伴侣如何保持记忆" → Embedding → [0.23, -0.45, ...]
  vs 候选 1 "长期记忆机制"  → Cosine: 0.92 ✅ 返回！
  vs 候选 2 "天气 API 调用"  → Cosine: 0.11 ❌ 忽略
  vs 候选 3 "对话历史存储"   → Cosine: 0.85 ✅ 返回！
  ...
  Top-3 结果注入 Prompt
```
