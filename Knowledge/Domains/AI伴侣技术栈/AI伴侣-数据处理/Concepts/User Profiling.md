# User Profiling（用户画像）

## 类型判定
判别型 — 从行为数据中抽象出「用户是什么样的人」，AI 伴侣个性化服务的基石。

## 类比 ★
### 一句话比喻
User Profiling 像相亲网站的「会员档案建立师」——你不说「我是怎样的人」，但他们通过看你点了谁的资料、跟谁聊了多久、聊什么话题、几点上线，帮你整理出一份比你自己描述的还准的「个人画像」。标签从「喜欢运动」精确到「周三晚上十点后情绪低落时爱聊哲学」。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 从行为推断画像 | 相亲网档案师——不靠问卷靠行为，比你更懂你自己 |
| 静态标签 + 动态特征 | 身份证（年龄/性别）+ 心情日记（今日情绪/能量水平） |
| 画像实时更新 | 档案师每天翻看你的新行为——画像不是死的，是活的 |

## 是什么
用户画像（User Profiling）是根据用户的历史行为数据构建结构化用户模型的过程。在 AI 伴侣系统中，用户画像是「让伴侣认识你」的基础设施——伴侣需要知道你的性格、偏好、作息、情绪模式，才能提供个性化回应。画像数据来源：对话内容（话题偏好、语言风格）、行为模式（活跃时段、功能使用习惯）、情感轨迹（情绪波动曲线）、显式设置（用户自己填的偏好）。

## 输入-输出空间
- **输入**: 用户行为事件流（对话、点击、设置变更）、对话内容（NLP 分析后提取的特征）
- **输出**: 结构化用户模型——人口统计特征（静态）+ 行为特征（动态）+ 情感特征 + 偏好向量
- **更新频率**: 实时增量更新（新事件发生后几分钟内反映到画像中）

## 正例（≥2 个）
1. **AI 伴侣个性化回应**: 画像显示「用户是夜猫子 + 晚上容易情绪低落」→ 伴侣在 23:00 的回应自动更温柔、更多鼓励
2. **内容推荐**: 画像显示「用户对科幻话题参与度高」→ 伴侣主动分享科幻新闻/故事

## 反例/边界（≥1 个）
1. **显式 Profile 页**: 用户在设置页手动填的「年龄/性别/兴趣」——这是静态声明，不是画像。真正的 User Profiling 是从行为中「推断」，很多用户自己都不知道的偏好能被挖掘出来
2. **边界 — 冷启动**: 新用户没有行为数据——画像系统需要先收集 1-2 周的数据才能产生有意义的推断。冷启动阶段依赖默认画像 + 显式设置 + 对话中的主动询问

## 详细解释
用户画像的技术架构：
```
[数据收集层]
├─ 对话日志 (PostgreSQL)
├─ 行为事件 (Kafka)
└─ 情感分析结果
        ↓
[特征工程层: Spark / Python]
├─ 统计特征：活跃时段分布、话题偏好向量、平均消息长度
├─ NLP 特征：语言风格、情感轨迹、关键实体提取
└─ 时序特征：情绪周期、会话模式
        ↓
[画像存储层]
├─ 静态画像 (PostgreSQL)：年龄、性别、MBTI（如果有）
├─ 动态特征 (Redis)：当前心情、最近话题
└─ 向量画像 (向量库)：用户语义表示 → 用于相似用户推荐
```
画像不是存了就不变的——它是「活」的系统，持续消费事件流更新。

### → 指向
- [[Event Stream]] — 事件流是构建画像的原始数据源
- [[ETL]] — 用户画像依赖 ETL 流水线从原始行为提取结构化特征
- [[User Model]] — User Profiling 的结果输出为用户模型（User Model），存储在 AI 伴侣的 Memory 域中

### ← 被指向
- [[Apache Spark]] — Spark 负责画像特征工程的分布式计算
- [[Kafka]] — Kafka 传输用户行为事件供画像系统消费
- [[Personal AI]] — 个人 AI 以用户画像为核心输入，驱动个性化行为
