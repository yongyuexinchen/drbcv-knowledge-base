# 知识库检索增强生成

## 类型判定
将外部文档通过向量化存储和语义检索注入大模型回答的技术模式，使 AI 能够基于私有知识给出准确答案。

## 类比 ★
### 一句话比喻
就像考试前把课本撕成一页页贴满整面墙，考试时你扫一眼墙上的关键词找到相关那页，然后用自己的理解写答案——你不需要背下整本书，但你能答对书上有的任何问题。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| PDF / 文档上传 | 把课本交给图书管理员 |
| 文本分割器（Text Splitter） | 把书拆成一页页 |
| Embedding 向量化 | 给每页贴上编号标签 |
| 向量数据库（Vector DB） | 贴满标签页的档案墙 |
| 用户问题向量化 | 拿着问题去墙上找匹配的标签 |
| 向量检索 | 找到最相关的那几页 |
| LLM 综合回答 | 读懂这几页后用自己的话写答案 |

## 是什么
知识库检索增强生成（RAG）是将外部私有文档注入大模型回答的技术流程。核心步骤：① 上传文档（PDF/PNG）→ ② 文本分割器将大文档切分为小块 → ③ 通过 embedding 模型将文本块向量化 → ④ 存入向量数据库 → ⑤ 用户提问时，将问题也向量化 → ⑥ 在向量数据库中检索语义最相似的文本块 → ⑦ 将检索结果与用户问题一起交给 LLM → ⑧ LLM 基于检索内容生成回答。

## 正例（≥2 个）
1. **张一鸣知识库问答**：上传张一鸣相关的 PDF 文档 → 创建"张一鸣语录3"知识库 → 搭建知识库对话技能 → 用户问"张一鸣的创业思考" → 向量检索到相关内容 → LLM 基于检索结果回答。
2. **招股书分析**：上传 400+ 页招股书 PDF → 文本分割器切分 → embedding 向量化存入数据库 → 智能语义切分 → 用户问"主营业务、盈利模式" → 精确检索相关内容回答。

## 反例/边界（≥1 个）
1. 纯 LLM 对话（无知识库）：大模型只能基于训练数据回答，无法访问企业私有文档，知识时效也受训练截止日期限制。
2. 关键字匹配检索（非语义）：传统基于关键词的全文搜索只能做字面匹配，无法理解"创业思考"和"张一鸣创业历程"是同一语义。

## 详细解释
知识库 RAG 的组件与链路：
1. **知识库创建**：在"知识库"页面创建知识库 → 选择 embedding 模型（如 OpenAI ADA-002）→ 上传文件
2. **文本处理**：支持智能语义切分（按语义边界切分）和手动切分（按分隔符切分）
3. **核心组件链**：
   - 向量数据库组件（Vector Store）：已向量化的知识库
   - 向量检索组件（Retriever）：将用户问题传给向量数据库并检索
   - 检索增强组件（RetrievalQA Chain）：将检索内容和 LLM 连接，获取问题+检索文档 → 与 LLM 交流互动
4. **工具化封装**：整个知识库检索链路可封装为一个工具节点，供 Agent 调用
5. **Prompt 变量**：{context} 代表从知识库检索到的内容，{input} 代表用户问题

注意事项：如果已有预建知识库则在向量数据库组件中选择知识库；如果需要对话中实时上传新文件，则需要通过 embedding 组件对新文件做实时向量化。
