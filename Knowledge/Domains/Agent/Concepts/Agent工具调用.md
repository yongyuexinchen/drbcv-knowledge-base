# Agent工具调用

## 类型判定
Agent 识别用户意图后自主选择并调用外部工具以弥补 LLM 原生能力不足的执行过程。

## 类比 ★
### 一句话比喻
就像你让一个不会做饭的朋友做菜，他翻开菜谱（LLM 知识），发现需要烤箱但他自己没有，于是他打开手机叫了外卖烤箱（调用工具），把半成品放进去烤好端给你。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Agent 识别需要计算 | 发现需要算复杂账目 |
| 调用 Calculator 工具 | 拿出计算器按按钮 |
| 工具返回结果 | 计算器屏幕显示数字 |
| Agent 综合答案 | 把数字抄到报告里 |
| 调用搜索工具 | 打开浏览器 Google |
| 工具节点（Tool Node） | 抽屉里的各种工具 |

## 是什么
Agent 工具调用是单体 Agent 工作流中的关键环节。Agent 以大语言模型为核心，但 LLM 有天然短板（计算不准、无实时信息、无法操作文件），工具调用机制让 Agent 能够在推理过程中识别自身能力边界，主动选择并调用对应的外部工具（计算器、搜索引擎、向量检索、代码执行器等）来完成任务。工具节点是连接 LLM 和外部能力的"中间人"，通过预定义的名称和描述让 Agent 知道何时该调用哪个工具。

## 正例（≥2 个）
1. **计算工具调用**：用户问"12345 × 6789 + 456"，Agent 思考后判定需要执行计算操作 → 调用 Calculator 工具 → 工具返回精确结果 → Agent 将结果整合到回答中。
2. **搜索工具调用**：用户问"今天成都天气"，Agent 调用 Bing 搜索工具 → 获取实时天气数据 → 返回"成都今天是雾天，气温在 14-23 度"。
3. **多工具组合调用**：招股书分析场景中，Agent 同时连接搜索工具、计算工具和向量检索工具，根据问题类型自动路由到对应工具。

## 反例/边界（≥1 个）
1. 纯 LLM 对话：没有连接工具的大模型对话只能依赖训练数据，问"今天天气"只能给出通用回答或拒绝回答，无法获取实时信息。
2. 工具未正确描述：如果工具的描述不清（什么场景该用、什么场景不该用），Agent 会"不知道该用哪个工具"，导致工具形同虚设。

## 详细解释
工具调用的执行流程：
1. **意图识别**：用户输入问题 → Agent 解析意图
2. **决策**：Agent 根据 prompt 中预设的行为指南，判断是否需要调用工具、调用哪个工具
3. **调用**：Agent 将任务参数传递给工具节点
4. **执行**：工具执行（计算、搜索、检索等）
5. **反馈**：工具返回原始结果给 Agent
6. **综合**：Agent 将工具返回的结果整合为最终回答

关键设计要点：
- 工具必须有清晰的名称和描述
- Agent 的 prompt 需要明确"何时调用什么工具"
- 工具节点通过 LLM 连接点与 Agent 绑定
- 可以同时连接多个工具，Agent 自主选择
