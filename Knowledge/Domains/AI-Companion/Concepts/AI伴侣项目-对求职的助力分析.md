# AI伴侣项目-对求职的助力分析

## 是什么（What）

AI伴侣"永月"项目不是一个"玩具项目"，它是对AI应用开发全栈技能的最佳展示载体——涵盖了RAG（知识库）、Agent（对话编排）、记忆系统（向量数据库+LLM提取）、API工程化（FastAPI+WebSocket）、多模态（TTS语音）。一个项目=能回答面试中所有核心技术问题。

这就像考驾照时的那辆教练车：你不需要造一辆完美的跑车，你只需要证明你"能开、能倒库、能上路"。AI伴侣MVP就是你的教练车——证明你能独立做AI应用。

## 为什么重要（Why）

- 面试官不问"你学了什么"，只问"你做出过什么"
- AI伴侣项目天然覆盖AI应用开发岗的所有核心考点：
  - RAG → 知识库检索（用户Profile存储+语义搜索）
  - Agent → 对话编排（角色调度+工具调用）
  - 记忆系统 → 向量数据库+LLM提取+Prompt注入
  - 工程化 → FastAPI后端+WebSocket实时通信
- **与普通RAG项目的区别**：普通RAG是"把文档转成问答"，AI伴侣是"让AI有记忆和人格"——档次完全不同
- 用户已有优势资产：45张SillyTavern DRBCV卡片、Memobase/Letta/Open-LLM-VTuber的全维度调研

## 怎么做（How）

### 面试能用上的"技术故事"

```python
# 面试官问："聊聊你做的项目"

# 你能说的(3分钟版本):
"我独立开发了一个AI伴侣系统'永月'。
 1. 后端用FastAPI+WebSocket实现实时对话，支持语音打断
 2. 记忆系统借鉴了Letta+Memobase的设计，做了四层架构：
    Persona层(角色自我认知)、Profile层(用户结构化档案)、
    Episodic层(事件时间线)、Vector层(ChromaDB语义搜索)
 3. 用DeepSeek API+Prompt Engineering管理角色人格，
    example_dialogs策略保证角色一致性
 4. 做了完整的API工程化：异常处理、限流降级、结构化日志

 最大的技术挑战是记忆一致性——
 怎么让AI在100轮对话后还能记得关键信息。
 我用了'混合窗口策略'：最近20轮完整保留+更早的压缩摘要
 +向量库全量存档，平衡了成本和效果。"
```

### MVP范围（2周可完成，面试够用）

```
永月 MVP（面试展示版）:
├── 对话引擎：DeepSeek API + 角色Prompt
├── 短期记忆：最近10轮对话上下文
├── 长期记忆：自建SQLite/JSON存储（3-5条Profile信息）
├── 语音输出：edge-tts（免费TTS）
├── API层：FastAPI + Swagger文档
└── 演示：curl调API + 录屏3分钟
```

### 项目在面试中的价值分层

| 面试环节 | 项目展示 | 证明什么 |
|---------|---------|---------|
| 简历筛选 | "独立开发AI伴侣系统(已开源)" | 有独立项目能力 |
| 技术面(RAG) | "记忆系统的向量检索+混合召回" | 深入理解RAG |
| 技术面(Agent) | "角色编排+对话状态管理" | 理解Agent设计 |
| 技术面(工程) | "FastAPI+异常处理+日志" | 有工程化意识 |
| 系统设计 | "四层记忆架构的设计取舍" | 能做技术决策 |
| HR面 | "从0到1的产品思维" | 有ownership |

### 什么不该做（省时间）

- ❌ 不要追求完美产品→MVP够面试就行
- ❌ 不要做前端UI→curl+Swagger够用
- ❌ 不要在MVP阶段搞Live2D→时间黑洞
- ❌ 不要自己训模型→用API够展示工程能力

### 项目演进路线（面试→入行→长期）

```
面试阶段(2周MVP):
  证明"我能做AI应用"→ 拿到offer

入行后(持续迭代):
  在工作中积累的工程能力反向改进"永月"
  → 加入多模态→加入情感计算→加入人格建模

长期(终极目标):
  "永月"成为真正的AI伴侣系统
  → 本地优先+独立人格+完全自主
```
