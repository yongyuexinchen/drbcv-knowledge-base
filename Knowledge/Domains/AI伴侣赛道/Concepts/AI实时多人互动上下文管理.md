# AI 实时多人互动的上下文管理

## 是什么
Neuro-sama 在直播中同时处理三类对话对象（Vedal、联动嘉宾、大量观众 chat 流 10-100 msg/s），通过"消息优先级队列 + 选择性回应 + 角色锚定 + 上下文窗口管理"四层策略，在 LLM 有限上下文窗口内高效管理多人交互。核心原则是"回应选择而非回应全部"。

## 关键洞察

1. **"选择性回应"是多人场景的核心策略**：Neuro 不需要回复每条消息——她只挑有趣的说。消息按优先级排序（@Neuro 定向 > 打赏者/订阅者 > 有趣/有梗 > 普通消息），纯表情和重复消息直接过滤。这个策略大幅降低了 LLM 的输入负载。对永月的群聊场景（如果未来支持）：AI 伴侣在群聊中是参与者之一而非中心，不需要回应每一条消息。

2. **角色锚定通过"当前对话对象"标签实现**：Neuro 对 Vedal 撒娇依赖、对联动嘉宾好奇、对观众吐槽——底层人格一致，但互动语气因对象而异。这是通过 System Prompt 中注入"当前对话对象"标签实现的。对永月的启示：即使在一对一中，用户也可能以不同情绪/状态出现——可以在 System Prompt 中注入"用户当前状态"标签来处理。

3. **上下文窗口管理用"精选"而非"全量"**：短期记忆只保留当前直播的精选对话，而非完整 chat 流（否则几秒就爆 context window）。对永月：长对话历史应做摘要和关键事件提取，而非全量塞入 context。

## 与 AI 伴侣的关系

永月的多人场景优先级不高——当前阶段应先做好一对一私聊。但架构上需要预留扩展空间：(1) 消息处理 pipeline 设计为可扩展——当前只有一个输入源，未来可以加过滤/优先级/多源合并；(2) 上下文管理策略从一对一模式设计起，但不要堵死群聊的扩展路径。一对一场景下的上下文管理同样重要——用户与永月的长对话历史需要智能摘要和关键词检索，而非全量 context window 硬塞。
