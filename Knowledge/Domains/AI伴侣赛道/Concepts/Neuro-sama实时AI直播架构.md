# Neuro-sama 实时 AI 直播架构

## 类型判定
过程型 — 回答"一条 Twitch 消息怎么变成 Neuro 的一句带表情的语音回复"的问题，核心是端到端数据流和延迟分析。

## 类比
**一句话比喻：** 像流水线工厂——聊天消息是原材料，经过筛选（质检）→ LLM（大脑）→ TTS（嘴巴）+ Live2D（脸）→ OBS（包装）→ 直播（出货），3-8 秒从原料到成品。

| 维度 | 生活映射 |
|------|---------|
| 消息优先级队列 | 急诊分诊——@Neuro 的先看、打赏者的次之、普通消息排队 |
| LLM 结构化输出 | 大脑不只说话，还同时发指令给嘴巴和脸 |
| 思考停顿 | 等电梯时的短暂沉默——没人觉得是故障，都觉得是正常 |
| 三路并行 | 厨房同时炒菜、摆盘、上菜——各干各的，最后凑一桌 |

## 是什么
Neuro-sama 的全栈实时 AI 直播系统：Twitch IRC 接入观众聊天 → 消息过滤和优先级排序 → LLM 本地 GPU 推理（结构化输出：文本+情感+动作）→ 三路并行：TTS 流式合成 + Live2D 参数控制 + 游戏交互 → OBS 合成推流。端到端延迟 3-8 秒，全程由单人开发维护。

## 输入-输出空间
- **输入**：Twitch Chat 消息、游戏状态、语音指令（Vedal）
- **输出**：TTS 音频 + Live2D 动画画面 + 可能的游戏操作 → Twitch 直播流

## 正例（≥2 个）
- **"思考停顿"把延迟变成 UX 资产**：Neuro 说话前的自然停顿让观众觉得"她在思考"而不是"系统卡了"。停顿恰好给 TTS 合成留出缓冲时间（200ms-1s）。这是把技术约束转化为体验优势的经典案例。
- **结构化输出实现多模态同步**：LLM 不输出纯文本，而是输出 `{text: "...", emotion: "happy", action: "wave"}`。TTS 读 emotion 调音调，Live2D 读 action 调动画参数，各子系统并行消费同一份输出。

## 反例/边界（≥1 个）
- **这个架构不适合 AI 伴侣**：Neuro 是广播式（一对多），永月是对话式（一对一）。Neuro 的延迟可以靠"思考停顿"掩盖——但私密对话中用户等 3-8 秒回复会感到疏远。永月应该优先降延迟而非美化延迟。
- **单机架构有上限**：Vedal 的单机部署能扛 15K 在线观众（聊天消息），但不可能同时服务 15K 个一对一会话。永月的本地优先架构天然解决这个问题——每个用户跑自己的实例。

## 详细解释

### 端到端数据流
```
[观众发消息 "Neuro you're so cute!"]
        │ Twitch IRC (irc.chat.twitch.tv:6667)
        ▼
[消息过滤层] — 去表情符号纯文本、过滤重复、识别 @Neuro
        │
        ▼
[优先级队列] — @Neuro / 打赏者 / 有趣消息 → 优先消费
        │
        ▼
[上下文组装] — System Prompt + 当前直播聊天历史 + 选中消息
        │
        ▼
[LLM 本地推理] — GPU (推测 RTX 4090 / A系列)
   结构化输出: {
     text: "Aww thank you! *blushes*",
     emotion: "embarrassed",
     action: "shy_sway"
   }
        │
   ┌────┼────┐
   ▼    ▼    ▼
[TTS] [Live2D] [游戏]
   │    │    │
   └────┼────┘
        ▼
[OBS 合成] → RTMP → Twitch
```

### 延迟分解
| 环节 | 延迟 | 是否可感知 |
|------|------|----------|
| IRC 消息到达 | 0.1-0.5s | 否 |
| 过滤+优先级 | <0.1s | 否 |
| LLM 推理 | 0.5-2s | **主瓶颈** |
| TTS 合成 | 0.2-1s | 被停顿掩盖 |
| 推流 | 2-5s | Twitch 固有 |
| **总计** | **3-8s** | |

### 关键设计决策

**为什么用本地 GPU 推理而不是 API？**
- 延迟：API 往返增加 200-500ms 网络延迟
- 成本：日播 4 小时 × 30 天 = 120 小时推理，API 按 token 计费远贵于电费
- 人格控制：API 模型的"安全对齐"会抹掉角色的独特语气

**为什么输出结构化标记而不是纯文本？**
- 解耦：换 TTS 引擎不改 LLM 输出格式
- 同步：情感标签同时控制声音和表情，不需要额外的情感分类步骤
