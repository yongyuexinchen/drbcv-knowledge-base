# 开源伴侣引擎（Open-Source Companion Engine）

## 类型判定
判别型 — 它是「伴侣系统的 LangChain」—— 做基础设施而非终端产品，服务开发者而非最终用户。

## 是什么
开源伴侣引擎是面向开发者的中间件/库：将 AI 伴侣的核心能力（人格管理、记忆存储、情绪动力学）封装为独立模块，通过 pip install 或 API 调用集成到任何前端（SillyTavern、自定义 App）。所有竞品全闭源，开源伴侣引擎是蓝海。

## 输入-输出空间
**输入**：角色配置（YAML/JSON）+ 对话文本 + API 调用
**输出**：记忆查询结果 + 人格状态 + 情绪参数 + 上下文注入模板

## 正例（≥2个）
- companion-core（少女项目 v0.1 蓝图）：Persona + Memory + Emotion 三模块，pip install
- LangChain 模式：框架而非平台，被集成而非独立运营
- Memobase 作为记忆中间件：验证了「伴侣组件独立化」的可行性

## 反例/边界（≥1个）
- SillyTavern：虽开源但是**前端工具**，不提供人格引擎 — 这是互补关系
- Airi（42k⭐）：虽开源但是**完整应用**（monorepo），定位是终端产品而非中间件
- 引擎 ≠ 应用：引擎应独立于任何具体前端，提供标准 API/MCP 协议接口

## 详细解释
开源伴侣引擎的核心价值：
- **被集成，不被替代**：引擎嵌入 SillyTavern、自定义 App 等，而非代替它们
- **模块化，非 monolithic**：Persona、Memory、Emotion 三个模块可独立使用
- **开源免费，托管收费**：核心库永远开源 + 可选云备份/托管服务收费

商业模式（双轨）：
1. **社区版**：开源免费，本地运行，所有核心功能
2. **云备份/托管版**：记忆加密同步、多设备同步、优先支持 — 订阅付费

为什么是蓝海：
- 所有 5 大竞品全闭源，不提供可集成的伴侣引擎
- 开源项目分两类：前端（SillyTavern）或完整应用（Airi），缺少中间件层
- 记忆层（Memobase 2.8k⭐）和人格层（Shikigami 3⭐）都还很小，引擎层几乎空白

## 细节备注
- MCP 协议接入：作为 Model Context Protocol 服务，任何支持 MCP 的客户端都可调用
- Python 优先策略：降低集成门槛，Python 生态最丰富
- v0.1 不做：前端 UI、模型推理、移动端、硬件 — 专注引擎本身
