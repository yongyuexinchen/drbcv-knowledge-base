# 私有化大模型项目通用部署流程

## 类型判定
[Procedure — 跨项目通用的云服务器选型、环境配置、安全组设置和部署模式选择，是本域所有项目的部署基础]

## 类比 ★
### 一句话比喻
> 私有化大模型部署就像「在国外租一套带厨房的公寓」——服务器就是房子（必须选国外地址，不然 OpenAI 外卖送不到），GPU 是灶台的火力（火越大菜做得越快），Docker 是模块化厨具（不用自己砌灶台），安全组端口是房门上的猫眼（只开需要的口，防黑客闯入）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 云服务器选海外节点 | 租房必须选国外地址——国内地址 OpenAI 不送餐 |
| GPU 机型 (T4/V100/A10) | 灶台火力——T4 是中火，A10 是猛火，CPU 机型是电磁炉（也能做，但只能点外卖 API） |
| CPU + 内存配比 | 厨房大小 + 帮手人数——CPU 多=能同时做好几道菜，内存大=备菜台宽敞 |
| Docker / Docker Compose | 模块化厨具箱——不用自己砌灶台，解压即用 |
| 安全组端口放行 | 房门上的猫眼和门锁——只开 3000/5000/3001 等必要端口 |
| SSH 密钥对 (.pem) | 房门钥匙——丢了就进不去了，必须保管好 |
| API 调用模式 vs 本地模型模式 | 叫外卖 vs 自己做饭——API 是叫 OpenAI 外卖（省心但花钱），本地模型是自己买菜下厨（省钱但要 GPU 灶台） |
| 按量付费 | 短租——用一小时算一小时，测试完就退房 |

## 是什么
私有化大模型项目的部署遵循一套通用流程：选择合适的云服务商（阿里云/腾讯云）和海外节点 → 根据模型调用方式选择标准型（API 调用）或 GPU 机型（本地推理）→ 配置安全组端口 → SSH 密钥登录 → 安装 Docker/Conda 等基础环境 → 克隆项目并启动。核心决策点是「API 还是本地模型」——前者门槛低但需海外节点+API 费用，后者数据安全但需 GPU 硬件。

## 输入-输出空间
- **输入**: 云服务商账号 + 项目 GitHub 地址 + API 密钥（API 模式）或模型文件（本地模式）
- **输出**: 可通过公网 IP:端口 访问的私有化大模型服务
- **前置条件**: 云账号已完成实名认证（支付宝/微信扫码）；了解项目的最低配置要求；SSH 密钥文件已下载到本地

## 正例（≥2 个）
1. **API 模式（轻量项目）**: 阿里云 ECS → 新加坡节点 → 计算型 C7（4 核 8GB）→ 带宽 5Mbps → 海外节点直接调用 OpenAI API → Docker 部署 → 公网 IP:3000 访问。按量付费约 0.6 元/小时，适合测试和轻量使用。
2. **GPU 模式（本地推理）**: 腾讯云 CVM → 首尔节点 → GPU 机型 T4 × 1 → 32 核 188GB 内存 → 120GB 系统盘 → 安装 CUDA 12.2 + 驱动 535 → 下载 ChatGLM3-6B 模型权重 → 本地推理，数据不出境，适合金融/医疗等合规场景。

## 反例/边界（≥1 个）
1. **国内节点 + OpenAI API = 不可用**: 贪便宜选国内节点免费服务器，API 请求被墙——根本原因是 OpenAI 不对中国大陆提供服务。替代方案：要么选海外节点，要么用国内模型（千问/智谱/文心一言）的 API。
2. **标准型机器跑本地模型 = 死机**: 选了 2 核 4GB 的标准型机器却试图加载 ChatGLM3-6B，CPU 无 GPU 无法做推理，即使勉强 CPU 推理也慢到无法使用——本地模型必须用 GPU 机型。
3. **安全组端口忘记放行 = 外部无法访问**: 部署成功后公网 IP 打不开 → 99% 是安全组没放行对应端口。优先级检查顺序：安全组端口 → Docker 容器状态 (`docker ps`) → Nginx 服务重启。

## 详细解释

### 选型决策树
```
需要部署私有化大模型项目
│
├─ 数据安全要求高 / 不能出境？
│   ├─ 是 → 本地模型（GPU 机型）
│   │        ├─ 测试用: T4 × 1, 20+ 核, 80GB+ 内存
│   │        └─ 企业交付: A10 × 1, 32 核, 188GB+ 内存
│   └─ 否 → API 调用（标准型）
│             ├─ 阿里云: 计算型 C7, 新加坡, ~0.6 元/时
│             └─ 腾讯云: 4 核 16GB, 孟买, ~1 元/时
```

### 两朵云对比
| 维度 | 阿里云 | 腾讯云 |
|------|--------|--------|
| 费用 | 稍贵 | 更便宜（尤其孟买节点） |
| 登录方式 | 密钥直接登录 | 需微信扫码一次 |
| GPU 机型 | V100 / A10 / P4 | T4 / V100 / A10 |
| 特殊要求 | 无 | 每开新终端必须 `sudo su` |
| 推荐节点 | 新加坡（稳定） | 孟买（性价比）/ 首尔 |

### 通用部署步骤（以腾讯云为例）
| 步骤 | 命令/操作 | 说明 |
|------|-----------|------|
| 1. 提权 | `sudo su` | 腾讯云必须，每条新终端都要执行 |
| 2. 更新源 | `apt update && apt upgrade -y` | 确保软件包索引最新 |
| 3. 安装 Docker | `apt install docker.io -y` | GPU 机型还需 nvidia-docker |
| 4. 安装 docker-compose | 下载二进制 + `chmod +x` | 下载大小应为 ~56MB |
| 5. 克隆项目 | `git clone <repo_url>` | 部分项目需 git LFS（模型权重） |
| 6. 配置环境 | 编辑 `.env` 文件 | 填入 API 密钥 / 选模型 |
| 7. 启动 | `docker-compose up -d` 或 `python3 run.py` | 按项目文档 |
| 8. 放行端口 | 安全组添加 TCP:<端口> | 常用: 3000/3001/5000/8888 |
| 9. 访问验证 | 浏览器 `http://<公网IP>:<端口>` | 首次登录修改默认密码 |
