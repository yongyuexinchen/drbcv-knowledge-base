# 低代码大模型应用平台

## 类型判定
discriminant — 定义一种企业级 LLM 应用构建范式：通过可视化拖拽编排替代传统编码，让非技术人员也能搭建 AI 应用。本卡片综合了课程中某个具体低代码平台的介绍与 Docker 部署实操。

## 类比 ★
### 一句话比喻
低代码大模型应用平台就像一个 **AI 应用的乐高工厂**——流水线上摆了上百个预制积木模块（数据清洗、文本切分、向量化、提示词编排、知识库、Agent），你不需要写代码焊接电路板，只需拖拽拼接，就能组装出合同审核机、招股书分析器、面试官机器人。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 可视化编排画布 | 乐高底板——拖拽模块代替写代码 |
| 数百种开发组件 | 乐高零件箱——数据清洗/切分/向量化/提示词/Agent 随便挑 |
| 大模型底座可选（千问/ChatGLM/百川） | 选发动机——国产进口都能用，丰俭由人 |
| 应用模板 | 预设菜谱——填几个参数就能出菜 |
| 非结构化数据治理 | 整理杂乱的旧档案——把合同/报告/发票全部分类归档 |
| Docker Compose 多服务部署 | 车间里的多条产线——NGINX（门卫）+ API（引擎）+ 前端（操作台）同时运转 |
| 安全组端口放行 | 给工厂开门——不开门（端口）外面的人进不来 |

## 是什么
低代码大模型应用平台是一类让企业通过**可视化编排**而非手写代码来构建 AI 应用的工具。核心思路是把大模型能力（推理、检索、生成）封装成可拖拽的积木模块，业务人员通过填写表单 + 连线组合就能搭建智能应用，开发人员则可以用高级编排实现更复杂的逻辑。

这类平台通常具备三个核心特征：
1. **低门槛**：预置应用模板 + 表单填写，不懂模型底层也能用
2. **高灵活**：数百种组件自由编排，不限于简单的提示词工程
3. **企业级**：支持高并发、非结构化数据治理、持续迭代优化

## 正例（≥2 个）
1. **招股书分析报告**：上传招股说明书 PDF → 拖拽「数据清洗→要素提取→报告生成」三个模块 → 自动输出结构化分析报告，含财务数据摘要、风险评估、行业对比。
2. **规章制度知识库问答**：将 HR 手册、财务制度、IT 安全规范分别导入三个知识库 → 创建知识库问答应用 → 员工用自然语言问"产假多少天"，系统自动定位到 HR 知识库精准回答并标注出处。
3. **合同要素提取**：上传批量合同扫描件 → 配置「要素提取」模块 → 自动抽取出甲方/乙方/金额/签约日期等关键字段，输出结构化 Excel。

## 反例/边界（≥1 个）
1. **不是简单的提示词套壳**：如果只是在前端写死一段 system prompt 然后调 API，那不算低代码平台——真正的低代码平台有可视化编排画布和数百个可组合的功能模块。
2. **不是模型训练工具**：低代码平台操作的是**已训练好的模型**，它解决的是"怎么用模型搭应用"，而非"怎么训练模型"。微调、精调、二次预训练不在其核心能力范围内。
3. **配置不够会死机**：这类平台对服务器要求较高（通常需要 GPU + 32GB+ 内存），配置太低模型加载时可能直接死机。生产环境建议 T4 起步、内存 80GB 以上。
4. **首次登录报错不等于部署失败**：Docker 多服务启动后，后端服务可能需要额外时间就绪，若首次登录报红色错误框，进容器重启 backend 服务通常能解决。

## 详细解释

### 四大核心应用场景
| 场景 | 说明 | 典型例子 |
|------|------|---------|
| 分析报告生成 | 输入文档 → 自动生成结构化报告 | 合同审核、信贷调查、招股书分析、投研报告 |
| 知识库问答 | 导入领域文档 → 自然语言问答 | 用户手册、药典查询、规章制度、研报问答 |
| 日常 Chat | 大模型对话 + 角色扮演 | 面试官模拟、文案助手、简历优化、外交对话 |
| 要素提取 | 从非结构化文档抽取结构化字段 | 工程报告要素、卡证票据 OCR、元数据提取 |

### 典型部署流程（Docker + 腾讯云）
| 步骤 | 操作 | 关键检查点 |
|------|------|-----------|
| 1. 提权 | `sudo su` 切换到 root | 腾讯云**每开一个新终端都要重新 sudo su** |
| 2. 安装 Docker | `apt update` → 导入 GPG key → `apt install docker` | `docker --version` 验证 |
| 3. 安装 docker-compose | 下载二进制 → `chmod +x` | **必须是 56MB 左右**，KB 级别说明下载失败 |
| 4. 安装 Git | `apt install git` | 用于克隆项目仓库 |
| 5. 克隆项目 | `git clone <仓库地址>` → `cd <项目目录>` | — |
| 6. 启动服务 | `docker-compose up -d` | 看到 **5 个服务全部 running** 才算成功 |
| 7. 安全组放行 | 控制台 → 安全组 → 添加规则 | TCP:3001，来源 0.0.0.0/0，**冒号必须英文小写** |
| 8. 登录验证 | `http://公网IP:3001` | 默认账号 ADMIN / 密码 1234，**首次登录后立即改密码** |

### 常见排错
| 现象 | 原因 | 解决 |
|------|------|------|
| 公网 IP:3001 打不开 | 安全组未放行 3001 端口 | 添加 TCP:3001 规则，刷新页面 |
| 安全组放行后仍打不开 | Docker 服务未完全启动 | 新终端 `sudo su` → 进项目目录 → `docker-compose restart` |
| 登录弹出红色错误框 | backend 服务未就绪 | 进容器 → 重启 backend 服务 → 刷新登录页 |

### 平台选型对比
| 维度 | 低代码 LLM 平台 | 传统后端开发 | 简单提示词工程 |
|------|-----------------|-------------|---------------|
| 开发方式 | 拖拽编排 | 手写 Python/JS | 写一段 system prompt |
| 模型切换 | 千问/ChatGLM/百川自由换 | 硬编码 API | 固定一个模型 |
| 应用场景 | 分析报告/知识库/Agent/提取 | 取决于开发能力 | 仅对话 |
| 数据治理 | 内置非结构化数据治理 | 需另行开发 | 无 |
| 灵活性 | 数百组件自由组合 | 代码写死后难改 | 极低 |
