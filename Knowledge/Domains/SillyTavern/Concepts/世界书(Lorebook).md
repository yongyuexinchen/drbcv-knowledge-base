# ⬜ 世界书(Lorebook)

## 类型判定
**连接型** — 回答「它如何影响其他东西？」——推测/预测

## 是什么
AI的世界背景知识库，按需检索

## 输入-输出空间
- **输入**: 对话中触发的关键词
- **输出**: 对应的世界背景信息
- **映射关系**: 关键词→世界条目（按需检索）

## 正例
1. **场景A**: 对话提到"王都"→检索到"赛博朋克首都，AI女王统治，常年下雨"→AI融入"雨中的王都霓虹闪烁..."
2. **场景B**: 提到"魔法"但世界书无此条目→AI不会主动创造魔法体系。世界书决定AI"知道"什么。

## 反例/边界
1. **常见误解**: 不是"一次性全塞进去的背景故事"——是按需检索。全塞会撑爆上下文。
2. **边界**: 关键词匹配不准→该触发的不触发，不该触发的乱触发。

## 详细解释
世界书（Lorebook/World Book）是AI角色扮演中的背景知识库。不同于把整个世界观一次性塞进prompt（会撑爆上下文窗口），世界书通过关键词触发机制按需检索——只有对话提到"王都"时，才把王都的设定注入上下文。这让AI既能"知道"大量世界细节，又不会浪费上下文空间。


## 细节备注

### 词条三要素
| 元素 | 说明 |
|------|------|
| **触发关键词** | 决定何时激活（已独立为概念卡） |
| **词条内容** | 3-5句话，只说核心信息。铁律：少即是多 |
| **插入位置** | 控制内容注入到上下文的哪个层级（角色定义前/近对话前等），影响AI对信息的重视程度 |

### 高级特性（进阶）
| 特性 | 说明 |
|------|------|
| **正则匹配** | 支持模糊关键词匹配，一行正则匹配几十种表达 |
| **选择性过滤** | 控制不同世界书在不同场景的激活状态 |
| **多世界书叠加** | 不同角色卡搭配不同世界书，灵活切换世界观 |
| **常量与变量** | 动态值替换，世界书内容随状态实时变化 |

### 设计哲学
- 世界书 ≠ 设定集。只放"AI当下需要知道的关键信息"
- 长设定放 Obsidian/Notion，世界书只放"小抄"
- 好的角色卡作者往往也是世界书作者——两者共同编织完整世界
- 先拆解学习优质作者的世界书，再动手修改，最后才独立创作
