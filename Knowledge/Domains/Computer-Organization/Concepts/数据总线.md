# 数据总线

## 类型判定
判别型 — 回答"数据总线是什么、宽度如何决定、为什么是双向、与地址/控制总线什么关系"，属于系统互连类概念。与 [[总线概述]]（总线总纲）是"整体-部分"关系。

## 类比 ★
**一句话比喻：** 一条双向多车道货运路——CPU、主存、硬盘这些部件都靠它运"货"（实际数据），路多宽决定一次能并排运几箱货（总线宽度），路双向通行（可读可写），但任何时刻只能有一辆车在路上开（分时）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 数据总线双向 | 双向六车道——货既能从仓库运到工厂，也能从工厂运回仓库 |
| 数据总线宽度=机器字长 | 车道数 = 卡车的车厢数——车厢数和"一次运一个完整货物"匹配，就不用分两趟 |
| 数据总线 vs 地址总线 | 货运路（运实际货物）vs 导航信号（告诉目的地）——货物走货运路，导航走另一条路 |
| 数据总线宽度<存储字长 | 货运车太小，一个完整货物要分两次运（读一个字要传两组数据） |
| 多根信号线组成一根总线 | 一条"路"其实是并排的多个车道，每根线=一个车道 |

## 是什么
数据总线（Data Bus，DB）是系统总线的一种，用于**在各功能部件之间传递实际的数据信息**——包括从主存取指令、取操作数、写回结果。关键特性：

1. **双向**：数据可以从 CPU→主存（写），也可以主存→CPU（读）——与地址总线（CPU→设备单向）不同
2. **宽度决定并行度**：数据总线包含多根信号线，N 根线=一次并行传 N bit。宽度通常与**机器字长/存储字长**一致——这样一次主存读/写就能传完一个存储字；若宽度只有存储字长一半，取一个字要分两次传
3. **分时共享**：同一时刻只允许一个部件在总线上发送数据（否则信号冲突），多个部件共享同一组线
4. **物理介质**：数据总线是承载数据流动的**物理媒介**，区别于"数据通路"（数据流经路径的逻辑描述）

## 输入-输出空间
- **输入**：发送方（如 CPU 或主存）把高低电平加到数据总线的各信号线上
- **输出**：所有挂在总线上的部件都能检测到这些信号，但只有被地址总线选中的部件才响应
- **前提条件**：发送方需先获得总线控制权（仲裁），且地址总线已给出目标地址

## 正例（≥2 个）
1. **CPU 读主存**：CPU 经地址总线送出目标地址 → 主存被选中 → 主存把存储单元的内容放到数据总线 → CPU 从数据总线接收。整个过程数据总线是"主存→CPU"方向（读）。
2. **CPU 写主存**：CPU 把数据放到数据总线 → 主存从数据总线取走 → 写入对应单元。方向是"CPU→主存"（写）——同一条数据总线，两个方向都能走（双向）。
3. **宽度=字长的设计**：机器字长 32 bit → 数据总线做 32 根线 → 一次传 32 bit = 一个存储字 → 读一个字只需一次总线操作；若只有 16 根线，读 32 位字要分两次（性能减半）。

## 反例/边界（≥1 个）
1. **"数据总线只传数据"不准确**：它传的是"实际数据信息"，包括指令和操作数——指令在取指阶段也走数据总线（从主存取指令码）。它和地址总线的分工是"内容 vs 位置"，不是"数据 vs 指令"。
2. **数据总线 ≠ 数据通路**：数据通路是逻辑层面的"数据流经路径"描述（如单总线结构/专用通路结构的抽象）；数据总线是物理层面的导线集合。同一个数据通路概念下可以有具体的总线实现。
3. **"总线宽度 = 数据线+地址线+控制线之和"不严谨**：通常说"总线宽度 32 bit"特指**数据总线宽度**（并行传数据的位数），不包含地址线/控制线。

## 详细解释
### 为什么是多根线？
一根"数据总线"内部由多根信号线组成（如 4 根、32 根、64 根）。要并行传 N bit，就放 N 根线，每根线传 1 bit。决定宽度的核心需求：**与存储字长匹配**——保证一次访存传一个字。

### 为什么必须分时？
若两个部件同时往同一条信号线上发不同电平（如 CPU 发 0、SSD 发 1），信号冲突、接收方无法判断。所以任何时刻只能有一个发送方，由总线仲裁决定谁先用。

### 三种系统总线对比
| 总线 | 传输内容 | 方向 | 宽度决定因素 |
|------|---------|------|-------------|
| 数据总线 DB | 实际数据（指令/操作数） | 双向 | 机器字长/存储字长 |
| 地址总线 AB | 存储单元地址 | 单向（CPU→设备） | 主存地址空间（MAR 位数） |
| 控制总线 CB | 读写控制命令 | 逐根单向（整体双向） | 控制信号种类 |
