# 程序查询方式

## 类型判定
程序型 — 描述 CPU 通过轮询检查 IO 状态寄存器来控制数据传送的完整流程及两种变体（独占/定时），属于"过程"类概念。

## 类比 ★
**一句话比喻：** 像在微波炉前盯着转盘死等——CPU 启动外设后就一直反复问"好了没好了没"，外设没好它就原地踏步什么也不干，直到"叮"一声才取走数据。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| CPU 轮询状态寄存器 | 不停掀开微波炉门看热好了没 |
| IO 设备就绪信号（ready） | 微波炉"叮"一声 |
| 独占查询 | 全程盯着微波炉什么也不干 |
| 定时查询 | 设个闹钟每隔一会儿看一眼，中间去刷手机 |

## 是什么
**程序查询方式**是 CPU 通过反复执行 `in` 类 IO 指令轮询 IO 接口状态寄存器，等待外设就绪后再用 `out` 类 IO 指令完成一次数据传送的 IO 控制方式。CPU 在启动外设后不断检查状态，直到外设 ready 才取走/写入一个字，传送完修改计数值，若还有数据未传完则回到轮询循环。整个过程 CPU 和外设**串行工作**，CPU 有大量时间消耗在"踏步等待"上。

## 输入-输出空间
- **输入**：IO 端口地址（状态寄存器 N+1、数据寄存器 N）+ CPU 通用寄存器中的命令字/数据
- **输出**：命令字写入 IO 端口启动外设；数据从数据缓冲寄存器取走（输入）或写入（输出）
- **前置条件**：CPU 已通过地址线/控制线/数据线指定目标 IO 端口；外设初始状态为未就绪

## 正例（≥2 个）
1. **打印三个字符 ABC**：CPU 用 `out` 发启动命令 → 轮询 `in` N+1 端口等 ready → `out` 写入 A 到数据寄存器 N → 打印机打印 A 时又忙，CPU 轮询等 → 再送 B → 再送 C → `out` 发停机命令。全程 CPU 一直在轮询，不能干别的。
2. **鼠标定时查询**：CPU 每秒查询鼠标 30 次，每次 2000 ns，时间开销仅 0.006%——对慢速设备，定时查询几乎不影响 CPU 性能。

## 反例/边界（≥1 个）
1. **硬盘高速传输崩溃**：硬盘每 32 位需查询一次，为达目标传输率每秒需查 2^19 次，每次 2000 ns，总时间占比 105%——即便 CPU 把所有时间都花在查询上也完不成任务。所以程序查询只适合慢速 IO，高速设备必须换方案。
2. **"CPU 只能死等"是误区**：独占查询确实死等，但定时查询允许 CPU 在两次轮询之间干其他事——只是要保证查询间隔足够短，不至于丢失外设数据（如鼠标连续双击，第一次点击信息可能在第二次查询前被覆盖）。

## 详细解释
### 流程（独占查询）
1. **预置传送参数**：设置计数器记录剩余待传字符数（如 I=3）
2. **启动外设**：`out` 命令字 → N+1 端口，IO 接口逻辑电路发出启动信号给外设
3. **轮询检查**：`in` 读取 N+1 状态寄存器 → 检查 ready 位 → 未就绪则回到步骤 3 死循环
4. **传送一次数据**：`out`（输出）或 `in`（输入）操作数据寄存器 N → 一个字传送完成
5. **修改传送参数**：计数器减 1；若计数器 ≠ 0 回到步骤 3
6. **结束**：发停机命令字给外设

### 两种变体
- **独占查询**：CPU 启动 IO 后 100% 时间轮询，直到传送全部完成——图里经典的"踏步"循环
- **定时查询**：CPU 隔固定时间查一次，查到未就绪就切去干别的事，下次定时到了再查——需保证查询频率 ≥ 外设数据到达频率，否则数据丢失

### 例题计算套路
时钟频率 50 MHz → 每时钟 20 ns。每次查询需 100 时钟周期 = 2000 ns。每秒查询 N 次 → 时间占比 = N × 2000 ns / 1s。

## 关系
### → 指向
- [[程序中断方式]] (解决了程序查询方式的"踏步等待"问题，让 CPU 和外设并行工作)
- [[DMA方式]] (进一步解放 CPU，整块数据由 DMA 控制器搬运，CPU 只做预处理和后处理)
### ← 被指向
- [[IO控制方式]] (程序查询是三种 IO 控制方式中最简单、效率最低的一种)
- [[IO接口]] (程序查询依赖 IO 接口中的状态寄存器和数据缓冲寄存器)

## 备注
- 核心缺点口诀：**串行踏步，CPU 空转**——CPU 和外设串行工作，大量时间在轮询等待
- 考点：独占查询 vs 定时查询的区别；慢速设备用定时查询 OK，高速设备绝对不行
- 408 计算题常考：给时钟频率和每次查询时钟数，算特定外设的 CPU 时间占比——先算单次查询耗时，再乘以每秒查询次数
- 易混淆：这里的 `in`/`out` 是 x86 的 IO 指令（访问 IO 端口），不是 C 语言的输入输出函数
