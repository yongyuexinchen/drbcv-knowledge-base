# 跳转指令

## 类型判定
判别型 — 定义改变程序执行流的转移类指令（JMP/CALL），判别无条件/条件跳转与直接/相对/间接三种跳转寻址方式——属于"指令系统"类概念。

## 类比 ★
**一句话比喻：** 总裁府邸里，PC 总管按流程单顺序翻页办单；**跳转指令**就是总裁夫人改口："直接办 7 号单！"（无条件跳转，PC 被覆盖成 7）或"如果收到加急件就去 7 号单，否则按流程走"（条件跳转，标志位=是否收到加急件）。改口的方式有三种：**"去第 7 页"**（直接/绝对）、**"往后翻 3 页"**（相对，从当前看的那页起算）、**"看便签上写的页码"**（间接，目标藏在寄存器/柜子里）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 无条件跳转 JMP（PC 强制改为目标地址） | 总裁改口："直接办 7 号单！"——流程单翻到第 7 页 |
| 条件跳转（标志位满足才跳，否则顺序） | "如果收到加急件就去 7 号单，否则按流程走" |
| 相对跳转（PC+偏移量，偏移相对下一条指令） | "往后翻 3 页"——从**当前看的那页（下一条）**起算，不是从刚办完的这页 |

## 是什么
**跳转指令**是改变程序执行流的转移类指令（无条件 JMP、条件转移、CALL 等）：执行时**强制修改 PC 为目标地址**，程序不再顺序执行。与顺序寻址对比：普通指令让 PC 自动 + 指令字长；跳转指令让 PC **覆盖**为目标地址（52 号课：JMP 就像 C 语言的 goto）。

三种维度：
- **无条件 vs 条件**：无条件必跳；条件跳转由**标志位**（ZF/CF/SF/OF 等）决定——条件满足才跳，否则顺序执行下一条
- **三种跳转寻址**：**直接跳转**（目标地址写在指令里，绝对地址）、**相对跳转**（指令只给偏移量，目标 = PC + 偏移）、**间接跳转**（目标地址在寄存器或内存单元里）
- **跳转 vs 调用**：JMP 不保存返回地址；CALL 要把返回地址**压栈**（RET 再弹回）——调用是"去办事还要回来"，跳转是"一去不回"

**相对跳转的偏移计算（408 必考）**：目标地址 = PC 当前值 + 偏移量。注意 x86 中取指后 PC 已指向**下一条指令**——偏移量相对的是**下一条指令**，不是当前指令。

## 正例（≥2 个）
1. **JMP 7（52 号课原例）**：执行地址 3 处的 JMP 7 → CPU 先取指（PC 从 3 变 4），执行时发现是无条件转移 → PC 被**强制改为 7** → 下一条执行地址 7 的指令（而不是 4）——这就是"覆盖而非偏移"。
2. **条件跳转 JE（相等则跳）**：比较两条数据后，ZF=1（相等）→ 跳转；ZF=0 → **顺序执行**下一条。C 语言的 if/else 在机器级就是条件跳转（59 号课选择语句）。
3. **相对跳转计算**：当前指令地址 100，指令长 2 字节，指令中偏移量 +6 → x86 中目标 = (100+2) + 6 = **108**（先取指 PC 变 102，再加偏移）。

## 反例/边界（≥1 个）
1. **"跳转后 PC 还会自动加一"是错的**：跳转指令的取指阶段 PC 照常 +1，但**执行阶段 PC 被覆盖为目标地址**——最终 PC = 目标地址，绝不在目标上再偏移（52 号课：覆盖而非偏移）。
2. **"相对跳转的偏移相对当前指令"是错的（x86 陷阱）**：偏移量相对**下一条指令**（取指后 PC 已更新）——算目标地址先 + 指令长度再 + 偏移，顺序不能错。
3. **"条件跳转一定会跳"是错的**：条件不满足就**顺序执行**（这就是 if 不带 else 时"不满足就跳过"的机器级实现）。
4. **"JMP 和 CALL 一样"是错的**：JMP 一去不回（不保存返回地址）；CALL 要**压栈返回地址**、RET 弹回——调用是过程调用，跳转是执行流转移。

## 详细解释
### 跳转指令执行时序
```
取指：PC ← PC + 指令字长（照常，先指向下一条）
执行：判断条件（无条件直接跳 / 标志位判断）
     ├─ 满足 → PC ← 目标地址（覆盖）
     └─ 不满足 → PC 保持（顺序执行下一条）
```

### 三种跳转寻址方式
| 方式 | 目标地址怎么来 | 优点/场景 | 类比 |
|------|--------------|----------|------|
| 直接（绝对） | 指令中直接给出 | 简单直接 | "去第 7 页" |
| 相对 | PC + 偏移量 | 程序浮动（代码搬家不用改） | "往后翻 3 页" |
| 间接 | 寄存器/内存里存的目标 | 灵活（动态跳转表） | "看便签上写的页码" |

### 相对跳转为什么用得多
- 偏移量是**带符号数**（可正可负，往前跳也能往后跳）
- 程序整体移动（重定位）时，相对偏移**不变**——代码块搬家不用重算目标地址；绝对地址跳转搬家就全废了

### 控制冒险（衔接流水线）
- 流水线会**预取**后续指令；跳转改变执行流后，已预取/译码的指令**全部作废**（冲刷流水线）
- 跳转指令之后的几条指令白白占用了流水线节拍——**分支预测**就是为降低这个代价（超标量章节）

## 备注
- **408 考点 — 相对寻址计算**：目标 = (PC + 指令长度) + 偏移量——x86 偏移相对**下一条**指令，先加后偏移
- **408 考点 — 无条件/条件判别**：条件转移看标志位（ZF/CF/SF/OF）；无条件必跳
- **408 考点 — JMP vs CALL**：跳转不保存返回地址，调用压栈返回地址
- **C 语言对应**：goto → JMP；if/else/循环 → 条件跳转；函数调用 → CALL/RET
- **记忆口诀**：总裁改口（跳转覆盖 PC）、加急件判断（条件跳转）、翻几页（相对偏移从下一条起算）
