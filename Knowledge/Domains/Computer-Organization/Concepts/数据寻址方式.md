# 数据寻址方式

## 类型判定
判别型 — 描述指令中形式地址 A 如何映射为有效地址 EA 的十种规则，涵盖六种基本寻址、三种偏移寻址和堆栈寻址，属于"映射规则"类概念。

## 类比 ★
**一句话比喻：** 总裁夫人（CU）签发取货单，IR 跑腿小哥按单取货——十种寻址方式就是十种取货单写法：有的把货直接塞在单子上（立即寻址），有的写死门牌号（直接寻址），有的写"先去前台查货在几号格"（间接寻址），有的说"从仓库起点排往东走 3 排"（偏移寻址），还有一张专柜取货券（堆栈寻址）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 形式地址 A（指令中的地址码） | 取货单上写的货物提示（写死门牌/写转查提示/写相对位置） |
| 有效地址 EA（真实存放位置） | 货实际所在的仓库格号——跑腿小哥最终要去的格 |
| 寻址特征位（CPU 怎么解读 A） | 取货单右上角的便签："这是写死的地址/要转查的地址/相对位置" |

## 是什么
**数据寻址**是 CPU 根据指令中给出的形式地址 A，配合寻址特征位，计算出操作数真实存放地址（有效地址 EA）的机制。同一条指令的 A，在不同寻址方式下被完全不同的规则解读。十种数据寻址方式分三大类：**六种基本寻址**（直接/间接/寄存器/寄存器间接/隐含/立即）、**三种偏移寻址**（基址/变址/相对）、**一种堆栈寻址**。偏移寻址共同公式：`EA = 基地址 + A`，区别仅在"基地址"是谁（BR / IX / PC）。

## 输入-输出空间
- **输入**：形式地址 A + 寻址特征位
- **输出**：有效地址 EA（操作数的真实主存地址）或操作数本身（立即寻址）
- **关键变量**：BR（基址寄存器）、IX（变址寄存器）、PC（程序计数器）、SP（堆栈指针）

## 正例（≥2 个）
1. **直接寻址→立即取数**：指令 `LDA 5`，寻址特征=直接，A=5。EA=A=5，跑腿小哥直接去仓库 5 号格取货。执行期访存 1 次（取指令那次另算）。简单但灵活性差——货搬家就得改取货单。
2. **基址寻址→程序浮动**：程序从主存 100 开始存放（BR=100），指令 `ADD 5` 采用基址寻址。EA = BR + A = 100+5 = 105。操作系统把程序搬到 200 处时只需改 BR=200，取货单一个字不用改——多道程序并发的基石。
3. **变址寻址→循环遍历数组**：数组 A[0..9] 首址 7，IX 初始 0。`ADD 7(IX)`：EA = A + IX。每轮 IX++，依次访问 A[0]=7, A[1]=8, …, A[9]=16——一条取货单指令跑完十轮，跑腿小哥每轮往东挪一格。

## 反例/边界（≥1 个）
1. **"PC 相对寻址基于当前指令地址"是错的**：CPU 取完当前指令后 PC 已自动递增 → 相对寻址的基地址是**下一条指令地址**，不是当前指令地址。王道书此处理有歧义，408 以"下一条指令地址"为准。
2. **基址 vs 变址 ≠ 只有寄存器不同**：基址寻址中 A 是偏移量、BR 是基地址，BR 由操作系统管（用户不可改）；变址寻址中 A 是基地址、IX 是偏移量，IX 面向用户（程序员可改）。角色恰好互换！
3. **立即寻址没有"取货"过程**：A 就是货本身（立即数），不存在"地址→数据"映射——跑腿小哥不用出府，执行期访存 0 次（取指令那次仍算）。
4. **间接寻址扩大寻址范围但拖慢速度**：A 只有 16 位（寻址范围 64K），但 A 指向的单元里存了 32 位地址 → 范围扩到 4G。代价：每次间接寻址多 1 次访存（一次间接=2 次，二次间接=3 次）。

## 详细解释
### 十种寻址方式对比总表（取货单写法全集）
| 寻址方式 | 有效地址 EA | 执行期访存 | 取货单写法（比喻） | 核心用途 |
|---------|------------|-----------|------------------|---------|
| 直接寻址 | EA = A | 1 | 写死门牌号 | 简单直接，范围受 A 位数限制 |
| 间接寻址 | EA = (A) | ≥1 | "先去前台查货在几号格" | 扩大寻址范围，多级指针 |
| 寄存器寻址 | 数据在 Ri 中 | 0 | 货就在府内临时仓库 ACC | 最快，寄存器有限 |
| 寄存器间接 | EA = (Ri) | 1 | 临时仓库里存着地址条 | 比主存间接少一次访存 |
| 隐含寻址 | 隐含在 ACC 等 | 0 | 约定俗成"默认放 ACC" | 缩短指令字长 |
| 立即寻址 | 操作数 = A | 0 | 货直接塞在取货单上 | 最快，立即数范围受限 |
| **基址寻址** | EA = (BR) + A | 1 | "从仓库起点 B 区往东走 3 排" | 程序整体浮动（BR 由 OS 管） |
| **变址寻址** | EA = A + (IX) | 1 | "从 5 号排开始每轮往后挪 1 排" | 循环/数组遍历（IX 程序员改） |
| **相对寻址** | EA = (PC) + A | 1 | "从我这单往后数 3 单" | 代码段内部浮动（转移指令） |
| 堆栈寻址 | EA = (SP) | 0（硬）或 1（软） | 后进先出专柜，只取最上面那格 | 函数调用、中断现场保存 |

> 访存次数**不含取指令**那一次；三种偏移寻址执行期访存均 1 次，区别在"基地址是谁"。

### 偏移寻址核心公式与区别
```
EA = 基地址 + 形式地址 A（A 可正可负，补码表示）

基址寻址：基地址 = BR（程序起始存放地址），A = 偏移量 → "程序能在主存任何位置跑"
变址寻址：基地址 = A（数组首地址），偏移量 = IX → "一条指令遍历整个数组"
相对寻址：基地址 = PC（下一条指令地址），A = 偏移量 → "代码挪位置不用改跳转"
```

### 堆栈寻址（两种实现）
- **硬堆栈**（寄存器组）：SP 指向栈顶，push/pop 不访存，最快最贵
- **软堆栈**（主存划区）：push/pop 各需 1 次访存（先改 SP，再读写主存），成本低
- **入栈**：SP 先减/加（看栈增长方向）→ 新元素写入 SP 新指向的位置
- **出栈**：先读 SP 指向的元素 → SP 再加/减（逻辑删除）

## 备注
- **408 大题最高频考点**——几乎每年必有一题：给指令格式，判断各地址码的寻址方式
- 基址 vs 变址一句话：BR 面向 OS（不改指令让程序搬家），IX 面向用户（不改指令遍历数组）
- 相对寻址的 EA = (PC) + A，"PC"是取指后已递增的值——做题先看"当前指令地址"还是"下一条指令地址"
- 堆栈方向：SP 加还是减，取决于题目规定的"栈向低地址增长"还是"向高地址增长"
