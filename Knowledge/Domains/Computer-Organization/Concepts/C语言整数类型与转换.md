# C语言整数类型与转换

## 类型判定
混合型 — 既定义C语言中有符号/无符号整数类型的存储规则，又说明类型转换（等长、长→短、短→长）的底层机制，兼有概念定义和操作过程。

## 类比 ★
**一句话比喻：** 像快递打包——同一个箱子（机器码不变），快递单上写"易碎品"（signed）还是"普通件"（unsigned），拆箱方式完全不同；长箱子截短就是"暴力锯断只留底部"（高位截断），短箱子加长分两种：加泡沫（零扩展，无符号数）还是加同款填充物（符号扩展，有符号数）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 同一补码解释为有符号/无符号 | 同一箱物品，标"易碎品"开箱小心拆，标"普通件"直接倒出来 |
| 长数据截断为短数据 | 长木板锯断只留要的那段，锯掉的部分永久丢失 |
| 符号扩展（高位补符号位） | 用和原作一模一样的材质加长桌子——负数用黑色板材（补1），正数用白色板材（补0） |
| 零扩展（高位补0） | 短桌子加长时全用白色板材（补0），不管原来什么颜色 |

## 是什么
C语言中整数用**补码存储**（signed: short/int/long）或**无符号数存储**（unsigned修饰）。强制类型转换分三种情况：①**等长转换**（如 short→unsigned short）：机器码原封不动复制，只改变解释方式（补码→无符号数）；②**长→短**（如 int→short）：高位直接截断，仅保留低位字节；③**短→长**（如 short→int）：无符号数用**零扩展**（高位补0），有符号数用**符号扩展**（高位补符号位），保证真值不变。

## 输入-输出空间
- **输入**：源类型的二进制机器码 + 源类型（有/无符号、长度）+ 目标类型
- **输出**：目标类型的二进制机器码（或对应的真值）
- **前置条件**：明确各类型所占字节数（short=2B，int=4B，char=1B）和是否 unsigned

## 正例（≥2 个）
1. **等长转换（short→unsigned short）**：short x = -4321，16位补码 = 1110 1111 0001 1111；强转 unsigned short y，机器码不变，按无符号数解析 = 61215
2. **长→短截断（int→short）**：int a = -9115，32位补码 = 0xFFFFDC45；强转 short c，仅保留低16位 0xDC45，作为16位补码解析 = -9115（刚好未溢出）
3. **短→长符号扩展（short→int）**：short x = -4321（16位补码=1110 1111 0001 1111）；转为 int 时高位补满符号位1 → 32位补码 = 1111 1111 1111 1111 1110 1111 0001 1111，真值仍为 -4321
4. **无符号数零扩展（unsigned short→unsigned int）**：unsigned short n = 61215（16位无符号）；转为 unsigned int p，高位全部补0，真值不变为 61215

## 反例/边界（≥1 个）
1. **长→短可能丢失数据**：若 int 值超出 short 范围（如 int=70000），截断后低16位可能表示完全不同的数——高位数据永久丢失，不可逆。
2. **负数符号扩展补错位**：若把16位负数补码的高位补0（零扩展）而非补1（符号扩展），真值会从一个负小数变成一个巨大的正数，结果错误。例如 -90 的8位补码=10100110，零扩展到16位=0000000010100110 → 解析为巨大正数（错误）。
3. **等长转换可能得到"异常大"的值**：short -1 → unsigned short = 65535（16位全1），因为 -1 的补码是全1，按无符号解析就是最大值。

## 详细解释
**三种转换的底层规则对比：**

| 转换类型 | 条件 | 规则 | 数据可能变否 | 示例 |
|---------|------|------|------------|------|
| 等长有符号↔无符号 | 长度相同 | 机器码原封不动，改变解释方式 | 二进制不变，真值可能变 | short -1 → unsigned short 65535 |
| 长数据→短数据 | 源更长 | 高位截断，仅保留低位 | 可能丢失数据（溢出） | int 32位→short 16位，高16位抛弃 |
| 短数据→长数据（无符号） | 无符号数 | 零扩展：高位全部补0 | 真值不变 | unsigned short 99 → unsigned int 99 |
| 短数据→长数据（有符号） | 补码 | 符号扩展：高位补满符号位 | 真值不变 | short -4321 → int -4321 |

**零扩展与符号扩展的硬件原因**：寄存器与ALU的位数（机器字长）是固定的（如32位），但主存中数据长度各异（char 8位、short 16位、int 32位）。运算前需把短数据装入寄存器并扩展到与ALU相同的位宽。零扩展适用无符号数（高位补0不改变值），符号扩展适用补码（高位补符号位保证补码真值不变——多出来的高位拷贝符号位不会改变补码的数学值）。

**C语言整数类型速查：**

| 类型 | 典型字节数 | 编码方式 |
|------|----------|---------|
| char | 1 | 补码（有符号） |
| short / unsigned short | 2 | 补码 / 无符号 |
| int / unsigned int | 4 | 补码 / 无符号 |
| long / unsigned long | 4或8 | 补码 / 无符号 |

## 备注
- 等长转换口诀："机器码不动，解释方式换"——short 和 unsigned short 在寄存器里是完全相同的二进制串
- 符号扩展正确性：负数的补码高位全补1，相当于在真值上加0（模运算下全1的高位不影响低N位的值），见补码数学原理
- signed 和 unsigned 混算（如 int + unsigned int）时，C语言会隐式将 signed 转为 unsigned 再计算，可能导致意料之外的"正数+负数=正数"
- 截断是"不可逆操作"——int截成short后，无法从short恢复原int的高16位数据
