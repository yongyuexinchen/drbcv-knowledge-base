# Cache 和主存的映射方式

## 类型判定
混合型 — 既定义三种映射方式（全相联/直接/组相联）是什么，又对比它们的优缺点和适用场景，兼有定义与关系。

## 类比 ★
**一句话比喻：** 像火车站存包柜——全相联是"任意空柜都能放"（灵活但每个柜子都要贴大标签找半天），直接映射是"按身份证尾号固定柜号"（省事但人一多就撞柜），组相联是"按尾号分到一组柜子里随便放"（折中方案）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 全相联映射 | 自由停车场，任意空位可停，但找车要全场扫一遍 |
| 直接映射 | 固定车位（车牌尾号对号入座），冲突就得赶走别人 |
| 组相联映射 | 按片区划分的车位，尾号决定片区，片区内随便停 |

## 是什么
Cache 保存的是主存数据块的副本，必须确定「哪个主存块能放在哪个 Cache 块」的规则，这就是映射方式。三种方式：
- **全相联映射**：主存块可放入任意 Cache 块，最灵活，但比较所有 Cache 块的标记（慢、硬件贵）。
- **直接映射**：主存块号对 Cache 总块数取余，余数即唯一存放位置，最简单，但冲突率高（多个主存块争一个 Cache 块，频繁换入换出）。
- **组相联映射**：Cache 分组，主存块号对组数取余决定放哪组，组内任意空块可放——前两者的折中（如 2 路组相联 = 每组 2 块）。

## 输入-输出空间
- **输入**：CPU 要访问的主存地址（主存块号 + 块内地址）
- **输出**：命中 → Cache 中数据；未命中 → 访问主存并调入对应块
- **前置条件**：主存块大小 = Cache 块大小；每个 Cache 块配标记（主存块号）+ 有效位（1 有效 / 0 无效）

## 正例（≥2 个）
1. **直接映射定位**：Cache 共 8 块，主存 1 号块 → 1%8=1 只能放 1 号 Cache 块；9 号块 → 9%8=1 也只能放 1 号块，冲突时覆盖旧数据。
2. **全相联访问**：Cache 8 行、每行 64B、主存 256MB（28 位地址）：前 22 位是主存块号作标记，后 6 位是块内地址。访问时把块号与每行标记比对，标记匹配且有效位=1 → 命中。

## 反例/边界（≥1 个）
1. **"只有标记就够了"是错的**：硬件二进制位只有 0/1，没有"空"状态——空闲 Cache 块标记初始全 0，若不配有效位，会把"空块"误判为"0 号主存块的副本"。必须有有效位区分。
2. **直接映射的致命缺点**：Cache 明明有空闲块却用不了（主存块只能去固定位置），空间利用率差——这正是组相联存在的理由。
3. **术语陷阱**：组相联的"组内路数"（如 2 路组相联）用块数描述，做题时先算清 Cache 总块数和组数再取余。

## 详细解释
**三种映射的核心参数对比**（以 Cache 8 块、主存块号 22 位为例）：

| 映射方式 | 位置规则 | 标记位数 | 优点 | 缺点 |
|---------|---------|---------|------|------|
| 全相联 | 任意 Cache 块 | 22 位（全块号） | 命中率最高、无冲突 | 需要并行比较所有标记，硬件贵、速度慢 |
| 直接映射 | 块号 % 8 | 22-3=19 位（块号高位） | 硬件最简单、查得快 | 冲突率高、空间利用率差 |
| 组相联 | 块号 % 组数，组内任意 | 22-组号位数 | 命中率与硬件成本平衡 | 比直接映射复杂一点 |

**地址划分**（直接映射为例）：主存地址 = 标记（19 位）+ Cache 行号（3 位）+ 块内地址（6 位）。Cache 行号直接取主存块号低 3 位，无需查找；标记只存高 19 位即可区分冲突块。

**有效位的作用**：每个 Cache 块除标记外配 1 位有效位。调入数据时置 1；CPU 访问时标记匹配 **且** 有效位=1 才算命中，否则未命中须访存并调入。

**组相联的折中本质**：把直接映射的"一个位置"放宽成"一组位置"——主存块先按取余落到某个组，组内几个空位随便放，冲突率大幅下降，硬件成本仅略升（组内并行比较几路标记即可）。考试最常考 2 路/4 路组相联的地址划分计算。

## 备注
- 标记位数公式：直接映射标记 = 主存块号位数 − Cache 行号位数；组相联标记 = 主存块号位数 − 组号位数（例题：22 位块号、8 块 Cache → 直接映射标记 19 位）
- 有效位是硬性要求：硬件没有"空"状态，无有效位会把全 0 标记的空块误判为 0 号主存块副本
