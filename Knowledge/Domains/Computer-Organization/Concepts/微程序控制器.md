# 微程序控制器

## 类型判定
构型 — 描述一种引入"存储程序"软件思想来实现控制器 CU 的方案：用微程序（微指令序列）解释机器指令的执行，包含微指令格式设计、编码方式、微地址形成、控制存储器结构及与硬布线控制器的对比，属系统架构类概念。

## 类比 ★
**一句话比喻：** 像餐厅的标准化食谱手册——每道菜（每条机器指令）对应一页食谱（一个微程序），食谱上每一步（每条微指令）写着"同时开火 + 倒油 + 拿锅"，厨师照着念就行，换菜只需加一页食谱不用改造厨房。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 控制存储器 CM（库存，ROM 实现） | 塑封的标准化食谱手册，出厂就印好，断电不丢 |
| CMAR（微地址寄存器，别名 μPC） | 手指指到食谱第几行——下一步该念哪条指令 |
| 微指令的操作控制字段 + 顺序控制字段 | 食谱一行里"同时做哪几件事"+"念完翻到第几页" |
| 微地址形成部件 | 服务员看客人点了什么菜 → 翻到对应食谱起始页 |

## 是什么
**微程序控制器**是用"存储程序"思想实现的控制单元 CU。CPU 出厂前，厂家将每条机器指令对应的微程序（一段微指令序列）写入 CU 内部的只读控制存储器 CM（Control Memory，又称库存）。执行一条机器指令时，CU 根据指令操作码通过微地址形成部件找到该指令对应的微程序首地址，然后从 CM 中逐条取出微指令执行——每条微指令包含"操作控制字段"（决定发出哪些微命令）和"顺序控制字段"（指明下一条微指令地址）。所有指令的取指周期/间址周期/中断周期的微程序公用（只需存一份），只有执行周期的微程序各指令不同。这本质上是套娃：**微指令之于机器指令，就如同机器指令之于程序**。

## 输入-输出空间
- **输入**：IR 中的机器指令操作码（→微地址形成部件）、顺序逻辑的标志信息（中断信号、寻址特征位等）、CMDR 中当前微指令的控制字段（→译码发出控制信号）
- **输出**：一组微操作控制信号（每条微指令的执行可并行发出多个微命令）
- **关键部件链**：CMAR（存微地址）→ 地址译码器 → CM（按地址读出微指令）→ CMDR（暂存微指令）→ 操作控制字段译码 → 发出控制信号 + 顺序控制字段 → 顺序逻辑 → 下一条微地址 → CMAR（形成闭环）

## 正例（≥2 个）
1. **取数指令 LDA X 的微程序执行**：取指周期从 CM 0 号单元开始（微指令 0→1→2 顺序执行，完成 PC→MAR→取指令→送 IR）→ 若无需间址，顺序逻辑跳过 3 号地址，直接将执行周期首地址（如 13）送入 CMAR → 执行 13→14→15 三条微指令（MAR←X → M(MAR)→MDR → MDR→ACC）→ 15 的下地址指回 0（进入下一条指令取指）。
2. **微程序个数的计算题**：某 CPU 有 N 条机器指令，则 CM 中微程序段的个数至少为 N+1（N 个执行周期微程序 + 1 个公用取指微程序）。若系统有间址/中断功能，需再各加 1 段。但逻辑上可以说"微程序个数 = N"，因为把取指+间址+执行+中断四段视为一条指令完整微程序的四个组成部分。

## 反例/边界（≥1 个）
1. **间址周期和中断周期的微程序不是必然存在**：早期 CPU 或嵌入式微型 CPU 可能不提供间接寻址和中断功能，此时只存取指+执行两段微程序。考题中若出现"至少"二字，默认不含间址和中断。
2. **微指令周期 ≠ 指令周期**：微指令周期是从 CM 取出一条微指令并执行完成的时间；指令周期是从主存取出一条机器指令并执行完成的时间——指令周期 >> 微指令周期（慢得多）。

## 详细解释

### 微程序控制器核心部件

| 部件 | 英文/别名 | 功能 |
|------|----------|------|
| 控制存储器 CM | 库存 | ROM 实现，出厂时写入所有微程序；非易失，断电不丢 |
| CMAR | μPC | 存放下一条微指令的地址，相当于 PC+MAR 的结合体 |
| 地址译码器 | — | 将 CMAR 的地址译为 CM 存储单元的选通信号 |
| CMDR | μIR | 暂存当前取出的微指令，位宽 = 微指令字长 |
| 微地址形成部件 | — | 根据机器指令操作码 → 该指令执行周期微程序首地址 |
| 顺序逻辑 | — | 结合微指令下地址 + 标志信息（中断/寻址特征）→ 决定下一条微指令地址 |

### 微指令格式：水平型 vs 垂直型 vs 混合型

| 维度 | 水平型微指令 | 垂直型微指令 |
|------|------------|------------|
| 并行能力 | 一条可并行发出多个微命令 | 一条只能发一个微命令 |
| 微程序长度 | 短（指令条数少） | 长（指令条数多） |
| 微指令字长 | 长（控制字段位宽大） | 短（只需微操作码） |
| 编写难度 | 难 | 易（格式规整） |
| 执行速度 | 快（并行度高） | 慢（逐条串行） |

混合型 = 两者的折中，在垂直型基础上增加少量并行操作。

### 微指令编码方式（高频考点）

**① 直接编码（直接控制法）**：操作控制字段每一位对应一个微命令。优点是速度快、简单直观、并行性好；缺点是 N 个微命令就需要 N 位，微指令字长过长 → CM 容量过大 → CPU 面积增大（Intel CPU 的 CM 可占芯片面积一半）。

**② 字段直接编码**：将互斥的微命令分同一段，相容的微命令分不同段，每段经译码器译出具体微命令。每个段需保留全 0 状态表示"不发出任何微命令"。优点：显著缩短微指令字长。缺点：需译码电路，速度比直接编码慢。
- **计算题**：某段含 k 个互斥微命令 → 该段至少需 ⌈log₂(k+1)⌉ 位（+1 是保留的"不操作"状态）

**③ 字段间接编码**：一个字段的译码输出作为另一字段译码器的输入，双层译码。进一步缩短字长但速度更慢、并行性降低。简单了解即可。

### 微地址形成方式（下地址确定）

| 方式 | 说明 | 考频 |
|------|------|------|
| 断定法 | 微指令的顺序控制字段直接给出下地址 | ★★★ |
| 增量计数法（μPC+1） | 类似 PC+1，顺序执行时地址自动递增 | ★★★ |
| 根据机器指令操作码 | 微地址形成部件根据 IR 操作码产生首地址 | ★★ |
| 分支转移 | 转移类微指令根据条件决定跳转地址 | ★ |
| 测试网络 | 顺序逻辑根据标志信息修改地址 | ★ |
| 硬件直接产生 | 取指周期首地址固定为 0 号单元；中断周期首地址由硬件固定给出 | ★★ |

### 设计步骤（与硬布线对比）

1. 分析所有指令各阶段的微操作序列（同硬布线）
2. 安排微操作时序——可并行的微操作放同一节拍 = 同一条微指令（同硬布线）
3. **特有步骤**：取指周期每条微指令（除最后一条）执行后，需额外一个节拍将下地址送入 CMAR；取指周期最后一条微指令执行后，需额外一个节拍将微地址形成部件产生的执行周期首地址送入 CMAR——导致微程序比硬布线多消耗节拍，速度更慢
4. 确定微指令格式（选择编码方式）→ 确定微指令字长 → 编写每条微指令的码点（控制码各比特填 0/1）→ 写入 CM

### 微程序 vs 硬布线 对比（408 高频）

| 维度 | 硬布线控制器 | 微程序控制器 |
|------|------------|------------|
| 实现原理 | 纯硬件组合逻辑电路 | "存储程序"思想（微程序存于 ROM） |
| 控制信号产生 | 逻辑门即时运算 | 逐条取微指令译码 |
| 速度 | 快 | 慢（多消耗节拍 + 译码延迟） |
| 电路规整性 | 不规整，设计繁琐 | 规整，设计相对简单 |
| 扩展性（加指令） | 难（需改电路） | 易（用已有微指令编写新微程序即可） |
| 适用场景 | RISC（指令少且固定） | CISC（指令多，需灵活扩展，如 x86） |
| 控制信号产生速度 | 快 | 慢 |

## 备注
- 概念层次（套娃）：程序 > 机器指令 > 微程序 > 微指令 > 微命令 = 微操作。微命令与微操作一一对应；一条微指令可包含多个微命令（一对多）
- 名词对应表（同一个东西多个名字，考试会混用）：CMAR = μPC，CMDR = μIR，控制存储器 CM = 库存；取微指令+执行时间 = 微指令周期 ≠ 指令周期
- 混脸熟考点：动态微程序设计（出厂后可通过电擦除 ROM 修改微程序以扩展指令集，如 Intel x86）vs 静态微程序设计（写入 ROM 后不可改）；毫微程序 = 用毫微指令解释微指令（更深的套娃，简单了解）
- 字段直接编码算位数公式：每段 ⌈log₂(该段互斥微命令数 + 1)⌉，各段位数相加 = 操作控制字段总位数；"断定法"确定下地址位数 = ⌈log₂(CM 中微指令总数)⌉
