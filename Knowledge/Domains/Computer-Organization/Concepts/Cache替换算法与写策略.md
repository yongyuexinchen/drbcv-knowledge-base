# Cache 替换算法与写策略

## 类型判定
对比型 — 回答"Cache 满了淘汰谁（四种替换算法）"和"CPU 写操作时如何保持 Cache 与主存一致（写策略）"，属于 Cache 工作机制的两大配套决策。

## 类比 ★
**一句话比喻：** 替换算法像合租房的冰箱管理——随机算法是闭眼扔一个菜（纯看命），FIFO 是最早买的菜先扔（不管你还吃不吃），LRU 是最久没动过的菜扔掉（科学断舍离），LFU 是整年只吃过一次的菜扔掉（但你今天可能突然想吃）。写策略像笔记本誊写——写回法是先在草稿纸上改（Cache），等草稿纸满了再统一誊到正式本（主存）；全写法是草稿纸上写一笔就立刻誊一笔，随时一致。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| LRU（最久未使用） | 衣柜断舍离——最长时间没穿的衣服先捐掉 |
| 写回法+脏位 | 在白板上打草稿，改完标记*号，最后统一誊到正式文档 |
| 全写法+写缓冲 | 微信同时发两份——聊天框发一份（Cache），又秒转存到云盘（主存） |

## 是什么

**替换算法**解决"Cache 满了之后换哪一块出去"的问题。只用于全相联映射和组相联映射（直接映射位置固定，无需选择）。四种算法：**随机算法（RAND）**、**先进先出（FIFO）**、**近期最少使用（LRU）**、**最不经常使用（LFU）**。LRU 实际效果最好，是考试重点。

**写策略**解决"CPU 写操作时 Cache 和主存数据一致性"的问题。分命中与不命中两种情况：
- **写命中**：全写法（写直通法，同时写 Cache 和主存）vs 写回法（只写 Cache，淘汰时才写回主存）
- **写不命中**：写分配法（先调入再写，配合写回法）vs 非写分配法（直接写主存不调入，配合全写法）

## 输入-输出空间
- **输入（替换算法）**：已满的 Cache + 新主存块号 → 被替换的 Cache 块号
- **输入（写策略）**：CPU 写操作（目标地址 + 数据）→ Cache 和/或 主存被更新
- **输出**：命中/未命中的访存行为 + 一致性保证
- **前置条件**：替换算法需每个 Cache 块配计数器（LRU/LFU）；写回法需每个 Cache 块配脏位（修改标记）

## 正例（≥2 个）
1. **LRU 替换手算**：Cache 4 块，访问序列 1→2→3→4→1→2→5→1→2→3→4→5。前 4 次调满；访问 5 时往前看，1/2 最近用过，4/3 中 3 最久未用→淘汰 3 换 5。后续类推。手算技巧：从当前位置往前扫，最后出现的那个块号就是 LRU 淘汰目标。
2. **写回法+写分配法**：CPU 写地址 X（未命中）→ 先把 X 所在主存块调入 Cache → 在 Cache 中修改该块 → 脏位置 1 → 该块被淘汰时才写回主存。CPU 只访存一次（调入），后续多次写同块都是写 Cache，速度极快。

## 反例/边界（≥1 个）
1. **FIFO 抖动现象**：访问 1→2→3→4→1→2→5→1→6… 时，1 刚被淘汰立刻又被访问 → 调回 1 又淘汰 2 → 形成频繁换入换出的"抖动"。即便是最优 LRU，当频繁访问的块数 > Cache 块数时仍会抖动（如访问 5 个块但只有 4 块 Cache）。
2. **LFU 的"过时数据霸占"问题**：视频聊天期间相关块的计数器累加到很大值；停止聊天后这些块因为计数器太大而长期占着 Cache 不被淘汰，导致新的热点数据进不来——违背了局部性原理（只看近期，不看历史总量）。
3. **全写法+写缓冲饱和**：CPU 写操作频繁时，写缓冲（SRAM 先入先出队列）可能写满 → CPU 必须阻塞等待写缓冲有空位 → 性能骤降。
4. **LRU 计数器溢出**：Cache 共 4 块时计数器值只有 0~3，用 2 位即可，不会溢出。规则保证了"比命中的计数器小的才加一，大的不变"→ 值域始终是 0~N-1。

## 详细解释

**四种替换算法对比：**

| 算法 | 替换规则 | 硬件复杂度 | 命中率 | 是否考虑局部性 |
|------|---------|-----------|--------|--------------|
| 随机 RAND | 随机选一块 | 最低（无需额外硬件） | 低，不稳定 | ❌ |
| 先进先出 FIFO | 淘汰最早调入的块 | 低（轮流替换） | 低，易抖动 | ❌ |
| 近期最少 LRU | 淘汰最久未被访问的块 | 中（每块配 log₂N 位计数器） | **最高** | ✅ |
| 最不经常 LFU | 淘汰总访问次数最少的块 | 高（计数器位数大） | 中 | ❌（看全局不只看近期） |

**LRU 计数器变化规则（硬件实现）：**
- 未命中且有空闲行 → 新块装入，计数器=0，其余非空闲行计数器+1
- 命中 → 命中行计数器=0，比它原来值小的计数器+1，比它大的不变
- 未命中且无空闲行 → 替换计数器最大的行，新块计数器=0，其余全部+1

**写策略组合：**

| 场景 | 方案A | 方案B |
|------|-------|-------|
| 写命中 | **全写法**（同时写 Cache+主存） | **写回法**（只写 Cache，脏位置 1） |
| 写不命中 | **非写分配法**（直接写主存，不调入） | **写分配法**（先调入 Cache 再写） |
| 典型组合 | 全写法 + 非写分配法 | 写回法 + 写分配法 |
| 应用场景 | L1→L2 级 Cache 之间 | Cache→主存 之间 |

**多级 Cache 写策略**：现代 CPU 有 L1/L2/L3 三级 Cache。各级 Cache 之间通常用全写法+非写分配法（保证上级数据快速同步到下级）；Cache 和主存之间通常用写回法+写分配法（减少访存次数）。

## 备注
- LRU 是 408 大题最爱，手算技巧「从当前位置往前看，最后出现的淘汰」比计数值法快得多
- FIFO 抖动：刚换出立刻又调入→反复折腾；LRU 也会抖（当频繁访问块数>Cache 块数时）
- 写回法配脏位：脏位=1 淘汰时才写回，脏位=0 直接丢弃→省一次写主存时间
- 全写法+写缓冲：写缓冲是 SRAM FIFO 队列，降低 CPU 等待时间，但频繁写可能饱和
