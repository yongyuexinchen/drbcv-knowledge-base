# 数据的存储和排列

## 类型判定
概念型 — 定义多字节数据在内存中的两种字节排列方式（大端/小端）以及现代计算机的边界对齐存储策略，涵盖按字节/半字/字寻址的地址转换。

## 类比 ★
**一句话比喻：** 像写快递单上的门牌号——大端是"省→市→区→门牌号"从大到小写（符合人类阅读习惯），小端是"门牌号→区→市→省"从小往大倒着写（方便快递员从最小单位开始分拣）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 大端存储（高字节在低地址） | 中国人写地址：国家→省→市→街道（从大到小，从左往右读是正确顺序） |
| 小端存储（低字节在低地址） | 快递分拣机从"门牌号"开始读——先处理最具体的、最先要用到的 |
| 边界对齐（空间换时间） | 停车场按固定车位宽度画线——会有空余但一次就能停进去，不用跨两个车位 |

## 是什么
**数据的存储和排列**涉及两个独立问题：

### 大小端模式
多字节数据（如 int 占 4 字节）在内存中占据连续地址时，字节的排列顺序有两种：
- **大端模式**：最高有效字节（MSB）存储在**低地址**，最低有效字节（LSB）存储在高地址——符合人类阅读顺序（从左往右读 = 从低地址往高地址读就是正确数值）
- **小端模式**：最低有效字节（LSB）存储在**低地址**，最高有效字节（MSB）存储在高地址——便于机器按地址递增顺序从低位开始运算（如加法先从 LSB 开始）

### 边界对齐
现代计算机按字节编址，但也支持按半字（2 字节）和按字（4 字节）寻址。若数据跨字边界存放（如 short 变量的第 1 字节在一行的最后、第 2 字节在下一行的最前），则需要**两次访存**才能读出完整数据。**边界对齐**策略宁可浪费少量空间（一个字的末尾空余字节弃用），让每个数据都从一个字的起始位置或半字边界开始，从而只需**一次访存**——用空间换时间。

## 输入-输出空间
- **输入**：一个多字节数据的值 + 目标存储模式（大端/小端，是否边界对齐）
- **输出**：该数据在内存中的字节序列（每字节对应一个内存地址）
- **前置条件**：了解机器的存储字长（通常 32 位 = 4 字节）和寻址方式（按字节/半字/字）

## 正例（≥2 个）
1. **int 型 01234567H 的大端/小端存储**：假设 int 占 4 字节，MSB=01H，LSB=67H。大端低地址→高地址：01 23 45 67；小端低地址→高地址：67 45 23 01。若从低地址开始按字节依次读取，大端读出来就是 01234567H（人类友好），小端读出来是 67452301H（需逆序拼合）。
2. **边界对齐的访存效率**：结构体含 3 个 char（各 1 字节）+ 1 个 short（2 字节）。边界对齐方式：3 个 char 占 3 字节后剩 1 字节空位 → 弃用，short 从下一个字开始存储 → 只需 1 次访存读出整个 short。边界不对齐方式：short 的 1 字节塞入前一字末尾、1 字节在后一字开头 → 需要 2 次访存 + 拼接。
3. **按字寻址 → 字节地址转换**：存储字长 32 位，要访问第 2 号字 → 字地址 2（二进制 10）逻辑左移 2 位（乘 4）→ 字节地址 = 8。同理半字地址转字节地址：逻辑左移 1 位（乘 2）。

## 反例/边界（≥1 个）
1. **"小端模式不方便人类阅读"是缺点但不是 bug**：小端模式下内存 dump 看到的是逆序，编程时需要注意字节序转换（网络字节序通常是大端，x86 是小端），通信双方的字节序不一致会导致数据解析错误。
2. **边界不对齐虽然省空间但可能严重拖慢速度**：如果一个 int 变量跨两个字存储，读一次需要 2 次访存——在频繁访问的场景（如循环内）累积的延迟非常可观。
3. **"内存总是按字节寻址的"需要澄清**：内存按字节编址意味着每个字节都有唯一地址，但 CPU 指令可以指定按"半字"或"字"来寻址——此时给出的地址是该半字/字的起始字节地址，通过逻辑左移转换得到。

## 详细解释
### 大端 vs 小端（以 01234567H 为例，地址递增 →）
```
大端（Big-Endian）：  [01] [23] [45] [67]   ← 低地址存高字节
                    低地址 → → → → → 高地址

小端（Little-Endian）： [67] [45] [23] [01]  ← 低地址存低字节
                       低地址 → → → → → 高地址
```

### 边界对齐示意图（存储字长 32 位）
```
对齐方式：
 字0: [char1][char2][char3][空  ]  ← short 放不下，空位浪费
 字1: [short高][short低][ ...  ][ ... ]
 字2: [int字节0][int字节1][int字节2][int字节3]

不对齐方式：
 字0: [char1][char2][char3][short高]  ← short 跨两个字！
 字1: [short低][ ...  ][ ...  ][ ... ]
```
对齐方式：读 short → 1 次访存（读字 1）。不对齐：读 short → 2 次访存（读字 0 + 字 1，再拼接）。

### 地址转换公式
- 半字地址 → 字节地址：半字地址 × 2（逻辑左移 1 位）
- 字地址 → 字节地址：字地址 × 4（逻辑左移 2 位）

## 备注
- **408 考点 — 大小端的英文**：MSB = Most Significant Byte（最高有效字节），LSB = Least Significant Byte（最低有效字节）
- **408 考点 — 大端 "符合阅读习惯"，小端 "便于机器处理"**：小端先读入的字节就是加法先从低位开始的那个字节，更契合运算顺序
- **408 考点 — 边界对齐的本质**：空间换时间——浪费少量存储空间换取访存次数减半
- **408 考点 — 地址转换**：给定字地址求字节地址 = 字地址 × 4（逻辑左移 2 位）；半字地址 × 2（左移 1 位）。每次访存只能读写一个字，不可跨行
