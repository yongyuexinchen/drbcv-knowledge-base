# 取消收藏

## 类型判定
procedure — DELETE 请求，按 user_id + news_id 双条件删除收藏记录，检查命中数量判断是否真的删了。

## 类比 ★
### 一句话比喻
取消收藏就像撕掉书上的书签——你翻开书找到自己的那张书签（user_id + news_id），撕掉它（delete），然后检查手里是不是真的撕掉了一张纸（rowcount > 0）。如果根本没找到那张书签（rowcount = 0），说明有人已经撕过了，抛异常。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| DELETE 请求方法 | "撕掉"这个动作 |
| where user_id=... AND news_id=... | 找到"大邱在第1本书上的那张书签" |
| db.execute(delete_stmt) | 动手撕 |
| result.rowcount | 检查手里有没有撕下来的纸 |
| rowcount > 0 → 成功 / =0 → 抛 404 | 撕到了纸 → 成功 / 没撕到 → "书签不存在" |

## 是什么
取消收藏接口（DELETE `/api/favorite/remove?newsId=xxx`）从收藏表中删除当前用户对某条新闻的收藏记录。核心逻辑：执行 `delete(Favorite).where(user_id=..., news_id=...)`，通过 `result.rowcount` 判断是否命中。命中数 > 0 说明成功删除，命中数 = 0 说明记录不存在，抛 404。

## 输入-输出空间（程序型必填）
- **输入**：news_id: int（查询参数，别名 newsId）、user（Depends 注入）、db（Depends 注入）
- **输出**：`{"code": 200, "message": "删除收藏成功"}`
- **前置条件**：用户已登录、收藏记录存在（否则 404）

## 核心代码 + 步骤表
```python
# ===== CRUD/favorite.py =====
async def remove_news_favorite(db: AsyncSession, user_id: int, news_id: int):
    stmt = delete(Favorite).where(
        Favorite.user_id == user_id,
        Favorite.news_id == news_id
    )
    result = await db.execute(stmt)
    await db.commit()
    return result.rowcount > 0   # 命中数 > 0 说明真的删了

# ===== routers/favorite.py =====
@router.delete("/remove")
async def remove_favorite(
    news_id: int = Query(..., alias="newsId"),
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    result = await favorite_crud.remove_news_favorite(db, user.id, news_id)
    if not result:
        raise HTTPException(status_code=404, detail="收藏记录不存在")
    return success_response(message="删除收藏成功")
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 构造删除语句 | `delete(Favorite).where(...)` | 双条件精准定位要删的收藏记录 |
| ② 执行 + 提交 | `await db.execute(stmt)` + `await db.commit()` | 删完别忘了 commit |
| ③ 检查命中数 | `result.rowcount > 0` | > 0 才是真正删了 |
| ④ 路由层判断 | `if not result: raise HTTPException(404)` | CRUD 返回 bool，路由层决定是否抛异常 |

## 正例（≥2 个）
1. **正常取消**：大邱收藏了新闻3，点击橙色星星触发 `DELETE /remove?newsId=3` → rowcount=1 → 成功响应 → 星星变回白色。
2. **从收藏列表页取消**：用户在我的收藏页点某条新闻右侧的叉号，前端调用同一个 `/remove` 接口，rowcount=1 → 该条目从列表中消失。
3. **幂等删除**：已取消的收藏再次点星星（前端可能不做判断），rowcount=0 → 后端抛 404，前端收到后忽略或提示即可，不会造成数据异常。

## 反例/边界（≥1 个）
1. **忘记 commit**：只 execute 不 commit，虽然 execute 返回了结果，但事务未提交，数据库实际没删——刷新后记录还在。
2. **不检查 rowcount**：无论删没删到都返回成功 → 用户取消一个不存在的收藏也提示"删除成功"，前端误以为操作生效。
3. **用 scalar_one 查后 delete**：先查询再 delete（两次数据库操作）比直接用 `delete(...).where(...)` 多一次 IO，且存在竞态风险（查和删之间记录被其他请求修改）。

## 详细解释
**DELETE 方法为什么用查询参数而非路径参数？** 取消收藏和添加收藏都用 `news_id` 定位新闻。添加收藏是 POST，用请求体；取消收藏是 DELETE，习惯用查询参数（`?newsId=1`）。两种方式都可以，关键是与接口文档保持一致。

**rowcount vs scalar_one_or_none 的区别**：检查收藏状态用 `select + scalar_one_or_none`（需要返回具体数据），取消收藏用 `delete + rowcount`（只需要知道删没删）。前者拿对象，后者拿影响行数，场景不同。
