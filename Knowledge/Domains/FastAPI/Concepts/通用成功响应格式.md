# 通用成功响应格式

## 类型判定
procedure — 三步工程化封装：抽取工具函数 → 定义 data 数据类型 → 路由调用响应。

## 类比 ★
### 一句话比喻
通用成功响应格式就像公司的统一工牌——不管你是研发部还是市场部（不同接口），工牌的样式（code + message + data 结构）完全一样，只是姓名和照片（data 内容）各不相同。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| `success_response()` 工具函数 | 公司人事部统一的工牌模板——谁都用同一套 |
| `code: 200` | 工牌上的公司 Logo——始终不变 |
| `message` 参数 | 工牌上的职位名称——注册成功/登录成功各不相同 |
| `data` 参数 | 工牌上的姓名和照片——每个员工（接口）内容不同 |
| `JsonResponse` + `jsonable_encoder` | 工牌塑封机——确保任何材质（ORM/Pydantic/dict）都能压成标准工牌 |
| `model_validate(user)` | 把员工档案（ORM对象）转换成工牌上的信息 |

## 是什么
通用成功响应格式是头条项目的工程化封装：将每个接口返回的 `{code, message, data}` 结构抽取为一个工具函数 `success_response()`，用 Pydantic 模型类定义 `data` 的具体类型，通过 `JsonResponse` + `jsonable_encoder` 保证序列化兼容性。此后所有接口不再手写 `return {"code": 200, ...}`，统一调用 `success_response(message, data)` 即可。

## 输入-输出空间（程序型必填）
- **输入**：`message: str`（提示信息）、`data: Any`（业务数据，默认 None）
- **输出**：`JsonResponse` 对象，格式为 `{"code": 200, "message": "...", "data": {...}}`
- **前置条件**：`from fastapi.responses import JSONResponse`、`from fastapi.encoders import jsonable_encoder`

## 核心代码 + 步骤表
```python
# ===== utils/response.py：第一步，抽取工具函数 =====
from fastapi.responses import JSONResponse
from fastapi.encoders import jsonable_encoder

def success_response(message: str = "success", data: Any = None):
    content = {"code": 200, "message": message, "data": data}
    return JSONResponse(content=jsonable_encoder(content))

# ===== schemas/users.py：第二步，定义 data 数据类型 =====
from pydantic import BaseModel, ConfigDict

class UserInfoResponse(BaseModel):
    """用户关键信息（脱敏后的）"""
    model_config = ConfigDict(from_attributes=True)   # ← 允许从ORM取值
    id: int
    username: str

class UserInfoBase(BaseModel):
    """可选信息基类"""
    nickname: str | None = None
    avatar: str | None = None
    gender: str | None = None
    bio: str | None = None

# 最终 data 的类型
class UserResponseData(BaseModel):
    model_config = ConfigDict(from_attributes=True, populate_by_name=True)
    token: str
    user_info: UserInfoResponse = Field(alias="userInfo")

# ===== routers/users.py：第三步，路由调用 =====
@router.post("/register")
async def register(...):
    # ... 业务逻辑 ...
    response_data = UserResponseData(
        token=token,
        user_info=UserInfoResponse.model_validate(user)  # 从ORM提取值
    )
    return success_response(message="注册成功", data=response_data)
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 抽取函数 | `success_response(message, data)` | 统一返回 `{code, message, data}` |
| ② 定义 data 类型 | `class UserResponseData(BaseModel)` | 规定 data 里包含 token + userInfo |
| ③ model_config | `ConfigDict(from_attributes=True)` | 允许从 ORM 对象属性中取值 |
| ④ model_validate | `.model_validate(user)` | 从 ORM 对象提取所需字段（自动忽略未定义的如 password） |
| ⑤ 路由调用 | `return success_response(...)` | 替代手写 `return {"code": 200, ...}` |

## 正例（≥2 个）
1. **注册接口**：`success_response("注册成功", response_data)` → 返回 `{code:200, message:"注册成功", data:{token:"...", userInfo:{...}}}`。
2. **登录接口**：同样调用 `success_response("登录成功", response_data)` → 只需改 message，data 格式复用。
3. **新闻列表接口**：`success_response("获取新闻列表成功", news_data)` → 同一套函数，不同 data 类型。

## 反例/边界（≥1 个）
1. **忘记 from_attributes=True**：`model_validate(user)` 时报错——因为模型类不知道可以从 ORM 属性取值。必须加 `ConfigDict(from_attributes=True)`。
2. **data 为空**：某些接口（如修改密码成功）不需要返回数据 → `success_response("修改密码成功")` 不传 data，默认 None，响应中 `data: null`。
3. **别名不兼容**：前端用驼峰 `userInfo`，模型类用下划线 `user_info`——需要 `Field(alias="userInfo")` + `populate_by_name=True` 双向兼容。

## 详细解释
**为什么不用 FastAPI 默认的自动转换？**
FastAPI 默认将 dict/Pydantic 自动转为 JSON，但遇到 ORM 对象时序列化可能丢失字段或报错。使用 `jsonable_encoder` 显式转换，确保三种对象（dict、Pydantic、ORM）都能正确序列化为包含 `code/message/data` 的统一格式。

**model_validate 的妙用**：
- `UserInfoResponse` 只定义了 `id` 和 `username`，没定义 `password`
- 调用 `UserInfoResponse.model_validate(user)` 时，自动从 ORM 的 user 对象提取 `id` 和 `username`
- `password` 字段不在模型类中 → 自动忽略，不会泄露到响应中

**from_attributes 和 model_validate 的配合**：
- `from_attributes=True`：声明"我允许从对象属性取值"（开闸门）
- `model_validate(obj)`：真正执行取值动作（放水）
