# 获取浏览历史列表

## 类型判定
procedure — GET 分页查询，联表（News JOIN History）+ 聚合统计总量 + has_more 判断，与获取收藏列表模式完全一致，只是联合的表从 favorite 换成了 history。

## 类比 ★
### 一句话比喻
获取浏览历史列表就像翻看图书馆的借阅登记本——你只能看自己的借阅记录（user_id 过滤），每行记录告诉你"借了哪本书 + 最后一次借阅的时间"（News JOIN History），按最近借阅排列（order by view_time DESC），一次翻一页（分页），翻到底部标注"还有 N 页"（has_more）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| News JOIN History | 借阅登记本的每一行 = 书名 + 借阅日期 |
| view_time（浏览时间） | 借阅日期——最近一次翻看的日期 |
| func.count 统计总量 | 快速数一下"大邱总共借过多少本书" |
| order_by(view_time.desc()) | 登记本从新到旧排列——最近看的在上面 |
| NewsItemBase 继承复用 | 书名描述卡片是通用的——收藏和浏览都用同一张 |

## 是什么
获取浏览历史列表接口（GET `/api/history/list?page=1&pageSize=10`）分页返回当前用户的浏览记录，每条记录包含新闻信息和浏览时间。核心实现与获取收藏列表完全一致：联表查询（News JOIN History）、聚合统计总量、分页排序、has_more 判断。唯一的区别是连接的表从 `Favorite` 变为 `History`，联表条件相同（`news_id`），返回的时间字段变为 `view_time`。

## 输入-输出空间（程序型必填）
- **输入**：page: int(默认1, ≥1)、page_size: int(默认10, ≤100, 别名 pageSize)、user（Depends 注入）、db（Depends 注入）
- **输出**：`{"code": 200, "data": {"list": [...], "total": 8, "has_more": false}}`
- **前置条件**：用户已登录、News 和 History 模型类已定义、NewsItemBase Schema 已定义（复用）

## 核心代码 + 步骤表
```python
# ===== CRUD/history.py =====
async def get_history_list(db: AsyncSession, user_id: int, page: int, page_size: int):
    # ① 统计总量
    count_stmt = select(func.count(History.id)).where(History.user_id == user_id)
    total = (await db.execute(count_stmt)).scalar_one()

    # ② 联表查询
    offset = (page - 1) * page_size
    list_stmt = (
        select(News,
               History.view_time.label("view_time"),
               History.id.label("history_id"))
        .join(History, History.news_id == News.id)
        .where(History.user_id == user_id)
        .order_by(History.view_time.desc())
        .offset(offset)
        .limit(page_size)
    )
    result = await db.execute(list_stmt)
    rows = result.all()
    return rows, total

# ===== routers/history.py =====
@router.get("/list")
async def get_history_list(
    page: int = Query(1, ge=1),
    page_size: int = Query(10, ge=1, le=100, alias="pageSize"),
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    rows, total = await history_crud.get_history_list(db, user.id, page, page_size)
    offset = (page - 1) * page_size
    history_list = [{
        **news.__dict__,
        "view_time": view_time,
        "history_id": history_id
    } for news, view_time, history_id in rows]
    has_more = (offset + len(history_list)) < total

    return success_response(data=HistoryListResponse(
        list=history_list, total=total, has_more=has_more
    ))
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 统计总量 | `func.count(History.id).where(user_id=...)` | 聚合查询浏览总数 |
| ② 联表查询 | `select(News).join(History, ...)` | 主体 News，联合 History |
| ③ 排序分页 | `order_by(view_time.desc()).offset().limit()` | 最近看的在前面 + 分页 |
| ④ 整合数据 | 列表推导式解包元组 | `{**news.__dict__, "view_time": ..., "history_id": ...}` |
| ⑤ has_more | `offset + len(list) < total` | 判断是否还有更多 |

## 正例（≥2 个）
1. **标准浏览历史**：大邱看过 8 条新闻，请求 `page=1, pageSize=10` → offset=0，8 条全返回，total=8，has_more=false。
2. **Schema 继承复用**：`HistoryNewsItem` 继承 `NewsItemBase`（含 id/title/image 等），新增 `view_time` 和 `history_id`——与收藏列表共享同一个 News 基础 Schema。
3. **与收藏列表对照**：浏览历史列表和收藏列表代码结构几乎完全一致，只是 favorite → history、create_at → view_time、favorite_id → history_id——"换表名和字段名"即可迁移。

## 反例/边界（≥1 个）
1. **盲目复制收藏代码忘记改表名**：从 `get_favorite_list` 复制代码后，join 条件仍写 `Favorite.user_id == user_id` 和 `Favorite.news_id == News.id`——查的还是收藏表，浏览历史接口返回收藏数据。
2. **忘记修改 Schema 字段名**：Schema 中继承的 `news_id` 用了 `Field(alias="newsId")` 驼峰别名，而 `view_time` 忘了加 `alias="viewTime"`——前端拿到的是 `view_time` 而非 `viewTime`。
3. **has_more 公式复用错误**：`page * page_size < total`（错误）vs `offset + len(list) < total`（正确）——page=1 时有 10 条 total=10，前者 10<10=false（错判为没更多），后者 0+10<10=false（正确）。

## 详细解释
**与获取收藏列表的异同**：

| 对比项 | 获取收藏列表 | 获取浏览历史列表 |
|-------|------------|---------------|
| 主表 | News JOIN Favorite | News JOIN History |
| 时间字段 | `Favorite.create_at` → `favorite_time` | `History.view_time` → `view_time` |
| ID 字段 | `Favorite.id` → `favorite_id` | `History.id` → `history_id` |
| 排序依据 | 按收藏时间降序 | 按浏览时间降序 |
| 其他 | 完全相同（统计/分页/has_more） | 完全相同 |

**Schema 继承设计**：在 `schemas/base.py` 中定义 `NewsItemBase`，收藏的 `FavoriteNewsItem` 和浏览历史的 `HistoryNewsItem` 都继承它，各自新增专属字段。这样新增模块只需继承 + 加字段，不用重写全套 News 字段。
