# 新闻模块总结

## 类型判定
discriminant — 对新闻模块三大接口（分类、列表、详情）的核心知识和新增知识点进行系统回顾。

## 类比 ★
### 一句话比喻
新闻模块就像一份完整报纸的生产线——栏目导航（分类）→ 新闻目录（列表）→ 文章详情（详情+推荐），每个环节各司其职又环环相扣，背后是同一套 ORM 操作流水线。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 接口开发四步流程 | 报社的标准化出稿流程——每个记者都按这个套路写 |
| APIRouter + prefix/tags | 报头格式——所有新闻版面的抬头风格统一 |
| ORM 模型类继承 Base | 新闻稿模板——标题、作者、时间等格式全报统一 |
| 数据库索引 | 报纸的目录页——按分类找新闻不用从第一页翻 |
| order_by DESC 降序 | 最新的新闻放头版头条——浏览量高的优先展示 |
| update + rowcount 检查 | 发行量统计——每卖出一份都要计数，漏记要追责 |

## 是什么
新闻模块是头条项目的第一个功能模块，包含三个核心接口：获取新闻分类（GET `/api/news/categories`）、获取新闻列表（GET `/api/news/list`）、获取新闻详情（GET `/api/news/detail`）。三个接口都遵循"路由→模型类→CRUD→调用响应"的四步开发流程。新闻模块引入了多个新知识点：数据库索引、ORM 排序（order_by）、update 更新语法、rowcount 命中检查、scalar_one 提取单结果。

## 正例（≥2 个）
1. **接口开发流程复用**：新闻分类 → 新闻列表 → 新闻详情，三个接口开发步骤完全一致——验证了四步流程的通用性。
2. **索引加速高频查询**：对 category_id 建索引后，按分类查新闻从全表扫描变为索引定位——查询速度提升明显。
3. **全面覆盖 CRUD**：分类（查）、列表（分页查+聚合统计）、详情（单条查+更新浏览量+关联查推荐）——新闻模块覆盖了查询和更新的主要场景。

## 反例/边界（≥1 个）
1. **跨域问题**：新闻模块写完，交互式文档测试正常，但前端页面请求失败——CORS 跨域是必踩的坑。必须在 main.py 添加 CORSMiddleware。
2. **不存在的新闻 ID**：详情接口不判断 scalar_one_or_none 的 None 情况 → 服务器 500。必须 if not 抛 404。

## 详细解释
**新闻模块核心知识点清单**：

| 知识点 | 位置 | 说明 |
|--------|------|------|
| 接口开发四步流程 | 全模块 | 路由→模型类→CRUD→调用响应 |
| 模块化路由（APIRouter） | routers/news.py | prefix="/api/news", tags=["news"] |
| ORM 查询：select + where | CRUD/news.py | 条件查询，链式调用 |
| 分页查询：offset + limit | 列表接口 | offset=(page-1)×page_size |
| 聚合统计：func.count | 列表接口 | 统计某分类下新闻总数 |
| 数据库索引：__table_args__ | models/news.py | 对 category_id 和 publish_time 建索引 |
| ORM 排序：order_by + desc() | 详情-推荐 | 浏览量降序、发布时间降序排列 |
| ORM 更新：update + where + values | 详情-浏览量 | 更新浏览量字段 |
| 命中检查：result.rowcount | 详情-浏览量 | 检查更新是否真的命中数据 |
| 单结果提取：scalar_one_or_none | 详情接口 | 查不到返回 None 而非报错 |
| 列表推导式过滤字段 | 详情-推荐 | 只返回前端需要的字段子集 |
| CORS 跨域中间件 | main.py | CORSMiddleware 解决前后端跨域 |
| 参数别名：Query(alias="xxx") | 列表接口 | 驼峰与下划线命名互转 |

**has_more 计算公式**：`offset + len(news_list) < total` → true 表示还有更多新闻未加载

**排序默认行为**：不写 desc() 就是升序（ASC），浏览量最低的在前面——对于推荐场景必须显式加 desc()。
