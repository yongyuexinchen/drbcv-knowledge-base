# 修改用户信息与密码

## 类型判定
procedure — 两个子流程共享认证前置：Token 验证（复用）→ 更新字段（修改信息用 update，修改密码用赋值+加密）。

## 类比 ★
### 一句话比喻
修改用户信息与密码就像去人事部更新档案——你要先刷卡证明是你本人（Token 验证），然后告诉 HR 你想改什么（昵称/头像/密码），HR 在你档案上划掉旧信息、填上新信息（数据库 UPDATE），最后给你看更新后的档案（返回最新用户信息）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| `Depends(get_current_user)` | 刷工牌——先证明"我就是我" |
| `model_dump(exclude_unset=True)` | HR 说"你只改了简介对吧？头像和性别不动" |
| ** 解包 dict | 把表单上的修改项逐一填入档案 |
| `result.rowcount == 0` | HR 查了一遍档案——"没找到你的记录？" |
| `verify_password(old, hashed)` | 改微信密码要先输一遍旧密码——确认是你本人操作 |
| `db.add(user)` 确保提交 | 办事员把档案亲手交到档案室——确保一定归档 |

## 是什么
修改用户信息与密码是用户模块的两个 PUT 接口：**修改用户信息**（PUT `/api/user/update`）更新昵称/头像/性别/简介/手机号等可选字段；**修改用户密码**（PUT `/api/user/password`）要求先验证旧密码，再将新密码 bcrypt 加密后更新入库。两者都复用 `get_current_user` 依赖注入来验证登录状态。

## 输入-输出空间（程序型必填）
- **修改信息输入**：`nickname/avatar/gender/bio/phone`（均为可选，通过 `UserUpdateRequest` 校验）
- **修改密码输入**：`old_password: str`、`new_password: str`（通过 `UserChangePasswordRequest` 校验）
- **输出**：`{"code": 200, "message": "修改信息成功" / "修改密码成功", "data": {...用户信息...}}`
- **前置条件**：已登录（Token 有效）、Token 验证依赖已注入

## 核心代码 + 步骤表
```python
# ===== schemas/users.py：定义请求体模型 =====
class UserUpdateRequest(BaseModel):
    """修改信息——所有字段可选"""
    nickname: str | None = None
    avatar: str | None = None
    gender: str | None = None
    bio: str | None = None
    phone: str | None = None

class UserChangePasswordRequest(BaseModel):
    """修改密码——两个字段必填"""
    old_password: str = Field(..., alias="oldPassword")
    new_password: str = Field(..., alias="newPassword", min_length=6)

# ===== CRUD/users.py：修改用户信息 =====
from sqlalchemy import update

async def update_user(db: AsyncSession, user_data: UserUpdateRequest, username: str):
    # ① model_dump 转字典，只提取用户真正设置了值的字段
    update_values = user_data.model_dump(exclude_unset=True, exclude_none=True)

    # ② 执行 UPDATE
    stmt = (
        update(User)
        .where(User.username == username)
        .values(**update_values)     # ** 解包字典 → 字段=值
    )
    result = await db.execute(stmt)
    await db.commit()

    # ③ 检查是否命中记录
    if result.rowcount == 0:
        raise HTTPException(status_code=404, detail="用户不存在")

    # ④ 返回更新后的用户
    return await get_user_by_username(db, username)

# ===== CRUD/users.py：修改用户密码 =====
async def change_password(
    db: AsyncSession, user: User,
    old_password: str, new_password: str
) -> bool:
    # ① 验证旧密码是否正确
    if not verify_password(old_password, user.password):
        return False

    # ② 新密码加密
    hashed_new = get_hash_password(new_password)

    # ③ 更新并提交
    user.password = hashed_new
    db.add(user)          # ← 确保由 SQLAlchemy 接管，避免 session 过期问题
    await db.commit()
    return True

# ===== routers/users.py：两个路由 =====
# 修改用户信息
@router.put("/update")
async def update_user_info(
    user_data: UserUpdateRequest,
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    updated_user = await users_crud.update_user(db, user_data, user.username)
    return success_response(
        message="修改信息成功",
        data=UserInfoResponse.model_validate(updated_user)
    )

# 修改密码
@router.put("/password")
async def update_password(
    password_data: UserChangePasswordRequest,
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    result = await users_crud.change_password(
        db, user, password_data.old_password, password_data.new_password
    )
    if not result:
        raise HTTPException(status_code=500, detail="修改密码失败，请稍后再试")
    return success_response(message="修改密码成功")
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① Token 验证 | `Depends(get_current_user)` | 复用认证依赖，确保登录状态 |
| ② model_dump | `exclude_unset=True, exclude_none=True` | 只提取用户真正填了的字段 |
| ③ 执行 UPDATE | `update(User).where(...).values(**dict)` | SQLAlchemy update 语法 |
| ④ 检查命中 | `result.rowcount == 0` | 没命中则抛 404 |
| ⑤ 密码校验 | `verify_password(old, hashed)` | 改密码前先验证旧密码 |
| ⑥ 密码更新 | `db.add(user)` + `commit()` | add 确保 SQLAlchemy 接管对象，避免 session 过期提交失败 |

## 正例（≥2 个）
1. **只改简介**：user_data 只传 `{"bio": "我喜欢FastAPI"}` → `model_dump(exclude_unset=True)` 只提取 bio 字段 → UPDATE 只改 bio，头像、性别等保持原样。
2. **改密码流程**：输入当前密码 123456、新密码 666666 → `verify_password("123456", hash)` 返回 True → `get_hash_password("666666")` 生成新密文 → 更新 password 字段 → 返回"修改密码成功"。
3. **多个字段同时改**：`{"nickname": "秋", "bio": "新简介"}` → `model_dump` 提取两个字段 → `**解包` 生成 `nickname='秋', bio='新简介'` → 一次 UPDATE 改两个字段。

## 反例/边界（≥1 个）
1. **旧密码错误**：用户输错旧密码 → `verify_password` 返回 False → `change_password` 返回 False → 路由抛 500"修改密码失败"。
2. **忘记 exclude_none**：用户只传了 bio，其他字段默认 None → 不加 `exclude_none=True` 时，头像、性别等全部被更新为 None → 原来的默认头像丢失，变成空。
3. **修改密码忘记 db.add(user)**：只做 `user.password = new_hash` 然后 `commit()` → 如果数据库 session 恰好过期或关闭，commit 失败，密码没改成功且没有报错。加上 `db.add(user)` 让 SQLAlchemy 重新接管对象，确保提交成功。

## 详细解释
**model_dump 的三个参数**：
| 参数 | 作用 | 示例 |
|------|------|------|
| `exclude_unset=True` | 排除"根本没传"的字段 | 没传 avatar → 不生成 avatar |
| `exclude_none=True` | 排除"值为 None"的字段 | 传了 `avatar=None` → 也不生成 |
| 两者齐用 | 只提取"用户真正设置了值"的字段 | `{"bio":"xx"}` → 只更新 bio |

**为什么要 ** 解包？**
```python
# update_values = {"nickname": "秋", "bio": "新简介"}
update(User).values(**update_values)
# 等价于：
update(User).values(nickname="秋", bio="新简介")
```
`**` 把字典的 key=value 拆成关键字参数传入 `.values()`。

**修改信息 vs 修改密码的关键差异**：
| | 修改信息 | 修改密码 |
|---|---|---|
| 请求方法 | PUT | PUT |
| 更新方式 | SQLAlchemy `update()` 语句 | 直接赋值 `user.password = ...` |
| 特殊处理 | `model_dump + exclude` | `bcrypt.verify` + `bcrypt.hash` |
| 响应 data | 返回更新后的用户信息 | data 为 null |
| 安全要求 | 必须登录 | 必须登录 + 验证旧密码 |
