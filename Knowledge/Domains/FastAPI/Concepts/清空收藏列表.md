# 清空收藏列表

## 类型判定
procedure — DELETE 请求，按 user_id 批量删除所有收藏记录，用 rowcount 拿到删除数量拼入响应消息。

## 类比 ★
### 一句话比喻
清空收藏列表就像把整个书架清空卖掉——不需要一本一本挑，而是"大邱的所有书签"一把抓走（delete where user_id=大邱）。卖之前数一下总共撕了多少张书签（rowcount），告诉用户"已清空 N 条收藏记录"。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| delete(Favorite).where(user_id=...) | "把大邱的所有书签全撕掉"——按人批量操作 |
| result.rowcount | 数一数撕下来多少张——3 张就告诉用户"清空了3条" |
| f"清空了{count}条收藏记录" | 收据上写"本次处理 X 件" |
| DELETE 无请求参数 | 清空不需要指定哪本书——就是全部 |

## 是什么
清空收藏列表接口（DELETE `/api/favorite/clear`）一次性删除当前用户的所有收藏记录。核心逻辑：`delete(Favorite).where(Favorite.user_id == user_id)`，execute + commit 后，通过 `result.rowcount` 获取删除数量，拼入响应消息 `"清空了 N 条收藏记录"`。无需请求参数，仅靠 token 识别用户。

## 输入-输出空间（程序型必填）
- **输入**：user（Depends 注入）、db（Depends 注入）——无需额外请求参数
- **输出**：`{"code": 200, "message": "清空了3条收藏记录"}`
- **前置条件**：用户已登录

## 核心代码 + 步骤表
```python
# ===== CRUD/favorite.py =====
async def remove_all_favorites(db: AsyncSession, user_id: int):
    stmt = delete(Favorite).where(Favorite.user_id == user_id)
    result = await db.execute(stmt)
    await db.commit()
    return result.rowcount or 0   # 返回删除数量，没有就 0

# ===== routers/favorite.py =====
@router.delete("/clear")
async def clear_favorite(
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    count = await favorite_crud.remove_all_favorites(db, user.id)
    return success_response(message=f"清空了{count}条收藏记录")
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 构造批量删除 | `delete(Favorite).where(user_id=...)` | 只按 user_id 过滤，不限制 news_id |
| ② 执行 + 提交 | `await db.execute(stmt)` + `await db.commit()` | 批量删除 + 提交 |
| ③ 获取命中数 | `result.rowcount` | 删了多少条 |
| ④ 拼消息 | `f"清空了{count}条收藏记录"` | 动态消息告知用户删了多少 |

## 正例（≥2 个）
1. **有收藏时清空**：大邱收藏了 3 条新闻，点击清空 → rowcount=3 → 响应 `"清空了3条收藏记录"` → 收藏列表变空。
2. **无收藏时清空**：大邱的收藏列表已经是空的，点清空 → rowcount=0 → 响应 `"清空了0条收藏记录"` → 列表仍是空的，不会报错。
3. **多用户隔离**：大邱清空自己的收藏（user_id=22），小美的收藏（user_id=23）不受影响——`where user_id=22` 精确限定了范围。

## 反例/边界（≥1 个）
1. **忘记 where 条件**：`delete(Favorite)` 不加任何 where → 清空了所有用户的所有收藏，灾难性操作！必须带 `where(user_id=...)`。
2. **commit 写在 execute 之前**：代码顺序写错 → execute 没执行就 commit，什么都没删。
3. **rowcount 为 None 时报错**：某些数据库驱动下 rowcount 可能返回 None，直接拼 f-string 会显示 "清空了None条"——用 `result.rowcount or 0` 兜底。

## 详细解释
**清空 vs 逐条取消**：清空收藏是 `delete(Favorite).where(user_id=...)`（一条 SQL 删所有），逐条取消是 `delete(Favorite).where(user_id=..., news_id=...)`（每条一条 SQL）。性能上清空只需一次数据库往返，前端调用一个接口即可。

**message 中使用 rowcount**：与取消收藏不同，清空收藏的 API 要求在 message 中返回删除数量（如 `"清空了3条收藏记录"`）。rowcount 在 MySQL/PostgreSQL 中都能正确返回 DELETE 影响的行数。
