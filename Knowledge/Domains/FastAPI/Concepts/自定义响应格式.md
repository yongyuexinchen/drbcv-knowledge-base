# 自定义响应格式

## 类型判定
procedure — 两步标准流程：定义 Pydantic 模型作为"格式模板" → 在装饰器中用 `response_model` 参数绑定模板，FastAPI 自动校验输出。

## 类比 ★
### 一句话比喻
自定义响应格式就像给所有接口穿上**统一制服**——不管哪个服务员（接口）端菜上来，客人看到的都是同样的 `{code, message, data}` 包装。后端想偷偷多塞一个字段或少一个字段？不行，制服上有几个口袋是钉死的，多一个少一个都会被安检拦住（FastAPI 自动校验）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| `response_model=News` | 统一制服样式——所有接口的"穿着标准" |
| Pydantic 模型定义（ID/title/content） | 制服上固定的口袋——只能有这些，多一个补丁都不行 |
| FastAPI 自动校验 | 安检门——输出不符合模型 → 直接报 Internal Server Error |
| 少一个字段 | 制服少个口袋——安检不过，报 "missing content" |
| 多一个字段 | 制服多缝了个兜——安检不过（除非模型允许） |

## 是什么
自定义响应格式通过 `response_model` 参数约定接口的**输出数据格式**。先用 Pydantic 定义模型（声明返回哪些字段、各是什么类型），然后在路由装饰器中用 `response_model=模型类` 绑定。FastAPI 会自动校验返回数据是否符合模型——**多一个字段或少一个字段都会报错**。这是确保 API 输出一致性的核心机制。

## 输入-输出空间
- **输入**：处理函数的 return 值（Python 字典或对象）
- **输出**：经过 Pydantic 模型校验和过滤后的 JSON 数据
- **前置条件**：已定义 Pydantic 模型（`from pydantic import BaseModel`）

## 核心代码
```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 第一步：定义响应格式模型
class News(BaseModel):
    id: int
    title: str
    content: str

# 第二步：在装饰器中绑定 response_model
@app.get("/news/{id}", response_model=News)
async def get_news(id: int):
    return {
        "id": id,
        "title": f"这是第{id}本书",
        "content": "这是一本好书"
    }

# ❌ 错误示例：缺少 content 字段
@app.get("/news2/{id}", response_model=News)
async def get_news2(id: int):
    return {
        "id": id,
        "title": f"这是第{id}本书"
        # 缺少 content → 报错: missing content
    }
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 定义格式模型 | `class News(BaseModel):` | 继承 BaseModel，声明字段名和类型 |
| ② 绑定 response_model | `@app.get("/news/{id}", response_model=News)` | 在装饰器中添加参数绑定模型 |
| ③ return 数据 | `return {"id": id, "title": ..., "content": ...}` | 返回字典必须包含模型的所有字段 |
| ④ FastAPI 自动校验 | （框架自动执行） | 输出不符合模型 → 500 Internal Server Error |

## 正例（≥2 个）
1. **统一 API 响应格式**：定义 `class ApiResponse(BaseModel): code: int; message: str; data: dict`，所有接口用 `response_model=ApiResponse`，前端只需处理一种结构。
2. **用户信息接口**：`class UserOut(BaseModel): id: int; username: str; email: str` — 只暴露安全字段，密码等敏感字段不在模型中就不会输出。
3. **新闻详情接口**：`class NewsDetail(BaseModel): id: int; title: str; content: str; author: str` — 保证前端拿到的数据格式完全一致，不会出现"有时有 author、有时没有"的情况。

## 反例/边界（≥1 个）
1. **少字段**：模型要求 `id, title, content` 三个字段，但 return 只返回了 `id, title` → 报错 `missing content`（Internal Server Error）。
2. **类型不匹配**：模型定义 `id: int`，但 return 返回 `"id": "abc"` → FastAPI 校验失败。
3. **多字段不报错（重要！）**：默认情况下，return 多了模型未定义的字段**不会报错**，FastAPI 会静默过滤掉多余字段——这是"宽松校验"而非"严格校验"。如果需要严格模式，需额外配置。

## 详细解释
**`response_model` vs 手动校验的区别**：
- 不用 `response_model`：return 什么就输出什么，字段随便加减，类型随便变——输出不可控。
- 用了 `response_model`：FastAPI 自动过滤（去掉多余字段）、自动校验（检查必需字段和类型）、自动转 JSON——输出始终一致。

**实际项目中的最佳实践**：通常会封装一个统一的响应基类，如：
```python
class ApiResponse(BaseModel):
    code: int = 200
    message: str = "success"
    data: dict = {}
```
所有接口的 `response_model` 指向这个类或其子类，确保前端收到的永远是 `{code, message, data}` 结构。
