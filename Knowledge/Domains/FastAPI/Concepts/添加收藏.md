# 添加收藏

## 类型判定
procedure — POST 请求，接收请求体参数 news_id，构造 ORM 对象写入数据库，给新闻"贴上收藏标签"。

## 类比 ★
### 一句话比喻
添加收藏就像给喜欢的书贴上书签放入"我的书架"——你拿出一个空白书签（ORM 对象），写上书名和你的名字（user_id + news_id），夹进去（add），合上书（commit），这本书就在你的书架上了。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Favorite 模型类 | 空白书签模板——有 user_id、news_id、create_at 三个空 |
| 构造 ORM 对象 | 在书签上写下 "大邱收藏了新闻1" |
| db.add(favorite) | 把书签夹进书里（加入数据库缓冲区） |
| db.commit() | 合上书本——确认保存，不反悔 |
| db.refresh() | 回头再看一眼书签位置——拿到数据库最新记录 |

## 是什么
添加收藏接口（POST `/api/favorite/add`）将一条新闻加入用户的收藏列表。核心逻辑：接收请求体中的 `news_id`，结合当前登录用户的 `user_id`，构造 Favorite ORM 对象，执行 `db.add()` + `db.commit()` + `db.refresh()` 完成持久化。前端新闻详情页点击空心小星星触发此接口，成功后星星变为橙色。

## 输入-输出空间（程序型必填）
- **输入**：news_id: int（请求体参数，需定义 Pydantic 请求体模型）、user（Depends 注入）、db（Depends 注入）
- **输出**：新增的 Favorite ORM 对象（含 id、user_id、news_id、create_at）
- **前置条件**：用户已登录、news_id 对应的新闻存在、Favorite 模型类已定义

## 核心代码 + 步骤表
```python
# ===== schemas/favorite.py：请求体模型 =====
class FavoriteAddRequest(BaseModel):
    news_id: int = Field(alias="newsId")

# ===== CRUD/favorite.py =====
async def add_news_favorite(db: AsyncSession, user_id: int, news_id: int):
    favorite = Favorite(user_id=user_id, news_id=news_id)
    db.add(favorite)
    await db.commit()
    await db.refresh(favorite)   # 拿到数据库生成的最新数据
    return favorite

# ===== routers/favorite.py =====
@router.post("/add")
async def add_favorite(
    data: FavoriteAddRequest,           # 请求体参数
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    result = await favorite_crud.add_news_favorite(db, user.id, data.news_id)
    return success_response(data=result, message="添加收藏成功")
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 定义请求体 Schema | `class FavoriteAddRequest` | POST 方法参数必须用请求体，所以先定义 Pydantic 模型 |
| ② 构造 ORM 对象 | `Favorite(user_id=..., news_id=...)` | 用模型类实例化一条收藏记录 |
| ③ 添加到会话 | `db.add(favorite)` | 标记为待插入 |
| ④ 提交事务 | `await db.commit()` | 真正写入数据库 |
| ⑤ 刷新对象 | `await db.refresh(favorite)` | 获取数据库生成的 id 和 create_at |

## 正例（≥2 个）
1. **首次收藏**：用户浏览新闻2，点击空心星星 → POST `/add` 传 `newsId=2` → 数据库新增一条记录 → 星星变橙色。
2. **批量收藏**：用户连续点击新闻3、新闻4、新闻5的星星 → 三次 POST 请求，favorite 表新增三条记录——每一条独立添加，互不影响。
3. **请求体 vs 查询参数**：POST 方法中 `news_id` 必须定义为请求体参数（Pydantic 模型），不能用 `Query()`——这保证了参数在请求体中传递，URL 上不暴露。

## 反例/边界（≥1 个）
1. **重复收藏**：同一用户对同一新闻点两次星星 → 第二次 POST 会因为 favorite 表的 `UniqueConstraint(user_id, news_id)`（唯一约束）抛 IntegrityError。前端应该先调用"检查收藏状态"接口，已收藏的新闻不再发起添加请求。
2. **忘记 refresh**：add + commit 后直接 return favorite，但 favorite.create_at 可能还是 None（Python 默认值）而非数据库生成的时间戳——必须 refresh 后拿到最新数据。
3. **POST 参数误用 Query**：在 POST 路由中用 `news_id: int = Query(...)` 定义为查询参数，导致前端按请求体传参时收不到——POST 参数应定义为请求体 Schema。

## 详细解释
**为什么 POST 参数要用请求体？** RESTful 规范中，GET 和 DELETE 用查询参数/路径参数，POST 和 PUT 用请求体。请求体参数需要定义 Pydantic 模型（BaseModel），FastAPI 会自动从请求体中解析 JSON 并校验。

**唯一约束（UniqueConstraint）的作用**：favorite 表在 `(user_id, news_id)` 上创建了唯一约束，保证同一个用户对同一条新闻最多只有一条收藏记录。如果代码层面忘记检查就去 add，数据库层也会兜底报错。
