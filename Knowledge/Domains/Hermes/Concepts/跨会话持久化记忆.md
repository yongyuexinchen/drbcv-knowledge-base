# 跨会话持久化记忆

## 类型判定
Hermes Agent 通过自动维护 memory.md 和 user.md 两个文件，在多个独立会话之间持久化保留用户信息和工作环境的能力。

## 类比 ★
### 一句话比喻
就像公司前台有个聪明的接待员——你第一次来登记了姓名和偏好，下次再来她不用你再填表，直接认出你说"张先生，还是老位子对吧？"而且她还会默默更新你的档案，记下你新提到的喜好。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| memory.md | 办公室环境登记簿（操作系统、语言、代码规范） |
| user.md | 访客登记表（姓名、年龄、个人偏好） |
| 会话内记忆（Session Memory） | 你这次来访期间的短暂记忆 |
| 持久化记忆（Persistent Memory） | 档案室的永久记录 |
| Agent 自动维护文件 | 接待员默默更新登记表 |
| 新会话读取文件 | 下次来访前台翻查档案 |

## 是什么
跨会话持久化记忆是 Hermes Agent 的记忆系统，使 Agent 能在关闭重启后依然记住之前的对话信息。它通过两个 Markdown 文件实现：**memory.md** 记录客观环境信息（操作系统、编程语言、项目配置、代码规范等），**user.md** 记录用户个人信息（姓名、偏好等）。这两个文件在 Hermes 每次启动时被自动加载为系统提示词，在对话过程中由 Agent 自主决定哪些内容需要写入、更新或删除，无需用户手动干预。文件有大小上限（约 800KB/500KB），超限后自动压缩。

## 正例（≥2 个）
1. **用户姓名跨会话记忆**：会话 A 中说"我叫张三"→ Agent 自动在 user.md 中记录 → 关闭重启 Hermes → 会话 B 中问"我叫什么名字？"→ Agent 回答"你叫张三"。
2. **环境信息记忆**：会话 A 中说"系统环境是 Ubuntu，使用 Java 语言"→ Agent 写入 memory.md → 后续会话中 Agent 自动按 Ubuntu + Java 环境执行操作。
3. **自动更新**：会话 B 中说"代码规范改为 Google Style"→ Agent 自动更新 memory.md 中的代码规范条目。

## 反例/边界（≥1 个）
1. **会话内记忆（非持久化）**：默认对话中，Agent 记得同一会话内前面说过的话，但关闭 Hermes 重开后完全不知道之前的对话内容——持久化记忆就是为了解决这个跨会话失忆问题。
2. **分类错误**：Agent 有时会把客观环境信息（如"系统是 Ubuntu"）错误写到 user.md 中——这是个已知小问题，但不影响实际使用，因为两个文件都会被加载。

## 详细解释
记忆系统的工作原理：
1. **文件位置**：`~/.hermes/memory/memory.md` 和 `~/.hermes/memory/user.md`
2. **加载时机**：Hermes 启动时，两个文件内容被作为系统提示词注入
3. **写入时机**：对话中 Agent 自主决策——说出姓名 → 写入 user.md；描述系统环境 → 写入 memory.md
4. **维护方式**：完全自动——Agent 自主决定"记什么、改什么、删什么"
5. **用户显式控制**：可以说"忘掉我的名字"来删除特定记忆，Agent 会更新对应文件
6. **文件大小限制**：memory.md 约 800KB，user.md 约 500KB，超限自动压缩

操作演示：
- 删除 memory 文件 → 重启 Hermes → 说"我叫李四"→ user.md 自动生成
- 说"系统是 Windows"→ 如果和"用户"无关 → 应写入 memory.md（偶尔误写入 user.md）
- 后续新会话中 Agent 能正确回答用户姓名和系统环境
