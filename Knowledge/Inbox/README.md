# Inbox（暂存区）

> 定位：认知流入的 staging table——半成品想法先停这，不强行分类。
> 原则：能用约定解决的问题，不用结构解决；能局部修补的问题，不推翻架构。

## 为什么存在

真实认知流入不是"阅读→理解→分类→存储"，而是：

```
看到一个东西
    ↓
产生半成品想法
    ↓
未来可能有价值
    ↓
暂时不知道属于哪里
```

没有入口的两个坏行为：
- **行为A 强行分类**：这个属于哲学？心理？AI？Self？→ 输入成本过高，放弃记录
- **行为B 直接丢弃**："以后整理" → 然后消失

## 使用规则

1. 碎片想法直接丢进来（一个想法一个文件，不用管格式）
2. **定期清空**（每周）：Inbox 里的东西必须被处理——要么进 Authors/Domains/Self，要么进 Backlog，要么删掉
3. Inbox 不是仓库，是**过境区**——超过一周不处理 = 默认丢弃
4. 从 Inbox 正式入库时，顺手标注来源类型（见 schema 约定）

## 与 Backlog 的区别

- **Inbox**：半成品想法（"不知道属于哪"）→ 短期过境
- **Missing-Concepts-Backlog**：已确认的知识缺口（"知道缺什么"）→ 研究时触发补卡
