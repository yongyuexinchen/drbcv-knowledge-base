# 体系演化雷达（System Evolution Radar）

> 记录**我认为哪些系统正在失稳、迁移、重构**，以及我准备如何响应。
> 创建：2026-08-06 ｜ 定位修正：机会是结果，不是核心；核心是提前发现转换位置。

## 这是什么

三层架构，各管一事，不要混：

```
              世界
               |
       ----------------
       |              |
    KOS知识层       Radar演化层
       |              |
 "现在是什么"     "未来会怎么变"
       |
    Self认知层
       |
 "我为什么这样判断"
```

- **KOS** 记录：人类已经知道什么（明斯基假说、RAG原理、架构模式）
- **Self** 记录：我如何形成判断（我为什么认为AI会改变就业结构）
- **Radar** 记录：我认为哪些系统正在变化，以及我准备如何响应 —— **行动层**

Radar 的核心对象是 **Transition（转变）**，不是 Opportunity。
"2020 买新能源"事后叫机会，当时只是：能源系统迁移 + 政策方向变化 + 成本曲线下降 + 传统车企失速。
机会 = 结果偏见。Radar 只记录转换本身，布局动作在 Position 卡。

## 四实体

```
System（体系）→ Pressure（压力）→ Transition（转换点）→ Position（布局）
```

| 实体 | 定义 | 形式 |
|------|------|------|
| System | 长期运行的系统：组成 + 稳定机制 + 脆弱点 | `Systems/` 卡 |
| Pressure | 正在积累的系统压力（来源/指标/影响） | **正文结构，不单独建实体** |
| Transition | 压力突破阈值后系统进入什么状态。**一张卡=一个可监控的预测** | `Transitions/` 卡（核心） |
| Position | 判断正确时我该学什么/投什么/做什么项目/建什么关系 | `Positions/` 卡 |

Gap→Pressure 的原因：很多变化不是"缺口"而是多股力量叠加（模型能力+成本下降+利润压力+组织调整=AI替代白领）。

## 转换点状态机（每个状态有可观测进入判据，推进必须在卡上写依据）

```
seed → observing → strengthening → triggered → positioning → resolved
   ↘                                              ↘ invalidated（任意状态可进入）
```

| 状态 | 含义 | 进入判据 |
|------|------|---------|
| seed | 刚出现单一信号 | 一个信号源出现（如"Agent可能改变开发模式"） |
| observing | 多信号源支持 | ≥2 个独立信号源，指标可观测 |
| strengthening | 越来越明显 | 指标连续 2 期增强，且无反证 |
| triggered | 关键阈值突破 | 卡内 trigger 字段量化条件满足 |
| positioning | 开始行动 | Position 卡激活，动作有截止时间 |
| resolved | 结果出来 | 转换完成 / 机会兑现或错失 |
| invalidated | 判断失效 | 卡内 invalidation 条件出现，记录原因，不删卡 |

## 转换点卡模板

```yaml
---
type: transition
system: "[[体系名]]"
status: observing            # 6态之一
trigger: "可观测量化阈值"
invalidation: "出现则失效"     # ← 铁律：无失效条件 = 无法证伪 = 不是预测
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

## 前提（Premises）      # CAO 铁律：无前提不成立
## 现状
## 压力（Pressure）      # 固定三字段
### 来源
### 指标
### 影响
## 触发阈值
## 转换方向
## 时间窗口
## 失效条件
## 布局 → [[对应Position卡]]
```

## 第一批五个体系（不贪多）

1. **AI产业体系** — 职业输入侧（Agent/模型成本/开源/企业采用）
2. **软件工程体系** — 吃饭的手艺（编程范式/后端岗位/架构趋势）
3. **中国经济体系** — 经济机器怎么转（实体+政策：房地产/人口/财政/利率政策）
4. **资本市场体系** — 钱往哪流（价格+资金：流动性/周期/资产迁移）
5. **个人成长体系** — 自己也是一个系统（学历/技能/项目/求职）

边界纪律：利率政策→中国经济；DR007资金面→资本市场。一个压力只记一处，跨体系在正文交叉引用。

## 与 Self 的闭环（个人战略操作系统）

```
世界变化 → Radar（哪些系统在变？）→ Self（我如何理解和行动？）
    → Project（我如何进入这个变化？）→ Experience → 更新 Self
```

## 维护纪律

1. 转换点卡必须有失效条件；状态推进必须写**依据**（哪个指标变了）
2. **每周五巡检**（绑定 weekly_check 习惯）：逐卡推进状态机 + 更新信号 checkbox
3. triggered 后 24h 内激活对应 Position 卡，动作必须带截止时间
4. invalidated 不删卡，记录原因（失败也是资产）
5. 不追求数量：5 体系起步，扩体系要问"我和它有什么利益相关"
6. git 纪律：本目录单独 `git add Radar/`，禁 `-A`（单仓库混跑多任务）
