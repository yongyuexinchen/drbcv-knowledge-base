# 体系演化雷达（System Evolution Radar）

> 个人认知演化实验系统的**演化监控模块**（总览见 [[认知演化实验系统-总览]]）。
> 记录**我认为哪些系统正在失稳、迁移、重构**，以及我准备如何响应。
> 创建：2026-08-06 ｜ 定位：**个人版系统动力学推演引擎**（不是机会收集箱，不是趋势追踪器）

## 理论底座（哲学源头，2026-08-06 确认）

Radar 不是从零设计的——它有两个哲学源头，同属一套底层思想：

**源头一：混沌-确定性循环**（见 [[确定性是压缩模型_混沌是更新机制]]）

```
混沌 → 人类提取规律 → 确定性 → 建立体系文明 → 路径依赖僵化 → 新变量进入 → 新混沌
```

- KOS = 保存已提取的确定性
- Self = 记录观察者如何形成确定性
- **Radar = 监控确定性何时被混沌突破**（本模块）

对应关系：前提三（体系可被打败）← 循环的"僵化→新变量"环节；disruption 字段 ← "改变规则空间/让优化目标失效"；purpose 字段 ← "体系最初解决什么问题，现在还能解决吗"。

**源头二：泰勒展开历史观**（见 [[泰勒展开历史观_历史是体系的局部展开]]）

历史不是事件列表，是体系在不同尺度下的**局部展开**。Radar = 泰勒历史观的工程化：研究寻找"体系函数"，Radar 监控"函数导数变化"——当前状态/一阶趋势/二阶趋势变化/高阶黑天鹅 → 转换窗口。

**转换卡 = 局部历史求导模型**（2026-08-06 定稿）：

```
状态变量变化 + 压力积累 + 临界点 = 相变
```

例：AI工程师转换——状态变量（学历/代码能力/项目经验/市场需求），当供需差超过阈值 → 职业状态转换。

研究协议见技能 `history-system-analysis`（结构比较 + 极限还原 + 相变点 + 保留尺度）。

## 第一性原理（2026-08-06 用户提出，三条前提）

1. **高维系统对低维系统具有短期预测能力**：宏观长期不可预测，短期可预测。
   → Radar 的单位不是"预测未来"，而是"**监控当前状态，在有限窗口内判断变化方向**"。
   → 长期判断 = `scenario`（场景），短期判断 = `forecast`（预测）。状态机判据只依赖短期可观测指标。
2. **任何体系都有目的性**：存在本身为解决特定矛盾。**把握存在目的是推演体系变化的关键**；不知目的可通过历史运作反推。
   → 目的反推验证纪律：反推的目的必须能生成可证伪预测——"如果目的是 X，条件 Y 出现时体系应做 Z"。兑现→推断有效；落空→推断作废。禁止 just-so story。
3. **体系可以被打败且失效**：对确定且牢固的体系，引入混沌是最好的办法。
   → 不要在对方规则内竞争，改变状态空间（汽车不是更好的马车）。disruption 只记录**攻击体系目的实现方式**的外部变量，其他不录。

## 核心模型（四实体 + v2 深度字段）

```
             System
                |
        ----------------
        |              |
     Purpose       Structure
        |
        ↓
    Contradiction（核心矛盾）
        |
        ↓
    Pressure（压力：来源/指标/影响）
        |
        ↓
   Transition Point（转换点 = 相变点）
        |
   ----------------
   |              |
Internal      External Chaos
Evolution     Disruption
   |
   ↓
Position（布局）
```

| 实体 | 定义 | 形式 |
|------|------|------|
| System | 长期运行的系统：**目的** + 结构 + 核心矛盾 + **v2深度字段** | `Systems/` 卡 |
| Contradiction | 体系存在的目的所对抗的矛盾（目的无法实现时=系统要变） | 体系卡字段 |
| Pressure | 正在积累的压力（来源/指标/影响）——**变化的前兆** | 正文结构，不单独建实体 |
| Transition | 压力突破阈值后系统进入什么状态。**一张卡=一个可监控的短期预测** | `Transitions/` 卡（核心） |
| Position | 判断正确时我该学什么/投什么/做什么项目/建什么关系 | `Positions/` 卡 |

## 体系卡模板 v2（2026-08-06 深度字段定稿）

```yaml
---
type: system
name: "体系名"
purpose: "存在目的（缓解什么矛盾）"       # ← 第一性原理字段
core_contradiction: "目的对抗的核心矛盾"
disruption: "攻击目的实现方式的外部混沌"   # 只记攻击目的的，其他不录
death_drive_normal: "死亡驱力下的正常结构表现（可选·人文体系）"   # ← 2026-08-07 新增：体系在生存威胁下的'正常'行为范式 = 死亡恐惧的结构化表达
weakness: "弱点/脆弱点（明斯基式积累）"
alternatives: "同级系统（对比替代性）"
supersystem: "上级系统（上级视角有方向性）"
high_dim_view: "高维观察（站在高维才有短期预测，必须可证伪）"
created: YYYY-MM-DD
---
# 体系名
## 存在目的（Purpose）
## 核心矛盾（Contradiction）
## 外部混沌（Disruption）
## 死亡驱力下的正常结构表现（可选·人文体系）
## 组成
## 稳定机制
## 弱点（脆弱点积累）      # Pressure 前兆
## 同级系统（替代性对比）
## 上级系统（当前状态 + 短期预测）
## 高维观察（当前状态 + 短期预测，可证伪）
## 泰勒展开（结构比较 + 调研报告）
## 下级系统（协同监控，每个带当前状态+短期预判）
## 监控指标
## 转换点（Transitions/）
```

字段纪律：
- **死亡驱力字段（2026-08-07 用户定稿，GPT 理论化）**：所有结构都会在死亡压力下表现出它的专属"正常"行为——王朝生命受威胁时的反应、公司危机时的裁员、个人的结婚生子；"正常"随时代变化（德勒兹：资本主义下的"记账"和封建王朝下的"记账"不同——同一件事死亡对象不同结构不同）。死亡是所有人文存在的课题。**暂时限定人文体系**（国家/王朝/公司/组织/个人），工程体系暂不加。**分析模板三件套**（调研人文体系时按此展开）：①生存主体（谁正在避免死亡？死亡威胁是什么——个体/家族/组织/制度/文明/意义六层死亡谱系）②死亡信号（结构感知到什么危险→对应的"正常"反应清单）③反应（正常化行为=结构视角的求生）。核心问题："它害怕什么死亡，因此必须这么做？"——比利益分析更接近底层。
- **上级系统只记直接相关的 1-2 层**（防无限回归），必须带当前状态 + 短期预测
- **高维观察必须可证伪**（带短期预测），否则是"站在高维看"的空话
- **泰勒展开**：结构比较（目的/结构/约束/反馈/失效方式）+ 详细调研（可用 agent 执行，报告收录进 `Research/Reports/` 并在本字段链接）
- **下级系统**：体系拆解为可监控的子系统（如 AI 产业=模型商品化/Agent劳动力化/企业转型/就业重构/记忆机会），每层带当前状态+短期预判
- 🔴 **协同原则（2026-08-06 用户定稿）**：**系统并不孤立存在，它与其他系统越是紧密，能造成的影响越大**——体系卡之间、上下级之间必须互链状态与短期预判；一个系统的转换点要检查它在下级/同级/上级的连锁效应（例：Agent 劳动力化 → AI 就业市场重构 → 个人成长体系窗口）

## 剧本层（Scenarios/，2026-08-06 新增）

> **定位**：体系的"可能性空间"——对未来函数的几个局部展开（泰勒思想：当前点+一阶趋势+二阶转折+高阶混沌）。
> **用户洞察**：KOS 是工程师视角（卡片/字段/状态机），Scenario 是**人类接口**（剧本/角色/演化链）——最容易被人理解的一层。

### 概率生成机制（贝叶斯工程化，禁止拍脑袋）

```
第一步 结构先验：历史样本集给出的基准概率（必须声明样本集——换样本必须重算先验）
  ↓
第二步 压力修正：体系卡 Pressure/弱点/优势 → ±修正量（每项写依据）
  ↓
第三步 信号更新：转换卡 trigger / S1-S5 → 概率跳变（每周巡检，单信号±10%，记录依据）
= 可追踪、可回查的概率，不是数字幻觉
```

### 三剧本模型（每体系 1 组，不超过 3 个）

- **剧本A 主路径**：当前趋势延续（一阶）
- **剧本B 压力路径**：系统阻力→转折（二阶）
- **剧本C 混沌路径**：混沌变量入场→规则空间改变（高阶，天然不可证伪，只作提醒层）

### 模板（每体系一组 A/B/C 剧本）

```yaml
---
type: scenario
system: "[[体系卡]]"
window: long_term      # 剧本=长期判断的合法容器（>24月），不驱动状态机
created:
updated:
---
## 概率生成机制（先验→压力修正→信号更新，含样本集声明）
## 剧本A：主路径（概率 + basis + 演化链 + 关键节点 + 证伪条件）
## 剧本B：压力路径
## 剧本C：混沌路径
## 更新日志（事件→概率±→依据）
```

### 纪律

- **数量**：只给有活跃转换卡的体系建剧本组（当前 3 组：中国经济/AI产业/个人成长），防剧本爆炸
- **窗口**：剧本=长期判断的合法容器，不驱动状态机（补上了窗口纪律的空白）；概率更新频率按窗口区分
- **不重复**：剧本的"关键节点"引用转换卡，不复制内容（防双重维护）
- **更新**：每周五巡检校准；不校准的剧本=故事会
- **概率来源等级**（2026-08-06 评审新增——不同概率不能混在一起，标注每个概率的性质）：
  - **L1 统计概率**：来自历史样本（如"日本泡沫后30年停滞概率"）——样本集声明
  - **L2 结构概率**：来自因果链（如"中国房地产模式不可持续概率"）——结构分析
  - **L3 主观贝叶斯**：来自个人判断（如"AI Agent 3年内成主流概率"）——个人判断+信号更新
  - 规则：每个概率标注等级；L3 概率不得伪装成 L1（防"70%概率"但不知道性质）
- **反身性**：个人成长剧本组的概率会被你的行动改变——它的意义不是预测，是让你看清每个决策在移动哪个概率

## 转换点状态机（每个状态有可观测进入判据，推进必须在卡上写依据）

```
seed → observing → strengthening → triggered → positioning → resolved
   ↘                                              ↘ invalidated（任意状态可进入）
```

| 状态 | 含义 | 进入判据 |
|------|------|---------|
| seed | 刚出现单一信号 | 一个信号源出现 |
| observing | 多信号源支持 | ≥2 个独立信号源，指标可观测 |
| strengthening | 越来越明显 | 指标连续 2 期增强，且无反证 |
| triggered | 关键阈值突破 | 卡内 trigger 量化条件满足 |
| positioning | 开始行动 | Position 卡激活，动作有截止时间 |
| resolved | 结果出来 | 转换完成 / 兑现或错失 |
| invalidated | 判断失效 | 卡内 invalidation 条件出现，记录原因，不删卡 |

## 系统失效模式（FMEA，2026-08-06 评审新增）

> 工程化失效模式分析——不盯"系统会不会坏"的抽象担心，盯**可识别的失效症状**：

| # | 失效模式 | 症状 | 修复 |
|---|---------|------|------|
| FM-01 | 信息吞噬 | 输入速度 > 理解速度，Inbox 爆炸 | 降低采集频率，卡数量让位于消化质量 |
| FM-02 | 模型幻觉 | Self 里的观点越来越像事实 | 强制分层：事实层/解释层/预测层分离 |
| FM-03 | 过拟合历史 | 所有新事件都能找到历史类比（日本→中国/互联网→AI） | 泰勒比较强制"比差异不比相同"+ 差异变量字段（已有护栏） |
| FM-04 | 维护成本爆炸 | 维护系统 > 使用系统 | 模块存在价值 = 新增认知收益 - 维护成本，为负即砍 |

> 巡视频率：每周五巡检时顺带自查 FM-01~04。

## 实验指标（本模块的考核）

1. **预测命中率**：转换卡的 trigger/失效条件是否被现实兑现（2027.2-3 考研结算）
2. **认知修正速度**：状态机推进是否基于信号（不是感觉）
3. **行动转化率**：triggered 后 Position 卡是否真的激活并执行

## 维护纪律

1. 转换点卡必须有失效条件；状态推进必须写**依据**（哪个指标变了）
2. **每周五巡检**（绑定 weekly_check）：逐卡推进状态机 + 更新信号 checkbox + Self 周期复盘
3. triggered 后 24h 内激活 Position 卡，动作带截止时间
4. invalidated 不删卡，记录原因（失败也是资产）
5. 不追求数量：5 体系起步；长期判断只进 scenario，不进状态机
6. **雷达审视雷达**：Radar 也是体系。目的=在转换前获得认知与进入机会；短期失效模式=**烂尾**（状态机无人推进/维护成本>产出，可预防）；长期=僵化（窗口外，不设防）
7. **不横向扩展**：新需求先进 schema 深化（v2 字段），不新增 OS 模块
8. git 纪律：本目录单独 `git add Radar/`，禁 `-A`（单仓库混跑多任务）
