# 机会雷达（Radar）

> 记录体系的**缺口**与**转换点**，在转换发生之前获得认知与进入的机会。
> 创建：2026-08-06 ｜ 起步范围：宏观金融 + AI产业 + 个人知识体系（用户拍板）

## 这是什么

KOS 回答"什么是对的"（后视镜/解剖课本）；雷达回答"**什么时候会变，变了怎么办**"（前挡风玻璃/监护仪）。
雷达是 AI认知OS 的**前瞻层**：记忆层管已发生，雷达管将要发生。

## 四个实体

```
体系(System) ──有缺口──> 缺口(Gap) ──累积触发──> 转换点(Transition) ──产生──> 机会(Play)
                                                                          ├─ 认知机会（先看懂）
                                                                          └─ 进入机会（先上车）
```

| 实体 | 定义 | 存放 |
|------|------|------|
| 体系 | 被监控的对象（结构+核心机制+关联知识） | `Systems/` |
| 缺口 | 体系内的弱点/裂缝（未塌，但结构在变弱） | 体系卡内清单 |
| 转换点 | 缺口累积到阈值触发的状态切换，**一张卡=一个可监控的预测** | `Transitions/` |
| 机会 | 转换点的认知/进入动作 | 转换点卡内字段；成规模后建 `Plays/` |

## 转换点状态机

```
observing（观测中）→ triggered（触发）→ executing（执行中）→ completed（完成）
                                          ↘ invalidated（失效）
```

- `observing`：缺口在累积，信号未到阈值
- `triggered`：触发阈值已满足 → **24h 内更新认知/进入机会或写执行计划**
- `completed`：转换已发生，复盘机会是否兑现
- `invalidated`：失效条件出现 → 记录原因，不删卡（失败也是资产）

## 转换点卡模板

```yaml
---
type: transition
system: "[[体系名]]"          # 挂到体系卡
status: observing            # observing | triggered | executing | completed | invalidated
trigger: "可观测的触发阈值"     # 什么情况算"转换开始"
invalidation: "出现则失效"     # ← 铁律：无失效条件 = 无法证伪 = 不是预测
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

## 前提（Premises）      # 判断成立的条件（CAO 铁律：无前提不成立）
## 现状
## 缺口信号（Signals）   # 先行指标，必须可观测
## 触发阈值
## 转换方向
## 时间窗口
## 认知机会
## 进入机会
## 失效条件
```

## 维护纪律

1. **每张转换点卡必须有失效条件**——没有失效条件的"预测"是自我感动
2. **不追求数量**：监控 3 个体系好过监控 20 个；起步三类，扩体系要问"我和它有什么利益相关"
3. **状态机不冻结**：巡检时逐卡推进状态（结合 weekly_check 每周看盘习惯）
4. **触发即行动**：`triggered` 后不更新的卡，等于警报响了不跑
5. **失败不删卡**：`invalidated` 卡记录原因，供下一次转换参考
6. **git 纪律**：本目录单独 `git add Radar/` 提交，禁 `-A`（单仓库混跑多任务）
