# AI岗位：从"会用工具"转向"会造 Agent"

## 前提（Premises）

- 大模型 API 成本持续下降，调用不再是壁垒（2026 已部分兑现）
- Agent 框架（LangGraph 等）成熟度越过"可用线"，非专家也能编排
- 企业从"试用 AI"进入"用 AI 改造流程"阶段，需要的不再是提示词而是工作流

## 现状

- 岗位 JD 实测：Agent 开发 73%、RAG 66%（全文扫描非标题匹配）；"记忆系统"类岗 25-50K 区间
- 技能关键词统计（Python 72%/Java 42%）≠ 实际工作内容（Agent/RAG 为主）——市场要的和自己会的有差距
- 本人：SQL 基础 + Python 薄弱，跟课 FastAPI 中，无 Agent 工程实操

## 缺口信号（Signals）

- [x] JD 中 Agent/RAG 出现率过半（已观测到 55-73%）
- [ ] "调 API"型初级岗薪资滞涨或 JD 要求上升（含 Agent 经验）
- [ ] 主流云厂商默认 Agent 产品上线（待观测）
- [ ] 记忆系统岗位从个位数增长到常见（25-50K 区间）

## 触发阈值

- 触发：云厂商默认 Agent 工作流产品 + JD 关键词率 > 70% 同时满足
- 部分触发：记忆系统岗位数量连续 2 个月环比增长 > 30%（单独触发"记忆系统"子计划）

## 转换方向

- 低端：纯调 API/写提示词的岗位被 Agent 平台挤压，薪资滞涨
- 高端："定义问题 + 编排工作流 + 给 Agent 加记忆"成为核心能力
- 你的位置：从"会用"区间迁入"会造"区间，目标岗=给 Agent 加记忆的公司（25-50K）

## 时间窗口

- 判断：转换进行中（不是未来时），窗口 12-24 个月——现在入场仍是早期，两年后是红海

## 认知机会

- 研究"给 Agent 加记忆"的工程实现（RAG/记忆架构/会话状态管理）——这是 25-50K 岗的入场券
- 理解 Agent 工作流本质（LLM 定每一步 vs 脚本定每一步），用代码写工作流
- 本地优先的私有化记忆方案（对应终极目标 AI 伴侣 + 差异化竞争力）

## 进入机会

- 短期：小厂上牌桌——进 AI 应用开发岗攒 Agent 实战（20-25K 区间），不要求一步到位
- 中期：带 1-2 个 Agent 实战项目（含记忆模块）跳 25-50K 记忆系统岗
- 储备：跟课完成后用 FastAPI + 一个真实 Agent 项目做跳板（今日头条项目可加记忆功能升级为展示项目）

## 失效条件

- Agent 商业化证伪：头部 Agent 产品营收兑现率持续低于预期 2 年 → 判断作废，回到"AI 辅助工具"定位
- 框架碎片化停滞：LangGraph 等主流框架 1 年无实质演进，生态分裂 → "会造"技能贬值，改盯"会训/会部署"
- 若 2027 年 JD 关键词率回落 < 50% → 转换反向，立即复查前提
