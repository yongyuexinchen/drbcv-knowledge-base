# AI岗位：从"会用工具"转向"会造 Agent"

> 跨体系：[[软件工程体系]]（编程范式迁移）／[[个人成长体系]]（职业身份跃迁）

## 前提（Premises）

- 大模型 API 成本持续下降，调用不再是壁垒（2026 已部分兑现）
- Agent 框架（LangGraph 等）成熟度越过"可用线"，非专家也能编排
- 企业从"试用 AI"进入"用 AI 改造流程"阶段，需要的不再是提示词而是工作流

## 现状（状态机依据）

- **status: observing**（2026-08-06 判定）
- 依据：JD 全文扫描实测 Agent 开发 73% / RAG 66%（≥2 独立信号源）；技能关键词（Python 72%）≠ 实际工作内容（Agent/RAG）
- 本人位置：SQL 基础 + Python 薄弱，跟课 FastAPI 中，无 Agent 工程实操

## 压力（Pressure）

### 来源

模型能力提升 + API 成本下降 + 企业利润压力（要降本）+ 组织结构调整（AI 进流程）

### 指标

- [x] JD 中 Agent/RAG 出现率过半（55-73%，已观测）
- [ ] 代码生成质量（模型能力曲线）
- [ ] Agent 可靠性/企业采用率（产品侧）
- [ ] "调 API"型初级岗薪资滞涨或要求上升

### 影响

初级程序员岗位 / 传统外包 / 重复劳动 → 低端被平台挤压；定义问题+编排工作流能力升值

## 触发阈值

- 触发：云厂商默认 Agent 工作流产品 + JD 关键词率 > 70% 同时满足
- 部分触发：记忆系统岗位数量连续 2 个月环比增长 > 30%（单独激活"记忆系统"子布局）

## 转换方向

- 低端：纯调 API/写提示词的岗位被 Agent 平台挤压，薪资滞涨
- 高端："定义问题 + 编排工作流 + 给 Agent 加记忆"成为核心能力
- 你的位置：从"会用"区间迁入"会造"区间，目标岗=给 Agent 加记忆的公司（25-50K）

## 时间窗口

- 判断：转换进行中（不是未来时），窗口 12-24 个月——现在入场仍是早期，两年后是红海

## 失效条件

- Agent 商业化证伪：头部 Agent 产品营收兑现率持续低于预期 2 年 → 回到"AI 辅助工具"定位
- 框架碎片化停滞：主流框架 1 年无实质演进，生态分裂 → "会造"贬值，改盯"会训/会部署"
- 2027 年 JD 关键词率回落 < 50% → 转换反向，复查前提
