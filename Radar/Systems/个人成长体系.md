# 个人成长体系

> 观察者即系统：世界演化 → 你演化，两套演化必须同步读。

## 存在目的（Purpose）

把"我"转化为目标状态：AI工程师（就业）+ 认知优势（AI认知OS）。
判断基准：目标状态有明确验收（2027 前进入 AI 应用开发岗带 Agent 实战）；目的无法推进（长期零进展）= 体系失效信号。

## 核心矛盾（Contradiction）

目标状态 vs 当前约束：学历门槛 + 经验不足 + Python 薄弱 + 四线并行精力有限。
转换判断基准：约束能否在窗口期内解除（跟课完成→项目→求职的接力）。

## 外部混沌（Disruption）

- AI 让"非科班转 AI"窗口提前关闭（转换太快）或突然打开（需求爆发）
- 考研政策变化（非全招生变动）
- 行业寒潮（AI 岗收缩）
- 只录攻击目的实现方式的变量，其他不录

## 组成

- **学历通道**：备考中山大学非全大数据研究生
- **技能通道**：SQL（还行）> Python（薄弱）→ FastAPI 跟课中（今日头条项目 day03-06）
- **项目通道**：今日头条项目（跟课）→ 待升级为展示项目
- **求职通道**：深圳 AI 应用开发 20-25K → 目标 25-50K 记忆系统岗
- **认知通道**：KOS（记忆层）+ Radar（前瞻层）+ Self（反思层）

## 稳定机制（目标态）

学习 → 技能 → 项目 → 求职 → 岗位实战 → 反馈学习（正循环）

## 压力（当前系统状态）

- **学历门槛**：非科班（本科动画）+ 本科背景 vs 计算机科班竞争者
- **经验不足**：工作 1 年，无前后端/AI 工程实战
- **代码基础薄弱**：Python 弱是最短木板
- **四线并行**：备考 + 学代码 + 做项目 + 找工作，精力是硬约束

## 转换（目标态）

```
当前系统: 非科班 → AI工程师
压力:     学历门槛 + 经验不足 + 代码薄弱
转换:     完成项目 + 研究生(非全) + 岗位经验 → 职业身份跃迁
布局:     RAG项目 + 开源 + 求职（→ Positions/）
```

## 监控指标

- 学习进度：以课+题实况为准（不是卡数）
- 缺卡 Backlog 数量变化（KOS 内置缺口探测器）
- 每周时间分配（备考 vs 代码 vs 项目）
- KOS 生产验证产出（跨域桥卡、新概念）

## 转换点（Transitions/）

- ✅ 考研分流-学历资产化还是直接进入AI工程市场（2026-08-06，用户亲手建的第一张真实样本）
- 待建候选：代码能力-从跟课转独立开发、职业身份-非科班转AI工程师
