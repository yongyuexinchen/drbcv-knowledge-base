# 软件工程体系

## 存在目的（Purpose）

以可接受成本把需求转化为可运行软件。核心矛盾：需求增速 > 工程师增速。
外包体系的目的是"低成本人力完成数字化需求"——AI 降低代码生产成本时，**目的没消失，实现方式被攻击**。

## 核心矛盾（Contradiction）

软件需求增长速度 > 人类工程师增长速度。这个矛盾长期存在，每次技术跃迁（高级语言→框架→低代码→Agent）都是对这个矛盾的缓解尝试。

## 外部混沌（Disruption）

- Agent 改变软件生产关系——从"人写代码"到"人定义问题+机器生成"，攻击"人力为核心资源"
- 开源生态压缩商业工具生存空间——攻击工具链收费结构
- 只录攻击目的实现方式的变量，其他不录

## 组成

- **编程范式**：CRUD 时代 → Agent 工程时代（LLM 定每一步 vs 脚本定每一步）
- **后端岗位**：Java（42%）/ Go（23%）岗位要求，Python 生态在 AI 侧；岗位结构随 Agent 化迁移
- **架构趋势**：单体 → 微服务 → Agent 工作流编排；记忆/状态管理成为新基础设施
- **工程方法**：TDD、重构、代码评审（个人：系统性调试、灰度迁移、验证铁律）

## 稳定机制

需求复杂度上升 → 抽象层出现 → 工具链成熟 → 岗位技能迁移 → 新范式固化

## 弱点（脆弱点积累，Pressure 前兆）

1. **CRUD 技能贬值**：低端增删改查被 Agent 平台挤压，薪资滞涨
2. **范式切换断层**：旧范式工程师的知识在新范式下失效，切换期是能力真空
3. **个人技能栈**：Python 薄弱 + 前后端无基础 → 范式切换期双重劣势（跨体系：[[个人成长体系]]）
- 积累路径：只会CRUD → 还能靠经验工作 → Agent化交付普及 → 初级岗位收缩 → 技能风险暴露

## 同级系统（替代性对比）

| 系统 | 承接需求 | 替代关系 |
|------|---------|---------|
| 低代码/无代码平台 | 简单业务需求 | 挤压初级开发岗位 |
| 外包 | 成本敏感需求 | 与内部开发竞争，同样被Agent冲击 |
| 海外远程 | 时区/成本套利 | 与本地开发竞争 |

## 上级系统（当前状态 + 短期预测）

**IT产业体系**
- 当前状态：需求持续增长，但交付方式重构中（人写 vs 机器生成）
- 短期预测：Agent 化交付从辅助走向主力（12-24 个月）——"会造 Agent"从加分项变基础项
- 方向性：交付效率提升不可逆，工程师角色上移（定义问题/架构/评审）

## 高维观察（当前状态 + 短期预测，可证伪）

视角：**生产力工具演进**——手工 → 工具 → 半自动 → 自动（每次跃迁，人类角色上移一层）。
- 当前状态：半自动向自动过渡（Agent 写代码，人做定义与验收）
- 短期预测："人写代码"占比下降、"人定义+机器生成"占比上升（可证伪：初级编码岗位 JD 要求从"熟练X语言"转向"会用Agent工具链"）
- 失效条件：若 Agent 生成质量长期不可验收（可靠性停滞），自动化解冻，人类角色不再上移

## 泰勒展开（结构比较 + 调研报告）

- 结构比较对象：**范式切换史**——COBOL→面向对象→框架→低代码→Agent：每次切换的失效方式（旧技能贬值）与新系统生成机制（新抽象层）同构
- 状态变量（可求导）：交付成本 / 抽象层高度 / 岗位技能要求——当前：成本下降加速（二阶导为正）
