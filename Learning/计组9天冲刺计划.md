> 起点：计组 64 张骨架卡（课 0% 题 0%）；OS 无卡无课无题（从零）

> 核心决策：**计组先行 9 天（极限压缩），OS 殿后 16 天（从容）**——不是随便排的，见下方"衔接红利"

## 〇、为什么这个顺序（先计组后 OS）

计组与 OS 约 30% 内容重叠，且计组在前 = 每重叠知识点隔一天见第二遍（间隔复习红利）：

```
计组第3章 虚拟存储器（页表/TLB） ──→ OS第3章 内存管理（页式/段式/置换）
计组第7章 中断/DMA            ──→ OS第5章 IO管理（中断处理/设备驱动）
计组第4章 指令/特权级          ──→ OS第2章 进程/系统调用
```

先难后易：计组是 408 公认最难之一，啃完后 OS 会感觉轻松一半。

## 一、第一阶段：计组（8/6–8/15，9 天 × 6h = 54h）

### 核心认知翻转：卡是地图，不是产出

别人从零学计组是黑灯摸路。你有 64 张骨架卡——**你知道每章有什么、重点在哪**。这就是优势。

学习方式 = 带图听课：

```
翻卡看地图(5min) → 听课对照卡(3h) → 做题(1.5h) → 修卡变自己的话(0.5h) → 复盘(0.5h)
```

每章结束时，卡从"AI 的话"变成"你的话"——**修卡动作不能省，这是知识过脑的唯一动作**。

### 计组时间账（54h）

| 项目 | 小时 | 说明 |
|---|---|---|
| 听课 | 26 | 核心章 1.5x 认真跟，中频章 2x，低频章 0 |
| 做题 | 15 | 选择题为主 + 必考大题 |
| 修卡 | 4.5 | 每天 0.5h |
| 复盘 | 3 | 每天 0.5h 答 3 问发 Hermes |
| 冗余 | 5.5 | 卡壳缓冲，留白是计划的一部分 |

### 计组砍课策略

| 章 | 处理 | 理由 |
|---|---|---|
| 1 概述 | **不听课**，看书 30min + 做题 | 常识性，性价比最低 |
| 2 数据表示 | 1.5x 全听（~6h） | 浮点/补码 = 必考 |
| 3 存储 | 1.5x 全听（~7h） | Cache+虚存 = 大题必考，最重 |
| 4 指令 | 2x 听（~3h） | 概念直白，倍速不损失 |
| 5 CPU | 1.5x 听核心：数据通路+控制器+流水线（~6h）；**跳过机器级表示** | 机器级表示≈汇编，预算养不起 |
| 6 总线 | **不听课**，看书+题（1h） | 考分最少 |
| 7 IO | 2x 听：中断+DMA（~3.5h） | 中断必考，DMA 大题常客 |

**战略性放弃**（不许回头补）：机器级表示（~5-8分）/ 硬布线细节（~2-3分）/ 总线定时（~2-3分）。放弃不是偷懒，是把时间投到 Cache/流水线/浮点。

## 二、第二阶段：操作系统（8/16–8/31，16 天 × 6h = 96h）

### OS 起点

- 知识库无 Operating-System 域 → **卡从零建**（约 40-50 张，沿用计组螺丝盒类比体系，但 OS 有自己的类比主场）
- 课源建议：王道 OS 基础课（1x 原速，预算够，不需要倍速赶）
- 计组刚学完 = 内存管理/中断/IO 已经见过一遍，OS 是二刷现场

## 三、全局时间线提醒（408 四门）

计组 + OS 到 8/31 结束，408 还剩**数据结构**和**计算机网络**两门：
- 你的知识库已有 Data-Structures 和 Computer-Network 域（有骨架卡？）——如果是，9 月补课会快很多
- 建议节奏：9 月过数据结构 + 网络（9/1-9/30），10 月 408 真题 + 二轮强化，11-12 月冲刺
- 这 26 天先不管那两门，但心里要有数：**9 月是下半场**

## 四、心态（两门连打的预防针）

- 计组 9 天是极限压缩 → 目标不是融会贯通，是"见过所有考点 + 必考大题会写"
- OS 16 天是稳扎稳打 → 目标是"理解和建卡并重"，PV 是唯一的硬骨头
- 两门中间 8/15 缓冲日 = 强制喘息点，不要跳过它直接开 OS
- 每天 6h 雷打不动，比偶尔 10h 更可持续——你是长跑不是冲刺
