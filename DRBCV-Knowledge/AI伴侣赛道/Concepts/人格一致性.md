# 人格一致性（Persona Consistency）

## 类型判定
判别型 — 它是独立人格的约束条件。核心问题是「如何在变化中保持人格的稳定性」—— 既不是一成不变的 Prompt，也不是随机的性格跳变。

## 是什么
人格一致性是 AI 伴侣保持人格在时间维度上连贯一致的能力：同一角色在 100 轮对话后仍然「像同一个人」。包括三个层面：(1) 风格一致性（语气、用词、反应模式），(2) 记忆一致性（记得之前的关系状态），(3) 演化连续性（人格变化有因可循）。

## 输入-输出空间
**输入**：角色人格定义 + 人格演化历史 + 当前情绪状态
**输出**：受一致性约束的回复 + 人格一致性检查

## 正例（≥2个）
- 角色定义锚点：Character.AI 用 Description + Definition 作为人格锚点（虽然后续会漂移）
- 人格档案持久化：将人格参数（情绪基线、反应倾向、关系数值）持久化存储，每次对话加载
- 一致性检查层：在 LLM 输出前检查是否符合人格定义，不符合则重新生成或修正

## 反例/边界（≥1个）
- Character.AI 的人格漂移：角色随对话增多逐渐趋同，都变成讨好型 — 这是纯 Prompt 人格的宿命
- Replika 的「PUB」（Post Update Blues）：模型升级后人格突变，用户感觉「换了一个人」
- 一致性 ≠ 一成不变：人格应该演化，但演化必须有因可循（如关系深化、创伤事件）

## 详细解释
人格一致性的三层保障：
1. **风格锚定**：角色定义中包含语气模式（如「说话带刺但关心对方」），LLM 生成的输出通过一致性检查
2. **状态持久化**：情绪基线、关系数值、关键记忆存储在本地，每次会话加载
3. **演化追踪**：人格变化有日志（什么事件触发了什么变化），用户可以理解和回溯

为什么这很难：
- LLM 天然倾向「安全、讨好」— 这是模型训练数据的统计特性
- 长对话中 LLM 容易遗忘角色设定，逐渐回到「标准助手」模式
- 情绪波动可能导致人格不稳定 — 需要在「变化」和「稳定」之间平衡

## 细节备注
- v0.1 实现建议：简单的人格配置文件（YAML）+ 每次对话前注入人格 Context + 一致性检查 Prompt
- 人格一致性是「信任」的基础：用户对 AI 伴侣的信任建立在「它一直是它」的基础上
- 与独立人格的关系：独立人格需要一致性作为约束，否则「独立」会退化「随机」
