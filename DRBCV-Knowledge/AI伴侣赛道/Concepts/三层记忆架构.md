# 三层记忆架构（Three-Layer Memory Architecture）

## 类型判定
连接型 — 它是连接短期上下文、中期摘要、长期画像的结构模式。三层协同解决了「对话连贯 + 跨会话回顾 + 用户画像积累」的递进记忆需求。

## 是什么
三层记忆架构是 AI 伴侣系统的事实标准记忆架构：
1. **短期记忆**：滑动窗口（最近 N 轮对话），保证即刻对话连贯性
2. **中期记忆**：LLM 摘要 + SQLite 存储，跨会话的要点回顾
3. **长期记忆**：向量检索（FAISS/Qdrant/Milvus）+ 语义召回，用户画像和事实性信息

## 输入-输出空间
**输入**：对话文本流
**输出**：
- 短期 → 注入 LLM 上下文的最近对话
- 中期 → 跨会话摘要文本
- 长期 → 向量检索返回的相关记忆条目

## 正例（≥2个）
- Memobase 的三层实现：短期（Session Buffer）→ 中期（User Profile）→ 长期（Vector Store）
- Shikigami Protocol 的自建三层架构：sliding window + summary cache + vector memory
- roleplay_chatbot 的记忆管道：context → compress → store → retrieve

## 反例/边界（≥1个）
- Character.AI / Replika 只有短期记忆（上下文窗口），无真正的跨会话记忆层
- 三层 ≠ 三层都要复杂：v0.1 可以中期用简单摘要，长期用 ChromaDB，不必追求完美
- 记忆不应该是「黑箱」：用户应该能看到 AI 记住了什么，有权修改/删除

## 详细解释
三层之间的数据流：
```
对话流 → 短期缓冲（最近 N 轮）
         ↓ 触发条件（对话轮次/时间/情感峰值）
         LLM 摘要 → 中期存储（SQLite）
                     ↓ 定期批处理
                     Embedding → 长期向量库（FAISS）
                                 ↓ 语义检索
                                 注入 LLM 上下文
```

关键设计决策：
- **触发条件**：什么时候生成摘要？（每 N 轮 / 每次对话结束 / 检测到重要事件）
- **摘要内容**：存什么？（事实、情感、关系变化、用户偏好）
- **召回策略**：怎么检索？（语义相似度 / 时间衰减 / 重要性加权）

## 细节备注
- 遗忘曲线：旧记忆需要定期召回才能保持，未被召回的记忆逐渐降低权重
- 记忆压缩：不是所有对话都值得记忆，需要过滤噪声
- 关系演化追踪：记忆不只是「事实」，还包括「关系如何变化」（从陌生 → 熟悉 → 亲密）
