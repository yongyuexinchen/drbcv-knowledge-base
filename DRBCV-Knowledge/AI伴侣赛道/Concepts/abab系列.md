# abab 系列大模型

## 类型判定
判别型 — MiniMax 自研的闭源大模型系列，是 Talkie/Glow/星野的底层引擎。中国少数同时拥有「自研基座模型 + AI 伴侣产品」的技术栈，模型能力直接决定 AI 伴侣产品天花板。

## 类比
**一句话比喻：** abab 系列就像 MiniMax 自己造的发动机——别人的 AI 伴侣用 OpenAI 的发动机，MiniMax 装自己的，好坏都是自己的。

| 维度 | 生活映射 |
|------|---------|
| 自研 vs 外购 | 自己造发动机 vs 买丰田发动机——自主但可能有差距 |
| 闭源黑盒 | 餐厅秘方——你知道好吃但不知道配方 |
| 迭代速度 | 手机系统更新——abab5→5.5→6→6.5→7，半年一版 |
| 与产品绑定 | iOS 只能在 iPhone 跑——abab 只服务 MiniMax 产品 |

## 是什么
abab 是 MiniMax（稀宇科技）自研的大语言模型系列，从 2023 年至今持续迭代。模型为闭源商用，仅通过 MiniMax API 对外提供，内部直接驱动 Talkie（海外 AI 伴侣）、Glow（国内角色聊天）、星野（AI 内容社区）三款产品。

## 与 AI 伴侣赛道的关系

```
abab 模型
  ├── 驱动 Talkie（海外）→ AI 角色聊天 + 虚拟礼物经济
  ├── 驱动 Glow（国内）  → AI 角色扮演 + 内容审查适配
  └── 驱动星野（社区）   → AI 内容生成 + UGC 生态
```

**关键点：** abab 的能力直接决定 Talkie/Glow 的对话质量天花板。如果 abab 在角色扮演、情感理解、长期记忆上不如 GPT-4/Claude，MiniMax 产品的用户体验就受限。

## 正例（≥2个）

- 自研可控：不需要给 OpenAI 交"模型税"，成本和定价自主
- 垂直优化：可以专门针对 AI 伴侣场景（角色扮演、情感对话）微调，通用模型做不到
- 快速迭代：半年一个大版本，发现问题可以直接改模型而非调 prompt
- 中国合规：国产模型更容易通过内容审查

## 反例/边界（≥1个）

- 闭源+云端：无法本地部署，用户对话数据全部经过 MiniMax 服务器（隐私黑洞）
- 质量差距：abab6.5 在通用 benchmark 上仍逊于 GPT-4o/Claude 3.5 Sonnet
- 生态封闭：不像 OpenAI 有插件和第三方工具链，开发者只能调 API
- 单一客户：模型只服务 MiniMax 自己的产品，外部使用有限

## 详细解释

### 为什么 MiniMax 要自研模型？

1. **成本**：Talkie 千万级用户，每天几亿次对话。用 OpenAI API 每月几千万美元。自研后边际成本接近零。
2. **垂直优化**：通用模型不懂"角色扮演"——不会撒娇、不会拒绝、不会吃醋。自研可以专门训练这些能力。
3. **政策风险**：中国监管要求 AI 模型备案+内容审查。用境外模型（OpenAI）有合规风险。

### 对少女项目的启示

- ❌ 不做自研模型——一个人训练不了基座模型
- ✅ 可以像 abab 一样做「垂直微调」——拿开源模型（Qwen/Llama）在角色扮演数据上 fine-tune
- ✅ abab 的快速迭代节奏值得学——先跑起来再优化，不做完美主义
- ✅ 本地推理 = abab 做不到的事 = 我们的差异化
