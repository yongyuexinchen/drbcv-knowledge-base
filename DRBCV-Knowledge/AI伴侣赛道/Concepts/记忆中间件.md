# 记忆中间件（Memory Middleware）

## 类型判定
判别型 — 它代表记忆系统从「应用内置功能」到「独立基础设施」的趋势。核心判断：记忆不是某个应用的功能，而是可被任何 AI 伴侣前端调用的独立服务。

## 是什么
记忆中间件是将长期记忆能力从具体应用中解耦，作为独立中间件服务提供：任何 AI 伴侣前端（SillyTavern、Airi、自定义 App）通过标准 API 调用，获得用户画像存储、语义检索、记忆压缩等能力。代表项目：Memobase。

## 输入-输出空间
**输入**：对话文本 + 用户 ID + 记忆查询请求
**输出**：记忆存储确认 + 语义检索结果 + 用户画像

## 正例（≥2个）
- Memobase（2.8k⭐）：专为 AI 伴侣设计的用户画像长期记忆中间件，三层架构
- Memvid（16k⭐）：视频记忆中间件，展示了记忆系统的独立化趋势
- LangChain Memory 模块：通用记忆抽象，证明记忆可以独立于应用

## 反例/边界（≥1个）
- 应用内置记忆（Character.AI 的无记忆、Replika 的弱记忆）：无法复用，每个应用重复造轮子
- 记忆中间件 ≠ 知识库（如 Pinecone/Weaviate）：通用向量数据库不做「用户画像」「关系追踪」等专业能力
- 记忆中间件需要解决隐私信任问题：如果中间件在云端，用户同样有隐私顾虑

## 详细解释
记忆中间件的三层价值：
1. **降低开发门槛**：新 AI 伴侣项目不需要自己实现记忆系统，调 API 即可
2. **标准化**：记忆格式、检索接口标准化后，用户可以在不同前端间迁移记忆
3. **专业化**：专注记忆的团队比通才团队做得更好（类比数据库 vs 应用内置存储）

开源生态中的记忆项目对比：
| 项目 | Stars | 定位 |
|------|-------|------|
| Memobase | 2.8k | AI 伴侣用户画像 |
| Memvid | 16k | 视频记忆 |
| LycheeMem | 1.1k | 轻量记忆 |
| nocturne_memory | 1.3k | 记忆服务器 |

记忆层的「蓝海」特征：最大项目仅 2.8k⭐，远小于前端层（SillyTavern 30k⭐），也小于 LLM 推理层（Ollama 100k+⭐）。这是少女项目可以建立技术壁垒的领域。

## 细节备注
- 少女项目策略：companion-core 自带记忆模块，不需要依赖外部中间件
- 但记忆作为独立服务的思路值得借鉴：模块化设计 + 标准化接口
- 隐私考量：companion-core 的记忆模块默认本地运行，用户的记忆不离开设备
