# 宏观传导发现引擎（Macro Conduction Discovery Engine）

## 类型判定
混合型 — 既是系统架构设计（procedure），也是设计哲学（discriminant）：用数据做锚、叙事做帆，自动发现跨资产的因果传导链。

## 类比 ★
### 一句话比喻
传统宏观研究像老中医把脉——凭经验说「美债收益率涨了，黄金该跌」。这个系统像一个全自动体检中心：12个科室（板块）同时抽血化验（数据采集），AI护士把症状描述转成结构化病历（叙事结构化），5台CT/MRI机器各自扫描因果传导路径（5种发现方法），最后算出「病人症状（叙事）和化验单（数据）之间的缺口有多大」——缺口大的就是还没被市场注意到的病根（低贴现率信号）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 12个资产板块 | 12个科室——国债科、A股科、黄金科、能源科…… |
| 数据锚 (data anchor) | 化验单——血糖血脂心电图，不说谎的硬数字 |
| 叙事帆 (narrative sail) | 病人自述——「我最近心慌」「吃不下饭」，有信息但可能夸张或滞后 |
| 贴现率 | 症状（叙事）和化验单（数据）的缺口——「喊得很凶但指标还没恶化」= 低贴现 = 预警窗口 |
| 5种发现方法并行 | 5台不同原理的扫描仪——CT看结构（PCMCI）、MRI看功能（传递熵）、X光看线性（Granger）——交叉验证 |
| 传导图演化 | 病历档案——今天发现的传导链和上周对比，哪些新出现、哪些消失了 |

## 是什么
宏观传导发现引擎是一个数据驱动的因果发现系统，从「LLM 驱动的新闻评分」重构为「因果发现引擎」。核心设计：**数据是锚（硬指标，来自 akshare/FRED），叙事是帆（结构化新闻信号），规律自动发现（5种因果推断方法），贴现率量化叙事与数据的缺口**。覆盖12个资产板块、74个硬指标、40+叙事主题，通过4层架构（基础层→信号层→发现层→输出层）自动产出传导图谱、贴现率看板和前瞻信号。

## 系统架构

```
基础层 (Phase 1):  config + schema + YAML配置
      ↓
信号层 (Phase 2):  数据采集(akshare/FRED) + 叙事结构化(新闻→NarrativeSignal)
      ↓
发现层 (Phase 3):  偏互相关 + Granger + 传递熵 + PCMCI + 结构突变 + 变量发现
      ↓
输出层 (Phase 4):  传导图(D3.js) + 贴现率看板 + 日报 → 飞书推送
```

## 正例（≥2 个）
1. **美债→美股传导链自动发现**: 系统从历史数据中发现「美债10Y收益率↑ → 滞后5天 → 美股科技板块↓」，贴现率0.35——传导已兑现35%，还有65%可能在路上。
2. **低贴现率预警**: 黄金急涨后，系统检测到「黄金→A股避险板块」传导链贴现率仅12%——叙事先行、数据滞后，提示A股防御性板块可能还有补涨空间。

## 反例/边界（≥1 个）
1. **LLM不参与因果推理**: 系统的LLM只做新闻结构化（填快递单：topic/direction/intensity），不做评分、不做因果推断。因果发现全部由统计方法（传递熵/PCMCI/Granger）完成，LLM只在最后一步生成自然语言摘要——这是核心设计约束。
2. **数据质量决定一切**: 如果 akshare 数据源中断、或某些板块只有月频数据无法做日频分析（如 CPI），系统对该板块的发现能力降级——不是方法的问题，是数据频率的根本约束。

## 详细解释

### 四层架构

**基础层**: `config/asset_indicators.yaml`（12板块×74指标定义）、`threshold_rules.yaml`（30+条硬阈值规则，如「美债2Y-10Y倒挂→severity 30→预期30天后美股负向传导」）、`topic_taxonomy.yaml`（40+叙事主题分类）。

**信号层**: 数据侧 — `akshare_collector` 采A股/宏观/商品、`fred_collector` 采美债/美股指标；叙事侧 — 新闻采集（天行API/RSS/热搜/DuckDuckGo）→ `structurer.py`（LLM辅助结构化，限定角色：只填空不做题）→ `NarrativeSignal`（topic + direction + intensity）。

**发现层**: 5种方法全量运行（详见各自卡片），结果去重后送入 `DiscountAnalyzer` 计算每条边的贴现率。

**输出层**: `ConductionGraph` 版本化管理 → D3.js力导向图 + 日报JSON/Markdown → API (`FastAPI :9000`) → 仪表盘。

### 关键设计决策
| 决策 | 选择 | 理由 |
|------|------|------|
| 传输熵库 | IDTxl | Python原生，比JIDT的Java桥接更稳定 |
| 因果发现 | Tigramite PCMCI | 学术主流，去中介能力强 |
| 特征选择 | SHAP + XGBoost | 高解释性，适合金融 |
| LLM角色 | 仅结构化+报告总结 | 不参与评分/传导/推理 |
| 存储 | SQLite + Parquet | 轻量单机，够用 |
