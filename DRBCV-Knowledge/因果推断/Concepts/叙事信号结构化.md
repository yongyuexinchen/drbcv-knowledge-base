# 叙事信号结构化（Narrative Structuring）

## 类型判定
程序型 — 将非结构化的财经新闻文本转换为结构化的 `NarrativeSignal`（topic + direction + intensity + affected_assets），LLM 只做填空题不做论述题。

## 类比 ★
### 一句话比喻
你是一家快递公司的分拣员。每天收到几千个包裹（新闻），你不能自己打开包裹评判里面东西好不好——你只能看快递单（LLM结构化提取）：**寄件人**（topic：这是关于什么的）、**收件人**（affected_assets：会影响哪些资产）、**急不急**（intensity：讨论热度）、**好消息还是坏消息**（direction：利多还是利空）。你绝对不能写「这个包裹很重要因为……」——那是评分，不是分拣。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 原始新闻文本 | 快递包裹——五花八门、格式不一、需要分拣 |
| LLM的约束角色 | 快递分拣员——只看快递单，不看内容，不做评价 |
| topic 匹配 | 寄件人类别——从40+预定义主题中选一个最匹配的 |
| direction (-1~+1) | 寄件标注——「易碎品请轻放」= 利空警告，「贵重物品」= 利多信号 |
| intensity (0~1) | 加急标识——「当日达」= 强度0.9，「普通件」= 强度0.3 |
| 关键词回退 | 不用LLM时靠关键词匹配分拣——速度快但精度低 |
| taxonomy | 分拣规则手册——40+个标准类别，覆盖所有可能的包裹类型 |

## 是什么
叙事信号结构化是将财经新闻转换为 `NarrativeSignal` 的流程：接收原始新闻文本 → 主题匹配（从 `topic_taxonomy.yaml` 的40+分类中选择）→ 情绪量化（direction/intensity）→ 输出结构化信号。LLM 的角色被严格限定为「结构化提取」——只做 topic 匹配、entity 识别、方向/强度判断，**禁止做风险评分、因果推理、传导判断**。这是系统设计的核心约束：叙事层只负责把文本变成信号，因果发现是发现层的事。

## 输入-输出空间
- **输入**: 标准化新闻 dict（title, summary, url, source, source_tier, published_at）
- **输出**: `NarrativeSignal`（id, timestamp, headline, topic, direction, intensity, affected_assets, entities, source_tier, confidence, is_new_event）
- **前置条件**: `topic_taxonomy.yaml` 已加载；可选 LLM API key

## 正例（≥2 个）
1. **美联储加息新闻**: 输入「美联储宣布加息25bp，鲍威尔表示不排除进一步加息」→ LLM输出 {topic: "fed_rate_policy", direction: -0.7, intensity: 0.85, affected_assets: ["us_debt","us_stock","gold"], entities: ["美联储","鲍威尔"]}
2. **中国PMI数据**: 输入「3月制造业PMI回升至50.8，高于预期」→ 输出 {topic: "cn_macro_data", direction: 0.5, intensity: 0.6, affected_assets: ["a_stock","cn_macro","raw_materials"], entities: ["制造业PMI"]}

## 反例/边界（≥1 个）
1. **LLM输出的诱惑**: 如果不严格控制 prompt，LLM 会倾向于加入推理（如「这意味着A股可能上涨因为……」）。系统的 prompt 设计用「严格的JSON格式」「不要评分，不要推理传导关系」「temperature=0.1」三道防线防止 LLM 越界。
2. **无LLM时的降级**: 系统默认 `use_llm=False`——只用关键词匹配 + 词典情绪量化。这比 LLM 快 100 倍、零成本、确定性高，但精度差（可能误匹配 topic）。生产环境中先用关键词过滤，仅对模糊新闻调用 LLM。

## 详细解释

### 流程
```
新闻采集 → 去重(URL hash / 标题相似度)
          ↓
       关键词匹配 (TopicMatcher: TF-IDF + 关键词)
          ↓
       情绪量化 (SentimentQuantifier: 词典法 direction + TF-based intensity)
          ↓
     [可选] LLM精提取 (仅用于: topic确认 / entity识别 / direction微调)
          ↓
       NarrativeSignal → narrative_store (时序存储) → 发现层消费
```

### 关键设计约束（来自规格书）
| LLM 允许做的事 | LLM 禁止做的事 |
|---------------|---------------|
| 从候选列表中选择 topic | 风险评分 |
| 提取实体/资产名称 | 因果推理 |
| 判断方向 (-1~+1) | 传导判断 |
| 判断强度 (0~1) | 自由发挥的评论 |

### LLM Prompt 核心片段
```
请严格按以下 JSON 格式输出 (不要输出其他内容):
{
  "topic": "从候选主题列表中选择最匹配的1个",
  "direction": -1.0到1.0,
  "intensity": 0.0到1.0,
  ...
}
注意: 不要评分，不要推理传导关系。只做结构化提取。
```
