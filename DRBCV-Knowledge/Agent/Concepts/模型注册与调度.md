# 模型注册与调度

## 类型判定
在平台上注册和配置不同的大语言模型服务，使其可在全局或具体技能中被调用的模型管理机制。

## 类比 ★
### 一句话比喻
就像公司车队管理——你可以注册不同品牌的汽车（GPT-4、ChatGLM3）、记录每辆车的停放地址（API 地址），使用时按需调度，而不是每次都去4S店临时借车。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| RT 服务管理器 | 车队调度中心 |
| 创建模型 | 注册新车到车队 |
| 模型名称 + 地址 | 车牌号 + 停车位 |
| 上线/下线 | 车辆可用/维修中 |
| 全局默认大模型 | 日常默认使用的车 |
| 技能内选择模型 | 特殊任务调用特定车辆 |

## 是什么
模型注册与调度是必胜项目的模型管理模块。通过 RT 服务管理器，管理员可以创建和注册不同的大语言模型（如 ChatGLM3-6B、GPT-4、OpenAI 系列），为每个模型配置名称和 API 请求地址。注册完成后上线即可在技能创作中选用。系统配置中的"全局默认大模型"决定整个平台的默认模型底座，而具体技能可覆盖使用不同模型。

## 正例（≥2 个）
1. **部署 ChatGLM3**：上节课已跑通 ChatGLM3 → 在 RT 服务管理器中创建 → 填入 model 名称"ChatGLM3-6B"和 API 地址 → 点击上线 → 刷新后可在技能中选择该模型。
2. **添加自定义模型**：想使用其他开源模型（如千问、文心一言）→ 在 RT 服务管理器中创建新模型 → 填入模型名称和对应 API 地址 → 上线后即可使用。

## 反例/边界（≥1 个）
1. 模型未上线：模型虽已创建但状态为"下线"，此时在任何技能中都无法选择该模型，必须点击上线后才生效。
2. 模型地址错误：API 地址填错 → 技能运行时请求失败 → 虽已上线但实际不可用。

## 详细解释
模型管理的关键配置：
- **RT 服务管理器**：模型注册入口，管理所有已部署的模型底座
- **系统配置中的全局模型**：填入 model 名称（如 ChatGLM3-6B）和 API 请求地址，作为平台的默认大模型
- **全局 embedding 配置**：填入 OpenAI ADA-002 的 API 地址和 Key，用于知识库向量化
- **向量数据库配置**：配置 IP 地址、数据库连接参数
- **超时配置**：防止模型请求长时间挂起

模型选型建议：
- GPT-4 效果最佳但成本高（一次 Agent 调用可能花费数元）
- ChatGLM3 免费但当前版本可能因 LangChain 版本问题"带不动"
- 等待项目更新后可正常调用国产模型
