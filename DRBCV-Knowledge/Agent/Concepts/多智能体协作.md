# 多智能体协作

## 类型判定
将多个具有不同角色和能力的 AI Agent 组织起来协同完成复杂任务的架构范式。

## 类比 ★
### 一句话比喻
就像把一群各有专长的同事拉进一个微信群，你扔一个问题进去，他们自己辩论、分工、互相补位，最后把答案端到你面前。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 多智能体（Multi-Agent） | 微信群里的群成员 |
| AutoGen Assistant | 有特定技能和立场的群成员（如正方辩手） |
| AutoGen User | 在群里发布任务的人（你） |
| GroupChat Manager | 群管理员，决定谁先发言 |
| Agent Chain | 把所有人拉进群的"建群"动作 |
| System Message | 每个成员的岗位说明书 |

## 是什么
多智能体协作是将多个 AI Agent 组织成一个团队，每个 Agent 拥有独立角色设定（System Message）、特定技能和知识领域，通过一个群聊管理器（GroupChat Manager）协调发言顺序和任务分配，共同完成用户目标的框架。它不是单一 AI 的一次性回答，而是多个 AI 的讨论、分工与协同。

## 正例（≥2 个）
1. **辩论赛**：定义正方辩手和反方辩手两个 Agent，主持人发布辩题后，正方先发言，反方回应，交替进行三轮辩论，群管理员控制轮流顺序。
2. **代码编写 + 执行**：一个 Assistant Agent 编写 Python 代码，另一个 Coder Agent 负责在环境中执行代码并返回结果，实现"写代码—执行—返回答案"的闭环。
3. **多知识库问答**：Agent A 挂载"张一鸣创业"知识库，Agent B 挂载"雅思面试题"知识库，用户提问时管理员自动路由到对应知识的 Agent。

## 反例/边界（≥1 个）
1. 单一 Agent 对话：只有一个 LLM + 工具的单体 Agent 虽然也能完成一些任务，但没有多角色分工和协同辩论能力，无法处理需要多视角讨论的复杂任务。

## 详细解释
多智能体系统的核心组件包括：
- **AutoGen Assistant**：群聊成员，拥有独立的 name、model、system message 和 temperature。name 只能使用字母、下划线和数字，不能使用中文。system message 定义该成员的角色、工作流程和要求。
- **AutoGen User**：用户代理，通过 max_consecutive_auto_reply 参数控制用户是否可以中途插话（always 可插话，never 不可插话）。
- **GroupChat Manager**：群聊管理员，根据每个成员的 system message 和历史聊天记录判断下一个发言人，max_round 参数（默认 50）防止群聊陷入死循环。
- **Agent Chain**：连接组件，将 User、Assistant 和 Manager 整合为一个可执行的工作链。

温度参数（temperature）控制输出随机性：值越大越有创造性思维越发散，值越小回答越死板循规蹈矩。
