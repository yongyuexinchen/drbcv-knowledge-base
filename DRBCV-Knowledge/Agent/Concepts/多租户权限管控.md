# 多租户权限管控

## 类型判定
平台管理员对不同用户和角色进行精细化权限分配和数据隔离的系统管理机制。

## 类比 ★
### 一句话比喻
就像公司大楼的门禁系统——老板有所有房间的钥匙（ADMIN），财务部的人只能进财务室不能进研发部，每个员工的工卡权限由老板统一设定，防止资料串用和泄密。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 系统管理员（ADMIN） | 公司老板 / 大楼安保主管 |
| 普通用户 | 各部门员工 |
| 角色（Role） | 工卡权限模板（如"财务部权限"） |
| 角色授权 | 给员工发工卡 |
| 知识库授权 | 规定哪个部门能看哪些资料 |
| 决策管理 | 老板在后台配置谁能看什么 |

## 是什么
多租户权限管控是必胜项目的用户管理体系，分为两类用户：唯一的系统管理员（ADMIN）拥有最高权限，可管理所有用户、创建角色、分配权限；普通用户由管理员创建并分配角色，每个角色限定可访问的知识库、可使用的技能和应用。该机制确保企业内部资料按部门隔离，防止信息串用和滥用。

## 正例（≥2 个）
1. **部门级数据隔离**：创建"PDF管理员"角色 → 只授权"张一鸣语录2"知识库 → 将角色赋予用户"222" → 该用户登录后只能看到被授权的知识库和技能，无法访问其他部门资料。
2. **多部门账号分发**：市场部 10 个员工 → 管理员每人发放一个账号 → 分别赋予"市场部"角色 → 只能访问市场相关的 AI 技能和企业资料。

## 反例/边界（≥1 个）
1. 所有用户共享同一权限：没有角色和权限管控，所有用户能访问全部知识库和技能，企业内部敏感资料（财务数据、人事档案）存在泄露风险。
2. 单用户系统：只有 ADMIN 一个人使用，不需要复杂的权限体系。

## 详细解释
用户管理结构：
- **ADMIN 用户**：系统唯一管理员账号（默认用户名 ADMIN / 密码 1234），拥有最高权限
- **普通用户**：由 ADMIN 创建和管理，可自定义用户名和权限
- **角色管理**：ADMIN 创建角色 → 定义角色的知识库和技能权限 → 将角色赋予用户
- **系统配置**：全局参数包括 embedding 模型地址、API Key、向量数据库 IP、全局默认大模型、超时配置等
- **配置文件**：/root/必胜/config/conf.yaml，可修改 ADMIN 用户名和密码

权限粒度：可精确到具体知识库（用户只能看被授权的那几个知识库）、具体技能和应用。
