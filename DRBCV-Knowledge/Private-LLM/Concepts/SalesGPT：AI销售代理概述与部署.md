# SalesGPT：AI 销售代理概述与部署

## 类型判定
[Mixed — 既是「是什么」（Agent 驱动的销售 AI 的架构与理念），也是「怎么搭」（腾讯云 + Miniconda 环境部署全流程）]

## 类比 ★
### 一句话比喻
> SalesGPT 像一个「永不下班的销冠机器人」——你给它一份产品手册、一个销售剧本（8 个阶段从开场到成交），它就能自动打电话/发短信推销床垫，聊得好引导线下、聊不下去礼貌挂断，还会自己翻产品目录找卖点。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| SalesGPT Agent | 销冠机器人——按剧本行动，会使用工具 |
| 8 阶段销售流程 | 销售培训手册：开场→资格筛选→产品介绍→需求挖掘→展示→引导成交 |
| 产品知识库（product doc） | 机器人手里的产品目录——床垫规格、卖点、价格都在里面 |
| Agent 工具调用（Search） | 机器人翻目录的动作——客户问「有机海绵床垫」，它去目录里找到对应条目 |
| 对话状态判断 | 销售经理在旁监听——判断「现在到哪个阶段了，该推进还是继续聊」 |
| API 模式 | 把机器人外派到企业电话系统/官网——不用终端，嵌入真实业务流程 |
| 最大对话轮次 | 防闲聊开关——聊够 N 轮自动结束，省 API 费用 |

## 是什么
SalesGPT 是一个将大语言模型与 Agent 思想结合的 AI 销售代理项目。它将销售对话分解为 8 个标准化阶段（开场介绍 → 资格筛选 → 需求挖掘 → 产品展示 → 引导成交/引流线下），Agent 在对话中可根据当前阶段调用工具（如产品知识库搜索），实时判断对话状态并推进到下一阶段。支持中文/英文提示词模板、终端对话和 API 两种模式。

## 输入-输出空间
- **输入**: OpenAI API 密钥 + 腾讯云服务器 + 销售配置（姓名/公司/产品/价值观）+ 产品知识库文档
- **输出**: 终端中运行的销售对话 Agent，或通过 API 接入企业电话/官网系统
- **前置条件**: 建议使用 GPT-4（GPT-3.5 使用工具时表现很差）；需注释掉 `run.py` 中 OS 相关的 4 行代码；配置文件从 `.env.template` 复制为 `.env`

## 正例（≥2 个）
1. **床垫公司电话销售**: 配置销售代表「张三」→ Sleep Haven 床垫公司 → 产品文档包含记忆海绵床垫（$999）和凝胶床垫（$799）→ 客户说「最近睡得不好」，张三自动切入需求挖掘阶段，介绍产品特点并引导线下体验店。
2. **API 嵌入企业呼叫中心**: 启动 API 模式后，企业前端通过 API 与 SalesGPT 交互，实现「AI 先接电话做初步筛选，有意向的客户转接真人销售」——降低人力成本的同时不丢失商机。

## 反例/边界（≥1 个）
1. **GPT-3.5 在工具调用下严重退化**: 如果为了省钱使用 GPT-3.5 而非 GPT-4，Agent 在使用产品搜索工具时表现极差——回复不准确、工具调用失败率高。这在部署时必须将 `run.py` 中的 `model_name` 替换为 GPT-4。
2. **客户直接拒绝→对话自动终止**: 如果客户说「没兴趣」，SalesGPT 内部的状态判断器会判定对话阶段结束，直接礼貌挂断——这不是 Bug，是设计如此（不浪费 API 资源闲聊）。
3. **对话轮次限制太小导致截断**: `run.py` 中默认 `max_turns=10`，复杂销售场景可能不够用——建议调整到 20-30，但不宜过大（过大浪费 API 费用）。

## 详细解释

### 核心架构：Agent 环路
```
┌──────────────────────────────────────────┐
│            SalesGPT Agent                │
│                                          │
│  ① 读取配置文件（销售信息+产品知识库）    │
│       ↓                                  │
│  ② 生成 System Prompt（角色+8阶段流程）  │
│       ↓                                  │
│  ③ 与客户对话 ──→ 调用工具(Search) ←──┐ │
│       ↓                              │ │
│  ④ 状态判断器：当前在哪一阶段？        │ │
│       ↓                              │ │
│  ⑤ 在同一阶段内循环（继续聊） ────────┘ │
│       或推进到下一阶段                    │
│       ↓                                  │
│  ⑥ 达到终止条件 → 结束对话              │
└──────────────────────────────────────────┘
```

### 部署流程（腾讯云 + Miniconda）
| 步骤 | 操作 | 关键点 |
|------|------|--------|
| 1. 服务器 | 腾讯云 CVM，亚太-首尔，4 核 4G+，Ubuntu 22.04 | 密钥登录 |
| 2. 环境 | `sudo su` → 安装 Miniconda → 创建虚拟环境 → 激活 | 前缀出现 base 即成功 |
| 3. 克隆配置 | git clone → pip install -r requirements.txt → cp .env.template .env → vi .env 填入 OpenAI 密钥 | env 文件编辑：按 `I` 进入编辑，`ESC` + `:wq` 保存退出 |
| 4. 修复代码 | vi run.py → 找到 4 行 `os.` 开头代码 → 注释掉（`#`） | 不注释会启动失败 |
| 5. 启动 | `python3 run.py`（中文提示词用对应中文命令） | 看到销售代表打招呼即成功 |
