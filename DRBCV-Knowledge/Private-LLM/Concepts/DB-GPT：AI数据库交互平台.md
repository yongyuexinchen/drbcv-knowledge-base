# DB-GPT：AI 数据库交互平台

## 类型判定
[Mixed — 既是「是什么」（以大模型为底座的数据库交互平台），也是「怎么用」（6 种对话模式 + 知识库 + 模型管理 + 部署配置）]

## 类比 ★
### 一句话比喻
> DB-GPT 像一个「会说话的数据库管家」——你不需要写 SQL，只需要用中文说「帮我画一个上季度销售趋势图」「查一下学号 2024001 的各科成绩」，它自己翻数据库、生成 SQL、画图表，全自动搞定。你甚至可以上传一张 Excel 表格让它当场分析。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Chat Data（数据对话） | 管家直接翻账本给你看——「张三的余额是多少？→ 5,000 元」 |
| Chat DB（数据库对话） | 请管家教你记账——「这个查询怎么写 SQL？→ SELECT...」 |
| Chat Excel（表格对话） | 把账本丢给管家，让他画趋势图——上传 CSV，秒出折线图 |
| Chat Knowledge（知识库对话） | 管家翻你公司的 SOP 手册回答问题——「年假怎么算？→ 第 3 页...」|
| Dashboard（仪表盘） | 管家在墙上架个大屏幕，实时展示销售数据看板 |
| Agent Chat（智能体对话） | 管家不仅会翻账本，还会上网搜资料、调插件完成复杂任务 |
| 嵌入模型 (Embedding) | 管家给每本手册贴标签——方便以后快速检索 |
| 切片分块 (Chunking) | 把一本书撕成 500 字一页的活页——方便按需翻找 |

## 是什么
DB-GPT 是一个以大语言模型为底座的 AI 数据库交互平台，支持用自然语言与多种数据库（MySQL、SQLite、Oracle 等）交互。它提供 6 种对话模式：Chat Data（直接查询数据）、Chat DB（生成 SQL/数据库运维建议）、Chat Excel（上传表格分析+绘图）、Chat Knowledge（基于知识库问答）、Dashboard（数据可视化看板）和 Agent Chat（插件+工具链）。支持接入 OpenAI API 或本地部署开源模型（如 ChatGLM3-6B）。

## 输入-输出空间
- **输入**: 数据库连接 + 模型（API 密钥或本地模型路径）+ Excel/CSV/文档文件 + 自然语言问题
- **输出**: 数据查询结果 / SQL 语句 / 图表（折线图、饼图、柱状图）/ 数据分析报告
- **前置条件**: 模型必须能正常推理（API 或本地 GPU）；知识库需完成向量化（Embedding）；GPU 机型推荐 T4/V100/A10

## 正例（≥2 个）
1. **学生成绩分析**: 连接学校 SQLite 数据库 → Chat Data 模式 → 问「查询所有 CS 专业学生的平均成绩」→ DB-GPT 自动生成 SQL 并返回结果 → Dashboard 模式 → 「绘制各专业平均成绩分布图」→ 自动生成柱状图。
2. **上证 50 ETF 走势分析**: Chat Excel 模式 → 上传近一年 ETF 数据 CSV → 系统自动分析日期和收盘价字段 → 「绘制 10 日均线图」→ 生成折线图 → 「分析近期价格趋势」→ 输出文字分析报告。

## 反例/边界（≥1 个）
1. **Agent Chat 模块不成熟**: 当前版本的 Agent Chat 经多次测试无法正常运行，项目方表示近期会更新 Agent 框架——生产环境中暂时不要依赖该模式。
2. **知识库切分质量决定回答上限**: 如果上传的文档没有标题/正文层级结构，或者所有文章混在一个知识库里（如经济会议纪要和证券政策放一起），检索精度大幅下降——必须按「标题明确+正文规整+同类归档」三原则预处理。
3. **Chat Data vs Chat DB 混淆**: Chat Data 是直接展示数据结果（面向业务人员），Chat DB 是生成 SQL 语句和优化建议（面向数据库运维人员）——给财务用 Chat DB 会看到一堆看不懂的 SQL，必须用 Chat Data。

## 详细解释

### 六种对话模式全览

| 模式 | 功能 | 适用角色 | 典型输入 | 典型输出 |
|------|------|----------|----------|----------|
| Chat Data | 直接查询数据库中的数据 | 业务人员 | "查销售额 Top 10 产品" | 表格+数据 |
| Chat DB | 生成 SQL / 数据库运维建议 | DBA / 开发 | "如何给这个表加索引" | SQL 语句 + 建议 |
| Chat Excel | 上传表格分析 + 绘图 | 分析师 | "绘制销售趋势折线图" | 折线图/饼图/柱状图 |
| Chat Knowledge | 基于知识库文档问答 | 全员 | "年假政策是什么" | 文字回答 + 出处 |
| Dashboard | 数据可视化看板 | 管理层 | "生成销售数据看板" | 交互式图表面板 |
| Agent Chat | 多工具智能体（待完善） | 高级用户 | 复杂多步骤任务 | 综合解决方案 |

### 部署架构
```
用户浏览器（公网IP:5000）
        ↓
   DB-GPT 前端
        ↓
   模型层（LLM）
   ├── API 模式：OpenAI / 智谱 / 讯飞星火
   └── 本地模式：ChatGLM3-6B / 千问 / 百川
        ↓
   数据层
   ├── 关系型数据库（MySQL/SQLite/Oracle）
   ├── 向量数据库（知识库 Embedding）
   └── 文件系统（Excel/CSV/PDF）
```

### 部署关键步骤
| 步骤 | 操作 | 关键点 |
|------|------|--------|
| 1. 环境 | Miniconda 虚拟环境 → pip install 依赖 | 依赖安装需 5 分钟 |
| 2. 数据库 | 导入官方示例数据库 | 3 条成功提示即导入成功 |
| 3. 模型下载 | git clone Embedding 模型 + ChatGLM3-6B（GPU 机型） | 用 git LFS 拉取权重文件（约 5 分钟/模型） |
| 4. 配置模型 | vi .env → 编辑 `LLM_MODELS` 字段 | 选 API 模式填 URL+密钥；选本地模式填模型名 |
| 5. 启动 | 运行启动命令 → 公网 IP:5000 访问 | 安全组放行 5000 端口 |

### 知识库优化三原则
1. **文档格式规整**: 用 Word 标题样式（标题 1/标题 2）+ 正文，让切分器知道层级
2. **标题言简意赅**: 标题 5-10 字，准确概括下文内容——模糊标题导致检索失败
3. **同类归档**: 经济类放一起，政策类另建知识库——不同内容类型物理隔离
