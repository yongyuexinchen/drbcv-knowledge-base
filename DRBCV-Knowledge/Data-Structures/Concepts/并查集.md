# 并查集（Disjoint Set / Union-Find）

## 类型判定
程序型 — 并查集是一种表示「互不相交集合」的数据结构，支持两种核心操作：**并（Union）**和**查（Find）**。物理上用**双亲表示法的树**实现。

## 是什么
并查集用于管理若干互不相交的集合，每个集合用一棵树表示（树的根 = 集合的代表）。两个核心操作：
- **Find（查）**：给定元素 x，找到 x 所属集合的根结点——即「一路向北找根」
- **Union（并）**：给定两个元素，将它们所属的集合合并——即「让一个根指向另一个根」

## 输入-输出空间
- **输入**：n 个互不相交的元素（初始各自为独立集合）
- **Find(x)**：输入元素下标 x → 输出其所属集合的根下标
- **Union(root1, root2)**：输入两个集合的根下标 → 合并为一个集合
- **存储结构**：长度为 n 的 int 数组 `S[]`（双亲表示法）

## 正例（≥2 个）
1. **大学社团合并问题**：判断两个人是否在同一个社团（Find），把两个社团合并（Union）
2. **Kruskal 最小生成树算法**：判断加入一条边是否形成环——用并查集的 Find 检查两个端点是否同属一个集合
3. **朋友圈 / 等价类划分**：所有人初始各自为营，每有一条「A 和 B 是朋友」就 Union

## 反例/边界（≥1 个）
1. **未优化的 Union**：每次随意合并，可能导致树退化为链（高度 = n），Find 退化为 $O(n)$
2. **Union 同一集合的两个元素**：如果 Find 后发现它们根相同，应直接返回，否则`S[root2]=root1`会形成环

## 详细解释

### 存储结构

```c
#define SIZE 100
int S[SIZE];   // 并查集数组
// S[i] >= 0 → i 的父结点下标
// S[i] < 0  → i 是根结点，|S[i]| = 该集合的元素总数
```

### 初始化（Initial）

```c
void Initial(int S[], int n) {
    for (int i = 0; i < n; i++)
        S[i] = -1;   // 初始每个元素自成一个集合（各自为根）
}
```

### Find 操作（查）

```c
int Find(int S[], int x) {
    while (S[x] >= 0)    // 不是根结点（根的值 < 0）
        x = S[x];        // 一路向北找父亲
    return x;            // 返回根的下标
}
```

时间复杂度：$O(h)$，h 为树高。未优化时最坏 $O(n)$。

### Union 操作（并）— 未优化版

```c
void Union(int S[], int root1, int root2) {
    if (root1 == root2) return;
    S[root2] = root1;    // root2 的父结点指向 root1
}
```

时间复杂度：$O(1)$。

### Union 优化：小树并入大树

**核心思想**：用根结点值的**绝对值**表示集合的大小（结点数）。每次合并让**小树合并到大树**下面，使树高增长最慢。

```c
void Union(int S[], int root1, int root2) {
    if (root1 == root2) return;
    if (S[root1] > S[root2]) {  // root1 的绝对值更小 → root1 是小树
        S[root2] += S[root1];    // 累加结点总数
        S[root1] = root2;        // 小树根指向大树根
    } else {
        S[root1] += S[root2];
        S[root2] = root1;
    }
}
```

**优化效果**：树高不超过 $\lfloor \log_2 n \rfloor + 1$，Find 时间复杂度降为 $O(\log n)$。

### 完整使用示例

```c
// 给定元素 a 和 b，合并它们所在的集合
void UnionElements(int S[], int a, int b) {
    int rootA = Find(S, a);
    int rootB = Find(S, b);
    Union(S, rootA, rootB);  // 内部会自动小树并大树
}
```

### 时间复杂度对比

| | Find | Union |
|---|---|---|
| 未优化 | $O(n)$ 最坏 | $O(1)$ |
| 小树并大树优化 | $O(\log n)$ | $O(1)$ |
| 进一步优化（路径压缩） | 接近 $O(1)$ | $O(1)$ |

> 路径压缩（考研不要求但可了解）：Find 时将路径上所有结点直接挂到根下，进一步降低树高。

## 类比

### 一句话比喻
**并查集就像大学社团联合会——初始每个人都是「一个人的社团」（S[i]=-1）。有人喊「A 和 B 是同一个社团的！」就用 Union 把两个社团合并。想查「C 和 D 是不是同社团？」就分别 Find 找到他们的社长，看是不是同一个人。合并的优化就是「小社团并入大社团」——让小的改挂大社团名下，这样社团层级不会越来越高，查社长时不至于爬十层楼。**

### 生活映射
| 数据结构世界 | 大学社团管理 |
|---|---|
| `S[i] = -1` | 初始每个人自己建了一个社团，自任社长 |
| Find(x)：一路向北 | 「你社长是谁？」→「我社长是 B」→「B 的社长是 A」→「最终社长是 A」 |
| Union(root1, root2) | 「两个社团合并，小社团的成员全部归入大社团」 |
| `S[root]` 的绝对值 | 社团人数 |
| 优化：小树并大树 | 「50 人的社团并入 500 人的社团」→ 层级几乎不变 |
| 未优化：大树并小树 | 「500 人的社团并入 50 人的社团」→ 所有人多了一层，查社长爬楼更累 |
| 树高 $O(\log n)$ | 最多爬 $\log n$ 层就能找到社长 |
| 判断同集合 | 「你俩社长是同一个吗？」→ 是 = 同社团 |
