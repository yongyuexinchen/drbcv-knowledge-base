# 串的存储结构

## 类型判定
判别型 — 串是特殊的线性表，存储结构完全复刻线性表的两种实现（顺序/链式），`depends_on` [[线性表]]，区别在于数据元素固定为 `char` 类型，以及存储密度问题的特殊处理。

## 是什么
串的存储结构分为**顺序存储**（定长数组 / 堆分配动态数组）和**链式存储**（链表结点存字符）。王道教材采用「舍弃 `ch[0]` + 独立 `length` 变量」的顺序存储方案。

## 输入-输出空间
- 无（存储结构定义，非算法）

## 正例（≥2 个）
1. **顺序存储 — 静态数组**：`char ch[MAXLEN]; int length;` —— 编译期确定大小，不可扩展，函数返回时自动回收
2. **顺序存储 — 堆分配（动态数组）**：`char *ch; int length;` 然后用 `malloc` 从堆区申请，需要手动 `free`，可动态扩展
3. **链式存储 — 多字符结点**：每个链表结点存 4 个 `char` + 1 个 `next` 指针 → 存储密度提升

## 反例/边界（≥1 个）
1. **单字符链式结点**：每个结点只存 1 个 `char`（1 字节）+ 指针（4 字节）→ 存储密度仅 $1/5 = 20\%$，极其浪费，实际不用
2. **用 `\0` 标记结尾但不存长度**：每次求串长需 $O(n)$ 遍历，频繁取长度时性能差

## 详细解释

### 顺序存储的三种方案

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 方案一 | 数组 + 独立 `length` | 位序=下标+1，简单 | `ch[0]` 浪费 |
| 方案二 | `ch[0]` 存长度 | 位序=下标，一一对应 | 长度上限 255（`char` 只有 1 字节） |
| 方案三 | `\0` 标记结尾 | 省一个字段 | 求长度需 $O(n)$ 遍历 |

**王道采用方案**：舍弃 `ch[0]`（从 `ch[1]` 开始存），同时用独立的 `int length` 记录长度——兼具方案一二的优点。

### 链式存储的存储密度问题
```
单字符结点: [char|1B] → [ptr|4B] → ...   密度 = 1/5 = 20% ❌
多字符结点: [c1|c2|c3|c4|4B] → [ptr|4B]  密度 = 4/8 = 50% ✅
```
最后一个结点未满时用特殊字符（如 `#` 或 `\0`）填充。

### 基本操作的代码实现

#### 求子串
```c
bool SubString(SString &Sub, SString S, int pos, int len) {
    if (pos + len - 1 > S.length) return false;  // 越界
    for (int i = pos; i < pos + len; i++)
        Sub.ch[i - pos + 1] = S.ch[i];
    Sub.length = len;
    return true;
}
```

#### 串比较
```c
int StrCompare(SString S, SString T) {
    for (int i = 1; i <= S.length && i <= T.length; i++)
        if (S.ch[i] != T.ch[i])
            return S.ch[i] - T.ch[i];   // 不等→返回差值
    return S.length - T.length;          // 前缀全等→长的大
}
```

#### 定位操作（朴素匹配版）
```c
int Index(SString S, SString T) {
    int n = S.length, m = T.length;
    SString sub;
    int i = 1;
    while (i <= n - m + 1) {
        SubString(sub, S, i, m);
        if (StrCompare(sub, T) == 0) return i;
        i++;
    }
    return 0;  // 未找到
}
```
> 这正是朴素模式匹配算法——后续 [[KMP算法]] 将对其进行优化。

## 类比

### 一句话比喻
**顺序存储的串就像一列火车停在连续的铁轨上——每节车厢（字符）紧挨着，你随时可以跳上第 5 节（随机存取）。链式存储的串像是一串用绳子连起来的竹筏——每个竹筏上挤了 4 个人（多字符结点），想找第 7 个人，你得从第一个竹筏开始数过来（顺序存取）。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 顺序存储（静态数组） | 固定 255 座的电影院——座位号连续，但满了就满了没法加座 |
| 堆分配（动态数组） | 可以随时搭建的临时看台——需要多少搭多少，用完拆掉归还场地 |
| 链式存储（多字符结点） | 一串连起来的旅游大巴——每辆坐 50 人，你要找第 137 号乘客就得从车头数起 |
| `ch[0]` 存长度 | 火车第一节车厢不坐人，只贴张纸写明全车共几节 |
| 存储密度 | 每辆大巴里「坐人的座位 / 总座位数」——越高越不浪费 |
| `length` 字段 | 列车长手里的小本本，翻开就知道有多少节车厢 |
| `\0` 结尾 | 队伍末尾插一面小红旗——你得从头走到尾才知道队伍多长 |
