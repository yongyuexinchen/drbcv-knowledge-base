# 基数排序（Radix Sort）

## 类型判定
程序型 — 基数排序是一种**不基于比较**的特殊排序算法，通过按关键字各位进行"分配+收集"完成排序。脑洞最大，通常用链表实现。

## 是什么
将关键字拆分为 d 个"位"（如个位、十位、百位），每位可能有 r 种取值（r 称为**基数**）。按照**关键字位权重递增**的次序，进行 d 趟"分配"和"收集"：
- **分配**：顺序扫描各元素，按当前位的值放入对应的 r 个队列中
- **收集**：把 r 个队列按顺序串联成一个链表（递增则从小到大收，递减则从大到小收）

## 输入-输出空间
- **输入**：n 个记录（链表存储），每个关键字可分 d 位，每位取值 0..r-1
- **输出**：按关键字有序的链表
- **前置条件**：关键字可拆分为 d 位，r 个辅助队列

## 正例（≥2 个）
1. **10000名学生按生日排序**：拆分为年月日3位（d=3），年15种、月12种、日31种 → 3趟分配收集 → $O(3 \times (10000 + 31)) \approx 30000$，远优于 $O(n \log n)$
2. **数字排序**：3位数 → d=3, r=10，3趟完成

## 反例/边界（≥1 个）
1. **d大n小（如5个身份证号排序）**：身份证18位 → d=18，n=5 → 18趟分配收集，效率极低
2. **r 过大（如中文人名排序）**：汉字有上万个 → r=上万 → 空间和时间都不可接受
3. **适用条件**：n 较大 + d 较小 + r 较小 → 三者缺一不可

## 详细解释

### 算法过程（以递减排序为例）
给定序列，每位取值 0~9（r=10），分 d=3 位（个十百）：
1. **第一趟（个位）**：按个位分配到 Q0~Q9，收集时从 Q9→Q0 串联
2. **第二趟（十位）**：按十位分配到 Q0~Q9，收集时从 Q9→Q0 串联
3. **第三趟（百位）**：按百位分配收集 → 全局递减有序

### 为什么"权重递增"？
个位影响最小（权重最低）→ 先按个位排 → 再按十位排 → 最后按百位排。如果反过来先排百位（最高位优先 MSD），需要递归处理各子序列。

### 代码实现核心
```c
// 定义链队列
typedef struct {
    LinkNode *front, *rear;   // 队头和队尾指针
} LinkQueue;
LinkQueue Q[10];              // 10个队列对应0~9

// 一趟分配：顺序扫描链表，按当前位放入对应队列的队尾
// 一趟收集：从 Q9 到 Q0 依次拆下队列，串联成新链表（递减）
// O(1) 收集一个队列：只需 p->next = Q[i].front
```

### 时间复杂度
| 组成部分 | 复杂度 |
|---------|--------|
| 一趟分配 | $O(n)$ |
| 一趟收集 | $O(r)$ |
| 总 d 趟 | $O(d(n + r))$ |

- 空间复杂度：**$O(r)$**（r 个队列，每个只需两个指针）
- 稳定性：**稳定**（后入队的在队尾，收集时保持先后顺序 → "鸡你太稳"）
- 适用存储：通常用链表

## 类比 ★

### 一句话比喻
**基数排序就像图书馆给书排序——先不管大类，按书名的最后一个字分到26个字母箱里（按个位分桶）→ 收集起来；再按倒数第二个字分→再收集；再按第一个字分→收集。三轮下来，书就按完整书名排好了。最神奇的是，整个过程你一次都没有比较"两本书谁的名字更大"——全靠分桶和收集。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| d 个关键字位 | 书名的第1个字、第2个字、第3个字 |
| r 个队列 | 26个字母箱（A~Z） |
| 分配（distribution） | 把书扔进对应字母的箱子里 |
| 收集（collection） | 按箱子顺序把书一本本拿出来串好 |
| 权重递增 | 先按最后一个字排，最后按第一个字排 |
| 稳定 | 同一个箱子里的书，先进箱的排在前面 |
| 适合 n 大 r 小 | 10000本书按字母排 → 高效；按笔画排 → r太大了 |
