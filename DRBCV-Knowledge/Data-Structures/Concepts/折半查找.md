# 折半查找（二分查找）

## 类型判定
程序型 — 核心算法含代码、查找判定树构造及性质、ASL 计算。高频考点。

## 是什么
在**有序的顺序表**中，每次取中间元素对比，排除一半区间，直到找到或区间为空。时间复杂度 $O(\log_2 n)$。又称二分查找。

## 输入-输出空间
- **输入**：有序顺序表（升序/降序数组），目标关键字 key
- **输出**：找到返回下标，未找到返回 -1
- **前置条件**：① 元素有序 ② 顺序存储（数组，支持随机存取）

## 正例（≥2 个）
1. **猜数字游戏**：1~100，每次猜中间值 → "大了""小了" → 每次排除一半，最多 $\lceil \log_2 100 \rceil = 7$ 次必中
2. **字典查词**：翻到中间页，目标词按字母序在前半还是后半 → 每次折半

## 反例/边界（≥1 个）
1. **链表**：无法 $O(1)$ 访问中间元素 → 折半查找无法用于链表
2. **无序数组**：中间值没有排除一半的意义 → 必须先排序或用顺序查找
3. **不一定比顺序查找快**：找第一个元素时顺序查找 1 次，折半查找可能 $\log n$ 次 → 折半查找只在"大多数情况"下更优

## 详细解释

### 核心代码（升序）
```c
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;         // 向下取整
        if (a[mid] == key) return mid;   // 查找成功
        else if (a[mid] > key) high = mid - 1;  // 左半区
        else low = mid + 1;                     // 右半区
    }
    return -1;  // low > high，查找失败
}
```

### 查找判定树（极其重要！）
判定树是**平衡二叉排序树**，特点：
- `mid = (low+high)/2` 向下取整 → 右子树结点数 ≥ 左子树结点数（多 0 或 1 个）
- 若向上取整 → 左子树结点数 ≥ 右子树结点数
- 树高 $h = \lceil \log_2(n+1) \rceil$（不含失败结点）
- 失败结点数 = $n + 1$（= 空链域数）
- **只有最下面一层是不满的**（类似完全二叉树）

### 判定树构造速记
| 元素数 | 判定树形态规律 |
|---|---|
| 1 | 单结点 |
| 2 | 右子树比左子树多 1 个 |
| 3 | 左右各 1 个 |
| 4 | 左右各 1，右边下面再挂 1 个 |
| ... | 右子树结点数 ≥ 左子树结点数 |

### ASL 计算
对 $n=11$ 的升序表：
- **成功 ASL**：$\frac{1\times1 + 2\times2 + 3\times4 + 4\times4}{11} = \frac{33}{11} = 3$
- **失败 ASL**：$\frac{3\times4 + 4\times8}{12} = \frac{44}{12} \approx 3.67$

### 复杂度
- **时间复杂度**：$O(\log_2 n)$
- **空间复杂度**：$O(1)$（非递归）

## 类比 ★

### 一句话比喻
**折半查找就是猜数字游戏：1 到 100，你每次猜中间（50），对方说"大了"你就砍掉 51~100，"小了"就砍掉 1~49——每次砍一半，100 个数最多 7 次必中。顺序查找是"1？不是。2？不是。3？不是……"——傻到姥姥家了。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| low / high 指针 | 两只手夹住字典的页码范围 |
| mid = (low+high)/2 | 翻到正中间那一页 |
| a[mid] > key → high = mid - 1 | "目标词字母序更小" → 左手往左夹 |
| a[mid] < key → low = mid + 1 | "目标词字母序更大" → 右手往右夹 |
| low > high | 两只手交叉了——这本字典里没这个词 |
| 判定树 | 每次翻页的决策树：翻哪、往哪翻 |
| 判定树树高 h | 最多翻几次能找到（或确认找不到） |
| $O(\log n)$ | 100 万条数据只需约 20 次对比 |
