# 最小生成树（MST）

## 类型判定
程序型 — 图的应用算法，含两种算法（Prim + Kruskal）的手动模拟过程、复杂度对比和适用场景。`defined_as` 带权连通无向图中各边权值之和最小的生成树。

## 是什么
- **生成树**：包含全部 $n$ 个顶点 + 连通 + 恰好 $n-1$ 条边（无回路）
- **最小生成树（MST, Minimum Spanning Tree）**：在带权连通无向图中，所有生成树中**边权值之和最小**的那棵

## 输入-输出空间
- **输入**：带权连通无向图 $G = (V, E)$
- **输出**：一棵最小生成树（$n$ 个顶点 + $n-1$ 条边）
- **约束**：MST 不唯一（可能有多个形态不同但总权值相等的 MST）当各边权值互不相等时 MST 唯一

## 正例（≥2 个）
1. **修路问题**：N 个村子要修路连通，每条候选路有成本 → 找总成本最低的修路方案 = MST
2. **网络布线**：N 个机房之间铺设光缆，要求所有机房互通且总花费最少 → MST

## 反例/边界（≥1 个）
1. **非连通图**：若图不连通则不存在生成树（只有生成森林），无法求 MST
2. **有向图**：MST 算法仅适用于无向图

## 详细解释

### 算法一：Prim（普里姆）— 选点法

**手动模拟步骤**：
1. 任选一个起始顶点加入生成树
2. 每次从尚未加入的顶点中，选一个与当前生成树**相连代价最小**的顶点加入
3. 重复直到所有顶点加入

**机器实现思路**（$O(|V|^2)$）：
```c
// isJoin[i]: 顶点 i 是否已加入
// lowCost[i]: 顶点 i 加入当前生成树的最小代价
// 每轮：找 min(lowCost) 的未加入顶点 → 加入 → 更新 lowCost
```
- 共 $n-1$ 轮，每轮扫描所有顶点 $O(|V|)$ → 总 $O(|V|^2)$
- **适合稠密图**（边多时高效）

### 算法二：Kruskal（克鲁斯卡尔）— 选边法

**手动模拟步骤**：
1. 所有边按权值递增排序
2. 每次选一条权值最小且两端顶点尚未连通的边，加入生成树
3. 重复直到选出 $n-1$ 条边

**机器实现思路**（$O(|E|\log|E|)$）：
- 用并查集判断两端是否已连通
- 遍历所有边，每轮判断 $O(\log|E|)$
- **适合稀疏图**（边少时高效）

### 对比

| | Prim | Kruskal |
|------|------|----------|
| 思路 | 选点——贪心扩展生成树 | 选边——贪心合并连通分量 |
| 时间复杂度 | $O(|V|^2)$ | $O(|E|\log|E|)$ |
| 适合场景 | 稠密图 | 稀疏图 |
| 依赖 | 仅顶点数 | 仅边数 |
| 辅助结构 | `lowCost` 数组 | 并查集 |

### 关键记忆点
- MST 的边权值和是最小的，但 MST 形态**可能不唯一**
- 当所有边权值互不相同时，MST 唯一
- 若图本身就是一棵树（连通无环），则 MST = 自身

## 类比

### 一句话比喻
**最小生成树 = 电信公司在 N 个城市之间铺光缆。公司老板发话：所有城市必须通网（连通），一根多余的缆都不许铺（$n-1$ 条边），预算用最低的（总权值最小）。Prim 的策略是「以城市为中心」：先找一个城市，贪心地不断把离现有网络最近的城市接进来。Kruskal 的策略是「以光缆为中心」：把所有备选光缆按单价排序，从最便宜的买起——买到一条就接通两座城，但如果两座城已经通了（成环了），这条缆就跳过不买。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 带权无向图 | 所有可选的光缆路线 + 铺设成本 |
| 生成树 | 一种让所有城市通网的方案 |
| 最小生成树 | 总成本最低的通网方案 |
| Prim 的 `lowCost` | 每个未通网城市接入现有网络的最便宜价格 |
| Prim 选最小 `lowCost` | 哪座城接入最便宜，就先接哪座 |
| Kruskal 排序 | 把所有光缆报价从低到高排好 |
| Kruskal「已连通就不选」 | 两座城已经通过别的缆间接通了，再铺就浪费了（成环） |
| 并查集 | 快速查：A 城和 B 城现在属于同一个网络吗？ |
| 稠密图用 Prim | 城市之间几乎全有备选缆路 → 以城为中心 |
| 稀疏图用 Kruskal | 可选缆路很少 → 以缆为中心 |
