# 哈夫曼树（Huffman Tree）

## 类型判定
程序型 — 哈夫曼树（最优二叉树）是通过贪心策略构造的带权路径长度最小的二叉树，核心应用是哈夫曼编码（数据压缩）。

## 是什么
给定 n 个带权值的叶子结点，构造一棵二叉树使**带权路径长度（WPL）**最小，这棵树就是哈夫曼树（最优二叉树）。

- **结点的带权路径长度** = 从根到该结点的路径长度 × 权值
- **树的带权路径长度 WPL** = 所有**叶子结点**的带权路径长度之和

## 输入-输出空间
- **输入**：n 个权值 $w_1, w_2, ..., w_n$
- **输出**：一棵带权路径长度最小的二叉树（哈夫曼树）
- **哈夫曼编码**：从根出发，左分支编码为 0，右分支编码为 1，叶子结点对应的路径即为该字符的编码

## 正例（≥2 个）
1. **数据压缩（哈夫曼编码）**：字符频率 `{C:80, A:10, B:8, D:2}` → 哈夫曼树构造后，高频字符 C 编码为 `0`（1 位），低频字符 D 编码为 `110`（3 位）——总比特数最小
2. **文件压缩**：英文 26 个字母出现频率不同，哈夫曼编码可将文本压缩至远小于 ASCII（固定 8 位/字符）

## 反例/边界（≥1 个）
1. **非前缀编码导致歧义**：若 A 的编码 `1` 是 B 编码 `111` 的前缀，解码 `111` 时无法区分是「A A A」还是「B」→ 哈夫曼编码天然是前缀编码（所有字符在叶子），解码无歧义
2. **哈夫曼树不唯一**：选择权值相等的最小两棵树时，合并顺序可不同，但 WPL 相同且最优

## 详细解释

### 构造哈夫曼树的贪心算法

1. 将 n 个权值视为 n 棵只有根结点的树，放入集合 F
2. 重复 n−1 次：
   - 从 F 中选出**根权值最小**的两棵树
   - 将它们合并为一棵新树（新根权值 = 两树根权值之和）
   - 新树放回 F
3. F 中只剩一棵树时结束 → 哈夫曼树

### 哈夫曼树的性质

| 性质 | 内容 |
|------|------|
| 叶子结点 | 初始的 n 个结点最终都是叶子 |
| 结点总数 | $2n - 1$（每次合并新增一个分支结点，共 n−1 次） |
| $n_1$（度为 1 的结点） | 恒为 0（哈夫曼树没有度为 1 的结点） |
| 不唯一性 | 选择合并顺序不同，树形不同但 WPL 相同 |
| 权值小的远离根 | 权值越小的叶子，路径长度越长 |

### 哈夫曼编码

- 所有权值 = 字符出现频率
- 构造哈夫曼树，左分支 → 0，右分支 → 1
- 每个叶子（字符）的编码 = 从根到该叶子的路径上的 0/1 序列
- 哈夫曼编码是**最优前缀编码**（无歧义，总长度最短）

### 手工计算示例

权值：`{1, 3, 4, 5}`

1. 选最小两个：1+3=4 → 新树（根权值 4，左 1 右 3）
2. 集合现在：新树(4), 4, 5 → 选两棵权值 4：4+4=8 → 新树(8)
3. 集合现在：新树(8), 5 → 8+5=13 → 完成
4. WPL = 1×3 + 3×3 + 4×2 + 5×1 = 3+9+8+5 = **25**（最小值）

### 时间复杂度

| 操作 | 复杂度 |
|------|--------|
| 构造哈夫曼树 | $O(n \log n)$（用最小堆优化选择过程） |
| 手工计算（选择题） | 每次选最小两个，合并，重复 |

## 类比

### 一句话比喻
**哈夫曼树就是「快递分拣中心」——高频包裹（'的'字）放在离出口最近的一楼（编码最短，1 位），低频包裹（'麒麟'）放在最高的五楼（编码最长，4 位）。这样每天搬的总楼层数（WPL）最小，分拣效率最高。如果用固定楼层（ASCII 每件都上 8 楼），搬运工累死。**

### 生活映射
| 数据结构世界 | 快递分拣中心 |
|---|---|
| 权值 = 频率 | 包裹每天出现的次数 |
| WPL（带权路径长度） | 每天搬运工走的总楼层数 |
| 高频字符编码短 | 畅销品放一楼——拿得快 |
| 低频字符编码长 | 冷门货放顶楼——偶尔爬一次没关系 |
| 贪心合并（每次选最小两个） | 每天把两个最闲的货架合并成一个新货架 |
| 前缀编码 | 每个包裹只有一个「路线编号」，不会撞号码 |
| 哈夫曼树不唯一 | 1 楼和 2 楼的货架可以互换——总楼层数一样 |
| $2n - 1$ 个结点 | n 种包裹 + n−1 个合并货架 |
| 没有度为 1 的结点 | 每个货架要么放包裹（叶子），要么是合并架（两个口子） |
