# 置换-选择排序（Replacement-Selection Sort）

## 类型判定
程序型 — 外部排序中用于**生成超长初始归并段**的算法，突破内存工作区大小限制，使归并段长度不受限于内存容量。

## 是什么
置换-选择排序在内存工作区（可容纳 L 个记录）中，通过不断**选出满足条件的记录输出并读入新记录**，生成比 L 长得多的初始归并段。核心机制：用一个 `MINIMAX` 变量记录当前归并段最后输出的值，只有 ≥ `MINIMAX` 的记录才能输出到当前段，否则"冻结"等待下一个归并段。

传统方法：内存工作区= L → 归并段长度 ≤ L。置换-选择排序：归并段长度 **平均约为 2L**。

## 输入-输出空间
- **输入**：外存中的无序文件 + 大小为 L 的内存工作区
- **输出**：若干初始归并段（每个段的长度 ≥ L）
- **前置条件**：MINIMAX 变量记录当前段最后输出值

## 正例（≥2 个）
1. **L=3 但生成长度远超 3**：如序列 `[4,6,7,9,11,13,10,14,16,22,2,30,3,...]`，第一个归并段可包含 `[4,6,7,9,11,13,14,16,22,30]` 共 10 个记录
2. **平均长度约 2L**：理论分析表明，置换-选择排序生成的归并段平均长度约为内存工作区的 2 倍

## 反例/边界（≥1 个）
1. **输入序列已有序**：每次都能输出 → 一个归并段就包含整个文件 → R=1（极端好）
2. **所有元素都 ≤ MINIMAX**：当前段结束 → 开始新段 → 此时内存工作区中所有元素解冻

## 详细解释

### 算法过程（递增归并段，L=3）
```
初始 MINIMAX = -∞

读出 3 个记录: [4, 6, 7] → 最小=4, 4 ≥ MINIMAX → 输出4, MINIMAX=4
读入: 9  → [6, 7, 9]   → 最小=6, 6 ≥ 4 → 输出6, MINIMAX=6
读入: 11 → [7, 9, 11]  → 最小=7, 7 ≥ 6 → 输出7, MINIMAX=7
...
读入: 10 → [10, 13, 14] → 最小=10, 但 10 < 13(MINIMAX) ❌ 冻结！
                             → 选次小=14, 14 ≥ 13 → 输出14, MINIMAX=14
...
当内存工作区所有记录都 < MINIMAX → 当前归并段结束
解冻所有记录 → 开始下一个归并段
```

### 关键注意事项
- **输出缓冲区**：算法逐个输出记录，但实际按磁盘块为单位批量写回外存
- **输入也是按块读入**：每次读一整块，然后逐个挪入内存工作区
- "置换"指用新读入的记录替换输出的记录；"选择"指每次选最小值

### 效果
- 生成更长的初始归并段 → R 减小 → 归并趟数减少 → 磁盘 I/O 减少
- 与败者树、最佳归并树联合使用，构成外部排序的最优方案

## 类比 ★

### 一句话比喻
**置换-选择排序就像在餐厅流水线上打包盒饭——打包台只能放 3 个饭盒（内存工作区），你要把菜按编号从小到大装盒（递增归并段）。每次装好一个最小的发出，厨房就补一个进来。如果新进来的编号比刚发出的还小（不满足递增），就先把它冰起来（冻结），等这一批装完再说。最后发现——居然用 3 个空位装出了 10 个盒饭！**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 内存工作区（L个） | 打包台上只能放 L 个饭盒 |
| MINIMAX | 刚发出的那个饭盒的编号 |
| 输出一个最小 | 装好最小号饭盒发出去 |
| 读入新记录 | 厨房补一个饭盒进来 |
| 冻结（标红） | 编号太小不能装进当前批次，先冰着 |
| 归并段结束 | 打包台上全是冰冻的 → 这批结束，解冻开始下一批 |
| 平均 2L 长度 | 台子只能放3个，但每批装了近6个 |
