# 十字链表与邻接多重表

## 类型判定
判别型 — 图的**进阶链式存储**实现，分别优化有向图（十字链表）和无向图（邻接多重表），解决邻接表和邻接矩阵的核心痛点。考研不要求手写代码，理解特性即可。

## 是什么

### 十字链表（存储有向图）
每个顶点和每条弧各一个结点：
- **顶点结点**：数据 + 第一条出弧指针（绿色）+ 第一条入弧指针（橙色）
- **弧结点**：弧尾编号 + 弧头编号 + 权值（可选）+ 下一条同弧尾的弧指针 + 下一条同弧头的弧指针

**顺绿色指针**走 → 找到所有出弧；**顺橙色指针**走 → 找到所有入弧。

### 邻接多重表（存储无向图）
每个顶点和每条边各一个结点：
- **顶点结点**：数据 + 第一条边指针
- **边结点**：两端的顶点编号 + 权值（可选）+ i-link（指向依附于 $i$ 的下一条边）+ j-link（指向依附于 $j$ 的下一条边）

每条边**只存一份**，无冗余。

## 输入-输出空间
- **输入**：顶点集 $V$ + 边集 $E$
- **输出**：顶点数组 + 弧/边结点链表
- **空间复杂度**：十字链表 $O(|V| + |E|)$；邻接多重表 $O(|V| + |E|)$

## 正例（≥2 个）
1. **有向图需要频繁操作入边和出边**：如社交网络的粉丝/关注双向关系分析 → 十字链表顺绿色找粉丝，顺橙色找关注
2. **无向图需要频繁删边或删顶点**：邻接表删一条边要删两份冗余 → 邻接多重表只需删一个边结点 + 修两个指针

## 反例/边界（≥1 个）
1. **用十字链表存无向图**：❌ 十字链表只能存有向图，无向图应使用邻接多重表
2. **考研手写十字链表代码**：实现复杂，考研初试不会要求手写代码，只考察理解

## 详细解释

### 为什么需要它们？

| 痛点 | 邻接矩阵 | 邻接表 | 十字链表/邻接多重表 |
|------|---------|--------|---------------------|
| 空间（存稀疏图） | ❌ $O(|V|^2)$ 太大 | ✅ $O(|V|+|E|)$ | ✅ $O(|V|+|E|)$ |
| 有向图入边查找 | ✅ $O(|V|)$ | ❌ $O(|E|)$ | ✅ 顺橙色指针走 |
| 无向图删边 | ✅ $O(1)$ | ❌ 需删两份冗余 | ✅ 删一份边结点即可 |
| 无向图删顶点 | ✅ $O(|V|)$ | ❌ 需遍历多个边表 | ✅ 只需遍历关联边 |

### 表示唯一性
- 十字链表：不唯一（弧结点插入顺序任意）
- 邻接多重表：不唯一（边结点插入顺序任意）
- 邻接矩阵：唯一

## 类比

### 一句话比喻
**十字链表就像每个人的双面记事本——左边贴满了「谁关注了我」（入边/橙色标签），右边贴满了「我关注了谁」（出边/绿色标签）。想查粉丝？往左边翻。想查关注？往右边翻。两边都能闪电找到，再也不用像邻接表那样把全世界的记事本都翻一遍。**

**邻接多重表就像婚礼上的座位牌——一张桌子（边）同时写着新郎和新娘的名字（两端的顶点）。离婚（删边）时只需撕掉这一张牌就行，不用跑到新郎家和新娘家各撕一张（邻接表的冗余噩梦）。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 十字链表绿色指针 | 「我关注了谁」清单 |
| 十字链表橙色指针 | 「谁关注了我」清单 |
| 十字链表弧结点 | 一条关注关系：谁→关注→谁 |
| 邻接多重表边结点 | 一条好友关系：A 和 B 是好友（只存一份） |
| 邻接表每条边两份冗余 | A 存「B 是好友」，B 也存「A 是好友」 |
| 删邻接多重表的边 | 直接撕掉这张关系卡 → 同时修 A 和 B 的指针 |
| 考研不考代码实现 | 太难了，只考选择题判断题 |
