# B+树

## 类型判定
判别型 — B+树是 B 树的变体，重点区分与 B 树的 4 大差异。广泛应用于数据库索引（如 MySQL InnoDB）。

## 是什么
**所有关键字都在叶子结点出现**的多路平衡查找树。非叶子结点只存索引（子树最大关键字 + 指针），叶子结点存全部数据并通过指针串成链表——**支持顺序查找**。

## 正例（≥2 个）
1. **MySQL 的 InnoDB 索引**：主键索引就是 B+ 树——非叶子层只放主键 + 子页指针，叶子层放完整行数据，叶子间用双向链表相连
2. **文件系统的目录索引**：目录项 = 索引结点，文件数据全在叶子

## 反例/边界（≥1 个）
1. **查找时停在非叶子结点**：在 B+ 树中，即使非叶子层匹配到关键字，也必须走到叶子层才能拿到数据 → 与 B 树不同（B 树匹配即停）
2. **分支结点关键字数 ≠ 子树数**：B+ 树中 n 个关键字 = n 个子树（而 B 树是 n 个关键字 = n+1 个子树）

## 详细解释

### B+ 树与 B 树的 4 大区别（高频考点！）

| # | B+ 树 | B 树 |
|---|---|---|
| ① 关键字-子树关系 | n 个关键字 → **n 个子树** | n 个关键字 → **n+1 个子树** |
| ② 关键字数范围 | 根：$1 \leq n \leq M-1$；非根：$\lceil M/2 \rceil \leq n \leq M-1$ | 根：$1 \leq n \leq M-1$；非根：$\lceil M/2 \rceil - 1 \leq n \leq M-1$ |
| ③ 关键字重复 | 非叶子结点的关键字在叶子中**重复出现** | 各结点关键字**不重复** |
| ④ 数据存储 | **仅叶子存数据**（含记录指针），非叶子只起索引作用 | **每个结点都存数据**（含记录指针） |

### B+ 树为什么更优秀（数据库选它的原因）
- **非叶子不含数据指针** → 每个磁盘块可存更多关键字 → **阶更大 → 树更矮 → 磁盘 I/O 更少**
- **叶子串成链表** → 支持高效**范围查询**（如 `SELECT * WHERE id BETWEEN 100 AND 200`）
- **查找必须走到叶子** → 查找时间稳定（不像 B 树可能提前停）

### 查找方式
1. **从根逐层查找**：必须走到叶子层
2. **顺序查找**：用叶子层链表，从第一个叶子开始依次扫描

### 复杂度
- 查找：$O(\log_M n)$

## 类比 ★

### 一句话比喻
**B+ 树就像图书馆的索引卡片柜——上面的抽屉（非叶子层）只有索引标签（"A-C"、"D-F"…），告诉你往哪个抽屉找，但实际书的信息全在最下面那层卡片上（叶子层）。而且叶子层的卡片被一根铁丝串在一起，你可以从头到尾翻（范围查询），不用跳回上层。B 树则是把书的信息分散放在各层抽屉里——上面找到就停了，不需要走到底。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 非叶子结点 | 索引卡片柜的抽屉标签（"最大编号=15"） |
| 叶子结点 | 最底层抽屉里的实际卡片（姓名+电话+地址） |
| 叶子层的链表指针 | 把所有最底层抽屉用铁丝串起来 |
| 范围查询 | 找"编号 20~50"→ 定位 20 号卡片，顺着铁丝一路翻到 50 |
| 非叶子不含数据 | 上面抽屉只写标签，不存完整信息——省空间 |
| 树更矮 | 每层抽屉更胖 → 翻的总层数少 |
| MySQL InnoDB | 全球最大图书馆的实际运营方案 |
