# 线索二叉树（Threaded Binary Tree）

## 类型判定
判别+程序型 — 线索二叉树是利用二叉链表中 n+1 个空指针域存储遍历序列中的前驱/后继，使查找前驱后继和遍历不再必须从根开始。

## 是什么
在普通二叉链表基础上，对每个结点增加两个标志位 `ltag` 和 `rtag`：
- `ltag=0`：`lchild` 指向左孩子；`ltag=1`：`lchild` 指向**前驱**（线索）
- `rtag=0`：`rchild` 指向右孩子；`rtag=1`：`rchild` 指向**后继**（线索）

根据遍历序列的不同，分为**中序线索二叉树**、**先序线索二叉树**和**后序线索二叉树**。

## 输入-输出空间
- **输入**：一棵已构建好的二叉树
- **输出**：线索化后的二叉树（空指针被前驱/后继线索填充）
- **核心操作**：`visit` 函数中处理当前结点与 `pre` 指针的关系

## 正例（≥2 个）
1. **中序线索化后找后继**：若 `rtag=1`，`rchild` 直接就是后继；否则后继 = 右子树最左下结点
2. **避免重复遍历**：以前找中序前驱需从根完整遍历一次（$O(n)$），现在 $O(1)$ 或 $O(h)$

## 反例/边界（≥1 个）
1. **先序线索化的「转圈圈」问题**：当 `ltag` 被设为 1 后，`lchild` 指向了前驱而非左孩子，如果不对 `ltag` 进行判断就去线索化左子树，会陷入死循环。解决方法：先序线索化时只对 `ltag==0` 的情况才递归左子树
2. **最后一个结点的处理**：遍历结束后，最后一个结点的 `rchild` 可能仍为空（`rtag` 未设置），需额外处理

## 详细解释

### 数据结构定义

```c
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;   // 0=孩子指针，1=线索
} ThreadNode, *ThreadTree;
```

### 中序线索化（核心 = 中序遍历 + 线索处理）

```c
ThreadNode *pre = NULL;  // 全局变量，指向当前访问结点的前驱

void InThread(ThreadTree T) {
    if (T != NULL) {
        InThread(T->lchild);     // 左（递归线索化左子树）
        visit(T);                // 根（处理当前结点）
        InThread(T->rchild);     // 右（递归线索化右子树）
    }
}

void visit(ThreadNode *q) {
    if (q->lchild == NULL) {     // 左孩子为空 → 建立前驱线索
        q->lchild = pre;
        q->ltag = 1;
    }
    if (pre != NULL && pre->rchild == NULL) {  // 前驱的右孩子为空 → 建立后继线索
        pre->rchild = q;
        pre->rtag = 1;
    }
    pre = q;                     // 更新前驱指针
}

void CreateInThread(ThreadTree T) {
    pre = NULL;
    if (T != NULL) {
        InThread(T);
        if (pre->rchild == NULL)  // 处理最后一个结点
            pre->rtag = 1;
    }
}
```

### 先序线索化（注意防转圈）

```c
void PreThread(ThreadTree T) {
    if (T != NULL) {
        visit(T);
        if (T->ltag == 0)         // ⚠️ 只有左孩子是真实孩子时才递归左子树
            PreThread(T->lchild);
        PreThread(T->rchild);     // 右子树始终递归（rtag 不影响）
    }
}
```

**转圈圈原因**：在先序线索化 `visit(T)` 之后，如果 `T` 的左指针被线索化（指向了 `pre`），此时再递归 `T->lchild` 就会回到前驱结点，而非真正的左孩子。

### 后序线索化

```c
void PostThread(ThreadTree T) {
    if (T != NULL) {
        PostThread(T->lchild);   // 左
        PostThread(T->rchild);   // 右
        visit(T);                // 根
    }
}
```

后序线索化**不会转圈**——因为 `visit` 时左右子树已经处理完了，`lchild` 被改掉也不会影响后续。

### 三种线索化对比

| | 中序线索化 | 先序线索化 | 后序线索化 |
|---|---|---|---|
| 本质遍历 | 左-根-右 | 根-左-右 | 左-右-根 |
| 转圈风险 | 无 | **有**（需判断 `ltag`） | 无 |
| 最后一个结点 | 无右孩子 | 无右孩子 | 无右孩子 |

## 类比

### 一句话比喻
**线索二叉树就像景区给每条死胡同贴「前方无路，回头是岸」的路标——二叉树的空指针就是死胡同，本来这些空指针白白浪费着，现在用来直接告诉你「你的下家是谁」（后继）或者「你上家是谁」（前驱）。游客不用每次都回到景区大门口（根结点）重新看地图，顺着路标就能走完全程。**

### 生活映射
| 数据结构世界 | 景区导航 |
|---|---|
| n+1 个空指针域 | 景区里的 n+1 个死胡同路口 |
| 线索 = 前驱/后继指针 | 「前一个景点往这儿走」「下一个景点往那儿走」的路标 |
| `ltag=0/1` | 路标是「去孩子家」还是「去邻居家」 |
| `rtag=0/1` | 路标是「去孩子家」还是「去下一个景点」 |
| `pre` 全局指针 | 你手上拿着的上一个景点的位置牌——路过新景点时，顺手给上个景点贴上「下一站在这儿」 |
| 先序转圈圈 | 你先给自己贴了路标，然后按路标走——结果走回自己，原地打转 |
| 中序不转圈 | 你先逛完左边、贴完路标，再往右走——路标都是指向已经逛过的，不会走回头路 |
| 最后一个结点 | 最后一个景点——逛完了，贴个「终点站，前方无景点」 |
