# 查找的基本概念

## 类型判定
判别型 — 定义查找、查找表、关键字等核心概念，区分静态/动态查找表，引入 ASL 作为查找算法评价指标。

## 是什么
**查找**就是在数据集合中找到目标数据元素；**查找表**是用于存储数据的数据结构（线性、树、图均可）；**关键字**是唯一区分各数据元素的数据项。评价查找算法看 **ASL（平均查找长度）**——所有查找情况下关键字对比次数的加权平均值。

## 正例（≥2 个）
1. **成绩单按学号查找**：学号是关键字（唯一），成绩单是静态查找表（成绩出来后不再修改）
2. **微信用户按微信号查找**：微信号是关键字，用户图谱是查找表（图结构）
3. **订餐系统按订单号查找**：订单号是关键字，订单表是动态查找表（会新增/取消订单）

## 反例/边界（≥1 个）
1. **姓名作为关键字**：有重名的人（两个"铁柱"），不满足唯一性 → 不能作为关键字
2. **所有整数集合**：无限集合 → 不能作为查找表（必须是有限序列）

## 详细解释

### 静态 vs 动态查找表
| | 静态查找表 | 动态查找表 |
|---|---|---|
| 操作 | 仅查找 | 查找 + 插入 + 删除 |
| 数据 | 不变 | 会变化 |
| 例子 | 成绩单 | 订单系统 |
| 影响 | 只需优化查找速度 | 还需考虑插入删除的方便性 |

### ASL 计算公式
$$\text{ASL} = \sum_{i=1}^{n} P_i \cdot C_i$$

- $P_i$：查找第 $i$ 个元素的概率（默认等概率 = $1/n$）
- $C_i$：查找第 $i$ 个元素所需的关键字对比次数
- 分**查找成功**和**查找失败**两种 ASL
- ASL 的数量级直接反映查找算法的时间复杂度

## 类比 ★

### 一句话比喻
**查找就像在图书馆找一本书——查找表是书架（数据容器），关键字是索书号（唯一标识），ASL 是平均翻了几次书才找到。静态书架上的书不会变（只查不写），动态书架天天有人借还（要能增删）。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 查找表 | 图书馆的所有书架 |
| 关键字 | 索书号（每本书独一无二） |
| 静态查找表 | 档案馆——资料入库后不再变动 |
| 动态查找表 | 图书馆借阅区——随时有人借走、归还 |
| ASL | "平均翻多少次书才能找到目标" |
| 查找成功 | 找到了你要的书 |
| 查找失败 | 翻遍了也没这本书 |
