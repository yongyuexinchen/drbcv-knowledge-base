# 栈在递归中的应用

## 类型判定
判别型 — 揭示递归调用背后**函数调用栈**（Call Stack）的工作原理，递归本质上就是系统自动帮你维护一个栈。

## 是什么
**任何函数调用背后都需要栈的支持。** 当函数 A 调用函数 B，系统把 A 的返回地址、实参、局部变量压入栈中，然后执行 B；B 返回时从栈顶弹出 A 的信息，继续执行下一句。递归就是函数调用自身的特例，递归层数 = 栈的深度。

## 输入-输出空间
- **入栈时机**：每次函数调用（进入更深一层递归）
- **出栈时机**：每次函数返回（递归到达边界条件后逐层返回）
- **风险**：递归层数太多 → 栈溢出（Stack Overflow）

## 正例（≥2 个）
1. **计算 n!**：`fact(n) = n * fact(n-1)`，`fact(1)=1` 为边界。计算 fact(10) 时栈中压入 10 层调用，到达边界后逐层弹出返回
2. **斐波那契数列**：`fib(n) = fib(n-1) + fib(n-2)`，栈中会有重复计算——fib(2) 被算多次

## 反例/边界（≥1 个）
1. **递归层数过大导致栈溢出**：`fact(100000)` → 栈空间有限，可能崩溃
2. **递归算法效率低**：斐波那契的递归实现有大量重复计算 → 不如迭代（非递归）高效

## 详细解释

### 函数调用栈的内容

每次函数调用，栈中压入三部分信息：
1. **返回地址**：调用结束后下一句该执行哪句代码
2. **实参**：传给被调函数的参数值（值传递 —— 副本）
3. **局部变量**：被调函数内部定义的变量

### 递归的两个要素

| 要素 | 说明 | 示例（阶乘） |
|------|------|-------------|
| **递归表达式** | 将问题规模 n 转化为更小的规模 | `fact(n) = n * fact(n-1)` |
| **边界条件** | 递归出口，不再继续调用自身 | `fact(1) = 1` |

### 阶乘递归的栈变化

```
fact(4) 调用：
  main → fact(4) → fact(3) → fact(2) → fact(1)
  压栈     压栈       压栈       压栈       压栈（到达边界）

  fact(1) 返回 1 → fact(2) 返回 2 → fact(3) 返回 6 → fact(4) 返回 24
  弹栈           弹栈            弹栈            弹栈
```

### 递归算法空间复杂度分析

递归深度 = 栈的最大深度 → 空间复杂度 $O(n)$。
例如计算 `fact(n)`，空间复杂度为 $O(n)$（栈中最多 n 层），而迭代仅需 $O(1)$。

### 递归 vs 迭代

| | 递归 | 迭代（循环） |
|---|---|---|
| 实现 | 函数自调用 | for/while 循环 |
| 空间复杂度 | $O(n)$（栈） | $O(1)$ |
| 栈溢出风险 | 有（层数多） | 无 |
| 代码可读性 | 简洁优雅 | 有时冗长 |
| 重复计算 | 可能有（如斐波那契） | 可避免 |

### 如何将递归改非递归

递归背后就是栈 → 自己手动定义一个栈，模拟系统栈的压入/弹出过程，即可将递归改写为非递归。

## 类比

### 一句话比喻
**递归就像俄罗斯套娃——你要打开最外面的娃娃（n=4），发现里面还有一个（n=3），再打开又有一个……直到最小的实心娃娃（n=1，递归出口）。然后你从里往外一层层合上，每合一层都记住"我合的是第几层"。栈就是你的工作台，每一层娃娃的"包装纸和说明书"都暂放在台上，合完一层就拿走一层的东西。**

### 生活映射

| 数据结构世界 | 现实世界 |
|---|---|
| 函数调用栈 | 工作台上的便签纸——每打开一层套娃，撕一张便签记下"这一层合上后该干嘛" |
| 压栈（函数调用） | 打开一个娃娃，便签上写"合上后继续数下一层" |
| 弹栈（函数返回） | 合上这一层娃娃，撕掉对应的便签，看下一张 |
| 边界条件（`n==1`） | 最小的实心娃娃——打不开，直接返回 |
| 栈溢出 | 套娃无限多，工作台堆满便签纸塌了 |
| 递归深度 = 空间复杂度 | 桌子上最多同时摞了多少张便签 |
| 斐波那契重复计算 | 每个娃娃都自己再拆一遍——同一个尺寸的娃娃拆了 N 次 |
| 手动栈改写非递归 | 不再相信自动套娃机，自己拿个本子记录每一层 |
