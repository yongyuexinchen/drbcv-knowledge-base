# 时间复杂度（Time Complexity）

## 类型判定
判别型 — 408考研每年必考的核心概念。定义了大O表示法、常见数量级口诀、分析步骤，为后续所有算法复杂度分析打基础。

## 是什么
**时间复杂度是用于评价一个算法时间开销的指标，描述算法运行时间 $T(n)$ 随问题规模 $n$ 的增长趋势——用大O表示法只关注数量级，忽略常数项和低阶项。** 它不是在计时器上看跑了多少毫秒，而是看「数据量翻倍时，运行时间会翻多少倍」。

## 输入-输出空间
- **输入**：算法代码 + 问题规模 $n$
- **输出**：一个 $O(f(n))$ 表达式表示时间复杂度的数量级
- **核心方法**：找到最深层循环中某条基本语句的执行次数与 $n$ 的关系

## 正例（≥2 个）
1. **逐步递增型爱你（单层循环 n 次）**：`for(i=0;i<n;i++) printf("爱你第%d遍", i)` → 循环内语句执行 n 次 → $T(n) = O(n)$
2. **双层嵌套循环**：外层 n 次 × 内层 n 次 → 最深层语句执行 $n^2$ 次 → $T(n) = O(n^2)$
3. **每次翻倍的循环**：`i=1; while(i<n) i*=2;` → 循环 $\log_2 n$ 次 → $T(n) = O(\log_2 n)$

## 反例/边界（≥1 个）
1. **用秒表计时来评价算法**（事后统计法）❌：跑出来快可能是因为机器好/语言底层高效，不代表算法本身好。同一个 $O(n^2)$ 算法在超级计算机上也可能比 $O(n\log n)$ 在低端机上快——但问题规模扩大后，$O(n^2)$ 一定会被反超。事后统计还受编程语言、编译器优化影响，且像导弹控制算法根本不能「先试试再说」。
2. **顺序执行的千行代码**：在循环前插入 1000 行顺序代码 → 只会增加常数项 $O(1)$，不影响整体数量级 → 忽略！

## 详细解释

### 大O表示法的三步简化

对于一个时间开销表达式 $T(n) = 3n^3 + 6n^2 + 1000$：

1. **只保留最高阶项**：$3n^3$（加法规则）
2. **去掉系数**：$n^3$（系数变为1）
3. **套上大O**：$O(n^3)$

### 加法规则和乘法规则
- **加法规则**（取最大值）：$O(f(n)) + O(g(n)) = O(\max(f(n), g(n)))$
  - 例：$O(n^3) + O(n^2) + O(1) = O(n^3)$
- **乘法规则**（相乘合并）：$O(f(n)) \times O(g(n)) = O(f(n) \times g(n))$
  - 例：嵌套循环，外层 $O(n)$ × 内层 $O(n) = O(n^2)$

### 口诀：**常对幂指阶**（从优到劣）
| 数量级 | 大O记法 | n=1000时 ≈ | 口诀 |
|--------|---------|-----------|------|
| 常数阶 | $O(1)$ | 1 | **常** |
| 对数阶 | $O(\log_2 n)$ | 10 | **对** |
| 线性阶 | $O(n)$ | 1,000 | — |
| 线性对数阶 | $O(n\log_2 n)$ | 10,000 | — |
| 平方阶 | $O(n^2)$ | 1,000,000 | **幂** |
| 立方阶 | $O(n^3)$ | 1,000,000,000 | **幂** |
| 指数阶 | $O(2^n)$ | $2^{1000}$ ≈ 宇宙原子数 | **指** |
| 阶乘阶 | $O(n!)$ | 1000! — 不可想象 | **阶** |

### 分析步骤
1. 找到**最深层循环**中的任意一条基本语句
2. 分析这条语句的**执行次数**与问题规模 $n$ 的数学关系
3. 用大O表示数量级
4. 如果算法随输入数据不同而变化（如顺序查找），还需区分**最好/最坏/平均**时间复杂度

### 三种复杂度
| 类型 | 含义 | 实战意义 |
|------|------|---------|
| **最坏时间复杂度** | 最背的情况下跑多久 | ⭐ 最常用——保证性能下限 |
| **平均时间复杂度** | 所有可能情况的数学期望 | 参考价值高 |
| **最好时间复杂度** | 走运的情况下跑多久 | 参考意义不大 |

### 真实血泪教训（讲师亲述）
讲师大四实习时用 $O(n^2)$ 算法做玩家匹配：本地测两三百玩家正常（$300^2=9$万），部署到线上几十万玩家时 → $10$万$^2=100$亿次运算 → 线上崩了，几十万玩家受影响。师傅改成 $O(n)$ 后才正常。

> **很多算法的性能问题，只有在问题规模足够大时才会暴露。**

## 类比

### 一句话比喻
**时间复杂度就像你给100个人发传单——$O(1)$ 是你站在喇叭上广播一次搞定所有人；$O(n)$ 是你一个一个递，递到第100个人时你已经腿软；$O(n^2)$ 是你每递一个人之前还要挨个确认前面所有人都拿到了——第100个人要在你面前站到你跑完 $100 \times 100 = 10000$ 次确认，传单还没发完天就黑了。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| $O(1)$（常数阶） | 广播通知——不管多少人，只喊一次 |
| $O(\log n)$（对数阶） | 猜数字（每次范围减半）——1000个数猜10次就够了 |
| $O(n)$（线性阶） | 逐个点名——100人点100次，1000人点1000次 |
| $O(n^2)$（平方阶） | 全班每人分别和全班每人握一次手——$n(n-1)/2$ 次，手断 |
| $O(2^n)$（指数阶） | 把所有可能的密码组合全试一遍——密码每多一位，尝试次数翻倍 |
| $O(n!)$（阶乘阶） | 给10本教材排出所有可能的阅读顺序——10! = 3628800种，你读到博士毕业也没读完 |
| 大O忽略常数 | 你有3000块，室友9000块——差3倍但同一数量级；但如果有人有900万，那就是另一个世界了 |
| 最坏时间复杂度 | 春运买票——按「排在队伍最后」的时候来预估等待时间（保证你无论如何不会等更久） |
| 平均时间复杂度 | 随机排队——按平均位置预估等待时间 |
