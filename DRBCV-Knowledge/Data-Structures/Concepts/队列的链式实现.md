# 队列的链式实现（Linked Queue）

## 类型判定
程序型 — 队列的**链式存储实现**，用单链表 + 头尾指针实现。插入在表尾、删除在表头，**同时维护 front 和 rear 两个指针**。

## 是什么
用带头结点（或不带头结点）的单链表存储队列元素，额外维护一个**尾指针 `rear`** 指向最后一个结点。入队 = 表尾后插（O(1)），出队 = 删除表头结点（O(1)）。如果没有 rear 指针，每次入队需 $O(n)$ 遍历到表尾。

## 输入-输出空间
- **EnQueue(Q, x)**：malloc 新结点 → 链到 rear 之后 → 更新 rear
- **DeQueue(Q, &x)**：删除 front->next（带头结点）或 front 本身（不带头结点）
- **前置条件**：入队无容量限制（内存够即可）；出队需非空

## 正例（≥2 个）
1. **带头结点**：初始化 front 和 rear 都指向头结点，第一个元素和后续元素入队逻辑统一
2. **不带头结点**：初始 front=rear=NULL，第一个元素入队时需同时修改 front 和 rear

## 反例/边界（≥1 个）
1. **最后一个元素出队时忘记改 rear**：出队后队列变空，rear 还指着已释放的结点 → 野指针 → 下次入队崩溃
2. **只有 front 没有 rear**：每次入队需 $O(n)$ 遍历到尾 → 效率退化

## 详细解释

### 结构体定义
```c
// 链式队列结点
typedef struct LinkNode {
    ElemType data;
    struct LinkNode *next;
} LinkNode;

// 链式队列（需要头尾两个指针）
typedef struct {
    LinkNode *front, *rear;   // 队头指针，队尾指针
} LinkQueue;
```

### 核心代码（带头结点）

```c
// 初始化（带头结点）
void InitQueue(LinkQueue &Q) {
    Q.front = Q.rear = (LinkNode *)malloc(sizeof(LinkNode));
    Q.front->next = NULL;
}

// 判空
bool QueueEmpty(LinkQueue Q) {
    return Q.front == Q.rear;  // 也可以判断 Q.front->next == NULL
}

// 入队（在表尾插入）
void EnQueue(LinkQueue &Q, ElemType x) {
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
    s->data = x;
    s->next = NULL;
    Q.rear->next = s;          // 链到当前表尾之后
    Q.rear = s;                // 更新尾指针
}

// 出队（删除表头）
bool DeQueue(LinkQueue &Q, ElemType &x) {
    if (Q.front == Q.rear) return false;   // 空队
    LinkNode *p = Q.front->next;            // 要删除的结点
    x = p->data;
    Q.front->next = p->next;                // 修改头结点指针
    if (Q.rear == p)                        // ⚠️ 若删的是最后一个结点
        Q.rear = Q.front;                   // 尾指针也回归头结点
    free(p);
    return true;
}
```

### 关键注意事项

**最后一个元素出队时**：必须额外判断 `Q.rear == p`，若成立则将 `Q.rear` 也指向头结点，否则 rear 变成野指针。

### 带头结点 vs 不带头结点

| | 带头结点 | 不带头结点 |
|---|---|---|
| **初始化** | malloc 头结点，front=rear=头结点 | `front = rear = NULL` |
| **判空** | `front == rear` 或 `front->next == NULL` | `front == NULL` |
| **第一个入队** | 统一逻辑 | 需同时修改 front 和 rear |
| **最后一个出队** | rear 回归头结点 | front 和 rear 都 = NULL |

### 时间复杂度

| 操作 | 复杂度 |
|------|--------|
| EnQueue | $O(1)$ |
| DeQueue | $O(1)$ |
| GetHead | $O(1)$ |
| 求队长 | $O(n)$（需遍历） |

⚠️ 求链队列长度需遍历，$O(n)$。若频繁需要长度信息，可在结构体中增加 `int length` 变量。

## 类比

### 一句话比喻
**链队列就像迪士尼排队的蛇形通道——入口（rear）源源不断进人，出口（front）一个个放人出去玩项目。每个游客只需要认识自己后面那位（next 指针），通道可以无限加长。工作人员头尾各站一个（front 和 rear），不用每次从入口跑到出口看还有多少人。**

### 生活映射

| 数据结构世界 | 现实世界 |
|---|---|
| `front` 指针 | 出口验票员——守着队头，一个一个放行 |
| `rear` 指针 | 入口引导员——守着队尾，安排新来的排到最后 |
| 入队 `s->next=NULL; rear->next=s; rear=s` | 新游客被引导到末端，引导员自己也往后挪 |
| 出队 `front->next = p->next` | 队头那位玩去了，后面那位变成新队头 |
| 最后一个出队后 `rear = front` | 全场没人了，出口和入口的工作人员面面相觑 |
| 不带头结点 | 连"入口大门"都没有，第一个人直接当队头 |
| 求队长 $O(n)$ | 不数人头不知道——必须从出口一个个数到入口 |
