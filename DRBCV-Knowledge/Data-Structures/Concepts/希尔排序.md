# 希尔排序（Shell Sort）

## 类型判定
程序型 — 希尔排序是**插入排序的优化版本**，核心思想是通过"增量递减"的策略先追求部分有序，再逐步逼近全局有序，从而利用插入排序"基本有序时效率高"的特性。

## 是什么
希尔排序先将待排序表按**增量 d** 拆分成若干"特殊的子表"（相距为 d 的元素属于同一子表），对各子表分别进行**直接插入排序**；然后逐步缩小增量 d（通常每次减半），重复上述过程，直到 d=1 时对整体进行一次插入排序，得到全局有序。

## 输入-输出空间
- **输入**：数组 A[1..n]（本算法只用顺序表），n 个元素
- **输出**：递增有序的数组
- **前置条件**：需指定增量序列（如 d=n/2, d=d/2, ..., 1）

## 正例（≥2 个）
1. **经典增量序列 n/2→1**：8个元素 → d₁=4, d₂=2, d₃=1，三趟完成排序，比直接插入快得多
2. **中量级数据**：在 n 不太大时，希尔排序效率可达 $O(n^{1.3})$，远优于 $O(n^2)$

## 反例/边界（≥1 个）
1. **增量 d₁ 直接取 1**：退化为直接插入排序 → 最坏 $O(n^2)$
2. **不稳定**：相同关键字可能因跨子表交换而改变相对位置。例如 [65, 49₁, 49₂] 取 d=2 → 49₁ 和 65 交换 → 最终两个 49 位置互换
3. **不能用于链表**：需要按增量 d 随机访问元素，链表无法做到

## 详细解释

### 核心代码
```c
void ShellSort(int A[], int n) {
    int d, i, j;
    // d 初始为 n/2，每次减半
    for (d = n / 2; d >= 1; d = d / 2) {
        // 对每个子表进行直接插入排序
        for (i = d + 1; i <= n; i++) {
            if (A[i] < A[i - d]) {      // 当前子表中需调整
                A[0] = A[i];             // A[0] 暂存（非哨兵，只是暂存）
                for (j = i - d; j > 0 && A[j] > A[0]; j -= d)
                    A[j + d] = A[j];     // 子表中后移 d 位
                A[j + d] = A[0];
            }
        }
    }
}
```

### 关键注意事项
- 代码中 `i++` 导致**轮流切换处理不同子表**（不是连续处理完同一子表再处理下一个）——这是课本的实现方式
- 也可以连续处理同一子表，逻辑上更清晰，两种写法等价
- `j -= d` 而非 `j--`：子表内元素间隔为 d

### 时间复杂度
- **无法用数学手段精确证明**——这是希尔排序的特殊之处
- 最坏：退化为直接插入排序时 $O(n^2)$
- 某范围内（n 不太大）：约 $O(n^{1.3})$
- 考试不要求精确复杂度，知道"优于 $O(n^2)$，但无法精确分析"即可

### 空间复杂度与稳定性
- 空间复杂度：**$O(1)$**
- 稳定性：**不稳定**（跨子表交换时可能破坏相同关键字的相对顺序）
- 适用存储：**仅顺序表**（需随机访问，无法用于链表）

## 类比 ★

### 一句话比喻
**希尔排序就像军训排队——教官不会让每个人逐一精确对比（太慢！），而是先喊"每4个人一组，组内从矮到高排好"（d=4，粗排），然后"每2人一组再排"（d=2，中排），最后"全体都有，从矮到高"（d=1，精排）。前三步大家已经基本有序了，最后一步精排特别快——比你上来就一个一个比快多了。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 增量 d | 军训时"每 d 个人一组"的那个间隔 |
| d 逐步缩小 | 从大范围粗排到小范围精排 |
| 子表直接插入排序 | 组内成员从矮到高排好 |
| d=1 最后一趟 | 全连集合，最终排队确认 |
| 不稳定 | 排的过程中有人从第4组蹦到第1组 |
| 只能顺序表 | 必须能一眼看到第 d 个人是谁——链表做不到 |
