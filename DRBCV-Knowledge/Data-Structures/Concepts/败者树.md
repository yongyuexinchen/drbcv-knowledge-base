# 败者树（Loser Tree）

## 类型判定
程序型 — 败者树是外部排序中优化多路归并的辅助数据结构，用于减少"从 K 个归并段中选最小元素"的关键字对比次数。

## 是什么
败者树是一棵**完全二叉树**（额外多一个根结点），K 个叶子结点对应 K 个归并段的当前最小元素。每个非叶结点记录**左右子树中的"败者"（较大的元素）来自哪个归并段**，胜者继续向上比赛，直到根结点产生冠军（全局最小元素）。

- **传统方法**：从 K 路中选最小 → 需 K-1 次关键字对比
- **败者树**：构造后每次选最小 → 只需 $\lceil \log_2 K \rceil$ 次对比

## 输入-输出空间
- **输入**：K 个归并段，每个段有一个"当前最小元素"
- **输出**：全局最小元素（来自哪个归并段）
- **前置条件**：需大小为 K 的数组存储败者树

## 正例（≥2 个）
1. **1024路归并**：传统方法需 1023 次对比/每次 → 败者树只需 10 次对比/每次（$\log_2 1024 = 10$）
2. **八路归并**：传统方法需 7 次对比 → 败者树构造需 7 次，之后每次只需 3 次

## 反例/边界（≥1 个）
1. **第一次构造仍需 K-1 次对比**：败者树省的是"之后每次"的对比，第一次构造各叶子结点之间的比拼仍需 K-1 次
2. **需要额外内存**：败者树本身占用 K 个 int 的空间（存储归并段编号）

## 详细解释

### 构造过程（八路归并为例）
8 个叶子对应 8 个归并段的当前最小元素：`[27, 12, 1, 17, 2, 9, 11, 4]`

```
        [冠军: 段3(值=1)]
              |
         [段5(2)]
         /      \
    [段2(12)]   [段3(1)]
    /    \      /    \
  [段1] [段4] [段3] [段8]
  /  \  /  \  /  \  /  \
 27  12 1  17 2  9 11  4
```

- 非叶结点存储的是**失败者来自哪个归并段**，而非具体值
- 叶子结点（虚拟）存储各段当前最小元素的值
- 新元素替代冠军后：只需沿路径向上对比——对比次数 = 树中灰色结点层数 = $\lceil \log_2 K \rceil$

### 对比次数分析
- 一个结点下坠一层：有两个孩子时比 2 次（孩子间 1 次 + 根 vs 选中孩子 1 次），只有一个孩子时比 1 次
- 构造败者树共需 K-1 次对比（和传统方法一样）
- 之后每次选最小：$\lceil \log_2 K \rceil$ 次（远优于 K-1）

### 存储结构
```c
int loserTree[K];     // loserTree[0] 存冠军编号
                       // loserTree[1..K-1] 存败者编号
                       // 叶子结点是虚拟的，不对应数组元素
```

- 空间复杂度：$O(K)$（仅需 K 个 int）
- 败者树 vs 胜者树：败者树重构更方便——新元素只需和路径上的"败者"比，不需要同时维护胜者信息

## 类比 ★

### 一句话比喻
**败者树就是一场足球淘汰赛——8个队的队长（叶子）先两两踢，输的人记在比赛结点上（败者），赢的人继续往上踢。最终冠军产生后，冠军退赛，新队长顶替——不用所有比赛重踢！新队长只需要沿着"输的人"那条路一层层打上去，最多打 $\log_2 8 = 3$ 场就能产生新冠军，而不是重新踢 7 场。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| K 个叶子结点 | K 个参赛队长 |
| 非叶结点（败者） | 每场比赛输的那个人的编号 |
| 冠军（根结点） | 全局最强的队长编号 |
| 新元素替代冠军 | 冠军退赛，新队长补位 |
| 沿路径向上对比 | 新队长只和之前"输过的人"比 |
| $\lceil \log_2 K \rceil$ 次 | 最多打树高那么多场比赛 |
