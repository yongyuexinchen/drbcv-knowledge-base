# B树（多路平衡查找树）

## 类型判定
判别型 + 程序型 — 定义（阶、子树数范围、绝对平衡）、查找、插入（分裂）、删除（借/合并）、高度分析。

## 是什么
**多路平衡查找树**。每个结点可含多个关键字和多个分叉，所有子树高度完全相同（绝对平衡）。设计目标是**减少磁盘 I/O**——让树变"矮胖"，每一层结点存更多关键字。

## 输入-输出空间
- **查找**：从根出发，结点内顺序/折半查找 → 确定下一层分支 → 直到叶结点（失败结点）
- **插入**：必插入终端结点 → 若溢出则**分裂**（中间关键字上提到父结点）→ 可能连锁分裂到根
- **删除**：终端结点直接删（不够向兄弟**借**或**合并**），非终端用前驱/后继替代后转终端删除

## 正例（≥2 个）
1. **5 阶 B 树（最多 4 关键字/5 分叉，最少 2 关键字/3 分叉）**：插入到溢出 → 中间关键字上提分裂
2. **磁盘文件系统索引**：每个结点 = 一个磁盘块，一次 I/O 读入多个关键字

## 反例/边界（≥1 个）
1. **退化为二叉树**：每结点只放 1 关键字 → 失去 B 树"矮胖"优势，磁盘 I/O 次数飙升
2. **不保持绝对平衡**：子树高度不同 → 不是 B 树

## 详细解释

### M 阶 B 树的核心特性（考试全看这几条！）

| 特性 | 含义 |
|---|---|
| ① 结点关键字数 | 根结点：$1 \leq n \leq M-1$；非根：$\lceil M/2 \rceil - 1 \leq n \leq M-1$ |
| ② 子树数 = 关键字数 + 1 | n 个关键字对应 n+1 个分叉 |
| ③ 绝对平衡 | 所有子树高度完全相同 → 所有叶结点（失败结点）在同一层 |
| ④ 左 < 中 < 右 | 指针 $P_{i-1}$ 所指子树的关键字 < $K_i$ < 指针 $P_i$ 所指子树的关键字 |

### 查找
类似 BST 的多叉版：从根出发，结点内顺序查找确定分支 → 直到叶结点（失败）。

### 插入（核心：分裂）
1. 通过查找确定插入位置（**必定在终端结点**）
2. 插入后若关键字数 > M-1 → **分裂**：
   - 取中间位置 $\lceil M/2 \rceil$ 的关键字**提到父结点**
   - 左右两部分拆成两个新结点
3. 若父结点也溢出 → 继续分裂，可能一直裂到根（树高 +1）

### 删除（三种情况）
| 情况 | 操作 |
|---|---|
| ① 删终端结点，删后仍 ≥ 下限 | 直接删 |
| ② 删终端结点，低于下限 | **向右兄弟借**（后继+后继的后继填补）或**向左兄弟借**（前驱+前驱的前驱填补） |
| ③ 兄弟不够借 | **合并**：当前结点 + 兄弟 + 双亲中间关键字 → 合并为一个结点；双亲关键字少 1 → 可能向上传导 |

### 高度分析
含 n 个关键字的 M 阶 B 树：
- **最小高度**（每结点满）：$h_{\min} \geq \log_M(n+1)$
- **最大高度**（每结点在下限）：$h_{\max} \leq \log_{\lceil M/2 \rceil}\left(\frac{n+1}{2}\right) + 1$
- 数量级：$O(\log_M n)$

### 复杂度
- 查找/插入/删除：均为 $O(\log_M n)$（树高极低）

## 类比 ★

### 一句话比喻
**B 树就像多层立体仓库——每个货架层（结点）能放好多商品（关键字），取货时（查找）从顶层看起，"你要的在这层左边"→ 下一层 → 再下一层，几层就到。层数少（树矮）= 爬楼梯次数少（磁盘 I/O 少）。传统 BST 像一排平房——要找就得一间间看，累死。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 一个 B 树结点 | 仓库的一层货架（能放很多 SKU） |
| 结点的关键字 | 货架上每个格子贴的编号 |
| M 阶 | 每层最多 M 个通道（分叉） |
| 分裂 | 这层货架塞爆了 → 中间那个编号升到上一层，左右拆成两个新货架 |
| 根结点分裂 | 连最高层都爆了 → 仓库加盖一层 |
| 兄弟借 | 左边货架空一半 → 匀几个商品过来 |
| 合并 | 左右两架都半空 → 并成一架，中间编号拉下来 |
| 绝对平衡 | 不管哪条路下楼，到出口的层数都一样 |
| $O(\log_M n)$ | 一个 100 阶 B 树存百万数据仅需 3 层 |
