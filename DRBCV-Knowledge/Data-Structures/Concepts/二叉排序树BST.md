# 二叉排序树（BST, Binary Search Tree）

## 类型判定
判别型 + 程序型 — 定义 BST 的递归特性，含查找、插入、删除、构造及 ASL 分析。

## 是什么
**左子树所有结点值 < 根结点值 < 右子树所有结点值**（递归定义）。中序遍历得到递增有序序列。查找、插入、删除的时间复杂度取决于树高 $O(h)$，最好 $O(\log n)$，最坏 $O(n)$。

## 输入-输出空间
- **查找**：输入根指针 + key → 返回结点指针（或 NULL）
- **插入**：输入根指针引用 + key → 新结点永远是叶子
- **删除**：输入根指针引用 + key → 分三种情况处理
- **构造**：输入关键字序列 → 按序插入即可

## 正例（≥2 个）
1. **字典序单词存储**：root="m"，左边全是 a~l，右边全是 n~z → 自然有序
2. **数据库索引的朴素版**：按主键构建 BST，查找时从根出发逐层判断

## 反例/边界（≥1 个）
1. **插入序列已有序**：如 1,2,3,4,5 依次插入 → 退化成单链表，树高 = n，查找 $O(n)$
2. **相同关键字的处理**：BST 不允许重复关键字 → 插入重复值应返回失败

## 详细解释

### 查找（非递归，$O(1)$ 辅助空间）
```c
BSTNode* Search(BSTNode *T, int key) {
    while (T != NULL && T->key != key) {
        if (key < T->key) T = T->lchild;
        else T = T->rchild;
    }
    return T;  // 找到返回结点，未找到返回 NULL
}
```

### 插入（递归，新结点必为叶子）
```c
bool Insert(BSTNode *&T, int key) {
    if (T == NULL) {
        T = (BSTNode*)malloc(sizeof(BSTNode));
        T->key = key;
        T->lchild = T->rchild = NULL;
        return true;
    }
    if (key == T->key) return false;          // 已存在，插入失败
    if (key < T->key) return Insert(T->lchild, key);
    else return Insert(T->rchild, key);
}
```

### 删除（三种情况）
| 情况 | 操作 | 示例 |
|---|---|---|
| ① 叶子结点 | 直接删 | 删 18 |
| ② 仅左/右子树 | 用子树替代 | 删 13（只有左子树）→ 左孩子顶上 |
| ③ 左右都有 | 用**直接后继**（右子树最左下）或**直接前驱**（左子树最右下）替代，再删替代结点 | 删 50 → 用 60 替代，60 变为情况② |

### 不同插入顺序 → 不同树形
同一组关键字，插入顺序不同，BST 形状不同，ASL 也不同。**同样 8 个结点，左边"胖树"ASL=2.625，右边"瘦树"ASL=3.75。**

### 复杂度
| 情况 | 查找/插入/删除 |
|---|---|
| 最好（平衡） | $O(\log n)$ |
| 最坏（退化为链） | $O(n)$ |

## 类比 ★

### 一句话比喻
**BST 就像图书馆按索书号排的书架——你站在中间，左边全是比你小的编号，右边全是比你大的。找书时每走一步都砍掉一半可能性（如果书架摆得匀称的话）。但要是管理员偷懒从 001 开始一本本往里塞……那书架就变成一条歪歪扭扭的长龙，找书跟翻垃圾堆一样。**

### 生活映射
| 数据结构世界 | 现实世界 |
|---|---|
| 根结点 | 你随手抽出的第一本书放在中间 |
| 左子树 < 根 < 右子树 | 编号小的放左边，编号大的放右边 |
| 中序遍历 | 从左到右把书脊编号念一遍——恰好递增 |
| 查找 | "T-101？比 M-500 小，去左边……比 G-200 大，去右边……找到了！" |
| 插入（新结点是叶子） | 新书总是被塞到书架最边缘 |
| 删除情况③ | 要抽走中间一本，用右边最小的那本填坑 |
| 退化 | 书架变成一条线——找最后一本要走遍整个图书馆 |
| 平衡 BST | 书架摆得四四方方——左右差不多高 |
