# 由遍历序列构造二叉树（Construct Binary Tree from Traversals）

## 类型判定
程序型 — 给定两种遍历序列，递归恢复出唯一的二叉树形态。核心是利用「中序划分左右子树」+「另一序列定位根结点」。

## 是什么
给定一棵二叉树的**中序遍历序列**和另一种遍历序列（先序/后序/层序），可以唯一确定该二叉树的形态。关键原理：中序序列中，根结点左边的都是左子树，右边的都是右子树。

## 输入-输出空间
- **输入**：中序遍历序列 + 先序/后序/层序序列（两个序列）
- **输出**：唯一的二叉树形态
- **前置条件**：必须包含**中序序列**，且两个序列中的结点集合相同

## 正例（≥2 个）
1. **先序 + 中序**：先序第一个是根，在中序中找到根的位置 → 左边是左子树，右边是右子树 → 递归
2. **后序 + 中序**：后序最后一个是根，同理递归
3. **层序 + 中序**：层序第一个是根，同理递归

## 反例/边界（≥1 个）
1. **仅有先序序列**：多棵不同的二叉树可以有相同的先序序列（例如 BDCAE 对应至少三种不同形态）
2. **先序 + 后序**：不能唯一确定二叉树——例如 AB（先序）和 BA（后序）对应两种形态（B 是 A 的左孩子还是右孩子？）
3. **先序 + 层序**：同样不能唯一确定

> **结论**：只有「中序 + 另一种」，才能唯一确定二叉树。

## 详细解释

### 为什么必须要有中序序列？

中序序列的本质特性：根结点在中间，**左右子树的结点分居两侧**。其他序列（先/后/层序）只能告诉你是谁根，但无法划分左右子树的范围。

### 算法步骤（以先序 + 中序为例）

1. 先序序列第一个结点 = **根结点** R
2. 在中序序列中找到 R 的位置 k
3. 中序序列中，R 左边的 k−1 个结点 = 左子树；右边的 n−k 个结点 = 右子树
4. 先序序列中，R 后 k−1 个结点 = 左子树的先序；剩余 = 右子树的先序
5. 对左右子树**递归**执行步骤 1-4

### 手算示例

**先序**：D A E F B G H C J I
**中序**：E A F D H G B J C I

1. 先序首字母 D → 根 = D
2. 中序中 D 的位置：EAF | **D** | HGBJCI
   - 左子树中序：EAF（3 个结点）
   - 右子树中序：HGBJCI（6 个结点）
3. 左子树先序：AEF（先序中 D 后面取 3 个）
   - A = 左子树根，中序中 E|A|F → E 左孩子，F 右孩子
4. 右子树先序：BGH CJI（剩余 6 个）
   - B = 右子树根，中序中 HG|B|JCI → HG 在左，JCI 在右……继续递归

### 三种组合的统一口诀

| 组合 | 找根 | 划分 |
|------|------|------|
| 先序 + 中序 | 先序**第一个**是根 | 中序中根左边=左子树 |
| 后序 + 中序 | 后序**最后一个**是根 | 中序中根左边=左子树 |
| 层序 + 中序 | 层序**第一个**是根 | 中序中根左边=左子树 |

## 类比

### 一句话比喻
**由遍历序列构造二叉树就像考古学家复原族谱——中序序列是一张「完整的家族名单」（知道谁是谁的后代但不知道谁是谁的爹），先序序列告诉你「谁是每代的老大」（第一个出现的就是当家人）。把「老大」插进名单的正中间，左边是他这一支的后人，右边是另一支的后人——如此反复，一棵家族树就拼出来了。**

### 生活映射
| 数据结构世界 | 族谱考古 |
|---|---|
| 中序序列 | 完整的家族人名清单（按辈分排好，但不知道父子关系） |
| 先序序列 | 「谁是家主」的顺序清单——历代家主的名册 |
| 根结点 = 先序第一个 | 「第一任家主叫 D」 |
| 中序中根左边 = 左子树 | 「D 左边的三个人是他这一支的」 |
| 递归 | 「好，现在把 D 这一支单独拿出来，同样用名册和家主名单分析」 |
| 只有一种序列 | 「只有名册没有家主名单——根本拼不出家族树」 |
| 先序+后序无中序 | 「知道第一代家主和最后一代家主，但中间怎么分的家不知道」 |
