# 电子邮件系统（SMTP/POP3）

## 类型判定
连接模型 — 回答"一封邮件从发件人到收件人经过哪些步骤完成传送"

## 是什么
电子邮件系统由用户代理、邮件服务器和电子邮件协议三部分组成。SMTP（简单邮件传输协议，端口25）用于发送邮件，采用push（推）方式；POP3（邮局协议第3版，端口110）用于接收邮件，采用pull（拉）方式。两个协议均采用C/S模型。

## 输入-输出空间
- **输入**: 发件人撰写的邮件（收件人、主题、正文）
- **输出**: 收件人在用户代理上成功阅读邮件
- **映射关系**: 映射关系（发送邮件 → 接收邮件）

## 正例（至少2个）
1. **QQ邮箱→网易邮箱**: 用户在QQ邮箱APP写邮件发给163邮箱 → SMTP推送到QQ邮件服务器 → SMTP推送到网易邮件服务器 → 收件人通过POP3从网易服务器拉取邮件
2. **SMTP工作过程**: 发送方邮件服务器（SMTP客户端）→ 接收方邮件服务器（SMTP服务器），经过hello→mail from→rcpt to→data→quit命令序列完成邮件传输

## 反例/边界（至少1个）
1. **常见误解**: POP3和SMTP都能发邮件？不，POP3只能接收/读取邮件，不能发送邮件。发邮件只能使用SMTP协议（现代系统也可用HTTP/HTTPS发邮件）

## 详细解释
### 三大组成部分
1. **用户代理（User Agent）**: 邮件APP（QQ邮箱、网易邮箱等），提供编写/发送/接收邮件的用户界面
2. **邮件服务器（Mail Server）**: 存放用户邮件，负责发送和接收邮件；同一台服务器在不同环节可扮演SMTP客户端或SMTP服务器
3. **电子邮件协议**: SMTP（发）+ POP3/IMAP（收）

### 邮件传输完整流程
```
发件人用户代理 →[SMTP推送]→ 发送方邮件服务器 →[SMTP推送]→ 接收方邮件服务器 →[POP3拉取]→ 收件人用户代理
```

### SMTP工作过程（发送方服务器→接收方服务器）
1. TCP三次握手连接25端口
2. 发送hello命令（打招呼）
3. 发送mail from命令（指明发件人邮箱地址）
4. 发送rcpt to命令（指明收件人邮箱地址，服务器检查收件人是否存在）
5. 发送data命令（告知开始传输邮件内容）
6. 传输邮件内容（首部+主体，全部为ASCII码）
7. 发送quit命令 → 断开TCP连接

**注意**: mail from和rcpt to携带的就是邮件的**信封**信息（给协议看的，不是给人看的）

### POP3工作过程（收件人→服务器）
1. TCP三次握手连接110端口
2. 发送用户名密码验证身份
3. 请求查看邮件列表
4. 请求下载邮件内容
5. 两种下载方式可选：
   - 下载并删除服务器上的邮件
   - 下载但保留服务器上的邮件

### 电子邮件的格式
- **信封**: 给SMTP协议使用的数据结构（mail from指明发件人，rcpt to指明收件人），用户代理自动生成
- **内容**:
  - 首部：to（收件人，必填）、from（发件人，必填）、subject（主题，可选）
  - 主体：邮件正文

### SMTP的局限性
SMTP只能传输7位ASCII码，意味着最初只能传输纯英文和基本符号，无法传输中文、图片、视频等。这个局限性由MIME解决。

### 邮件缓存
邮件服务器有邮件缓存（队列），先来先服务。发送端服务器空闲时从待发送队列取出邮件发送给接收方服务器。

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| SMTP端口 | 25 |
| POP3端口 | 110 |
| SMTP通信方式 | push（推）— 客户端主动推给服务器 |
| POP3通信方式 | pull（拉）— 客户端主动请求拉取 |
| SMTP传输限制 | 只能传7位ASCII码 |
| 应用层模型 | C/S模型 |
| IMAP协议 | POP3的进阶版，功能更丰富，也用于收邮件 |

### 补充
- 邮件服务器在不同环节可扮演不同角色：接收发件人时是SMTP服务器，转发给接收方时是SMTP客户端
- 现代邮件系统也常用HTTP/HTTPS收发邮件（通过浏览器登录邮箱）
