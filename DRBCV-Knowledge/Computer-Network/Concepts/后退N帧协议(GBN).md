# 后退N帧协议(GBN)

## 类型判定
连接型 — 回答"GBN协议如何运作"，涉及连续发送N帧的滑动规则、累积确认机制、出错后退回重传的完整逻辑。

## 是什么
后退N帧协议（Go-Back-N，GBN）是一种基于滑动窗口的可靠传输协议。**发送窗口大于1（WT>1），接收窗口等于1（WR=1）**。发送方可以连续发送最多WT个未确认帧，接收方只顺序接收、**累积确认**（只返回最后一个正确帧的ACK）。如果某个帧超时未收到确认，发送方将**后退**到该帧，重传该帧及其之后所有已发送的帧。这种"后退重传"的特性得名"Go-Back-N"。

## 输入-输出空间
- **输入**：数据帧序列 + 接收方返回的累积ACK + 超时事件
- **输出**：连续发送帧 / 后退重传帧序列
- **映射关系**：映射关系 — 发送方行为由"收到的最大连续ACK"和"超时帧的编号"共同决定

## 正例（至少2个）
1. **正常连续传输**：发送方WT=3，连续发送DATA0、DATA1、DATA2。接收方依次接收，连续收到3个帧后返回ACK2（累积确认，表示0~2均已收到）。发送方收到ACK2后窗口向前滑动3格。
2. **帧丢失后退重传**：发送方发DATA3、DATA0、DATA1（编号循环），DATA0丢失。接收方只收到DATA3（已收），DATA1到达但超出窗口（期待0号）→丢弃DATA1，返回ACK3（最近正确）。发送方收到ACK3但DATA0超时→后退到DATA0重传DATA0和DATA1。

## 反例/边界（至少1个）
1. **确认帧全部丢失**：发送方发送WT范围内的帧后全部收到ACK，但ACK全部丢失。发送方超时→后退到最早的帧重传所有帧。接收方收到重复帧→丢弃并重新返回各帧的ACK。GBN的"后退"特性在此场景下会导致大量不必要的重传。

## 详细解释

### 协议四要素
| 要素 | GBN的设定 |
|------|----------|
| **滑动窗口** | WT>1, WR=1 |
| **确认机制** | **累计确认** — 返回最后一个正确接收的帧的ACK |
| **重传机制** | 超时重传，且后退N帧重传（超时帧及其之后所有帧） |
| **帧编号** | N比特，满足 WT+WR ≤ 2ᴺ |

### 累积确认的含义
接收方返回ACK i 表示：**第i号帧以及i之前的所有帧都已正确接收**。
- 优点：减少确认帧数量
- 含义：ACK i 隐含了所有小于i的帧的确认

### 核心操作规则
- 发送方每发一帧启动计时器
- 接收方只接收序号等于WR期待值的帧（顺序接收）
- 收到乱序帧（超出WR）→ 直接丢弃，返回最近一个正确帧的ACK
- 收到错误帧 → 丢弃，不返回ACK
- WT内的某帧超时 → 发送方后退到该帧，重传该帧及之后所有帧

### 窗口大小约束
```
WT + 1 ≤ 2ᴺ
```
其中1是WR，WT越大，所需编号比特N越多。

### 优点与缺点
| 方面 | 说明 |
|------|------|
| **优点** | 比SW效率高（可连续发多帧）；实现简单（接收方只需1帧缓存） |
| **缺点** | 信道误码率高时效率极低（一个小错误就导致N帧重传）；接收方处理慢时也会频繁后退 |

## 生活类比
就像**批量发货但允许拒收中间件**——你一次性发10件快递给客户（连续发帧），但客户必须按顺序签收（WR=1），先签收包裹1才能签收2。如果包裹3在路上丢了，客户退回后面所有没签收的包裹（4~10），并通知你"包裹2拿到了"（累积确认ACK2）。你不得不重发包裹3和3之后的所有包裹——即使包裹4~10根本没有丢。这就是**后退重传**。
