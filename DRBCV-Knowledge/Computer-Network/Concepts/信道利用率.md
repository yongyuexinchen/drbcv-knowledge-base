# 信道利用率

## 类型判定
连接型 — 回答"信道利用率如何计算"，核心是公式推导、不同协议下的计算差异，以及结合窗口大小和帧编号的综合分析。

## 是什么
信道利用率（Channel Utilization）衡量**一条信道上实际有数据通过的时间占总时间的比例**。计算公式为：
```
信道利用率 = 发送信道上有数据通过的时间 / 总时间
```
总时间从一个数据帧开始发送算起，到可以发送下一个数据帧为止。在理想情况下（无差错、无丢帧），停止等待、后退N帧和选择重传三种协议的信道利用率各不相同，主要受**发送窗口大小**、**数据帧传输时延**和**单向传播时延**影响。信道利用率不会超过1（即100%），当分子超过分母时取1。

## 输入-输出空间
- **输入**：发送窗口大小WT、数据帧传输时延TD、两倍传播时延RTT、确认帧传输时延TA
- **输出**：信道利用率U（0~1之间的数值，或0%~100%）
- **映射关系**：映射关系 — U由上述参数和协议类型共同决定

## 正例（至少2个）
1. **SW信道利用率计算**：TD=4s、RTT=14s、TA=1s，则U = 4÷(4+14+1) = 4÷19 ≈ 21.05%。可见SW协议信道利用率较低。
2. **GBN/SR信道利用率计算**：WT=4、TD=4s、RTT=14s、TA=1s，则U = 4×4÷(4+14+1) = 16÷19 ≈ 84.2%。远高于相同条件下的SW。

## 反例/边界（至少1个）
1. **信道利用率不能超过1**：若WT=5，TD=4s，RTT=14s，TA=1s，公式算得U=5×4÷19≈1.05。但因为发完第5个帧时（20s后），第一个帧的ACK早已在第19s收到，从19s到20s信道上仍有数据在发送，信道一直处于忙碌状态——实际U=1（100%）。

## 详细解释

### 基本参数定义
| 符号 | 含义 | 说明 |
|------|------|------|
| TD | 数据帧传输时延 | 帧长÷信道速率 |
| RTT | 两倍单向传播时延 | 2×单向传播时延（不包括发送时间） |
| TA | 确认帧传输时延 | 确认帧长÷信道速率（常忽略不计） |
| WT | 发送窗口大小 | 可连续发送的最大未确认帧数 |

### 停止等待协议（SW）
每发一帧等一个确认，信道利用率公式：
```
U_SW = TD / (TD + RTT + TA)
```
- 分子：发送一帧的时间（信道上真的有数据流过）
- 分母：从该帧开始发送到可以发下一帧的总时间

**分析**：当RTT远大于TD时（如卫星链路），SW的U非常低。例如TD=0.08ms、RTT=100ms时，U不足0.1%。

### 后退N帧协议（GBN）与选择重传协议（SR）
理想情况下两种协议信道利用率相同（均受WT影响）：
```
U_GBN/SR = (WT × TD) / (TD + RTT + TA)
```
- 分子：发送窗口内所有数据帧的发送总时间
- 分母：从第一个帧开始发送到收到第一个ACK的时间

**关键**：当 WT × TD ≥ (TD + RTT + TA) 时，U=1（信道满负荷）。

### GBN与SR的差异（非理想情况）
在非理想情况下（信道有误码），SR的实际信道利用率高于GBN：
- GBN出错时后退N帧重传，大量帧被无效重传
- SR只选择性重传真正出错的帧

### 有关术语补充
| 术语 | 含义 | 包含协议 |
|------|------|---------|
| **ARQ协议** | 自动重传请求协议（有超时自动重传特性） | SW、GBN、SR |
| **连续ARQ协议** | 支持连续发送的ARQ | GBN、SR |
| **滑动窗口协议** | 指发送窗口>1的协议（考研题型） | GBN、SR |

### 综合题型思路
当考题同时考察"信道利用率≥某值"和"帧编号比特数"时：
1. 用信道利用率公式求出所需的最小WT
2. 根据协议类型（GBN/SR）代入 WT+WR ≤ 2ᴺ
3. GBN（WR=1）所需N更小（相同WT下）
4. SR（WR>1, 通常取WR=WT）所需N更大

## 生活类比
就像**高速公路的通行效率**——TD是每辆车通过收费站的时间（比如每辆5秒），RTT是你从收费站到出口再回来报告的时间（比如60秒）。SW模式：你等第一辆车到了出口报告，再放第二辆——利用率=5÷65≈7.7%。GBN/SR模式：收费站窗口WT=10，一口气放10辆，第1辆到出口报告时后面9辆还在路上——利用率=50÷65≈77%。如果放车足够多（WT很大），整个公路一直有车在跑，利用率=100%。
