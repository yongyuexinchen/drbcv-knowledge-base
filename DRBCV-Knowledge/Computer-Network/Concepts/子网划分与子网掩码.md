# 子网划分与子网掩码

## 类型判定
连接型 — 回答"给定网络号与子网规划要求，如何计算子网掩码、可划分的子网数、每个子网的主机数"，涉及输入（IP地址块+子网号位数）到输出（子网掩码、子网范围、主机数）的映射推导。

## 是什么
子网划分是在分类编址基础上，从主机号中借出若干比特作为**子网号**，将一个大网络划分为多个更小的子网，以提高IP地址利用率。**子网掩码**是一个32比特的位模式（高位为1对应网络号+子网号，低位为0对应主机号），通过与IP地址逐位相与，提取出**网络前缀**（网络号+子网号）。引入子网划分后，IP地址变为**三级结构**：网络号 + 子网号 + 主机号。

## 输入-输出空间
- **输入**：原始网络号（如B类166.1.0.0）、欲划分的子网数（或子网号位数K）
- **输出**：子网掩码、每个子网的网络前缀、每个子网的可用IP范围、每个子网最大主机数
- **映射关系**：映射关系 — 从主机号借K比特 → 2^K个大小相等的子网，每个子网主机数为2^(N-K)-2

## 正例（至少2个）
1. **校区分网**：学校拥有B类网络166.1.0.0（前16位网络号，16位主机号），取1比特作子网号→划分2个子网。第17位=0（子网0：166.1.0.0/17），第17位=1（子网1：166.1.128.0/17）。子网掩码=255.255.128.0（17个1+15个0）。每个子网最多2^15-2=32766台主机。
2. **四子网划分**：取2比特作子网号→可划分4个子网（00/01/10/11），每个子网2^14-2=16382台主机。子网掩码=255.255.192.0（18位1+14位0）。

## 反例/边界（至少1个）
1. **每个子网内的主机号不能全0或全1**：子网0的IP地址块中，主机号全0表示该子网本身（如166.1.0.0/17），主机号全1表示该子网的广播地址（如166.1.127.255/17），这两个地址不能分配给任何主机。

## 详细解释

### 子网划分核心流程

1. **确定原始网络号长度**：A类8位，B类16位，C类24位
2. **确定要借用的子网号位数K**：可划分2^K个子网
3. **每个子网主机号位数** = N - K（N为原始主机号位数）
4. **每个子网可用主机数** = 2^(N-K) - 2
5. **子网掩码**：前(原始网络号位数+K)位为1，余为0

### 子网掩码的作用机制

```
IP地址:    166.1.0.1  →  10100110.00000001.00000000.00000001
子网掩码:  255.255.128.0 →  11111111.11111111.10000000.00000000
    逐位与(AND): 10100110.00000001.00000000.00000000 → 166.1.0.0（网络前缀）
```

- 子网掩码用于从IP地址中提取**网络前缀**（网络号+子网号）
- 两台主机比较网络前缀：相同则属于同一子网；不同则属于不同子网

### 默认子网掩码
对于没有进行子网划分的网络，使用默认子网掩码：
| 类别 | 默认子网掩码 |
|------|------------|
| A类 | 255.0.0.0（8个1） |
| B类 | 255.255.0.0（16个1） |
| C类 | 255.255.255.0（24个1） |

### 路由器的转发表变化
支持子网划分的路由器，转发表每个表项包含**3个部分**：目的网络号、子网掩码、转发接口。查询时：用目的IP与子网掩码逐位与 → 提取网络前缀 → 与目的网络号匹配。

### 默认路由
- 目的网络号全0 + 子网掩码全0
- 任何目的IP与全0子网掩码相与的结果都是全0 → 总能匹配成功
- 作为转发表的兜底项，确保无匹配时也能正常转发

## 计算公式汇总

| 需求 | 公式 |
|------|------|
| 划分子网数 | 2^K（K为借用的子网号位数） |
| 每个子网主机数 | 2^(N-K) - 2 |
| 子网掩码1的位数 | 原始网络号位数 + K |
| 子网掩码（点分十进制） | 前(网号+K)位为1，余为0 |

## 生活类比
- **子网划分**：就像一栋大型写字楼（B类地址）被物业分成不同的办公区（子网），每个区有独立门禁。物业用门禁卡权限（子网掩码）来判断一个人应该去A区还是B区——只看身份证前几位（网络前缀）不够，还得看楼层号（子网号）。
- **子网掩码**：像是一张"镂空卡片"——把它盖在IP地址上，镂空的地方（1的位置）露出来的就是网络前缀，被遮住的地方（0的位置）就是主机号。同一个子网内大家"露出来"的部分一模一样。
