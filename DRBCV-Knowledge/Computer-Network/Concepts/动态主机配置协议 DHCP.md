# 动态主机配置协议 DHCP

## 类型判定
连接型 — 回答"新主机接入网络时如何自动获取IP地址、子网掩码、默认网关"，涉及DISCOVER→OFFER→REQUEST→ACKNOWLEDGE的完整四步工作流程以及每一层的封装细节。

## 是什么
DHCP（动态主机配置协议）使新接入网络的主机能**自动获取**IP地址、子网掩码、默认网关等网络配置参数。DHCP属于**应用层**协议，基于**UDP**传输，使用**客户/服务器（C/S）模型**。DHCP客户端口=68，DHCP服务器端口=67。

## 输入-输出空间
- **输入**：新主机（尚无IP地址）接入网络
- **输出**：主机获得IP地址、子网掩码、默认网关、租用期等信息
- **映射关系**：映射关系 — 四步交互协议：DISCOVER→OFFER→REQUEST→ACK，每步完成特定状态转换

## 正例（至少2个）
1. **学校局域网新主机入网**：H3主机新接入校园网，通过DHCP从服务器获取IP=166.1.128.2、子网掩码=255.255.128.0、默认网关=166.1.128.1。H3的DHCP客户进程（端口68）与DHCP服务器进程（端口67）完成四步交互。
2. **家庭路由器自动分配**：手机连接家中WiFi时，家用路由器（内置DHCP服务器）自动给手机分配内网IP如192.168.3.48、子网掩码255.255.255.0、默认网关192.168.3.1。

## 反例/边界（至少1个）
1. **DHCP发现报文的目的地址为何用广播**：新主机刚接入时不知道自己IP，更不知道DHCP服务器的IP和MAC，只能用**广播**方式（IP目的=255.255.255.255，MAC目的=全1）来寻找DHCP服务器。同理，网络中可能有多台DHCP服务器，REQUEST阶段也需要广播告知全网最终选择了哪个IP。

## 详细解释

### DHCP四步交互过程

#### 第一步：DISCOVER（发现报文）
- **客户端 → 广播**
- 客户构造DHCP Discover报文，内含自己的MAC地址
- **传输层**：源端口=68，目的端口=67
- **网络层**：源IP=0.0.0.0（本网络本主机），目的IP=255.255.255.255（广播）
- **数据链路层**：源MAC=自己MAC，目的MAC=全1（广播帧）

#### 第二步：OFFER（提供报文）
- **服务器 → 单播（精准投递）**
- DHCP服务器从地址池选一个空闲IP（如166.1.128.2），构建Offer报文
- 报文内容：分配IP、子网掩码、默认网关、**租用期**
- **网络层**：目的IP=255.255.255.255（因客户尚无IP），但**链路层**：目的MAC=客户MAC（因已知客户MAC）

#### 第三步：REQUEST（请求报文）
- **客户端 → 广播**
- 客户告知所有DHCP服务器："我接受IP=166.1.128.2"
- 用**广播**的原因：可能有多台DHCP服务器都发送了Offer，需广播告知全网的服务器最终选择了谁，以免其他服务器误以为地址已被占用
- **网络层**：源IP仍为0.0.0.0（第四步完成前尚未正式获得IP）

#### 第四步：ACKNOWLEDGE（确认报文）
- **服务器 → 单播**
- 服务器再次确认分配参数，客户正式获得IP
- 至此主机拥有完整的网络配置

```
DHCP交互流程：

Client                    Server
  │                         │
  │── DISCOVER (广播) ────→ │  "我是新人（MAC=33），谁给我IP？"
  │                         │
  │←── OFFER (单播) ────── │  "给你128.2，掩码255.255.128.0"
  │                         │
  │── REQUEST (广播) ─────→ │  "我要128.2，其他服务器请收回"
  │                         │
  │←── ACK (单播) ──────── │  "确认，128.2是你的了"
```

### 其他重要细节
- **租用期**：分配IP有使用期限，到期可续租
- **家庭场景**：家用路由器通常内置DHCP服务器功能
- **大型网络**：可能有多个DHCP服务器各管不同的地址池
- DHCP报文封装路径：应用层(DHCP) → 传输层(UDP) → 网络层(IP) → 链路层(MAC帧)

### 考试关键点
各阶段IP/MAC地址变化：

| 步骤 | 源IP | 目的IP | 源MAC | 目的MAC |
|------|------|--------|-------|--------|
| DISCOVER | 0.0.0.0 | 广播(全1) | 客户MAC | 广播(全1) |
| OFFER | 服务器IP | 广播(全1) | 服务器MAC | 客户MAC |
| REQUEST | 0.0.0.0 | 广播(全1) | 客户MAC | 广播(全1) |
| ACK | 服务器IP | 广播(全1) | 服务器MAC | 客户MAC |

## 生活类比
- **DHCP四步流程**：就像新生入学报道的流程——
  1. **DISCOVER**：新生到教务处大喊"我是新来的，学号是多少？"（广播找教务处）
  2. **OFFER**：教务处老师说"你叫张三，分在1班，教室在A栋3楼"（提供信息）
  3. **REQUEST**：新生对全场喊"我接受了，我就叫张三了！"（广播确认，防止其他老师也分配名字）
  4. **ACK**：教务处最后盖章确认"没错，你是张三"（完成注册）
- **租用期**：就像大学宿舍床位——给你住4年（租用期），到期可以续住（续租），不能永久占着。
