# 距离向量 vs 链路状态路由算法

## 类型判定
连接型 — 回答"两种动态路由算法如何工作、相互之间有何差异"的问题，核心是比较两种算法的运作机制、收敛特性与适用场景。

## 是什么
距离向量路由算法（DV）和链路状态路由算法（LS）是两种最主要的动态路由算法。DV算法基于"只听邻居的话"的信念——路由器只知道邻居告诉它的信息；LS算法基于"我掌握了全局地图再自己算"的信念——每台路由器先通过洪泛法获取全网拓扑，再用Dijkstra算法独立计算最佳路径。

## 输入-输出空间
- **输入**：网络拓扑结构、各链路度量值
- **输出**：每台路由器到各目的网络的最短路径（路由表）
- **映射关系**：映射关系 — 同样的输入（网络拓扑），两种算法以不同的策略输出路由表

## 正例（至少2个）
1. **DV类比——找熟人帮忙传纸条**：你想给苹果公司CEO递信，自己不认识对方，就问几个熟人"你到CEO有多远？"舍友A说"隔2层"，舍友B说"隔6层"——你选关系最近的舍友A。你不需要知道舍友A和CEO之间具体怎么认识的，这就是DV：只看距离不看拓扑。
2. **LS类比——先画人际关系图再规划路线**：同样是给CEO传信，你先把身边所有人的人际关系网摸清楚——舍友A的爸和CEO是结拜兄弟，舍友B认识一个外国朋友，又认识CEO。然后画出一张完整的关系网络图，用最短路径算法找到最佳路线。这就是LS：先了解全貌再计算。

## 反例/边界（至少1个）
1. **DV ≠ LS**：复杂场景下，DV可能因为"坏消息传得慢"导致路由环路（路由器们互相踢皮球），而LS因为拓扑变更立即洪泛全网，收敛快很多。但LS需要每台路由器保持完整的拓扑数据库，存储和计算开销更大，不适合超大规模网络。

## 详细解释

### 核心差异速览

| 对比维度 | 距离向量（DV） | 链路状态（LS） |
|---------|--------------|--------------|
| 算法本质 | Bellman-Ford | Dijkstra |
| 所需信息 | 只知道邻居的距离向量 | 知道全网拓扑 |
| 路由表更新 | 完全相信邻居 | 自己独立计算 |
| 信息传递 | 向邻居发送自己的**完整路由表** | 向全网洪泛**自己的链路状态** |
| 收敛速度 | 慢（特别是坏消息） | 快 |
| 主要问题 | 慢收敛、路由环路、计数到无穷 | 洪泛开销大、LSDB存储压力 |
| 典型协议 | RIP | OSPF |

### 距离向量算法工作过程

**核心公式**：$D_X(Y) = \min_{v \in N(X)} \{ C(X,v) + D_v(Y) \}$
- $D_X(Y)$：路由器X到目的网络Y的最短距离
- $N(X)$：X的所有邻居
- $C(X,v)$：X到邻居v的直接距离
- $D_v(Y)$：邻居v到目的网络Y的最短距离（由邻居告诉X）

**关键步骤**：
1. 每台路由器维护一个"距离向量表"（到每个目的网络的距离）
2. 每隔固定时间（RIP为30秒）向邻居发送自己的完整路由表
3. 收到邻居的路由表后，运行Bellman-Ford公式更新自己的路由表

**典型计算示例（2021年真题）**：
路由器E与邻居A、B、C、D的直接距离分别为8、10、12、6。邻居发来的距离向量：
- A：(12,24,36,8)
- B：(33,35,18,6)
- C：(20,30,28,20)
- D：(22,34,42,24)

E经过DV计算到达4个网络的最佳距离：
- net1: min(8+12, 10+33, 12+20, 6+22) = 20 → 不对，应仔细计算
  走A: 8+12=20; 走B: 10+33=43; 走C: 12+20=32; 走D: 6+22=28 → 选A得20
- net2: min(8+24, 10+35, 12+30, 6+34) = min(32,45,42,40) = 32 (走A)
- net3: min(8+36, 10+18, 12+28, 6+42) = min(44,28,40,48) = 28 (走B或C)
- net4: min(8+8, 10+6, 12+20, 6+24) = min(16,16,32,30) = 16 (走A或B)
→ 最终E的距离向量为 (20, 32, 28, 16)

### 链路状态算法工作过程

**核心思想**：每台路由器独立构建网络拓扑图，然后自行为每个目标运行Dijkstra算法

**关键步骤**：
1. **发现邻居**：每台路由器探测与自己直连的节点及链路代价
2. **构建LSA**：将探测到的信息封装为链路状态通告（LSA）——本质是一个单链表，记录"我是谁、我的邻居有谁、代价是多少"
3. **洪泛LSA**：将LSA通过洪泛法（Flooding）发送给全网所有路由器（一传十、十传百）
4. **构建LSDB**：每台路由器收集所有LSA，构建完整的链路状态数据库（LSDB）——即图的邻接表
5. **运行Dijkstra**：基于LSDB独立算得到各目的网络的最短路径
6. **生成路由表**：根据Dijkstra结果生成路由表（只记录下一跳，不记录完整路径）

### 为什么BGP用的是"路径向量"？

BGP在AS之间工作，既不是纯DV也不是纯LS。BGP报文携带的是**完整的AS路径**（AS_PATH属性），而不是简单的距离值。这样做有两个好处：
1. **防环**：收到BGP路由更新时，如果发现自己的AS号已在路径中，就知道出现了环路，直接丢弃
2. **策略路由**：网络管理员可以根据AS路径、本地偏好、政治/经济因素等灵活选路

## 细节备注

### 快慢收敛的直观理解
- **DV（常规更新）**：像闺蜜30天交换一次八卦，一个八卦传遍需要很久
- **DV（触发更新）**：像憋不住话的闺蜜，一有新八卦立即广而告之
- **LS（洪泛）**：像新闻联播，一旦探测到变化立即向所有人广播
