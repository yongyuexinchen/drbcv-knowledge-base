# TCP连接管理（三次握手与四次挥手）

## 类型判定
连接型 — 回答"TCP连接如何建立和释放"，涉及三次握手和四次挥手过程中标志位、序号、确认号的动态变化规律，以及进程状态的转换逻辑。

## 是什么
TCP是面向连接的协议，通信分为三大阶段：**建立连接**（三次握手）→ **数据传输** → **释放连接**（四次挥手）。建立连接时，主动方（客户端）和被动方（服务器）通过三次握手协商初始序号并确认彼此存在；释放连接时经过四次挥手逐步关闭双向通道。整个过程伴随着标志位（SYN/ACK/FIN）、序号和确认号的特定变化规律，以及进程TCP状态的转换。

## 输入-输出空间
- **输入**：两个进程决定建立/释放TCP连接的请求
- **输出**：三次握手的三个TCP段 / 四次挥手的四个TCP段（各包含特定标志位、序号、确认号）
- **映射关系**：映射关系 — 每次握手/挥手触发特定的状态转换和字段值变化

## 正例（至少2个）
1. **三次握手建立连接**：客户端向服务器发SYN=1、seq=x（如666）→ 服务器回复SYN=1、ACK=1、seq=y（如50）、ack=x+1 → 客户端回复ACK=1、seq=x+1、ack=y+1。建立完成后即可传输数据。
2. **四次挥手释放连接**：客户端发FIN=1、seq=u（如999）→ 服务器回复ACK=1、ack=u+1 → 服务器发完剩余数据后发FIN=1、seq=v → 客户端回复ACK=1、ack=v+1。客户端进入TIME-WAIT状态等待2MSL后关闭。

## 反例/边界（至少1个）
1. **挥手顺序可以互换**：建立连接必须是客户端先发第一次握手，但释放连接可以由任意一方（客户端或服务器）先发起挥手——谁先发完数据谁就先挥手。

## 详细解释

### 一、三次握手（建立连接）

#### 握手过程
```
客户端（主动方）                  服务器（被动方）
   │                                  │
   │──── SYN=1, seq=x ───────────────→│   握手一（SYN段）
   │                                  │
   │←── SYN=1, ACK=1, seq=y, ack=x+1─│   握手二（SYN+ACK段）
   │                                  │
   │──── ACK=1, seq=x+1, ack=y+1 ────→│   握手三（ACK段）
   │                                  │
   │ ←──── 开始数据传输 ──────────────→ │
```

#### 标志位变化
| 报文段 | SYN | ACK | FIN |
|--------|:---:|:---:|:---:|
| 握手一 | **1** | **0** | 0 |
| 握手二 | **1** | **1** | 0 |
| 握手三 | 0 | 1 | 0 |
| 之后所有数据段 | 0 | 1 | 0 |

**结论**：
- SYN=1：只有握手一和握手二
- ACK=0：只有握手一
- ACK=1：除握手一外所有TCP段

#### 序号与确认号
- **握手一**：客户端设置初始序号seq=x（不携带数据，但**必须消耗1个序号**）
- **握手二**：服务器设置初始序号seq=y；确认号ack=x+1（因为握手一消耗了序号x）
- **握手三**：确认号ack=y+1（握手二消耗了序号y）；seq=x+1（客户端数据的真正起始序号）

**关键区别**：
- 握手一、握手二：即使不携带数据也**必须消耗一个序号**
- 握手三：如果不携带数据则**不消耗序号**

#### 状态转换（建立连接）

| TCP状态 | 含义 | 触发事件 |
|---------|------|---------|
| **CLOSED** | 关闭 | 初始状态 |
| **SYN-SENT** | 同步已发送（客户端） | 客户端发出握手一 |
| **SYN-RCVD** | 同步已接收（服务器） | 服务器收到握手一 |
| **ESTABLISHED** | 已建立连接 | 客户端收到握手二 / 服务器收到握手三 |

```
客户端: CLOSED → SYN-SENT → ESTABLISHED
服务器: CLOSED → LISTEN  → SYN-RCVD → ESTABLISHED
```

#### 最短耗时分析
- **客户端**从发出握手一到可以发送数据：**1 × RTT**（收到握手二即可发）
- **服务器**从发出握手一到可以发送数据：**1.5 × RTT**（需收到握手三）

### 二、四次挥手（释放连接）

#### 挥手过程
```
客户端                             服务器
   │                                  │
   │──── FIN=1, seq=u ───────────────→│   挥手一（FIN段）
   │                                  │
   │←── ACK=1, seq=v, ack=u+1 ──────│   挥手二（ACK段）
   │                                  │
   │   服务器继续单向传输数据...        │
   │                                  │
   │←── FIN=1, ACK=1, seq=w, ack=u+1─│   挥手三（FIN段）
   │                                  │
   │──── ACK=1, seq=u+1, ack=w+1 ────→│   挥手四（ACK段）
   │                                  │
   │   客户端等待2MSL后关闭             │
```

#### 标志位变化
| 报文段 | FIN | ACK | SYN |
|--------|:---:|:---:|:---:|
| 挥手一 | **1** | 1 | 0 |
| 挥手二 | 0 | 1 | 0 |
| 挥手三 | **1** | 1 | 0 |
| 挥手四 | 0 | 1 | 0 |

**结论**：FIN=1只有挥手一和挥手三

#### 序号与确认号
- **挥手一**：seq=u（消耗1个序号，即使不携带数据）
- **挥手二**：ack=u+1；seq=v（服务器当前发送数据的序号）
- **挥手三**：seq=w（不携带数据也要消耗1个序号）；ack=u+1
- **挥手四**：ack=w+1

#### 是否可携带数据
| 报文段 | 是否可携带数据 | 说明 |
|--------|:------------:|------|
| 挥手一 | 理论上可，但通常不 | 消耗序号 |
| 挥手二 | **可以** | 服务器可能仍有数据要发 |
| 挥手三 | 理论上可，但通常不 | 消耗序号 |
| 挥手四 | **不可以** | 客户端到服务器的通道已关闭 |

#### 状态转换（释放连接）

| TCP状态 | 含义 | 触发事件 |
|---------|------|---------|
| **ESTABLISHED** | 已建立连接 | 开始挥手前的状态 |
| **FIN-WAIT-1** | 终止等待1（客户端） | 客户端发出挥手一 |
| **FIN-WAIT-2** | 终止等待2（客户端） | 客户端收到挥手二 |
| **CLOSE-WAIT** | 关闭等待（服务器） | 服务器收到挥手一 |
| **LAST-ACK** | 最后确认（服务器） | 服务器发出挥手三 |
| **TIME-WAIT** | 时间等待（客户端） | 客户端收到挥手三并发出挥手四 |
| **CLOSED** | 关闭 | 等待2MSL后 / 收到挥手四 |

```
客户端: ESTABLISHED → FIN-WAIT-1 → FIN-WAIT-2 → TIME-WAIT → CLOSED
服务器: ESTABLISHED → CLOSE-WAIT → LAST-ACK → CLOSED
```

#### MSL（最大报文段寿命）
- **MSL**：Maximum Segment Lifetime，TCP协议规定的固定时间长度
- 客户端收到挥手三进入**TIME-WAIT**状态，等待**2×MSL**后才CLOSED
- 作用：确保挥手四能到达服务器（若丢失，服务器重发挥手三，可重新确认）

#### 最短耗时分析
当服务器收到挥手一时已无数据要发送（可连续发出挥手二和挥手三）：

| 计时起点 | 总耗时 |
|---------|--------|
| 客户端发出挥手一到客户端CLOSED | **1×RTT + 2×MSL** |
| 客户端发出挥手一到服务器CLOSED | **1.5×RTT** |

### 生活类比
**像打电话的过程**：
- 三次握手 = 先确认对方在不在："在吗？"→"在的请讲"→"好的我要说了"
- 四次挥手 = 说完后说拜拜："我说完了"→"知道了，我还有个事要说"→"我也说完了"→"好的拜拜"
  - 前两次挥手 = 一方说完（但另一方可能还没说完）
  - 后两次挥手 = 另一方也说完了，双方挂断
