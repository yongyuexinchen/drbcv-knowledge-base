# BGP路由信息与工作原理

## 类型判定
连接型 — 回答"BGP路由信息长什么样、如何在AS之间逐层传递"的问题，核心是BGP路由更新的传播链：AS内部网络→通过EBGP通告给邻居AS→通过IBGP在AS内全连通传播→再通过EBGP继续向外通告。

## 是什么
BGP路由信息由**CIDR前缀**（目的网络）和**BGP属性**组成，核心属性包括**AS_PATH**（路径向量，记录经过的AS编号序列）和**NEXT_HOP**（下一跳路由器的IP地址）。一条目的网络的可达信息通过**EBGP会话**在AS之间逐层传递，再通过**IBGP会话**在AS内部全连通扩散。

## 输入-输出空间
- **输入**：BGP邻居发来的Update报文（含有CIDR前缀+AS_PATH+NEXT_HOP等属性）
- **输出**：本地的BGP路由表（经过策略选择后的最佳路由）
- **映射关系**：映射关系 — 外部AS的网络可达性通过EBGP→IBGP→EBGP的传播链，逐级映射为逐跳的路由转发表

## 正例（至少2个）
1. **AS1内部网络X被全网知道**：AS1内的网络X（边界路由器R1知道它）。R1通过EBGP告诉邻居AS2的R2"到我这边可到X，AS路径=[AS1]，下一跳=R1"。R2通过IBGP全连通告诉AS2所有BGP路由器。R4再通过EBGP告诉AS3的R6"到我这边可到X，AS路径=[AS2,AS1]，下一跳=R4"。逐层传递，全网都知道怎么到X。
2. **同一AS内路由信息的IBGP全同步**：AS2有R2/R3/R4/R5共4台路由器运行BGP，两两建立IBGP会话（共6条）。R2从外部学到网络X的路由后，通过IBGP批量通知R3/R4/R5，每台路由器都学到相同的路由，无需R3再二次传播给R5。

## 反例/边界（至少1个）
1. **IBGP ≠ EBGP的下一跳规则不同**：EBGP通告路由信息时，发送方会把下一跳地址改为**自己的IP地址**；而IBGP默认**不修改下一跳**（保留从EBGP学到的原始下一跳）。但根据路由器的具体实现（如Cisco），IBGP也可能修改下一跳为发送方自己——两种方案都能正常工作。

## 详细解释

### BGP路由信息的格式

```
BGP路由信息 = CIDR前缀 + BGP属性
                            ├── AS_PATH（AS路径向量）
                            └── NEXT_HOP（下一跳路由器IP）
```

- **CIDR前缀**：指向可到达的目的网络（如X.X.X.X/n）
- **AS_PATH**：到达该目的网络需要经过的AS编号序列，用于防环
- **NEXT_HOP**：下一跳路由器的IP地址

### 路由信息的传播过程

以一个具体示例阐述：AS1内有目的网络X，其可达信息如何传递到远处的AS3。

#### 第1步：AS1内部→R1知道怎么到X
AS1内部运行内部网关协议（RIP/OSPF），边界路由器R1知道在网络X怎么走。

#### 第2步：EBGP通告（AS1→AS2）
R1通过**EBGP会话**发送Update报文给R2（属于AS2）：
- CIDR前缀：X
- AS_PATH：AS1
- NEXT_HOP：**R1自己的IP地址**（EBGP发送方会修改下一跳为自身）

R2收到后在本地BGP路由表中记录：目的X，下一跳R1，路径[AS1]

#### 第3步：IBGP全连通扩散（AS2内部）
R2需要通过**IBGP会话**把这条路由告诉AS2内所有其他BGP路由器（R3/R4/R5）。

**关键规则**：IBGP学到的路由不能再通过IBGP传播。所以R2通过IBGP直接通知R3、R4、R5各一次（而不是让R3收到后再传R5）。

**IBGP下一跳规则**（默认）：**不修改下一跳**，仍保留R1。

但这对R3/R4/R5意味着什么？R3收到"下一跳R1"，而R3与R1不直连。R3如何处理？
- 先确定"出口路由器"是**R2**（因为这条IBGP消息是R2发来的，走这条路必须先到R2）
- 通过**内部网关协议**（如OSPF）找到从R3到R2的最短路径
- 最终的转发表中：目的X → 下一跳（根据IGP找到的下一跳）

> 例如：R4的转发表中，目的X的下一跳可能直接是R3（如果R4需要通过R3再到R2再到R1）

#### 第4步：EBGP再通告（AS2→AS3）
R4通过**EBGP会话**发送Update报文给R6（属于AS3）：
- CIDR前缀：X
- AS_PATH：**AS2, AS1**（追加了自己的AS号，形成新的AS路径向量）
- NEXT_HOP：**R4自己的IP地址**（EBGP发送方再次修改下一跳为自身）

#### 第5步：AS3内部IBGP扩散
R6通过IBGP全连通告诉AS3内所有BGP路由器。重复第3步的过程。

### 总结：EBGP vs IBGP的下一跳规则

| 场景 | EBGP（AS之间） | IBGP（AS内部） |
|------|--------------|--------------|
| 发送前下一跳修改 | **修改为发送方自身IP** | **默认不修改**（保留原始下一跳） |
| 原因 | AS之间物理直连，下一跳设为发送方是合理的 | AS内部可通过IGP找到通往出口路由器的路径 |
| 例外 | — | 某些厂商实现（如Cisco）可能会修改 |

### 为什么IBGP必须全连通？

因为BGP协议规定：**从IBGP学到的路由信息不能再通过IBGP传播给其他IBGP邻居**。

如果不做这个限制，路由信息可能在一个AS内部兜圈子（环路）；做了这个限制后，为了保证每台路由器都能收到外部路由，必须两两建立IBGP会话，即**全连通**。

### 数据转发路径示例

AS2的R4要转发IP数据报到目的X：
1. R4查BGP转发表：目的X → 通过AS2→AS1 → 下一跳（IGP结果）→ 可能需要先发给R3
2. R3收到后，查转发表：目的X → 下一跳R2（IGP结果）
3. R2收到后，查转发表：目的X → 下一跳R1（EBGP学到的）
4. R1通过内部网关协议将数据转发给网络X

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| AS_PATH防环 | 收到路由更新时检查自己的AS号是否已在路径中 |
| AS_PATH递增 | 每经过一个AS，在路径向量前追加自己的AS号 |
| IBGP全连通数量 | N×(N-1)/2 |
