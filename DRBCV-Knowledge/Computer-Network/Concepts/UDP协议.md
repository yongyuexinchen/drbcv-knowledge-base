# UDP协议

## 类型判定
混合型 — UDP的**特点**部分属于判别型（回答"UDP是什么，与TCP有何区别"），而**检验和计算**部分属于连接型（回答"校验和如何生成/如何检测差错"，涉及二进制加法和回卷的具体计算逻辑）。

## 是什么
UDP（User Datagram Protocol，用户数据报协议）是传输层的无连接、不可靠协议。它对每个应用层报文直接添加8字节首部后封装成UDP数据报，不做拆分或重组，不确认不重传，尽最大努力交付。UDP首部极小（仅8字节）且无拥塞控制，适用于实时性要求高、准确性要求低的场景（如直播、视频通话）。

## 输入-输出空间
- **输入**：应用层的一个完整报文 + 源端口号 + 目的端口号
- **输出**：8字节UDP首部 + 原始报文（封装为一个UDP数据报）
- **映射关系**：映射关系 — 完整报文 → 附加8字节首部后成为UDP数据报，不拆分、不重组

## 正例（至少2个）
1. **直播场景**：直播服务器将音视频数据封装到UDP数据报中，通过广播/多播IP数据包同时推送给成千上万的客户端。画面偶尔模糊可以容忍，但实时性必须高。
2. **DNS查询**：DNS客户端向DNS服务器发送域名解析请求，使用UDP协议（端口53）。查询通常只有几十字节，一查一答无需建立连接，效率极高。

## 反例/边界（至少1个）
1. **UDP不保证可靠传输**：如果UDP数据报在传输中出错或丢失，发送方不会得到任何通知。需要可靠性的应用（如文件传输）不能直接使用UDP，必须在应用层自己实现确认/重传机制。

## 详细解释

### UDP数据报格式
```
 0                   16                  31
 ├────────────────────┬────────────────────┤
 │     源端口号        │     目的端口号      │  ← 8字节首部
 ├────────────────────┼────────────────────┤
 │   UDP总长度（首部+数据）│      校验和        │
 ├────────────────────┴────────────────────┤
 │              数据部分                     │  ← 应用层报文
 └──────────────────────────────────────────┘
```

| 字段 | 长度 | 说明 |
|------|------|------|
| 源端口号 | 16比特 | 发送方进程端口（无需回复时可全0） |
| 目的端口号 | 16比特 | 接收方进程端口（必填） |
| UDP总长度 | 16比特 | 首部(8)+数据部分，单位字节。理论最大65535，实际受IP限制≤65515 |
| 校验和 | 16比特 | 用于检测比特错误，可置全0表示无需校验 |

### UDP与TCP的显著区别

| 对比维度 | UDP | TCP |
|---------|-----|-----|
| 首部大小 | **固定8字节** | 最小20字节，最大60字节 |
| 报文拆分/重组 | **不支持**，太大直接拒收 | 支持，自动拆分长报文并重装 |
| 连接性 | **无连接**，不打招呼直接发 | 面向连接，需三次握手 |
| 可靠性 | **不可靠**，无确认/重传机制 | 可靠，确认+重传 |
| 拥塞控制 | **不支持**，不降速 | 支持，检测到拥塞主动降速 |
| 通信方式 | **一对一、一对多**（广播/多播） | 仅支持一对一 |
| 传输单位 | 面向报文（一报文一UDP数据报） | 面向字节流（拆分字节流） |

### UDP检验（校验和计算）

UDP校验和用于检测整个UDP数据报（含伪首部）在传输中是否发生比特错误。

#### 校验和计算方法（发送方）
1. 在UDP数据报前临时添加 **12字节伪首部**：
   - 4字节源IP地址 + 4字节目的IP地址
   - 1字节全0 + 1字节协议字段(17)
   - 2字节UDP长度
2. 将**伪首部 + UDP首部 + UDP数据部分**以16比特为一组进行**二进制加法**
3. 最高位产生的进位需**回卷**（加到最低位）
4. 加法结果**逐位取反**，得到16比特校验和填入UDP首部
5. 移除伪首部（不实际传输）

#### 校验和检测方法（接收方）
1. 接收方重新构造伪首部
2. 将**伪首部 + 收到的UDP首部（含校验和字段）+ UDP数据部分**以16比特为一组进行二进制加法
3. 最高位进位需回卷
4. **结果为全1** → 无差错；**结果非全1** → 丢弃UDP数据报

#### 伪首部结构
```
 0                   16                   31
├────────────────────────────────────────┤
│              源IP地址                    │
├────────────────────────────────────────┤
│              目的IP地址                  │
├────────────┬───────────┬────────────────┤
│    全0     │ 协议(17)  │   UDP长度      │
└────────────┴───────────┴────────────────┘
```

注意：IP数据报的首部校验和只校验首部（不校验数据部分），且不添加伪首部——这是与UDP校验的主要区别。

### UDP适用场景
- 实时应用（视频通话、直播、在线游戏）
- DNS查询
- DHCP（动态主机配置协议）
- SNMP（简单网络管理协议）

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 面向报文 | 一个UDP数据报封装一个完整的应用层报文，不拆分 |
| 广播/多播 | UDP支持一对多，只需封装到广播/多播IP数据包中 |
| MSS限制 | 应用层报文太大时UDP直接拒绝，需应用层自行拆分 |
| 伪首部 | 只在校验和计算中使用，不随UDP数据报传输 |
