# 传输层服务与端口号

## 类型判定
判别型 — 回答"传输层提供什么服务""端口号如何分类"，属于对传输层基本概念和端口分类的识别归类。

## 是什么
传输层位于应用层和网络层之间，为上层（应用层）提供**端到端的通信服务**（进程到进程），同时利用网络层（IP协议）进行数据传输。其核心机制是**端口号**：用16比特标识主机上的特定进程，使得IP地址 + 端口号可以精确定位网络中的某个进程。传输层基于端口实现**复用**（多个应用层进程共用同一个传输层协议）和**分用**（传输层根据目的端口号将数据分发给正确的进程）。

传输层提供两种主要服务：**TCP**（面向连接、可靠）和**UDP**（无连接、不可靠）。

## 输入-输出空间
- **输入**：应用层进程的报文 + 目标IP地址和端口号 + 选择的协议（TCP/UDP）
- **输出**：封装了传输层首部的数据段（TCP段 / UDP数据报），递交给网络层
- **映射关系**：从属关系 — 端口号是进程的标识，传输层协议决定了如何封装和传输

## 正例（至少2个）
1. **端口号区分同一主机上的不同进程**：主机A上进程一绑定TCP端口250，进程二绑定TCP端口777，进程三绑定UDP端口32。当TCP数据到达时，传输层检查目的端口号250→交给进程一；目的端口777→交给进程二——实现分用。
2. **复用功能**：进程一和进程二都要通过TCP发送数据，它们共享同一个TCP协议实体，将各自数据封装后交给网络层——多个进程复用同一个传输层协议。

## 反例/边界（至少1个）
1. **不同主机的端口号可相同**：主机A的进程二使用TCP端口777，主机B的进程七也可以使用TCP端口777——端口号是每台主机自己的资源，不同主机间可以重复。

## 详细解释

### 传输层在协议栈中的位置
```
应用层（进程）——用户数据 + 可选的应用层首部
        ↓
传输层 —— 添加TCP/UDP首部（端口号等）
        ↓
网络层 —— 添加IP首部（IP地址等）
```

### 端口号分类

| 范围 | 分类 | 说明 |
|------|------|------|
| 0 ~ 1023 | **熟知端口号（Well-Known）** | 预留给全世界广泛使用的应用协议，如FTP(21)、SMTP(25)、DNS(53)、HTTP(80) |
| 1024 ~ 49151 | 注册端口号 | 通常用于服务器进程，但非强制 |
| 49152 ~ 65535 | 动态/私有端口号 | 通常用于客户端进程（主动发起通信的一方） |

### 端口号的独立性
- **主机间独立**：不同主机的端口号可以相同
- **协议间独立**：同一主机上，TCP和UDP的端口号空间相互独立（TCP 886和UDP 886是不同端口）
- **同一协议内唯一**：同一台主机上，同一种协议（如TCP）的端口号不能重复

### 套接字（Socket）
套接字是一个数据结构，封装了**IP地址 + 端口号**，用于唯一标识网络中的一个通信端点。程序员建立连接时只需指定socket，不需要每次都重复写对方IP、端口和协议类型。

### 传输层两大协议对比

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 可靠（确认+重传） | 不可靠（尽最大努力） |
| 首部大小 | 最小20字节，最大60字节 | 固定8字节 |
| 传输单位 | 报文段（segment） | UDP数据报 |
| 通信方式 | 仅支持一对一 | 支持一对一、一对多（广播/多播） |
| 拥塞控制 | 支持 | 不支持 |
| 差错检测 | 有，通知发送方重传 | 有，直接丢弃不通知 |

### 两大核心功能
1. **复用**：数据从上往下——多个应用层进程使用同一个传输层协议发送数据
2. **分用**：数据从下往上——传输层协议根据目的端口号将数据分发给正确的应用层进程

### 差错检测
- TCP和UDP都会检测比特错误
- 检测出错后：**TCP**通知发送方重传；**UDP**直接丢弃不通知

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 套接字 | 数据结构，包含IP和端口，类似"网络指针"指向通信对端进程 |
| 熟知端口号 | 0~1023，由IANA分配，全球通用的重要应用使用 |
| 进程通信三要素 | 协议类型 + 本机端口号 + 对方IP和端口号 |

### 使用原则
- 同主机同协议下端口号不能冲突
- 客户端通常主动发起连接，服务器被动等待连接
- 端口分类标准是建议性而非强制性的
