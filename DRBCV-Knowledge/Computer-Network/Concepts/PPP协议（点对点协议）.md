# PPP协议（点对点协议）

## 类型判定
连接型 — 回答PPP协议"如何工作"的问题，核心是LCP/NCP两阶段协商过程、帧封装与透明传输的机制。

## 是什么
PPP（Point-to-Point Protocol，点对点协议）是数据链路层协议，专门用于**点对点全双工链路**。它通过LCP和NCP两个子协议完成链路建立、配置和网络层协商，使两台直连设备（如主机与ISP路由器）能够建立逻辑数据链路，传输IP分组等高层数据。PPP在历史上广泛应用于拨号上网，现代演化为PPPoE（以太网上的PPP）用于宽带接入认证。

## 输入-输出空间
- **输入**：主机与ISP路由器之间的点对点物理链路（如电话线）已连通
- **输出**：经过LCP配置协商→LCP链路鉴别→NCP网络层协商后，可传输IP分组的逻辑数据链路
- **映射关系**：映射关系 — 输入物理连接，通过PPP的三步协商输出可用的网络连接

## 正例（至少2个）
1. **1998年拨号上网**：家庭电脑通过电话线连接电信ISP的路由器。物理线路接通后，电脑依次进行LCP协商（商定MTU=1500、认证协议PAP）、LCP身份鉴别（验证账号密码）、NCP协商（申请动态IP地址），三步完成即成功联网。
2. **现代PPPoE宽带认证**：家庭光猫连接运营商网络后，路由器进行PPPoE拨号——实质是以太网帧嵌套PPP帧，完成LCP协商和密码验证，验证通过后获得IP地址，即可上网。

## 反例/边界（至少1个）
1. **PPP不用于总线型以太网**：PPP只能用于点对点链路。在总线型以太网（多台设备共享同一介质）中不能使用PPP，而应使用CSMA/CD或以太网协议。

## 详细解释

### PPP协议的三大部分

| 组成部分 | 作用 |
|---------|------|
| **LCP（链路控制协议）** | 建立和配置数据链路层连接：协商MTU、选择认证协议（如PAP） |
| **NCP（网络控制协议）** | 为网络层协议建立和配置逻辑连接：申请IP地址等 |
| **PPP帧格式** | 定义数据以何种帧结构在链路上传输 |

### PPP帧格式

```
| 标志(1B:7E) | 地址(1B:FF) | 控制(1B:03) | 协议(2B) | 信息(可变) | FCS(2B) | 标志(1B:7E) |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| 标志 | 1字节 (01111110) | 帧定界符，标记帧开始和结束 |
| 地址 | 1字节 (FF) | 固定值，无实际意义（点对点无需寻址） |
| 控制 | 1字节 (03) | 固定值，无实际意义 |
| 协议 | 2字节 | 指明信息部分携带什么协议（如IPv4→0x0021, LCP→对应值） |
| 信息 | 可变(≤1500B) | 上层协议数据（IP分组、LCP/NCP数据） |
| FCS | 2字节 | CRC校验码，检测帧错误 |

### 透明传输（两种方式）

| 方式 | 适用场景 | 原理 |
|------|---------|------|
| **字符填充（字节填充）** | 异步传输（逐字节传送） | 信息中遇到7E转义为7D 5E，遇到7D转义为7D 5D |
| **零比特填充** | 同步传输（比特流连续传送） | 发送方检测到5个连续1，在其后插入一个0；接收方检测到5个连续1，删除后面的0 |

### PPP协议工作过程（三步协商）

**第一步：LCP配置协商**
- 主机发送LCP配置请求帧（携带MTU、认证协议等参数）
- ISP路由器返回LCP配置应答帧（同意/拒绝/协商）
- 建立LCP链路

**第二步：LCP链路鉴别**
- 主机发送账号密码（由LCP协商中确定的认证协议承载）
- ISP路由器验证身份，返回认证成功/失败
- LCP链路升级为"已鉴别的LCP链路"

**第三步：NCP配置协商**
- 主机发送NCP请求（例如IPCP请求分配IP地址）
- ISP路由器动态分配IP地址
- 建立NCP链路
- **联网成功**，可以正式开始传输IP数据

### PPP协议特点
- **只支持点对点全双工链路**（不支持广播链路）
- **无差错但不可靠**：检测到错误帧直接丢弃，不重传、不确认
- **支持多种网络层协议**：通过协议字段区分（IPv4、IPv6、AppleTalk等）
- **帧长度必须是字节的整数倍**

### PPPoE（PPP over Ethernet）
将以太网帧承载PPP帧（"套娃"）：
```
以太网帧首部 → PPP帧（完整） → 以太网帧尾部
```
现代宽带运营商常用PPPoE进行接入认证（交网费→获得账号密码→拨号验证→上网）。

## 细节备注

### 子特性
| 特性 | 说明 |
|------|------|
| 最大传输单元(MTU) | PPP帧信息部分默认不超过1500字节（可协商） |
| 差错处理 | 接收方检测到错误直接丢弃，**无确认重传机制** |
| 字节对齐 | PPP帧长度必须是整数字节 |

### 生活类比：拨号上网≈入住酒店
1. **LCP协商** → 入住时和前台确认房间规则（退房时间、WiFi密码规则）
2. **LCP鉴别** → 出示身份证验证身份
3. **NCP协商** → 前台给你分配房间号（相当于分配IP地址）
4. **联网成功** → 拿到房卡，可以自由出入
