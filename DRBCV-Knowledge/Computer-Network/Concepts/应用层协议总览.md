# 应用层协议总览

## 类型判定
混合型 — 汇总应用层涉及的所有协议、应用模型和核心概念，既是概念目录也是关系网。

## 类比
**一句话比喻：** 应用层就是用户直接打交道的「店面」——不管底下五层怎么运输包裹（分组）、怎么规划路线（路由）、怎么验货（差错控制），用户只关心"能访问网页吗？能发邮件吗？能下载文件吗？"

| 维度 | 生活映射 |
|------|---------|
| C/S 模型 | 去餐厅吃饭——你（客户）点菜，厨师（服务器）做菜上菜，你不能直接跟另一桌客人交换菜 |
| P2P 模型 | 跳蚤市场摆摊——人人都是买家也是卖家，东西可以直接从一个人手里飞到另一个人手里 |
| DNS | 电话本（黄页）——你记得公司名（域名）但不知道电话（IP），翻电话本就查到了 |
| HTTP | 在书店翻目录（URL）→ 找管理员要书（HTTP 请求）→ 管理员把书递给你（HTTP 响应） |

## 是什么
应用层是 OSI 模型和 TCP/IP 模型的**最高层**，直接为用户提供网络应用服务。它涵盖两大**网络应用模型**（C/S 和 P2P）和多个**应用层协议**（DNS、FTP、电子邮件、HTTP/万维网），每个协议解决不同类型的网络应用需求。应用层协议通常基于 TCP 或 UDP 传输。

---

## 一、网络应用模型

| 模型 | 特点 | 典型应用 |
|------|------|---------|
| **C/S（客户/服务器）** | 服务器长期被动等待，客户主动请求；客户间不直接通信；服务器是中心 | DNS、FTP、Web、Email |
| **P2P（对等网络）** | **去中心化**，各节点地位平等，彼此直接通信；"我为人人，人人为我" | BT 下载、区块链 |

## 二、应用层协议一览

### 核心对比表（考研重点）

| 协议 | 全称 | 传输层 | 端口 | C/S or P2P | 核心功能 |
|------|------|--------|------|-----------|---------|
| **DNS** | 域名系统 | UDP（也支持TCP） | 53 | C/S | 域名 → IP 地址解析 |
| **FTP** | 文件传输协议 | **TCP** | 21（控制）/20（数据） | C/S | 文件上传下载 |
| **SMTP** | 简单邮件传输协议 | **TCP** | 25 | C/S | **发送**邮件（push） |
| **POP3** | 邮局协议 v3 | **TCP** | 110 | C/S | **接收**邮件（pull） |
| **HTTP** | 超文本传输协议 | **TCP** | 80 | C/S | Web 网页传输 |
| **Telnet** | 远程终端协议 | TCP | 23 | C/S | 远程登录（明文，不安全） |
| **SSH** | 安全外壳协议 | TCP | 22 | C/S | 加密远程登录 |
| **SNMP** | 简单网络管理协议 | UDP | 161/162 | C/S | 网络设备监控管理 |

## 三、各协议详解

### 3.1 DNS（域名系统）

| 项目 | 内容 |
|------|------|
| **核心任务** | 域名 → IP 地址（如 www.baidu.com → 110.242.68.66） |
| **传输层** | UDP（端口 53），响应 ≤512 字节；超大数据时切 TCP |
| **四类服务器** | 根域名服务器 → 顶级域名服务器 → 权限域名服务器 → 本地域名服务器 |
| **两种查询** | **递归查询**（你帮我查到底）/ **迭代查询**（我告诉你下一个问谁） |
| **缓存** | 本地域名服务器和主机均有缓存，减少查询次数 |

> 详细内容 → [[DNS域名系统]]

### 3.2 FTP（文件传输协议）

| 项目 | 内容 |
|------|------|
| **双连接设计** | **控制连接**（21 端口，持久）传输命令 + **数据连接**（20 端口/随机，非持久）传输文件 |
| **两种模式** | 主动模式（服务器连客户端 20 端口）/ 被动模式（客户端连服务器随机端口，穿透 NAT） |
| **带外传输** | 控制信息与数据分流——即使正在下载大文件，也能随时通过控制连接发停止命令 |
| **局限** | 只能整体下载/上传，不能局部修改文件 |

> 详细内容 → [[FTP文件传输协议]]

### 3.3 电子邮件系统（SMTP + POP3）

| 环节 | 协议 | 端口 | 方向 |
|------|------|------|------|
| 用户→发送方服务器 | **SMTP** | 25 | push（推） |
| 发送方服务器→接收方服务器 | **SMTP** | 25 | push（推） |
| 接收方服务器→用户 | **POP3**（或 IMAP） | 110（或 143） | pull（拉） |

**SMTP 限制**：只能传输 7 位 ASCII 码。非 ASCII 内容（中文、图片）需通过 **MIME** 规范编码转换。

> 详细内容 → [[电子邮件系统（SMTP-POP3）]]、[[MIME（多用途互联网邮件扩展）]]

### 3.4 万维网（WWW）与 HTTP

| 项目 | 内容 |
|------|------|
| **三大组件** | URL（统一资源定位符）+ HTML（超文本标记语言）+ HTTP（超文本传输协议） |
| **HTTP 连接方式** | 非持续连接（HTTP/1.0，每次请求新 TCP）、持续连接非流水线（HTTP/1.1 默认）、持续连接流水线（最优） |
| **访问流程** | DNS 解析 → TCP 三次握手 → HTTP 请求/响应 → 获取 HTML → 解析引用资源（图片/CSS/JS）→ 重复请求 |

> 详细内容 → [[万维网WWW与HTTP]]

## 四、协议选择指南（考研速查）

| 应用需求 | 选什么协议 | 原因 |
|---------|-----------|------|
| 网页浏览 | HTTP | Web 标准协议 |
| 文件下载/上传 | FTP | 专业的文件传输，支持断点续传 |
| 发邮件 | SMTP | 唯一的邮件发送协议 |
| 收邮件 | POP3 / IMAP | 拉取邮件到本地（POP3）或服务器管理（IMAP） |
| 域名解析 | DNS | IP 不方便记忆，必须用域名 |
| 实时视频/直播 | UDP（非协议，是传输层选择） | 可容忍少量丢包，不能容忍延迟 |
| 远程登录管理 | SSH（优先）/ Telnet（不安全） | SSH 加密，Telnet 明文 |

## 正例（≥2个）

1. **DNS 递归查询全过程**：用户在浏览器输入 www.qq.com → 本地 DNS 服务器收到查询 → 缓存未命中 → 向根域名服务器递归查询 → 根说"我不直接知道，我帮你问 .com 顶级域名服务器" → .com 顶级服务器说"我帮你问 qq.com 的权限域名服务器" → 权限服务器返回 IP → 结果层层回传给用户。全程用户只发了 1 次请求。
2. **FTP 下载一个大文件**：客户端通过 21 端口连接到 FTP 服务器 → 登录验证（USER + PASS）→ 发送 RETR 命令请求下载 → 服务器建立数据连接（20 端口）→ 文件数据开始传输 → 传输完成，数据连接关闭（控制连接仍然开着）→ 用户可继续发出其他命令。

## 反例/边界（≥1个）

1. **DHCP 属于应用层，不是网络层**：虽然 DHCP 做的是"分配 IP 地址"这种看起来像网络层的事情，但它是一个完整的应用层协议（基于 UDP，端口 67/68，有完整的请求-响应交互流程）。"分配 IP 地址"是它的**功能**，但它的**实现方式**属于应用层。类似的还有 BGP（路由协议之一）虽然是网络层的功能，但 BGP 报文通过 TCP 179 端口传输——实现方式穿越了传输层。
