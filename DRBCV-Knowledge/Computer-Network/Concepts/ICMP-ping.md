# ICMP / ping

## 类型判定
判别 — 网络层的诊断协议。`ping` 命令通过 ICMP 协议测试主机是否可达和延迟。和 TCP/UDP 走的是不同的协议栈——所以"ping 通但连不上"是完全正常的。

## 类比 ★
### 一句话比喻
ping = 你朝一栋楼喊了一声"有人吗？"，楼里的人回了一声"有！"。这证明楼里有人——但你不能凭这句话就判断楼里的商店开门营业（TCP 端口开放）。可能商店关了、或者门锁了、或者保安不让你进特定楼层。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| ping 通 (ICMP 回显) | 喊话有人回——楼不是空的 |
| TCP 端口不通 (SYN 超时) | 商店门锁了——进不去 |
| 运营商封 TCP 但不封 ICMP | 保安只让你在楼下喊话，不进楼 |

## 是什么
ICMP（Internet Control Message Protocol）是 IP 层的辅助协议，用于网络诊断和错误报告。`ping` 发送 ICMP Echo Request → 目标主机返回 ICMP Echo Reply。ICMP 是独立协议（IP 协议号 1），不使用端口，不走 TCP/UDP。

## 正例
1. **VPS 在线验证**：`ping 192.255.128.175` → 174ms 延迟 → VPS 在线且路由可达。
2. **家庭电脑的"ping 通但 TCP 不通"**：`ping 192.255.128.175` 返回 174ms，但 `telnet 192.255.128.175 443` 超时——这是运营商封了 TCP 但没封 ICMP 的典型特征。

## 反例/边界
1. **ping 不通 ≠ 服务器挂了**：服务器防火墙可能禁用了 ICMP 响应（常见于安全意识高的配置）。此时 ping 超时但 TCP 服务可能正常。
2. **ping 通 ≠ 端口开放**：ICMP 不走端口，ping 通只证明 IP 可达，不证明特定的 TCP/UDP 端口在监听。
3. **不能用来测带宽**：ping 的包很小（默认 56 字节），延迟不反映大文件传输速度。

## 详细解释
本项目中 ping 的信息价值：
```
家里电脑:
  ping 192.255.128.175 → 174ms ✅  (IP 路由可达)
  TCP 443 → 超时 ❌                 (运营商封了 TCP 连接)
  TCP 10000 → 超时 ❌               (同上)

笔记本:
  ping 192.255.128.175 → 174ms ✅
  TCP 443 → 174ms ✅               (Hysteria2 通过)
```

这个对比直接确认了问题是**运营商 TCP 封锁**而非 VPS 宕机——如果只看 ping，两台电脑结果一样。必须交叉验证 ICMP + TCP 才能定位到封锁层。
