# 路由聚合

## 类型判定
连接型 — 回答"给定多条路由表项，如何将它们聚合成一条更短的前缀"，涉及从多条路由到单条路由的映射聚合计算。

## 是什么
路由聚合（又称**构成超网**）是CIDR的配套技术，将转发表中**转发接口相同**且**部分网络前缀相同**的多条路由表项合并为一条前缀更短的表项。聚合后路由表减小，查询速度更快。聚合操作可能引入**无效地址**（覆盖到尚未分配的子网），并可能引发**最长前缀匹配**问题。

## 输入-输出空间
- **输入**：多条路由表项（目的网络号+子网掩码+转发接口），它们转发接口相同
- **输出**：一条聚合后的路由表项（取公共前缀+子网掩码缩短）
- **映射关系**：映射关系 — 找出各条目的最长公共前缀位，缩短掩码

## 正例（至少2个）
1. **三合一聚合**：县电信路由器有三个表项→128.14.32.0/28（铁柱网吧）、128.14.32.16/29（旺财家）、128.14.32.24/30（狗剩家）。三者的前27位完全相同（128.14.32.0/27），转发接口都是G1，聚合为一条128.14.32.0/27→G1。
2. **合并效果**：聚合前IP数据报到达需查3次表，聚合后只查1次，转发时延降低。且路由表占用内存减少。

## 反例/边界（至少1个）
1. **转发接口不同不能聚合**：闲鱼电信路由器的三个表项中，铁柱网吧→F1、旺财家→F2、狗剩家→F3，虽然它们前缀部分相同，但转发接口不同，不能聚合。如果强行聚合会导致所有流量走同一个接口，无法正确送达各子网。

## 详细解释

### 路由聚合的计算方法

1. 将各目的网络号展开为二进制
2. 找出所有网络号的**最长公共前缀**
3. 将这个公共前缀作为聚合后的网络前缀
4. 子网掩码的长度 = 公共前缀的位数
5. 转发接口保持与原条目一致

```
示例：
  128.14.32.0/28  →  10000000.00001110.00100000.0000 0000
  128.14.32.16/29 →  10000000.00001110.00100000.0001 0000
  128.14.32.24/30 →  10000000.00001110.00100000.0001 1000
  公共前缀：      10000000.00001110.00100000.000 (27位)
  聚合结果：128.14.32.0/27
```

### 路由聚合的优点
- **减小路由表**：节省路由器内存
- **加快查表速度**：减少匹配次数，降低转发时延

### 路由聚合的问题

#### 1. 引入无效地址
聚合后的表项覆盖了尚未分配的子网地址段。如上述聚合覆盖了128.14.32.0/27的全部32个地址，但实际只分配了铁柱、旺财、狗剩3个子网。发往未分配子网的IP数据报到达闲鱼电信后无法匹配，最终被丢弃。这不影响正常网络工作。

#### 2. 最长前缀匹配原则
当路由聚合后，一个目的IP地址可能匹配多条表项。此时选择**前缀最长的匹配项**。

```
示例：铁柱网吧新增直连线路到县电信路由器
  表项1：128.14.32.0/27 → G1（聚合路由）
  表项2：128.14.32.0/28 → G3（铁柱网吧精确路由）
  
目的IP=128.14.32.131：
  - 与表项1: 前27位匹配 ✓
  - 与表项2: 前28位匹配 ✓（更长）
  → 选择最长前缀匹配 → 从G3转发（更快直达）
```

## 生活类比
- **路由聚合**：就像快递公司发现北京朝阳区所有包裹都走同一个分拣中心，于是不再在路由表里写"望京街道→中心A"、"三里屯街道→中心A"之类的几百条细项，而是直接合并为"朝阳区→中心A"一条。但如果某个街道新开了直达站点，就需要用更精确的地址（最长前缀匹配）覆盖这条聚合路由。
- **最长前缀匹配**：翻译原则"有精确地址找精确地址，没有精确地址再找模糊地址"——如果知道对方住几栋几号，肯定比只写到小区名更精准。
