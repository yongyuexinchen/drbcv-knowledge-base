# 协议与数据单元

## 类型判定
连接型 — 回答"协议如何构成、数据在分层结构中如何封装和传递"，核心是协议三要素（语法、语义、时序）与 PDU/SDU/PCI 的层次嵌套关系。

## 是什么
在计算机网络的分层结构中，**协议**是控制对等实体之间通信的规则集合，由**语法、语义、时序**三要素构成。数据在逐层传递时会被封装：每一层在上一层交付的数据（即本层的**服务数据单元 SDU**）前增加本层的**协议控制信息 PCI**（首部/尾部），形成本层的**协议数据单元 PDU**，再作为下一层的 SDU 向下传递。这就是数据封装/解封装的完整过程。

## 输入-输出空间
- **输入**：上层用户数据、各层协议规范
- **输出**：经过层层封装的数据帧/分组/报文段/报文
- **映射关系**：映射关系 — 垂直方向：每层 PCI+SDU=PDU，下层将上层 PDU 作为自己的 SDU；水平方向：对等实体之间按协议交换 PDU

## 正例（≥2个）
1. **数据封装的全过程**：应用层数据 → 传输层加 TCP 首部（形成 TCP 报文段）→ 网络层加 IP 首部（形成 IP 分组）→ 数据链路层加帧首部和尾部（形成帧）→ 物理层转为比特流发送。接收方逐层解封装，每层拆掉本层首部后上交给上层。
2. **压缩传输协议例**：假设应用层协议 YSCS 实现了数据压缩功能。发送方在数据前加首部注明压缩算法类型；接收方收到后根据首部信息选择对应解压算法。这就是"同一层对等实体通过协议控制信息协同完成功能"的典型例子。

## 反例/边界（≥1个）
1. **把 PCI 和 PDU 混为一谈**：PCI 只是协议控制信息（首部/尾部），而 PDU  = SDU + PCI，是完整的传输单元。不能把首部（PCI）当作完整的协议数据单元（PDU）。

## 详细解释

### 协议三要素

| 要素 | 英文 | 定义 | 类比 |
|------|------|------|------|
| **语法** | Syntax | 数据与控制信息的**格式**（首部几个字节、各字段含义、数据部分最大长度） | 信封的格式：左上角寄件人、中间收件人 |
| **语义** | Semantics | 需要发出何种控制信息、完成何种动作、做出何种应答 | 信封上的"急件"标签→收件人优先处理 |
| **时序** | Timing（同步） | 通信双方执行各种操作的**条件与时序关系**，对事件实现顺序的详细说明 | "发信→等回执→超时未回则重发"的时间顺序 |

三个要素相辅相成，共同组成一个完整的协议。

### PDU / SDU / PCI 的概念与关系

| 缩写 | 全称 | 含义 |
|------|------|------|
| **PDU** | Protocol Data Unit | 对等层次之间传送的数据单位，本层传输的"完整包裹" |
| **SDU** | Service Data Unit | 为完成上一层实体所要求的功能而传送的数据，本层要处理的"货物" |
| **PCI** | Protocol Control Information | 控制协议操作的信息——首部和/或尾部，本层加的"包装" |

**核心关系**：
```
本层 PDU = 本层 SDU + 本层 PCI
本层 PDU = 下一层的 SDU
```

### 数据封装与解封装

**发送方（从上到下，逐层加头）**：
```
应用层数据 → [传输层首部 | 应用层数据] → [网络层首部 | 传输层首部 | 应用层数据] 
→ [数据链路层首部 | 网络层首部 | 传输层首部 | 应用层数据 | 数据链路层尾部] → 比特流
```

**接收方（从下到上，逐层去头）**：
反向操作：物理层收到比特 → 数据链路层检查帧首尾并去掉 → 网络层检查并去掉 IP 首部 → 传输层检查并去掉 TCP 首部 → 应用层获得原始数据。

### 各层数据单元在不同体系结构中的名称

| 层次 | 数据单元名称 |
|------|-------------|
| 应用层 | 报文（Message） |
| 传输层 | 报文段（Segment）——TCP；数据报（Datagram）——UDP |
| 网络层 | 分组/数据报（Packet）——IP 数据报 |
| 数据链路层 | 帧（Frame） |
| 物理层 | 比特流（Bit Stream） |

### 从水平视角看协议的作用
以五层模型为例：同一层（如传输层）的对等实体之间遵循 TCP/UDP 协议。发送方传输层将上层（应用层）的 SDU 加上本层的 PCI（TCP 首部），形成传输层 PDU（TCP 报文段）。接收方传输层收到后，解析 PCI，剥离首部，将 SDU 上交给应用层。整个过程中，应用层感知不到传输层的存在——这就是分层带来的透明性。

## 生活类比
就像**快递发货的全流程**：
- **SDU** = 你放入快递盒的商品（上一层委托传输的数据）
- **PCI** = 快递单上填写的寄件人/收件人地址、运单号、增值服务标签（协议控制信息）
- **PDU** = 贴好快递单的完整包裹（本层交付给快递公司的单元）
- **语法** = 快递单各栏位的填写格式
- **语义** = "加急"标签→优先配送，"货到付款"→先收费后拆包
- **时序** = 先下单→再发货→收到后确认→未收到则重发
