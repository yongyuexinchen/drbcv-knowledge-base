# 微调（Fine-tuning）

## 类型判定
微调是对已训练好的大模型，用特定领域的数据集再训练一次，使其在特定任务上表现更好。

## 类比 ★
### 一句话比喻
一个医科大学毕业生（通用大模型）什么科室都学过，但让他做心脏外科手术还差点火候——再送他去心外科实习一年（微调），他就成了心脏外科专家。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 预训练大模型 | 医学本科毕业生（各科都懂一点） |
| 通用训练数据 | 医学院的通用教材 |
| 微调数据集 | 心外科的专科手术案例 |
| 微调后的模型 | 心外科主治医生 |
| 微调过程 | 在心外科轮转实习 |

## 是什么
微调是使用特定领域（法律、医疗、金融等）的任务数据，对已经预训练好的大模型进行进一步训练，修改模型参数（权重 W 和偏置 B），使其在特定领域的回答更精准、错误率更低、响应更符合专业要求。微调改变了模型本身，而非像 RAG 那样外挂知识库。

## 正例（≥2 个）
1. 某律所将过往五年的合同数据微调开源模型，得到一个专精合同审查的法律大模型，审查准确率从通用模型的 60% 提升到 95%。
2. 医院用电子病历数据微调模型，使其能根据症状描述辅助诊断，而非像通用模型那样只能给笼统建议。

## 反例/边界（≥1 个）
1. 企业只是想让客服机器人回答公司产品 FAQ——这种情况用 RAG 即可，不需要微调。微调成本高（需要准备数据集、GPU 算力），只适合 RAG 搞不定的 10% 的极端垂直场景。
2. 微调不是万能药——如果微调数据集质量差或太小，模型反而会"学坏"，不如不调。

## 详细解释
微调与 RAG 的区别（三圆模型）：用户上下文 + LLM 知识 = 模型问答（可能幻觉）；用户上下文 + 外部数据 = 传统检索（死板）；LLM 知识 + 外部数据 = 微调模型（内化知识）；三者全结合 = RAG（最常用方案）。RAG 解决 90% 问题，微调覆盖剩下的 10%。微调的代价包括：数据标注成本、GPU 算力、可能过拟合等风险。
