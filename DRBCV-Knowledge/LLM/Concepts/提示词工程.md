# 提示词工程

## 类型判定
提示词工程（Prompt Engineering）是采用工程化思维系统性地设计、优化、迭代提示词的方法论，目标是让大模型输出精准、符合预期的内容。

## 类比 ★
### 一句话比喻
普通用户跟 AI 聊天就像随便跟朋友发微信——想到啥说啥；提示词工程师跟 AI 聊天就像给特种兵下作战指令——角色、目标、步骤、限制条件、期望输出格式，一个都不能少。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 随便提问 | "帮我写个东西" |
| 提示词工程 | 给下属派任务：你是谁（角色）、做什么（任务）、怎么判断做得好（标准）、用什么格式交（输出要求） |
| 迭代优化 | 下属交了初稿 → 不满意 → 修改指令 → 再交 → 直到满意 |
| 内嵌到系统 | 给 B 端企业部署时，提前把所有指令写进系统配置 |
| 三个环节 | 明确目标 → 优化提示 → 评估迭代 |

## 是什么
提示词工程的核心三环节：①明确目标——确定希望模型做什么（写文案？智能问答？）；②优化提示——给模型具体指示（角色、任务、上下文、格式要求），让模型知道"自己是干什么吃的"；③评估和迭代——测试 → 分析输出质量 → 修改提示词 → 再测试，循环直到满意。提示词工程不只用于 C 端对话——在 B 端私有化部署时，提示词需提前写好并嵌入模型框架，让企业开箱即用。

## 正例（≥2 个）
1. 智能销售机器人：提前写好提示词"你是一名智能销售，要根据客户需求热情推荐产品，使用轻快风格……"，部署后企业直接用。
2. 国内 AI 工具的"功能分类"（AI 写作、AI 汇报、周报生成等）——本质上都是预设好的提示词工程模板。

## 反例/边界（≥1 个）
1. 随口说"帮我写篇文章"不是提示词工程——这只是用了一次 Prompt。提示词工程的核心是"工程化"：有方法论、可迭代、可复用、可嵌入系统。
2. 一次性的简单问答不需要提示词工程——提示词工程适用于需要稳定输出质量的业务场景。

## 详细解释
提示词工程背后的核心技术：①N-gram——通过统计前 N 个词共同出现的概率来预测下一个词（unigram 用前 1 个，bigram 用前 2 个）；②深度学习——多层神经网络自动学习文本特征，让模型不断自我优化。提示词工程也分为浅层（C 端用户优化提问）和深层（开发层面，结合微调不断调教模型）。两大编写原则：清晰明确的指令 + 给模型足够的思考时间/上下文。
