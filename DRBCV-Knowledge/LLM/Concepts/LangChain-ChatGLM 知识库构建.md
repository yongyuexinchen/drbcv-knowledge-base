# LangChain-ChatGLM 知识库构建

## 类型判定
[程序] — 在 LangChain-ChatGLM 项目中新建知识库、上传文件、配置检索参数并实现基于私有数据的问答，同时与提示词配合优化特定场景表现。

## 类比 ★
### 一句话比喻
你新开了一家私人图书馆（知识库），把公司内部文件一本本放进书架（上传文档），雇了一位懂书的管理员（Embedding 模型）给每本书贴智能标签（向量化），再来一位口才好的讲解员（LLM）用大白话回答读者——读者问"张一鸣的创业思考是什么"，讲解员翻两下就找到对应段落，还能说出处。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 知识库 | 私人图书馆 + 智能检索系统 |
| Embedding 模型 | 给书贴智能标签的管理员 |
| 上传文件 | 新书入库上架 |
| 匹配分数阈值 | 管理员找书的"严格度"：只找精确匹配 vs 也找相关书 |
| 匹配知识条数 | 一次借几本书给读者参考 |
| 知识库问答模式 | 读者提问 → 管理员找书 → 讲解员用大白话回答 |
| 搜索引擎问答模式 | 读者提问 → 讲解员先上 Bing 搜一下 → 再回答 |

## 是什么
LangChain-ChatGLM 项目的知识库功能允许用户上传企业私有文档（PDF、Word 等），通过 Embedding 模型将文本转为向量存入向量数据库，用户提问时系统先检索相关知识片段，再交给 LLM 生成基于私有数据的精准回答。相比微调，知识库是"成本最低、最省事"的企业定制方案——不需要 GPU 训练、不需要数据集标注，只需要上传文档即可。

## 输入-输出空间（程序型必填）
- **输入**: 知识库名称、简介描述、上传文件、Embedding 模型选择、匹配参数
- **输出**: 可对话的知识库，LLM 基于上传文档回答并标注出处
- **前置条件**: LangChain-ChatGLM 项目已部署运行

## 核心知识
### Embedding 模型选择
文本上传后先经过 Embedding 将文字转为数字向量（机器只认数字）：
- 默认模型：中文理解能力不错，推荐
- 另有英文更强的模型可选
- OpenAI Embedding 模型理论最强但处理中文"也就那样"
- 注意：处理大文件时可选择更大的向量维度类型

### 知识库匹配参数
| 参数 | 作用 | 建议 |
|------|------|------|
| 匹配知识条数 | 每次检索返回几条相关片段 | 4-6 条，过多会超上下文限制 |
| 匹配分数阈值 | 控制回答与知识库的贴合度 | 偏低→更贴近原文但死板；偏高→更有主见但可能偏离 |
| 提示词模板 | 预设角色和回答风格 | 与匹配阈值搭配使用，共同优化特定场景 |

### 三种对话模式
1. **大模型对话**：纯 LLM 对话，不用知识库——像用 ChatGPT
2. **知识库问答**：基于私有文档回答，标注出处——B 端核心场景
3. **搜索引擎问答**：LLM + Bing 搜索引擎实时检索——需海外节点

## 正例（≥2 个）
1. **企业内部知识库**：上传公司产品手册 → 选择默认 Embedding 模型 → 匹配阈值偏左 → 客户问"XX 功能怎么用"→ LLM 精准检索手册内容并回答，点开可看出处。
2. **张一鸣言论检索**：上传张一鸣的创业思考文档 → 问"张一鸣怎么看创业"→ 系统检索到对应段落 → LLM 用自己的话总结关键点 → 用户可验证来源。

## 反例/边界（≥1 个）
1. **知识库 ≠ 微调**：知识库是在 LLM 外部挂载文档，不改模型参数——成本低、见效快、可随时更新文档；微调是改变模型权重——成本高、不可逆、需要高质量数据集。知识库解决 90% 的企业需求，剩下 10% 的极端垂直场景才需要微调。
2. **Agent 模式在 GLM2 上不适配**：自定义 Agent 需要分裂成多角色协作，ChatGLM2 跑 Agent 时速度极慢且效果差（如让写贪吃蛇代码跑不动）。Agent 目前只有 GPT-4 级别模型能较好支持，ChatGLM3 发布后可能有改善。

## 详细解释

### 知识库创建步骤
| 步骤 | 操作 | 说明 |
|------|------|------|
| 1. 新建知识库 | 知识库管理 → 新建 → 填写名称和简介 | 简介类似"视频标题"，帮助 Agent 后续调度 |
| 2. 选择 Embedding | 向量库类型选默认值 | 大文件可选更多维度 |
| 3. 上传文件 | 添加文件 → 调整处理配置 | 数据清洗由系统自动完成 |
| 4. 开始对话 | 对话模式选"知识库问答" → 选刚创建的知识库 | 调整匹配参数 + 提示词 → 提问 |

### 知识库 vs 微调决策
- 你的文档经常更新？→ 知识库（上传覆盖即可）
- 你的领域极度垂直（如医疗诊断）？→ 微调（知识库不够精准）
- 你没有 GPU 预算？→ 知识库（零算力成本）
- 你需要模型"内化"知识而非"查询"知识？→ 微调
