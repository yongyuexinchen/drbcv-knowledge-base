# RAG（检索增强生成）

## 类型判定
RAG（Retrieval-Augmented Generation）是一种结合信息检索与文本生成的技术，先检索外部知识再让 LLM 基于检索结果生成回答。

## 类比 ★
### 一句话比喻
考试时你大脑一片空白（大模型不知道答案），但老师允许你翻书——你先翻书找到知识点（检索），再用自己的话写答案（生成），这就是 RAG。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 用户提问 | 考试题目 |
| LLM 自身知识 | 学生脑子里的记忆 |
| 向量数据库 | 允许翻阅的课本 |
| 检索相似文本块 | 翻到相关页找到答案段落 |
| LLM 生成回答 | 用自己的话作答 |

## 是什么
RAG 是"检索增强生成"的缩写，核心流程：用户提问 → 问题 Embedding（向量化）→ 在向量数据库中进行相似性检索 → 找到相关文本块 → 将文本块与提示词模板拼接 → 发送给 LLM → LLM 生成最终回答。RAG 解决了 LLM 的三大痛点：知识截止日期、幻觉（胡编）、以及无法访问私有数据。

## 正例（≥2 个）
1. 企业将产品手册导入知识库后，客户问"XX产品保修几年"，RAG 先检索到手册中的保修条款，再让 LLM 据此回答，确保答案准确、有据可查。
2. 律师事务所上传过往判例，律师提问后 RAG 检索相关判例文本，LLM 基于真实判例生成法律分析，而非编造法条。

## 反例/边界（≥1 个）
1. 直接问 ChatGPT 一个它训练数据里没有的冷门问题 = 不用 RAG，模型可能胡编（幻觉）。同样的问题经过 RAG 先检索权威资料再回答 = 有据可依。
2. RAG 和微调（Fine-tuning）不是非此即彼——RAG 解决 90% 的企业知识库需求（成本低、见效快），剩下 10% 垂直性极高的场景才需要微调。

## 详细解释
RAG 的三大环节：①检索（Retrieval）：从外部知识源找到相关信息；②增强（Augmented）：将检索结果作为上下文注入提示词；③生成（Generation）：LLM 基于增强后的提示词生成回答。RAG 技术在大模型出现前就已存在，大模型的出现让它更加实用。RAG 不能替代模型本身——它只是在模型和你之间加了一个"先查资料再回答"的中间层。
