# 数据寻址方式

## 类型判定
判别型 — 描述指令中形式地址 A 如何映射为有效地址 EA 的十种规则，涵盖六种基本寻址、三种偏移寻址和堆栈寻址，属于"映射规则"类概念。

## 类比 ★
**一句话比喻：** 像在大城市找人——十种寻址方式就是十种不同的"怎么找到你"的指令：有的直接给你门牌号，有的让你先找中介拿地址，有的说"从市政府往东走三条街"，最离谱的是直接把要给你的东西塞进信封里。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 形式地址 A（指令中的地址码） | 写在地图上的模糊提示（"从地标往东走"） |
| 有效地址 EA（实际存储位置） | 你要找的那个人的真实 GPS 坐标 |
| 寻址特征位（告诉 CPU 怎么解读 A） | 每条提示前面贴的便签——"这是绝对地址/相对地址/中介地址" |
| 偏移寻址 = 基地址 + 偏移量 | "以市政府为起点，往东走 3 条街" |

## 是什么
**数据寻址**是指 CPU 根据指令中给出的形式地址 A，配合寻址特征位，计算出操作数真实存放地址（有效地址 EA）的机制。指令中的地址码不是一成不变的——同一条指令的 A，在不同寻址方式下会被用完全不同的规则解读。十种数据寻址方式分为三大类：**六种基本寻址**（直接/间接/寄存器/寄存器间接/隐含/立即）、**三种偏移寻址**（基址/变址/相对）、**一种堆栈寻址**。偏移寻址的共同公式：`EA = 基地址 + A`，区别仅在于"基地址"是谁（BR / IX / PC）。

## 输入-输出空间
- **输入**：形式地址 A + 寻址特征位
- **输出**：有效地址 EA（操作数的真实主存地址）或操作数本身（立即寻址）
- **关键变量**：BR（基址寄存器）、IX（变址寄存器）、PC（程序计数器）、SP（堆栈指针）

## 正例（≥2 个）
1. **直接寻址→立即取数**：指令 `LDA 5`，寻址特征=直接，A=5。EA=A=5，CPU 直接去主存 5 号单元取数。取指 1 次 + 执行 1 次 = 共 2 次访存。最符合直觉，简单但灵活性差——如果操作数搬家，必须修改指令。
2. **基址寻址→程序浮动**：一段程序从主存 100 开始存放（BR=100），指令 `ADD 5` 采用基址寻址。EA = BR + A = 100+5 = 105，刚好访问到变量 A。当操作系统把程序搬到主存 200 处，只需改 BR=200，指令本身不用改——多道程序并发的基石。
3. **变址寻址→循环遍历数组**：数组 A[0..9] 首址=7，IX 初始=0。`ADD 7(IX)` 采用变址寻址，EA = A + IX。每轮循环 IX++，依次访问 A[0]=7+0, A[1]=7+1, ..., A[9]=7+9。只需一条加法指令搞定十轮循环。

## 反例/边界（≥1 个）
1. **"PC 相对寻址基于当前指令地址"是错的**：CPU 取完当前指令后 PC 已自动递增→相对寻址的基地址是**下一条指令地址**，不是当前指令地址。王道书此处理有歧义，408 考试以"下一条指令地址"为准。
2. **基址 vs 变址≠只有寄存器不同**：基址寻址中 A 是偏移量、BR 是基地址，BR 由操作系统管理（用户不可改）；变址寻址中 A 是基地址、IX 是偏移量，IX 面向用户（程序员可用指令修改）。角色恰好互换！
3. **立即寻址找不到操作数地址**：立即寻址的 A 就是操作数本身，不存在"地址→数据"的映射——所以"访存 0 次"说的是执行阶段，取指阶段仍需 1 次访存取指令。
4. **间接寻址扩大寻址范围但拖慢速度**：若 A 只有 16 位（寻址范围 64K），但 A 指向的主存单元里存了 32 位地址→寻址范围扩大到 4G。代价是每次间接寻址多 1 次访存（一次间接=2 次，二次间接=3 次）。

## 详细解释
### 十种寻址方式对比总表
| 寻址方式 | 有效地址 EA | 访存次数（执行期间） | 核心用途 |
|---------|------------|-------------------|---------|
| 直接寻址 | EA = A | 1 | 简单直接，寻址范围受 A 位数限制 |
| 间接寻址 | EA = (A) | ≥1 | 扩大寻址范围，支持多级指针 |
| 寄存器寻址 | 数据在寄存器 Ri 中 | 0 | 速度最快，寄存器数量有限 |
| 寄存器间接寻址 | EA = (Ri) | 1 | 比主存间接寻址快（少一次访存） |
| 隐含寻址 | 操作数隐含在 ACC 等 | 0 | 缩短指令字长，需专用硬件 |
| 立即寻址 | 操作数 = A（即立即数） | 0 | 执行最快，立即数范围受 A 位数限制 |
| **基址寻址** | EA = (BR) + A | 1 | 程序整体在主存中浮动（BR 由 OS 管） |
| **变址寻址** | EA = A + (IX) | 1 | 循环/数组遍历（IX 由程序员改） |
| **相对寻址** | EA = (PC) + A | 1 | 代码段内部浮动（常用于转移指令） |
| 堆栈寻址 | EA = (SP) | 0（硬堆栈）或 1（软堆栈） | 函数调用、中断现场的保存与恢复 |

> 访存次数**不含取指令**的那一次；偏移寻址三种访存次数相同（执行期间均 1 次），区分在"基地址是谁"。

### 偏移寻址核心公式与区别
```
EA = 基地址 + 形式地址 A（A 可正可负，补码表示）

基址寻址：基地址 = BR（程序起始存放地址），A = 偏移量 → "程序能在主存任何位置跑"
变址寻址：基地址 = A（数组首地址），偏移量 = IX → "一条指令遍历整个数组"
相对寻址：基地址 = PC（下一条指令地址），A = 偏移量 → "代码挪位置不用改跳转"
```

### 堆栈寻址（两种实现）
- **硬堆栈**（寄存器组）：SP 指向栈顶，push/pop 操作不访存，速度最快，成本最高
- **软堆栈**（主存划区）：push/pop 各需 1 次访存（先改 SP，再读写主存），成本低
- **入栈**：SP 先减/加（取决于栈增长方向）→ 新元素写入 SP 新指向的位置
- **出栈**：先读 SP 指向的元素 → SP 再加/减（逻辑删除）

## 备注
- 408 大题最高频考点——每年几乎必有一题给指令格式让你判断各地址码的寻址方式
- 基址 vs 变址的核心区别一句话：BR 面向 OS（不改指令让程序搬家），IX 面向用户（不改指令遍历数组）
- 相对寻址的 EA = (PC) + A，"PC"是取指后已递增的值——做题时看清楚"当前指令地址"还是"下一条指令地址"
- 堆栈寻址：SP 的操作方向（加还是减）取决于题目规定的"栈向低地址增长"还是"向高地址增长"
