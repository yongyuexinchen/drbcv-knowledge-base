# 输入输出系统与IO控制方式

## 类型判定
判别型 — 回答「IO 系统由哪些部分组成、CPU 如何控制 IO 设备完成数据交换」，属于系统控制类概念。

## 类比 ★
**一句话比喻：** 像餐厅后厨的出餐流程——程序查询是厨师一直盯着传菜口傻等（手头活全停），程序中断是服务员按铃叫厨师来取菜（不用傻等但不分轻重），DMA 是传菜员直接把菜端上桌（厨师只管做菜，偶尔看一眼），通道是雇了个副厨专门管传菜（大厨彻底解放）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 程序查询方式 | 厨师每隔 3 秒往传菜窗口探头——菜好了吗？好了吗？——自己啥也干不了 |
| 程序中断方式 | 传菜员按铃通知厨师"菜好了"——厨师手上的汤还能继续搅两下，听见铃就去取 |
| DMA 方式 | 传菜员推着餐车直接把菜端上桌，大厨只交代"3 号桌放 5 盘"就不管了——每端一盘占用传菜通道一瞬间 |
| 通道方式 | 雇了个副厨（通道），大厨说"你去管所有传菜，完事儿再叫我"——全程不需要大厨操心 |

## 是什么
**IO 系统** 由 IO 硬件（IO 接口 + IO 设备）和 IO 软件（驱动程序、操作系统管理程序等）组成。主机通过 IO 接口控制外部设备完成数据输入/输出。根据 CPU 介入 IO 操作的频率和方式不同，分为四种 **IO 控制方式**，从上至下效率逐步提高：**程序查询 → 程序中断 → DMA → 通道**。IO 指令（CPU 执行，结构为操作码+命令码+设备码）和通道指令（通道执行）是两套不同的指令系统。

## 输入-输出空间
- **输入**：CPU 发出的 IO 指令（操作码、命令码、设备码），通过 IO 总线传给 IO 接口
- **输出**：IO 设备完成操作后返回的数据（经数据寄存器中转）或状态反馈（经状态寄存器 / 中断信号）
- **前置条件**：IO 接口已正确连接在系统总线上；驱动程序已将厂商特有的命令码封装好

## 正例（≥2 个）
1. **scanf 卡住等于程序查询**：C 语言 `scanf("%c", &i)` 执行时 CPU 向键盘 IO 接口发出读命令后不断轮询状态寄存器——你一直不敲键盘，CPU 就卡死在这啥也干不了。这就是最傻的程序查询方式。
2. **中断方式解放 CPU**：同样是 scanf，采用中断方式时 CPU 发出读命令后转头去跑后台程序，当你敲下字符后键盘 IO 接口发中断请求信号，CPU 在每个指令周期末尾例行检查中断，发现后执行中断处理程序去取数据——CPU 利用率大幅提升。
3. **DMA 传磁盘数据**：CPU 告诉 DMA 控制器"从磁盘第 100 扇区读 1KB 数据到主存 0x2000 地址"，然后扭头干别的。DMA 控制器自己每次从磁盘读一个字写入主存（每次占一个存取周期），写完 1KB 后才给 CPU 发一个中断。比中断方式每传一字就打断一次 CPU 高效得多。

## 反例/边界（≥1 个）
1. **慢速设备用中断、快速设备用 DMA**：键盘每秒最多敲五六次，中断频率低，用中断方式完全够。但磁盘读写速度快，若也用中断方式，每传一个字就打断 CPU 一次，CPU 光处理中断就累死了。所以快速设备必须用 DMA。
2. **DMA ≠ 完全不需要 CPU**：DMA 只是把"每传一字中断一次"变成"传完一整块中断一次"，CPU 仍需要在开头交代任务、在结尾处理一次中断。微型计算机用 DMA 足够，但大型机（如云存储服务器挂几百块硬盘）哪怕每块盘传完一整块都中断一次，CPU 也受不了，所以才发明了通道。
3. **通道是"弱鸡 CPU"，不是普通 IO 接口**：通道可以执行通道指令（一种特殊的指令集），但它只能做 IO 管理，不能替代 CPU 算加减乘除。

## 详细解释
### 四种 IO 控制方式对比

| 方式 | CPU 介入频率 | 数据流向 | CPU 利用率 | 适用场景 |
|------|------------|---------|-----------|---------|
| 程序查询 | 每传一字、一直轮询 | 外设→IO接口数据寄存器→CPU→主存 | 极低（忙等） | 极简单系统/调试 |
| 程序中断 | 每传一字中断一次 | 外设→数据寄存器→CPU→主存 | 中 | 慢速设备（键盘/鼠标） |
| DMA | 每传一整块中断一次 | 外设↔主存（直接通路，CPU 不中转） | 高 | 高速设备（磁盘/SSD） |
| 通道 | 完成一大串任务中断一次 | 通道统一管理多设备 | 最高 | 大型机/服务器（海量 IO 设备） |

### DMA 方式核心机制
1. CPU 通过 IO 指令告诉 DMA 控制器：读还是写、磁盘地址、主存地址、数据量
2. DMA 控制器每准备好一个字，发出 DMA 请求，占用一个存取周期写入主存
3. CPU 若同时想访存，需等 DMA 写完这一个字（DMA 优先于 CPU）
4. 传完整块后 DMA 控制器发一次中断，CPU 执行中断处理程序确认完成

### IO 指令 vs 通道指令
- **IO 指令**：CPU 执行的指令，结构 = 操作码 + 命令码 + 设备码；命令码由驱动程序根据具体厂商设备生成（如罗技键盘亮灯命令码 ≠ 雷蛇键盘亮灯命令码）
- **通道指令**：通道执行的指令，存放在主存中（与 CPU 程序共存），CPU 通过 IO 指令告诉通道"去主存某位置取通道程序执行"

## 备注
- 408 常考顺序：程序查询 < 程序中断 < DMA < 通道，越往后 CPU 利用率越高
- 易混淆：IO 指令（CPU 执行）≠ 通道指令（通道执行），两者是两套完全不同的指令集
- 口诀：「查中断，D通高」——查询最傻、中断解放 CPU、DMA 直传不中转、通道管所有
- 驱动程序的本质作用是翻译：把通用操作翻译成特定厂商设备的命令码（同一操作对不同厂商设备命令码不同）
