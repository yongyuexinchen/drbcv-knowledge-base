# DMA方式

## 类型判定
程序型 — 描述 DMA 控制器以硬件方式在 IO 设备和主存之间直接批量传送数据的 IO 控制方式，涵盖预处理/数据传送/后处理三阶段及三种访存冲突解决策略，属于"过程"类概念。

## 类比 ★
**一句话比喻：** 像老板雇了个搬运工——CPU 交代"把这车货从仓库搬到三楼 301 室，一共 100 箱"就回去干自己的活了，搬运工（DMA 控制器）自己一箱箱搬完，最后才敲老板门说"搬完了"。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| DMA 控制器 | 搬运工小弟 |
| CPU 预处理（AR/WC/DAR） | 老板交代：搬到哪（AR）、搬几箱（WC）、从哪个仓库取（DAR） |
| DMA 请求（每字传送） | 搬运工每搬一箱要和电梯（系统总线）确认空闲才能用 |
| DMA 中断请求（整块完成） | 搬运工搬完全部 100 箱后敲门报告老板 |
| 周期挪用 | 老板和搬运工同时到电梯口，优先让搬运工进（他手上的货会丢） |

## 是什么
**DMA方式**是一种由专用硬件——**DMA控制器**——直接控制 IO 设备与主存之间批量数据传送的 IO 控制方式。CPU 只负责**预处理**（向 DMA 控制器指明传输方向、主存起始地址 AR、设备地址 DAR、传送字数 WC）和**后处理**（收到 DMA 中断后做善后），中间逐字传送过程由 DMA 控制器自主完成，CPU 可并行执行其他程序。DMA 方式每传送一整块数据只产生一次中断（而非中断方式那种每字一次中断），大幅降低了 CPU 开销，适用于磁盘等高速块设备。

## 输入-输出空间
- **输入**：CPU 预处理写入的传送参数（AR/WC/DAR/方向）；外设发来的 DMA 请求（每字就绪信号）
- **输出**：DMA 控制器通过系统总线完成的逐字主存读写；WC 溢出时向 CPU 发出的 DMA 中断请求
- **前置条件**：DMA 控制器获得系统总线控制权（CPU 通过 HLDA 信号授权）；主存空闲或仲裁通过

## 正例（≥2 个）
1. **磁盘读入整块数据（5 个字）**：CPU 预处理 → 设置 WC=5, AR=主存起始地址, DAR=磁盘块号 → 启动磁盘 → 磁盘逐字将数据送入 DR（数据缓冲寄存器）→ 每字就绪 DMA 控制器向 CPU 申请总线 → 获得授权后将该字写入主存 AR 指向位置 → AR+1, WC-1 → 循环至 WC=0（溢出）→ 中断机构向 CPU 发 DMA 中断 → CPU 后处理。中间 5 次总线申请和主存写入全都由 DMA 控制器完成，CPU 全程在干别的事。
2. **周期挪用解决访存冲突**：DMA 控制器需要访存时——若 CPU 此时不访存，DMA 直接访存；若 CPU 正在访存且该存取周期未结束，DMA 等当前周期结束后再访存；若二者同时请求访存，DMA 优先（防止 DR 中数据被下一字覆盖丢失）。

## 反例/边界（≥1 个）
1. **DMA 请求 ≠ DMA 中断请求**：DMA 请求是每传一个字外设就绪时发出的信号（发生频率极高）；DMA 中断请求是整块数据全部传送完毕、WC 溢出时才发出的信号（只发生一次）。考试中这两个概念极易混淆。
2. **"DMA 完全不需要 CPU"是错的**：DMA 的预处理（设置 AR/WC/DAR）和后处理（善后工作）仍需 CPU 通过执行指令完成——DMA 只是解放了数据传送阶段的 CPU 开销，不是完全脱离 CPU。
3. **三总线结构才有"访存冲突"问题**：单总线结构中 DMA 是否访存由 CPU 说了算（通过总线授权），不存在冲突；只有三总线结构（DMA 与主存有专用 DMA 总线）才可能出现 CPU 和 DMA 同时想访存的情况。

## 详细解释
### DMA 控制器内部关键寄存器
| 寄存器 | 缩写 | 作用 |
|--------|------|------|
| 主存地址计数器 | AR | 存放下次要读写的主存地址，每传一字自动+1 |
| 传送长度计数器 | WC | 记录剩余待传字数，每传一字-1，减到 0 溢出则触发中断 |
| 数据缓冲寄存器 | DR | 暂存外设输入/待输出到外设的一个字数据 |
| 设备地址寄存器 | DAR | 存放外设的读写地址（如磁盘块号） |
| DMA 请求触发器 | — | 外设送完一字后置 1，通知控制逻辑可以开始总线传送 |

### DMA 传送三阶段
1. **预处理**（CPU 执行）：设置 AR（主存地址）、WC（字数）、DAR（设备地址）、传输方向（读/写）→ 启动外设
2. **数据传送**（DMA 自主循环）：
   - 外设完成一字准备 → 数据进入 DR → DMA 请求触发器置 1
   - DMA 控制器向 CPU 发 HRQ（总线请求）→ CPU 回 HLDA（总线授权）
   - **DMA 操作周期**：AR 送地址总线 + DR 送数据总线 + 读写命令 → 主存完成读写
   - 完成后 AR+1, WC-1, DMA 请求触发器复位
   - WC ≠ 0 则等待下一个 DMA 请求；WC 溢出 → 进入后处理
3. **后处理**（CPU 执行）：响应 DMA 中断请求 → 运行中断服务程序做善后（如校验、释放总线等）

### 三种 DMA 传送方式（解决 CPU/DMA 访存冲突）
| 方式 | 做法 | 特点 |
|------|------|------|
| **停止 CPU 访存** | DMA 传送整块期间 CPU 完全不能用主存 | 控制简单，CPU 完全停滞，利用率最低 |
| **周期挪用（窃取）** | DMA 需要时借用一两个存取周期，CPU 和 DMA 冲突时 DMA 优先 | 最常用，CPU 基本不受影响 |
| **交替访存** | 主存时间片固定划分：C1 段归 DMA，C2 段归 CPU | 无需申请总线，但 DMA 可能浪费分配的时间片 |

### DMA 与程序中断方式的对比
| 维度 | 程序中断方式 | DMA 方式 |
|------|-------------|----------|
| 数据传送执行者 | CPU（通过 ISR 指令搬运） | DMA 控制器（硬件搬运） |
| 中断频率 | 每传一字一次中断 | 每传一整块一次中断 |
| 中断响应时机 | 每条指令周期末尾 | 每个机器/存取周期结束（总线空闲时） |
| 适用设备 | 低速 IO 设备 | 高速块设备（磁盘） |
| 异常通知能力 | 可通知各种异常 | 仅限数据传送完成 |
| CPU 并行程度 | 部分并行（ISR 期间不能并行） | 高度并行（数据传送全阶段并行） |

## 关系
### → 指向
- [[程序中断方式]] (DMA 的后处理阶段仍依赖中断机制通知 CPU 整块传送完成)
- [[IO接口]] (DMA 控制器本质上是一种功能更强的 IO 接口，包含 DR/AR/WC 等额外寄存器)
- [[总线的性能指标]] (DMA 传送依赖系统总线，总线带宽直接限制 DMA 传输速率)
### ← 被指向
- [[程序查询方式]] (DMA 彻底解决了查询方式的"踏步"和中断方式的"每字中断开销"问题)
- [[程序中断方式]] (中断方式每字一中断效率低，高速设备必须用 DMA)
- [[IO控制方式]] (DMA 是三种基本 IO 控制方式中效率最高的)

## 备注
- 核心口诀：**CPU 两头管，DMA 中间搬**——预处理 + 后处理归 CPU，数据传送归 DMA
- 408 高频考点：DMA 三阶段各做了什么事（预/传/后）→ AR/WC/DR 在传送阶段如何变化（AR+1, WC-1）
- 三种传送方式中**周期挪用**最常考：又称周期窃取，DMA 和 CPU 同时请求时 DMA 优先
- 易混淆铁律：DMA 请求（每字触发）≠ DMA 中断请求（整块结束触发）；中断隐指令发生在中断请求之后，不在 DMA 请求阶段
