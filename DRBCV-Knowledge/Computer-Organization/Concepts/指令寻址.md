# 指令寻址

## 类型判定
程序型 — 描述 CPU 如何确定下一条要执行指令的存放地址，包括顺序执行（PC 自动递增）和跳跃执行（转移指令修改 PC）两种机制，属于"过程"类概念。

## 类比 ★
**一句话比喻：** 像看连载小说——顺序寻址就是"读一页翻一页"（读完第 3 页自动翻到第 4 页），跳跃寻址就是"作者说请跳回第 7 页重读关键伏笔"（强行改变阅读顺序）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| PC（程序计数器） | 你的手指，始终指向"下一页要读的位置" |
| 顺序寻址（PC 自动 +"1"） | 正常阅读——读完一页顺手翻到下一页 |
| 跳跃寻址（JMP/CALL 修改 PC） | 作者标注"详见第 128 页"——你直接跳过去 |
| PC 具体加多少 | 取决于每页有多少行（按字编址/字节编址/变长指令） |

## 是什么
**指令寻址**是指 CPU 确定下一条即将执行的指令在主存中存放地址的机制，由**程序计数器 PC**（x86 中又称 IP 寄存器，Instruction Pointer）来指明。分为两种方式：**顺序寻址**——每取完一条指令，PC 自动递增指向下一条（递增量 = 当前指令的指令字长，视编址方式和指令长度而定）；**跳跃寻址**——当执行到转移类指令（JMP、CALL、条件转移等）时，PC 被强制修改为目标地址，程序执行流不再顺序进行。

## 输入-输出空间
- **输入**：当前 PC 值 + 当前执行的指令类型（普通指令或转移指令）
- **输出**：下一条指令的主存地址（PC 的新值）
- **关键变量**：按字编址 vs 按字节编址；定长指令字 vs 变长指令字

## 正例（≥2 个）
1. **定长指令字 + 按字编址**：指令字长 = 存储字长 = 2 字节，按字编址。PC 初始 = 0 → 取走第一条指令（占一个字）后 PC=1 → 取第二条后 PC=2。每取一条 PC 严格加 1。
2. **定长指令字 + 按字节编址**：指令字长 = 2 字节，按字节编址（每个字节一个地址）。第一条指令占地址 0 和 1，起始字地址 = 0；第二条占 2 和 3，字地址 = 2。每取一条 PC 加 2（即指令字长的字节数）。
3. **变长指令字 + 按字节编址**：CPU 先读入第一个字，根据操作码判断指令总长度（如 4 字节 = 2 个存储字）。取完整条指令后，PC = PC + N（N = 本条指令总字节数）。下一条指令的地址可能不是整齐的等差数列。

## 反例/边界（≥1 个）
1. **"PC 就是简单加一"是错的**：只有在指令字长 = 存储字长 = 编址单位时，PC 才严格加 1。实际 PC 的增量取决于编址方式和指令字长——"加一"应理解为"加一个指令字长"。
2. **变长指令字下的 PC 增量不可预判**：CPU 必须先读入指令的第一个字、解析操作码、确定指令总长度后，才能知道 PC 该加多少——这增加了取指阶段的复杂度。
3. **跳跃寻址后 PC 不再自动递增**：执行 JMP 7 后 PC 直接变成 7，不会在 7 的基础上再加——转移指令是"覆盖"而非"偏移"。

## 详细解释
### 顺序寻址——PC 自动递增的三种情况
| 条件 | PC 每次加的量 |
|------|-------------|
| 定长指令字 + 按字编址 + 指令字长=存储字长 | +1 |
| 定长指令字 + 按字节编址 | +指令字节数（如 +2 或 +4） |
| 变长指令字 + 按字节编址 | +本条指令的实际字节数（需先解析操作码确定） |

### 跳跃寻址——转移指令修改 PC
- **JMP 指令**：无条件将 PC 改为目标地址（类似 C 语言的 goto）
- **CALL 指令**：先将返回地址（PC 旧值）压栈，再将 PC 改为被调用函数的入口地址
- **条件转移指令**：根据标志位决定是否修改 PC（先执行 CMP 比较，再根据结果决定跳转）

### 关键时序
1. CPU 根据 PC 指向的地址，从主存取出一条指令
2. **取指阶段结束**：PC 自动递增（指向"顺序的"下一条——但转移指令执行后这个值可能被覆盖）
3. **执行阶段**：若当前指令是转移指令 → 执行时将 PC 强制修改为目标地址
4. 执行结束后，CPU 根据 PC 新值取下一条指令

## 备注
- 408 易错点：相对寻址基于"下一条指令地址"偏移而非"当前指令地址"——因为取指后 PC 已自动递增
- PC 在 x86 中称为 IP（Instruction Pointer），做题时看到 IP 寄存器要知道它就是程序计数器
- "变长指令字结构下 CPU 无法预先判断指令长度"——必须至少读入第一个字（含操作码）才能确定
- 转移指令的本质 = 修改 PC 的值——不论条件/无条件/函数调用，最终都是改写 PC
