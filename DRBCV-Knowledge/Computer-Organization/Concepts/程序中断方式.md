# 程序中断方式

## 类型判定
程序型 — 描述 CPU 通过中断机制响应 IO 设备的 IO 控制方式，涵盖中断原理、中断隐指令、中断判优、中断屏蔽（多重中断）及中断处理完整流程，属于"过程"类概念。

## 类比 ★
**一句话比喻：** 像老板处理员工紧急报告——CPU 正常干活，外设干完活就拍桌子喊"老大我好了"（中断请求），老板暂停手头工作、记下做到哪了（保存断点）、去处理紧急事务（中断服务程序）、处理完回来接着干。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 中断请求信号 | 员工拍桌子喊"老板！" |
| 关中断 IF=0 / 开中断 IF=1 | 老板挂"请勿打扰"牌 / 取下牌子 |
| 中断判优（排队器） | 多个员工同时喊，老板助理按级别排序 |
| 中断屏蔽字 | 处理高级客户时，交代助理"别让其他部门的来找我" |
| 保护/恢复现场 | 记下当前文档做到第几页、摊开的参考资料位置 |

## 是什么
**程序中断方式**是利用中断系统实现的 IO 控制方式：CPU 启动外设后继续执行原程序，外设完成数据准备后向 CPU 发中断请求信号，CPU 在执行完当前指令后响应中断，通过**中断隐指令**（关中断→保存断点→引出中断服务程序）转入**中断服务程序**处理数据传送，处理完后返回原程序继续执行。相比程序查询方式，CPU 和外设可以**并行工作**。支持**单重中断**（ISR 执行期间不响应新中断）和**多重中断**（高优先级可打断低优先级 ISR），多重中断通过**中断屏蔽字**实现灵活优先级控制。

## 输入-输出空间
- **输入**：中断源发来的中断请求信号（通过 INTR 引脚）；中断类型号（通过数据总线）
- **输出**：PC 指向中断服务程序入口；中断处理完成后 PC 恢复原程序断点（K+1）
- **前置条件**：CPU 处于开中断状态（PSW 中 IF=1）；指令执行阶段末尾例行检查中断请求

## 正例（≥2 个）
1. **键盘敲击输入字符 A**：键盘将 A 放入 IO 接口数据缓冲寄存器 → IO 接口发中断请求 → CPU 执行完当前指令 K 后检测到中断 → 中断隐指令保存 PC=K+1 → 转入键盘 ISR → ISR 用 `in` 指令取走 A → 恢复现场 → 返回 K+1 继续执行原程序。整个过程 CPU 没有空转等待键盘。
2. **多重中断例题**：四个中断源 ABCD，硬件优先级 A>B>C>D，要求改造为 D>A>C>B。设置屏蔽字：D 屏蔽所有人（全 1），A 只不屏蔽 D（D 位 0 其余 1），C 屏蔽 B 和自己（B/C 位 1 其余 0），B 只屏蔽自己（B 位 1 其余 0）。5 μs 时 B 到达，执行 B 的 ISR；10 μs 时 D 到达，打断 B；30 μs 时 D 结束回 B；35 μs 时 A 到达，打断 B；55 μs 时 A 结束回 B；60 μs 时 C 到达，打断 B；80 μs 时 C 结束回 B；85 μs 时 B 全部完成。
3. **408 真题中断时间计算**：CPU 主频 50 MHz（时钟 20 ns），CPI=4。设备 D 准备字符需 0.5 ms（25000 周期），中断响应 10 周期，ISR 共 20 条指令（第 15 条启动下次 IO）。传送 1000 个字符：每字 = 25000+10+15×4=25070 周期，总计 25,070,000 周期。CPU 中断处理开销 = (10+20×4)×1000=90,000 周期。

## 反例/边界（≥1 个）
1. **scanf 型等待 ≠ 中断并行**：scanf 等键盘输入时 CPU 必须等待——这属于程序本身语义要求的同步等待，不是中断方式没实现并行。printf 输出到屏幕则不需要 CPU 等待，这才是中断方式的典型并行场景。
2. **非屏蔽中断打破"关中断"铁律**：关机掉电等 NMI 信号通过专门的 NMI 引脚传入，无论 IF 是否为 0 都必须响应——这是唯一能打破关中断保护的例外。
3. **中断向量 vs 向量地址混淆**：中断向量 = 函数指针（jump 指令，指向 ISR 入口）；向量地址（中断类型号）= 指针的指针（指向中断向量的存储地址）。两级指针是为了让 ISR 可以灵活修改而不需改动硬件电路。

## 详细解释
### 中断处理完整流程
```
指令周期末尾检测中断请求 → 中断隐指令 → 中断服务程序(ISR) → 返回原程序
```

### 中断隐指令（CPU 自动完成，非一条真实指令）
1. **关中断**（防止保存断点过程被新的中断打断，实现原子操作）
2. **保存断点**：将 PC 当前值（K+1）压入内核堆栈
3. **引出中断服务程序**：硬件向量法——排队器输出 → 向量地址形成部件 → 中断类型号 → 查主存中对应中断向量（jump 指令）→ PC 指向 ISR 入口

### 中断判优
- **硬件排队器**：左边优先级最高，连锁与非门电路保证多个中断同时到达时只输出优先级最高的那个
- **软件查询**：按优先级顺序逐位检查中断请求寄存器，慢于硬件
- **优先级设计原则**（从高到低）：①硬件故障（掉电）②非屏蔽中断 ③DMA 请求 ④高速设备 ⑤输入设备 ⑥实时设备

### 中断服务程序（ISR）
1. **保护现场**：将原程序的寄存器值压入栈（ACC、通用寄存器等）+ 保存屏蔽字
2. **开中断**（仅多重中断需要——放在保护现场之后，允许更高优先级中断打断）
3. **中断服务主体**：处理具体 IO 事务（取数据/发数据/发启动下个 IO 的命令）
4. **关中断**（仅多重中断——恢复现场前关中断，保证恢复原子性）
5. **恢复现场**：弹栈恢复寄存器值 + 恢复屏蔽字
6. **开中断** → 返回原程序（弹栈恢复 PC=K+1）

### 单重 vs 多重中断的区别
| | 单重中断 | 多重中断 |
|---|---|---|
| 开中断时机 | ISR 全部结束后 | 保护现场后立即开 |
| 关中断时机 | 中断隐指令开始 | 恢复现场前再关一次 |
| ISR 可被中断？ | 否 | 是（仅更高优先级） |

### 中断屏蔽字
- 每个中断源配一个屏蔽字，bit=1 表示屏蔽对应中断源
- 至少屏蔽自身（自己的 bit 必须为 1，防止自己中断自己）
- 通过设置屏蔽字可灵活改变中断处理次序，打破固定硬件优先级

## 备注
- 中断隐指令三步口诀：**关→存→引**（关中断、存断点、引服务程序）
- ISR 六步口诀（多重中断）：**保→开→干→关→复→开→回**（保护、开中断、干事、关中断、恢复、开中断、返回）
- 408 常考：给主频+CPI+中断响应周期数，算传送 N 个字符的总时钟数——先算单次，注意区分准备时间（外设做）和中断处理时间（CPU 做）
- 易混淆：向量地址 ≠ 中断向量；DMA 请求 ≠ DMA 中断请求
