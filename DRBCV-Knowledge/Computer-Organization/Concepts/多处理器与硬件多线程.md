# 多处理器与硬件多线程

## 类型判定
构型 — 描述费林分类法（SISD/SIMD/MISD/MIMD）对并行计算机系统的顶层划分、MIMD 的两种子类型（共享存储多处理器 vs 多计算机）、向量处理器原理，以及三种硬件多线程实现（细粒度/粗粒度/同时多线程），属于并行体系结构基本概念。

## 类比 ★
**一句话比喻：** 像厨房后厨的分工模式——SISD 是只有一个厨师一口锅串行炒菜；SIMD 是一个厨师长同时指挥五位帮厨做同样的切菜动作（各切各的案板）；MIMD 是五个独立厨师各做各的菜互不干扰。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| SISD（单指令流单数据流） | 单人单灶，一次炒一盘菜——G组一直在学的单核 CPU |
| SIMD（单指令流多数据流） | 大厨吼一声"全给我切丝！"五个帮厨同时对自己案板上的不同食材做同一个动作 |
| MIMD 多处理器（共享存储） | 五个厨师共用一个大冰箱——你放进去的食材我直接取，通过冰箱传数据 |
| MIMD 多计算机（消息传递） | 五家独立餐厅——只能通过外卖小哥（网络消息）互相传菜 |

## 是什么
**费林分类法**按指令流/数据流的单/多将计算机分为四类。**SISD**（单指令单数据）即传统单核 CPU，指令只能并发不能并行，通过流水线提升效率。**SIMD**（单指令多数据）一个控制单元发出同一条指令，多个执行单元对各自局部存储器中的不同数据同时执行相同操作——数据级并行。**MISD** 纯理论，现实中不存在。**MIMD**（多指令多数据）多个核/处理器并行执行各自的指令流、处理各自的数据流，实现线程级或进程级并行。MIMD 又分为**共享存储多处理器系统**（各核共享一个物理主存和最低级 cache，通过 load/store 通信）和**多计算机系统**（各计算机独立主存，通过消息传递通信）。**向量处理器**是 SIMD 思想的进阶——一条指令直接操作一个 N 维向量，一次 load 取整条向量、一次 ADD 完成 N 对分量的并行加法。**硬件多线程**在处理器硬件上设置多套寄存器组（含 PC），使线程切换时无需保存/恢复寄存器上下文，用极低成本实现线程间快速切换；分为细粒度、粗粒度、同时多线程三种。

## 输入-输出空间
- **输入**：多道程序/多线程的指令序列（MIMD），或单一指令流 + 多份结构相同的数据（SIMD/向量处理器）
- **输出**：并行计算的结果（多核各自写回共享主存或通过消息传递汇总）
- **关键约束**：多处理器系统中各核通过 load/store 共享内存，需解决 cache 一致性；多计算机系统各机只访问私有内存，通信只能走网络消息；硬件多线程中线程间是否并行取决于实现方式

## 正例（≥2 个）
1. **SIMD 典型场景——图片加红色滤镜**：一张图片拆成三块，送入三个执行单元的局部存储器。控制单元发出一句"每条 RGB 的 R 分量 +50"，三个执行单元同时对各自块内所有像素并行执行，处理速度约为单核的 3 倍。
2. **MIMD 多处理器——Intel i7**：一个芯片内含多个核，共享一个主存和 L3 cache。每个核运行各自的线程，线程间可通过主存或 L3 cache 传递数据。你此刻用的手机/电脑就是 MIMD 共享存储多处理器系统。
3. **MIMD 多计算机——分布式集群**：三台独立服务器通过网络连接，各自有独立主存。大任务拆为三个子任务分发到三台机器，结果通过网络消息汇总——典型的 MapReduce 风格。

## 反例/边界（≥1 个）
1. **"SIMD 是线程级并行"**——错！SIMD 同一时刻只有一条指令在执行，属于**数据级并行**；说 SIMD 实现了线程级并行是经典张冠李戴（MIMD 才是线程级/进程级并行）。
2. **"多处理器系统中各处理器不能通过 load/store 访问对方存储器"**——错！这正是多处理器和多计算机的关键区别：多处理器共享主存，可通过 load/store 直接访问（对方的数据就在共享内存里）；多计算机才不能直接访问对方主存。
3. **"细粒度多线程实现了线程级并行"**——错！细粒度和粗粒度多线程的同一时钟周期内只有**一个线程**的指令在发射，线程间不并行（只有指令间可能并行）；只有**同时多线程 SMT** 才同时实现了指令级和线程级并行。

## 详细解释
### 费林分类法速查表
| 分类 | 指令流 | 数据流 | 并行级别 | 现实例子 |
|------|--------|--------|----------|----------|
| SISD | 单 | 单 | 无数据级并行（可加流水线） | 传统单核 CPU |
| SIMD | 单 | 多 | 数据级并行 | GPU 着色器、向量处理器 |
| MISD | 多 | 单 | —（理论上不实用） | 不存在 |
| MIMD | 多 | 多 | 线程级/进程级并行 | 多核 CPU、多计算机集群 |

### MIMD 的两种子类型
| 特性 | 共享存储多处理器 | 多计算机 |
|------|-----------------|---------|
| 物理主存 | 一个，各核共享 | 每个计算机私有 |
| 地址空间 | 共享同一物理地址空间 | 相互独立 |
| 通信方式 | load/store 指令通过主存/cache | 消息传递（网络） |
| 别称 | 多核处理器 / CMP（片级多处理器） | 消息传递系统 |
| 典型产品 | Intel i5/i7、手机 SoC | 分布式计算集群 |

### 向量处理器（SIMD 进阶）
- 一条 load 指令取整个 N 维向量到向量寄存器；一条 ADD 指令一次完成 N 对分量并行加法。
- 相比标量处理器（N 次加法），向量处理器只需 1 次——数据级并行的极端体现。
- 需要多端口主存支持多个向量处理器同时读写、大容量集中式主存（主存容量限制解题规模）。

### 三种硬件多线程
| 特性 | 细粒度多线程 | 粗粒度多线程 | 同时多线程（SMT） |
|------|------------|------------|------------------|
| 切换频率 | 每个时钟周期切换 | 仅流水线阻塞时切换（如 cache miss） | 每周期发射多个线程的指令 |
| 线程切换代价 | 低 | 高（须重载流水线） | 教材未详述 |
| 指令级并行 | ✓（同一线程多指令用不同功能部件） | ✓ | ✓ |
| 线程级并行 | ✗（同一时刻仅一个线程） | ✗ | ✓（同一时刻多个线程） |
| 核心特点 | "轮流坐庄"，每秒切换十亿次 | "不出事不换人" | "多线程同时上场" |

- 硬件多线程的本质：处理器内设多套寄存器组 + PC，每个线程一套。线程切换时直接切换寄存器组指针，不需要保存/恢复上下文到主存——这是硬件多线程比传统线程切换快的根本原因。

- 向量处理器=「一次 load 拉一车，一次 ADD 算一车」，本质是 SIMD 的硬件极致实现
