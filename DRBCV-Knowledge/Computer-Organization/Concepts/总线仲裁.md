# 总线仲裁

## 类型判定
判别型 — 回答"多个主设备同时申请总线控制权时，如何决定将总线分配给谁"，属于资源调度/硬件判优类概念。

## 类比 ★
**一句话比喻：** 像一群小孩抢一台 Game Boy 游戏机——**集中仲裁**是大哥说了算（大哥挨个问或是谁打电话就给谁），**分布仲裁**是小孩们自己亮拳头比大小，谁的仲裁号（拳头）大谁先玩。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 链式查询 | 大哥从 0 号小孩一路往后问"你玩不玩"，先问到的优先——1 号小孩是大哥亲弟弟，他若半路截胡，后面全没戏 |
| 计数器定时查询 | 大哥拿计数器从 0 开始数，数到谁就是谁——可以每次从 0 开始（固定优先级），也可以从上一次停的位置继续（公平轮转） |
| 独立请求 | 每个小孩都有大哥的微信，谁想玩直接私信大哥——大哥的排队器（手机消息列表）决定先回谁 |
| 分布仲裁 | 没大哥——三个小孩同时亮出自己的"战斗力数值"，战斗力低的主动放弃 |

## 是什么
总线仲裁解决**多个主设备同时争用总线控制权**的问题。由于总线同一时刻只能由一个主设备控制（其他设备只能接收），必须有判决机制。仲裁分两大类：**集中仲裁**（有一个总线控制器统一判优）和**分布仲裁**（各设备自带仲裁器，自行竞争）。集中仲裁又分三种：链式查询、计数器定时查询、独立请求。

## 输入-输出空间
- **输入**：各主设备通过 BR（总线请求）信号线向控制器发出请求
- **输出**：控制器通过 BG（总线允许）信号线将控制权分配给某个设备；获得控制权的设备通过 BS（总线忙）信号线通知"我已占用"
- **核心部件**：总线控制器（通常集成在 CPU 或桥接器内），内部含仲裁逻辑/排队器

## 正例（≥2 个）
1. **链式查询：设备 1 和设备 N 同时请求**：两者都向 BR 线发请求信号 → 控制器在 BG 线上发出允许信号 → 信号链式经过设备 0（不用，放行）→ 到设备 1（它在等，截断！）→ 设备 1 向 BS 线发"总线忙"，开始传数据。可怜的设备 N：BG 信号在半路被截胡了，永远等不到。
2. **独立请求：设备 N 抢先获得**：设备 0 和设备 N 同时通过各自的 BR 线发请求 → 控制器内部排队器判定设备 N 优先级更高 → 直接通过设备 N 专属的 BG 线发允许信号 → 无需逐个传递，响应最快。

## 反例/边界（≥1 个）
1. **链式查询的致命弱点：硬件故障敏感**。如果设备 1 损坏（无法传递 BG 信号），则设备 2 到设备 N 全部"断后"——永远得不到总线控制权。一根线上一环出问题，后面全废。
2. **"总线忙信号由控制器发出"是错的**：BS（总线忙）信号由**获得总线控制权的设备**发出，通知控制器"我还在用"。控制器检测到 BS 撤销后，才启动下一轮仲裁。

## 详细解释
### 三种集中仲裁方式对比（核心考点）
| 维度 | 链式查询 | 计数器定时查询 | 独立请求 |
|------|---------|--------------|---------|
| 控制线数 | **3 根**（BR + BG + BS） | log₂N + 2 根（BR + BS + 设备地址线） | **2N + 1 根**（N×BR + N×BG + BS） |
| 优先级 | **固定**（越近控制器越高） | 可编程控制（灵活） | 排队器灵活设置 |
| 响应速度 | 慢（链式传递） | 慢（逐个数过去） | **快**（直接发 BG 给目标设备） |
| 电路故障敏感度 | **高**（一环坏全链废） | 较低 | 低 |
| 是否产生饥饿 | 是（高优先级一直占） | 可避免（用轮转计数） | 取决于排队器策略 |

### 分布仲裁
- 无中央仲裁器，每个主设备自带仲裁器和唯一仲裁号
- 当多个设备想用总线时，各自把仲裁号发到共享仲裁总线上
- 各设备比较：自己的仲裁号 vs 总线上的仲裁号 → 若自己的优先级更低，自动撤销
- 最终**最高优先级的仲裁号保留**在总线上，该设备获得控制权
