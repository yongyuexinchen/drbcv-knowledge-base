# 计算机系统的工作原理

## 类型判定
程序型 — 描述一个 C 语言源程序经过预处理、编译、汇编、链接变成可执行文件，再调入主存由 CPU 逐条执行的完整流程，属于"过程"类概念。

## 类比 ★
**一句话比喻：** 像出版一本书——作者手稿（.c 源程序）→ 编辑润色去掉注释标记（预处理器）→ 翻译成外语初稿（编译器 → 汇编语言）→ 排版成印刷稿（汇编器 → 机器语言 .o）→ 装订目录附录（链接器 → .exe）→ 放进书店仓库（外存/硬盘）→ 读者借阅时搬到阅览室（调入主存）→ 读者逐页阅读（CPU 逐条执行）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 预处理器（展开 #define） | 编辑把"π"替换回"3.1415926"——恢复可读缩写为完整形式 |
| 编译器（C → 汇编） | 翻译成外文初稿（人类还能读的中间语言） |
| 汇编器（汇编 → 机器码） | 排版成印刷稿（机器可读的最终格式） |
| 链接器（.o → .exe） | 装订——把正文、目录、附录合并成一本完整的书 |

## 是什么
计算机系统的工作原理遵循**存储程序**方式：高级语言源程序经过**预处理器 → 编译器 → 汇编器 → 链接器**四步变成可执行文件存放在外存（硬盘）；运行时，可执行文件从外存**调入主存**，CPU 的 **PC（程序计数器）** 指向第一条指令地址，逐条执行——每条指令都经历**取指、分析、执行**三个阶段，PC 每取完一条指令自动 +1 指向下一条，直到程序结束。

## 输入-输出空间
- **输入**：高级语言源程序（.c / .java / .py 文件）
- **输出**：程序运行结果（通过输入/输出设备与用户交互）
- **转换链**：源程序(.c) → 预处理器 → 编译器 → 汇编语言(.s) → 汇编器 → 目标模块(.o) → 链接器 → 可执行文件(.exe) → 调入主存 → CPU 执行
- **前置条件**：翻译工具链（预处理器、编译器、汇编器、链接器）存在于系统中；操作系统提供加载和进程管理支持

## 正例（≥2 个）
1. **Hello World 的完整旅程**：程序员写 hello.c → 预处理器展开 #include <stdio.h> 和 #define 宏 → 编译器将 C 代码翻译为汇编语言 → 汇编器将汇编翻译为机器语言目标模块 hello.o → 链接器将 hello.o 与 printf 对应的标准库目标模块链接，生成 hello.exe 可执行文件 → 双击运行时，hello.exe 从硬盘调入内存 → CPU 从 main 第一条指令开始逐条执行。
2. **Y = A × B + C 在主存中的样子**：经编译链接后，主存 0-4 号单元存放 5 条机器指令（取数、乘法、加法、存数、停机），5-8 号单元存放变量 A/B/C/Y 的值。CPU 从 PC=0 开始，逐条取指→分析→执行，每次 PC+1，最终 Y=7。整个过程中指令和数据以同等地位、二进制形式共处主存，靠"取指阶段 vs 执行阶段"的时间差异区分指令和数据。

## 反例/边界（≥1 个）
1. **"可执行文件可以直接从外存执行"是错的**：硬盘（外存/辅存）属于 I/O 设备，CPU **不能直接**访问外存中的程序。任何程序启动时，操作系统必须先把可执行文件从外存**调入主存**，然后 CPU 才能逐条执行——这也是为什么打开 APP 需要等待 2-3 秒（把程序从机身存储读进运行内存）。
2. **"所有语言都走编译+汇编+链接"不完整**：Python、JavaScript 等解释型语言没有独立的编译链接阶段，而是由解释器边翻译边执行——但它们最终仍需要把语句翻译为机器指令才能被 CPU 执行。

## 详细解释
### 从源程序到可执行文件的四步转换
| 步骤 | 工具 | 输入 | 输出 | 做了什么 |
|------|------|------|------|---------|
| 1. 预处理 | 预处理器 | 源程序 .c | 展开后的源程序 | 处理 #define 宏替换、#include 头文件展开、去掉注释 |
| 2. 编译 | 编译器 | 展开后的源程序 | 汇编语言程序 .s | 将高级语言翻译为等价的汇编语言 |
| 3. 汇编 | 汇编器 | 汇编语言程序 .s | 目标模块 .o | 将汇编指令翻译为机器语言（01 二进制） |
| 4. 链接 | 链接器 | 多个 .o 目标模块 | 可执行文件 .exe | 将主程序目标模块与库函数目标模块合并，解决符号引用 |

### 程序执行时的宏观流程
1. 可执行文件存放在**外存**（硬盘，属于 I/O 设备）
2. 用户启动程序 → 操作系统将可执行文件**调入主存**（内存）
3. CPU 的 **PC** 指向第一条指令的主存地址
4. **循环**：取指（PC→MAR→主存→MDR→IR，PC+1）→ 分析（CU 译码）→ 执行（CU 指挥各部件完成操作）→ 指向下一条指令
5. 遇到停机指令或程序结束，CPU 停止执行
6. 执行过程中可通过 I/O 设备（键盘/鼠标/显示器）与用户交互

### 存储程序工作方式的核心要点
- 指令和数据以二进制形式、同等地位存放在主存中
- 每条指令/每个数据都有唯一的主存地址（按地址寻访）
- CPU 通过"当前处于取指阶段还是执行阶段"来区分读出的二进制串是指令还是数据
- PC 自动加一保证了程序的顺序执行（除非遇到转移指令修改 PC）

## 备注
- 408 考点常考：编译器、汇编器、链接器各自的作用和中间产物——预处理器（处理#开头的命令）、编译器（C→汇编）、汇编器（汇编→机器码 .o）、链接器（.o+.o→.exe）
- "调入主存"是关键动作：CPU 不能直接执行外存中的程序——辅存数据必须先入主存（这也是存储层次结构的设计依据）
- 目标模块（.o 文件）是汇编器的输出、链接器的输入——它是一个"半成品"，缺少库函数等外部引用的实现
- 区分三种"翻译"：编译（高级→汇编或机器）、汇编（汇编→机器）、解释（边翻译边执行），三者统称翻译程序
