# ISP 封锁（运营商级 IP 封锁）

## 类型判定
判别 — 互联网服务提供商（ISP）在路由层面对特定 IP 地址或 IP 段的 TCP/UDP 流量进行阻断，导致客户端无法与目标服务器建立连接。是中国大陆网络环境中自建 VPS 代理最常见的障碍。

## 类比 ★
### 一句话比喻
RackNerd 的 IP 地址 = 一座被当地城管（ISP）列入黑名单的仓库。你从笔记本（另一个城市的快递公司）打电话过去，仓库秒接——因为两个城市的城管名单不一样。你从家里电脑（被封锁城市）打过去，电话永远占线——城管在交换局就掐断了。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| VPS IP `192.255.128.175` | 被列入城管黑名单的仓库地址 |
| 笔记本 ISP (中国电信广东) | 没接到封锁令的快递公司 |
| 家里电脑 ISP (中国联通/移动) | 严格执法——直接掐断通信 |
| Cloudflare Tunnel 绕行 | 从仓库挖地道到商场门口——城管管不着地下通道 |

## 是什么
ISP 级封锁发生在网络层（比 DNS 污染更深一层）：运营商在路由器上配置了黑名单规则，对发往特定 IP 的 TCP SYN 包直接丢弃。ICMP ping 可能仍能通（因为 ping 走的是独立控制平面），但 TCP 连接建立永远超时。

## 正例
1. **家里电脑 ping VPS 通但 TCP 不通**：`ping 192.255.128.175` 返回 174ms 延迟，但 `telnet 192.255.128.175 443` 超时。这就是运营商级别的 TCP 封锁——ICMP 和 TCP 在路由器上分别处理。
2. **中间人/机场代理仍可用**：家里电脑通过第三方机场（中国境内的中继服务器）→ VPS，TCP 不被拦——因为目的地 IP 是中国境内服务器。

## 反例/边界
1. **不是 DNS 污染**：DNS 污染发生在域名解析层，结果是返回假 IP。ISP 封锁是路由层——即使你知道正确的 IP，数据包也发不出去。
2. **不是所有运营商都封**：同一 VPS IP，笔记本 ISP 不封，家里 ISP 封——不同运营商的封锁策略和 IP 段黑名单不同。
3. **封锁粒度是 IP 段，不是单个 IP**：RackNerd 洛杉矶机房的整个 C 段可能都被封了，换单个 IP 有概率仍被封。

## 详细解释
ISP 封锁的层级（从浅到深）：
```
1. DNS 污染 → 域名层面，换 DNS 或 DoH 可解
2. SNI 阻断 → TLS 握手层面，伪装 SNI 可解  
3. IP 封锁 → 路由层面，只能换 IP 或用隧道绕过
4. 协议封锁 → 深度包检测 DPI，连协议特征都拦截
5. 端口封锁 → 特定端口全封（如 443、22 的某些地区）
```

Cloudflare Tunnel 解决的是第 3 层——因为连接是 VPS 主动发起的（出站），运营商只看到去 Cloudflare 的流量，看不到最终目的地。
