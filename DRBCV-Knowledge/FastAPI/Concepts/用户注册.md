# 用户注册

## 类型判定
procedure — 四步标准流程：检查用户名唯一性 → 密码加密 → 写入数据库 → 返回结果。

## 类比 ★
### 一句话比喻
用户注册就像银行开户——你填好申请表（用户名+密码），柜员先查系统里有没有重名（唯一性校验），审核通过后把信息录入系统（写入数据库），最后给你一张银行卡（返回Token）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 用户名唯一性校验 | 银行查身份证号是否已开户——同名就重复 |
| bcrypt 密码加密 | 银行金库的保险柜——密码存的是密文，柜员也不知道你真正的密码 |
| 请求体参数（Pydantic） | 银行开户表单——按要求填姓名、密码，格式不对当场退回 |
| HTTPException(400) | 柜员说"先生您已经开过户了"——用户名重复就拒绝 |
| db.refresh(user) | 柜员录入后核对一遍电脑屏幕——确认数据已写入 |

## 是什么
用户注册是用户模块的第一个接口（POST `/api/user/register`），接收用户名和密码，检查用户名是否已存在，通过 bcrypt 加密密码后写入 `user` 表，完成注册。

## 输入-输出空间（程序型必填）
- **输入**：`username: str`（用户名）、`password: str`（明文密码），通过 Pydantic 模型 `UserRequest` 校验
- **输出**：`{"code": 200, "message": "注册成功", "data": {"token": "...", "userInfo": {...}}}`
- **前置条件**：已配置 ORM（数据库会话依赖项 `get_db`）、已定义 `User` 模型类

## 核心代码 + 步骤表
```python
# ===== schemas/users.py：定义请求体参数模型 =====
from pydantic import BaseModel

class UserRequest(BaseModel):
    username: str
    password: str

# ===== utils/security.py：密码加密工具 =====
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def get_hash_password(plain_password: str) -> str:
    return pwd_context.hash(plain_password)

# ===== CRUD/users.py：封装注册逻辑 =====
from sqlalchemy import select
from models.users import User

# ① 根据用户名查询用户（检查唯一性）
async def get_user_by_username(db: AsyncSession, username: str):
    stmt = select(User).where(User.username == username)
    result = await db.execute(stmt)
    return result.scalar_one_or_none()   # 有则返回User，无则None

# ② 创建用户
async def create_user(db: AsyncSession, user_data: UserRequest):
    # 密码加密
    hashed_pwd = get_hash_password(user_data.password)
    # 创建ORM对象
    user = User(username=user_data.username, password=hashed_pwd)
    db.add(user)
    await db.commit()
    await db.refresh(user)   # 从数据库读回最新数据
    return user

# ===== routers/users.py：路由调用 =====
@router.post("/register")
async def register(
    user_data: UserRequest,
    db: AsyncSession = Depends(get_db)
):
    # ① 检查用户名是否已存在
    existing_user = await users_crud.get_user_by_username(db, user_data.username)
    if existing_user:
        raise HTTPException(status_code=400, detail="用户已经存在")

    # ② 创建用户
    user = await users_crud.create_user(db, user_data)

    # ③ 生成Token（见"Token生成"卡片）
    token = await users_crud.create_token(db, user.id)

    # ④ 响应结果
    return success_response(message="注册成功", data=...)
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 定义请求体模型 | `class UserRequest(BaseModel)` | Pydantic 校验 username/password |
| ② 密码加密 | `pwd_context.hash(plain_password)` | bcrypt 哈希加密，不存明文 |
| ③ 检查唯一性 | `get_user_by_username()` → `scalar_one_or_none()` | 查库判重，存在则抛 400 |
| ④ 创建用户 | `User(...)` → `db.add()` → `commit()` → `refresh()` | ORM 新增，refresh 确保读回最新数据 |
| ⑤ 生成 Token | `create_token()` | 注册即登录，返回访问令牌 |
| ⑥ 响应结果 | `success_response(...)` | 统一格式返回 |

## 正例（≥2 个）
1. **首次注册**：用户"大秋"输入密码 123456 → 查库无此用户 → bcrypt 加密后写入 → 数据库中存的是 `$2b$...` 密文 → 返回 token + 用户信息。
2. **手机号注册**：修改为按手机号查重——只需把 `get_user_by_username` 换成 `get_user_by_phone`，其余逻辑完全不变。
3. **密码安全**：用户输入 123456，数据库存的是 bcrypt 哈希值——即使数据库泄露，攻击者也解不出原始密码。

## 反例/边界（≥1 个）
1. **重复注册**：用户"大秋"已存在，再次以"大秋"注册 → `existing_user` 不为 None → raise HTTPException(400)，返回"用户已经存在"。
2. **密码未加密直接入库**：`user = User(username=username, password="123456")` → 数据库存明文，安全灾难。必须先用 `get_hash_password()` 加密。
3. **忘记 refresh**：`db.add(user)` 后直接 `return user`，但 user 对象可能缺少数据库自动生成的字段（如 created_at） → 用 `db.refresh(user)` 确保读回完整数据。

## 详细解释
**注册流程的核心逻辑链**：
1. Pydantic 校验 → 确保 username 和 password 类型正确、非空
2. 唯一性查询 → `scalar_one_or_none()`：有用户则抛异常，无用户则 None（不抛异常）
3. bcrypt 加密 → `passlib` 的 `CryptContext(schemes=["bcrypt"])`：bcrypt 自带盐值（salt），每次加密结果不同
4. ORM 写入 → `db.add() → commit() → refresh()`：add 标记、commit 提交、refresh 读回
5. 返回 Token → 注册即登录，用户体验好（不用注册完再手动登录）

**bcrypt vs 直接哈希**：bcrypt 是专门为密码设计的哈希算法，特点是慢（故意慢，防暴力破解），且每次哈希自动生成随机盐值——同一密码两次 hash 结果不同。
