# 添加浏览历史

## 类型判定
procedure — POST 请求，用户查看新闻时自动记录浏览历史：首次浏览则新增，已浏览过则更新浏览时间，实现"去重 + 更新时间"逻辑。

## 类比 ★
### 一句话比喻
添加浏览历史就像图书馆的借阅登记本——每次有人翻看一本书，管理员就在登记本上记录。如果这个人是第一次借这本书，就新开一行（insert）；如果以前借过，就把原来的日期擦掉，写上今天的日期（update）。登记本永远一人一书只占一行。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 先查后决定 insert 或 update | 管理员先翻登记本："大邱借过这本书吗？" |
| 没借过 → insert 新记录 | "没借过" → 新开一行：大邱，新闻1，2025-01-15 |
| 借过 → update 浏览时间 | "借过了" → 擦掉旧日期，写上今天 |
| 一人一书只保留一条 | 登记本不会出现"大邱借了新闻1两次" |
| 浏览时间是最近一次 | 记录永远反映"最后一次翻看"的时间 |

## 是什么
添加浏览历史接口（POST `/api/history/add`）在用户进入新闻详情页时自动调用。核心逻辑：先查询 history 表中当前用户是否已浏览过该新闻。如果没浏览过 → `db.add()` 新增一条记录；如果浏览过 → `UPDATE view_time = NOW()` 更新浏览时间。实现一人一书只保留一条最新浏览记录的效果。

## 输入-输出空间（程序型必填）
- **输入**：news_id: int（请求体参数）、user（Depends 注入）、db（Depends 注入）
- **输出**：浏览历史 ORM 对象（含 id、user_id、news_id、view_time）
- **前置条件**：用户已登录、History 模型类已定义

## 核心代码 + 步骤表
```python
# ===== CRUD/history.py =====
async def add_history(db: AsyncSession, user_id: int, news_id: int):
    # ① 先查——有没有浏览过这条新闻
    stmt = select(History).where(
        History.user_id == user_id,
        History.news_id == news_id
    )
    result = await db.execute(stmt)
    record = result.scalar_one_or_none()

    if record:
        # ② 浏览过 → 更新浏览时间
        record.view_time = datetime.now()
    else:
        # ③ 没浏览过 → 新增记录
        record = History(user_id=user_id, news_id=news_id)

    db.add(record)        # add 对 update 也适用（merge 语义）
    await db.commit()
    await db.refresh(record)
    return record
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 先查是否存在 | `select(History).where(user_id=..., news_id=...)` | 双条件查询 |
| ② 存在 → 更新时间 | `record.view_time = datetime.now()` | 修改字段值 |
| ③ 不存在 → 新建对象 | `History(user_id=..., news_id=...)` | 构造新 ORM 对象 |
| ④ add + commit | `db.add(record)` + `await db.commit()` | add 对新对象是 insert，对已有对象是 update |
| ⑤ refresh | `await db.refresh(record)` | 拿到最新的 view_time |

## 正例（≥2 个）
1. **首次浏览**：大邱第一次打开新闻5的详情页 → 查询 history 表无记录 → insert 一条（user_id=22, news_id=5, view_time=now）→ 浏览历史表新增一行。
2. **再次浏览**：大邱第二天又打开新闻5 → 查询到已有记录 → `view_time = datetime.now()` 更新为今天的时间 → 表中的浏览时间刷新，但记录数不变。
3. **浏览+收藏独立性**：用户浏览新闻不一定要收藏，收藏也不一定正在浏览——history 和 favorite 是两张独立的表，互不影响。

## 反例/边界（≥1 个）
1. **不查直接 insert**：每次浏览都 insert 新记录 → history 表出现同一用户同一新闻的多条记录 → 获取浏览历史列表时同一条新闻重复出现，数据冗余。
2. **用 scalar_one 而非 scalar_one_or_none**：首次浏览查不到记录 → scalar_one 抛 `NoResultFound` 异常 → 程序崩溃，本该走新增逻辑的却报错了。
3. **add 后不 refresh**：新增记录后 return 时 view_time 可能是 None（Python 默认值），前端拿不到浏览时间。

## 详细解释
**先查后写的模式（Upsert）**：添加浏览历史的本质是"Upsert"（Update or Insert）——存在则更新，不存在则插入。SQLAlchemy 中简单的 upsert 就是：先 `scalar_one_or_none()` 查，然后判断走 add 还是改字段值，最后统一 commit。

**与添加收藏的区别**：
| | 添加收藏 | 添加浏览历史 |
|---|---|---|
| 数据库层 | UniqueConstraint 阻止重复 | 无唯一约束（允许重复 insert） |
| 防重复策略 | 数据库层报 IntegrityError | 代码层先查后写 |
| 重复行为 | 报错（不允许） | 更新时间（允许，语义不同） |
