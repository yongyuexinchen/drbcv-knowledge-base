# 头条项目架构

## 类型判定
discriminant — 定义 AI 掘金头条项目的整体架构、技术栈、目录结构和功能模块划分。

## 类比 ★
### 一句话比喻
头条项目架构就像一栋大楼的施工图纸——每层楼放什么、管道怎么走、各个部门在哪儿办公，全都提前规划好。有了图纸，施工队（开发者）各司其职，不会把水管接到电线上。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| project 根目录下的各文件夹 | 大楼里的不同楼层——每层有专属功能 |
| CRUD 文件夹 | 仓库区——只管存取货（数据库操作） |
| routers 文件夹 | 前台接待区——每个窗口处理不同业务 |
| schemas 文件夹 | 质检部——所有进出的数据都要验格式 |
| utils 文件夹 | 公共工具间——通用工具全楼共享 |
| models 文件夹 | 档案室——记录数据库表的图纸 |
| config 文件夹 | 配电房——数据库、缓存等基础设施配置 |
| main.py | 大楼总控室——整合所有模块，统一调度 |

## 是什么
AI 掘金头条项目是一个仿今日头条的新闻资讯类后端 API 服务。采用 FastAPI + MySQL + SQLAlchemy(异步 ORM) 技术栈，前后端分离架构（前端 Vue + 后端 FastAPI）。核心功能包括新闻模块（分类、列表、详情）、用户模块（注册、登录、个人信息）、收藏模块、浏览历史模块、缓存系统（Redis）和 AI 问答。

## 正例（≥2 个）
1. **前后端分离项目**：前端 Vue 运行在 localhost:5173，后端 FastAPI 运行在 127.0.0.1:8000，通过 RESTful API 交互——目录拆分后前端只需关注接口文档即可并行开发。
2. **模块化扩展**：后续新增"评论模块"只需在 routers/ 下新建 comment.py、在 CRUD/ 下封装评论方法、在 models/ 下定义评论模型类——对新闻和用户模块零影响。
3. **团队协作**：两人开发，一人管新闻模块，一人管用户模块——各自在对应文件夹写代码，互不冲突。

## 反例/边界（≥1 个）
1. **所有代码堆在一个 main.py**：项目初期功能少还能应付，但一旦功能增多（10+ 接口），单文件上千行代码，找 bug 如同大海捞针，改一处可能影响全局。
2. **目录拆分过细**：每个小功能都建一个文件夹导致目录层级过深（5 层以上），反而增加理解成本——按模块拆分即可，不要过度工程化。

## 详细解释
头条项目按照软件功能拆分为 6 个核心目录：

| 目录 | 职责 | 存放内容 |
|------|------|---------|
| CRUD/ | 数据库增删改查 | 按模块拆分文件（news.py, user.py） |
| models/ | ORM 模型类 | 数据库表对应的模型类定义 |
| routers/ | 模块化路由 | 按模块拆分路由文件（news.py, users.py） |
| schemas/ | 数据校验模型 | Pydantic 类型，用于请求参数校验和响应格式化 |
| utils/ | 工具函数 | 密码加密(security.py)、用户认证(auth.py)、全局异常处理器 |
| config/ | 配置 | 数据库配置(db_config.py)、缓存配置 |

项目物料包含：后端设计说明文档、API 接口规范文档（Markdown，含所有接口的路径/方法/参数/响应示例）、SQL 文件（含预置新闻数据）、前端 Vue 项目代码。
