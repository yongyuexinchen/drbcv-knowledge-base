# 获取收藏列表

## 类型判定
procedure — GET 分页查询，联表查询（news JOIN favorite）+ 聚合统计总量 + has_more 判断，三份数据构造统一响应。

## 类比 ★
### 一句话比喻
获取收藏列表就像翻开"我的书架"目录——书架上有你收藏的所有书（新闻），每本书旁边贴着收藏日期标签。你按收藏时间从新到旧排列（order by DESC），一次只看一页（分页），目录末尾标注"还有 N 本没显示"（has_more）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| news JOIN favorite 联表查询 | 把"书库"和"书架目录"两张表合并——看到每本书 + 标签 |
| func.count 统计总量 | 快速数一下书架上总共有多少本收藏的书 |
| order_by(create_at.desc()) | 最近收藏的书放最上面——新书优先 |
| has_more = total > offset+len | 目录底部"下接第X页"——提醒你还没看完 |
| label("favorite_time") | 给标签上的日期重命名——区分"出版日期"和"收藏日期" |

## 是什么
获取收藏列表接口（GET `/api/favorite/list?page=1&pageSize=10`）分页返回当前用户收藏的新闻列表。核心逻辑：① `func.count` 统计该用户收藏总量；② `select(News).join(Favorite, ...)` 联表查询新闻 + 收藏信息，按收藏时间降序、分页；③ 路由层计算 `has_more`；④ 将 ORM 结果（元组）转为列表套字典，通过 Pydantic Schema 构造统一响应。

## 输入-输出空间（程序型必填）
- **输入**：page: int(默认1, ≥1)、page_size: int(默认10, ≤100，别名 pageSize)、user（Depends 注入）、db（Depends 注入）
- **输出**：`{"code": 200, "data": {"list": [...], "total": 5, "has_more": false}}`
- **前置条件**：用户已登录、News 和 Favorite 模型类已定义、News 基础 Schema 已定义（复用）

## 核心代码 + 步骤表
```python
# ===== CRUD/favorite.py =====
async def get_favorite_list(db: AsyncSession, user_id: int, page: int, page_size: int):
    # ① 统计总量
    count_stmt = select(func.count(Favorite.id)).where(Favorite.user_id == user_id)
    total = (await db.execute(count_stmt)).scalar_one()

    # ② 联表查询（news JOIN favorite）
    offset = (page - 1) * page_size
    list_stmt = (
        select(News,
               Favorite.create_at.label("favorite_time"),
               Favorite.id.label("favorite_id"))
        .join(Favorite, Favorite.news_id == News.id)
        .where(Favorite.user_id == user_id)
        .order_by(Favorite.create_at.desc())
        .offset(offset)
        .limit(page_size)
    )
    result = await db.execute(list_stmt)
    rows = result.all()
    return rows, total   # 返回元组列表和总量
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 统计总量 | `select(func.count(Favorite.id)).where(...)` | 聚合查询该用户收藏总数 |
| ② 联表查询 | `select(News).join(Favorite, ...)` | 主体查 News，联合 Favorite，条件是 news_id 相等 |
| ③ 字段别名 | `.label("favorite_time")` | 两个表都有 create_at，用 label 区分收藏时间 |
| ④ 排序分页 | `order_by(...).offset(...).limit(...)` | 按收藏时间降序 + 分页 |
| ⑤ 整合数据 | 列表推导式解包元组 | `{**news.__dict__, "favorite_time": ..., "favorite_id": ...}` |
| ⑥ 计算 has_more | `offset + len(list) < total` | 判断后面还有没有更多 |

## 正例（≥2 个）
1. **标准分页**：用户收藏了 15 条新闻，请求 `page=2, pageSize=5` → offset=5，返回第 6~10 条，total=15，has_more=true。
2. **最后一页**：15 条，`page=3, pageSize=5` → offset=10，返回第 11~15 条（5 条），total=15，`10+5 < 15` 不成立 → has_more=false。
3. **Schema 继承复用**：News 基础字段（id/title/image 等）定义在 `NewsItemBase` 中，`FavoriteNewsItem` 继承它并增加 `favorite_id` 和 `favorite_time`——浏览历史模块复用同一个 `NewsItemBase`。

## 反例/边界（≥1 个）
1. **忘记 label 导致字段歧义**：News 和 Favorite 都有 `id` 和 `create_at`，如果不加 `.label()`，SQLAlchemy 返回时字段名冲突，拿到的可能是错误的值。
2. **联表条件写反**：`join(Favorite, News.id == Favorite.news_id)` 写成 `join(Favorite, News.id == Favorite.user_id)`——把新闻 ID 和用户 ID 连在一起，查出的结果完全错误。
3. **ORM 结果不转换就直接返回**：联表查询返回的是元组 `(News对象, favorite_time, favorite_id)`，直接塞进 data 响应会序列化失败——必须用列表推导式拆解成字典。

## 详细解释
**联表查询（join）的本质**：`select(News).join(Favorite, ...)` 等价于 SQL 的 `SELECT * FROM news JOIN favorite ON ...`。select 括号里是查询主体（主表），join 括号里是连接表 + 连接条件。也可以反过来写 `select(Favorite).join(News, ...)`，结果类似但主体不同。

**字段别名（label）的两种写法**：
```python
# 方式一：在 select() 里指定具体字段
select(News, Favorite.create_at.label("favorite_time"), Favorite.id.label("favorite_id"))

# 方式二：在模型类字段上起别名（不推荐，因为会全局生效）
```

**has_more 的计算**：`offset + len(current_page) < total`。例：total=23，page=2，page_size=10 → offset=10，len=10 → 10+10=20 < 23 → has_more=true（第3页还有3条）。
