# 检查收藏状态

## 类型判定
procedure — GET 请求查询收藏表，判断当前用户是否收藏了某条新闻，返回布尔值驱动前端小星星变色。

## 类比 ★
### 一句话比喻
检查收藏状态就像翻一本书看有没有贴过"已读"标签——不需要把整本书拿出来，只需要看看标签在不在，有就是收藏了（橙色星星），没有就是没收藏（白色星星）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| GET /check?newsId=1 | 翻到第1页，看看标签在不在 |
| user_id + news_id 双条件查询 | "大邱" + "第1篇" 两个条件交叉定位 |
| is_favorite: true/false | 标签在 = 橙色星星 / 不在 = 白色星星 |
| scalar_one_or_none() | 标签可能贴过也可能没贴——允许空 |
| is not None → bool | 有标签 → true，没标签 → false |

## 是什么
检查收藏状态接口（GET `/api/favorite/check?newsId=xxx`）查询当前登录用户是否收藏了指定新闻。核心逻辑：在收藏表（favorite）中按 `user_id` 和 `news_id` 双条件查询，查到记录返回 `true`，查不到返回 `false`。前端根据布尔值决定新闻详情页的小星星是橙色（已收藏）还是白色（未收藏）。

## 输入-输出空间（程序型必填）
- **输入**：news_id: int（查询参数，驼峰别名 newsId），user（Depends 注入当前用户），db（Depends 注入数据库会话）
- **输出**：`{"code": 200, "data": {"is_favorite": true/false}}`
- **前置条件**：用户已登录（token 认证通过）、favorite 表已存在、News 和 Favorite 模型类已定义

## 核心代码 + 步骤表
```python
# ===== CRUD/favorite.py：封装查询方法 =====
async def is_news_favorite(db: AsyncSession, user_id: int, news_id: int):
    stmt = select(Favorite).where(
        Favorite.user_id == user_id,
        Favorite.news_id == news_id
    )
    result = await db.execute(stmt)
    record = result.scalar_one_or_none()   # 可能没有收藏
    return record is not None              # → bool

# ===== schemas/favorite.py：响应模型 =====
class FavoriteCheckResponse(BaseModel):
    is_favorite: bool = Field(alias="isFavorite")

# ===== routers/favorite.py：路由 =====
@router.get("/check")
async def check_favorite(
    news_id: int = Query(..., alias="newsId"),
    user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    is_favorited = await favorite_crud.is_news_favorite(db, user.id, news_id)
    return success_response(
        data=FavoriteCheckResponse(is_favorite=is_favorited)
    )
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 接收参数 | `news_id`, `user`, `db` | 新闻ID + 当前用户 + 数据库会话 |
| ② 双条件查询 | `select(Favorite).where(user_id=..., news_id=...)` | 精准定位某用户某新闻的收藏记录 |
| ③ 容错提取 | `scalar_one_or_none()` | 可能没收藏，用 one_or_none 而非 scalar_one |
| ④ 转布尔值 | `record is not None` | 有记录 → True，没记录 → False |
| ⑤ 构造响应 | `FavoriteCheckResponse(is_favorite=...)` | Schema 包装成 `{"isFavorite": true}` |

## 正例（≥2 个）
1. **已收藏场景**：大邱（user_id=22）收藏了新闻1，前端请求 `GET /check?newsId=1` → 查 favorite 表找到记录 → `is_favorite=true` → 小星星变橙色。
2. **未收藏场景**：大邱没有收藏新闻2，前端请求 `GET /check?newsId=2` → 查不到记录 → `is_favorite=false` → 小星星保持白色。
3. **登录态联动**：登录了大邱看新闻1是橙色星星；退出登录后接口直接抛 401，压根不给查。

## 反例/边界（≥1 个）
1. **误用 scalar_one()**：如果用了 `scalar_one()`，未收藏时查询返回 0 行会直接抛 `NoResultFound` 异常——必须用 `scalar_one_or_none()` 容忍"没有收藏"的情况。
2. **忘记别名**：接口文档要求返回 `isFavorite`（驼峰），如果 Python 直接 `return {"is_favorite": True}`，前端拿到的是 `is_favorite`（下划线），前端代码可能不认——需要在 Schema 里加 `Field(alias="isFavorite")`。
3. **直接用 is_favorited 赋值**：路由中 `is_favorited` 是裸布尔值，不能直接 `data=is_favorited`——data 要求是对象格式（含 `isFavorite` 属性），必须通过 Schema 构造。

## 详细解释
**为什么用 scalar_one_or_none 而不是 scalar_one？** 收藏状态是"可能有、可能没有"的查询。`scalar_one()` 要求结果必须恰好 1 行，0 行或多行都报错。`scalar_one_or_none()` 允许 0 行返回 None，正好映射到"没收藏"。

**测试技巧**：开发阶段还没有"添加收藏"接口时，可以手动在数据库 favorite 表插入一条记录（指定 user_id 和 news_id），然后用前端界面验证小星星颜色变化。
