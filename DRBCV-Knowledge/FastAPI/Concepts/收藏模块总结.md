# 收藏模块总结

## 类型判定
discriminant — 本章节两个新知识点（ORM 联表查询 + 唯一约束）的提炼，汇总收藏模块五个接口的共性与差异，不做单一操作流程。

## 类比 ★
### 一句话比喻
收藏模块就像图书馆的"个人借阅收藏系统"——你可以查看某本书有没有在自己书架上（检查收藏状态）、把书放上书架（添加收藏）、从书架取下来（取消收藏）、翻看自己的书架目录（获取收藏列表）、或者把整个书架清空（清空收藏列表）。背后的书架管理规则只有两条：一本书不能重复放（唯一约束）、看书架目录时要同时看到书的信息和上架时间（联表查询）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 收藏模块五个接口 | 书架管理五件套——查看/放入/取出/盘点/清空 |
| UniqueConstraint(user_id, news_id) | 一本书在一个人书架上只能有一本——不能重复收藏 |
| select(News).join(Favorite) | 盘点时把"书的信息卡"和"上架日期签"合在一起看 |
| label("favorite_time") | 给日期签加标题——"上架日期"而非"出版日期" |
| 模型类继承（NewsItemBase → FavoriteNewsItem） | 书的信息卡是通用的——借阅历史也用同一张卡 |

## 是什么
收藏模块包含五个接口：检查收藏状态、添加收藏、取消收藏、获取收藏列表、清空收藏列表，全部围绕 favorite 表展开。涉及两个新知识点：
1. **ORM 联表查询**（获取收藏列表）：`select(News).join(Favorite, ...)` 合并新闻数据和收藏数据
2. **唯一约束 UniqueConstraint**（模型类）：防止同一用户重复收藏同一条新闻

其他操作（检查/添加/取消/清空）复用已学的增删改查模式，无全新知识。

## 联表查询关键点
```python
# 联表查询三要素
select(News                     # ① 查询主体：新闻表
       Favorite.create_at.label("favorite_time"),  # ② 字段别名（区分同名）
       Favorite.id.label("favorite_id"))
.join(Favorite,                 # ③ join 表 + 连接条件
      Favorite.news_id == News.id)
.where(Favorite.user_id == user_id)
.order_by(Favorite.create_at.desc())
.offset(skip).limit(page_size)
```

## 唯一约束写法
```python
class Favorite(Base):
    __table_args__ = (
        UniqueConstraint("user_id", "news_id", name="uq_user_news"),
    )
    user_id = Column(Integer, ForeignKey("user.id"))
    news_id = Column(Integer, ForeignKey("news.id"))
```

## 接口开发通用流程
收藏模块的五个接口全部遵循统一的四步开发流程：
1. **模块化路由**：创建 `routers/favorite.py`，定义 `APIRouter(prefix="/api/favorite")`
2. **模型类**：`models/favorite.py` 定义 Favorite 模型类，映射数据库表
3. **CRUD 封装**：`crud/favorite.py` 封装增删改查方法
4. **路由调用**：在路由处理函数中调用 CRUD 方法 + 构造响应（Schema）

## 正例（≥2 个）
1. **联表查询避免 N+1**：获取收藏列表一次 join 查出新闻 + 收藏数据，而不是先查收藏再循环查新闻（N+1 问题）。
2. **唯一约束兜底**：即使代码里忘记判断重复收藏，数据库层的 UniqueConstraint 会抛 IntegrityError 阻止重复插入，不会产生脏数据。
3. **Schema 复用**：News 基础模型类（NewsItemBase）被收藏和后续的浏览历史共用，避免重复定义。

## 反例/边界（≥1 个）
1. **不用 join 而用循环查询**：先 `select(Favorite).where(user_id=...)` 得到 100 条收藏，再循环 100 次 `select(News).where(id=...)`——总共 101 次数据库查询，性能极差。
2. **唯一约束忘加**：去掉 UniqueConstraint，用户点两次收藏星星 → favorite 表出现两条 user_id=22, news_id=1 的记录 → 获取收藏列表时同一条新闻出现两次。
3. **字段别名遗漏**：两表都有 `create_at`，不加 label → SQLAlchemy 可能只保留一个，拿到的收藏时间实际是新闻的创建时间。
