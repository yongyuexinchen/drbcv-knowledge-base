# 接口实现流程（四步心法）

## 类型判定
procedure — FastAPI 开发任何接口都遵循的标准四步流程：模块化路由 → 定义模型类 → 封装 CRUD → 路由调用响应。

## 类比 ★
### 一句话比喻
接口实现流程就像餐厅出一道新菜——先决定放哪本菜单（路由），再画货架图纸（模型），然后写标准菜谱（CRUD），最后服务员接单上菜（路由调用响应）。四步缺一不可，顺序不能乱。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| `APIRouter(prefix, tags)` — 模块化路由 | 决定这道菜放「川菜」还是「粤菜」菜单——客人按章节点菜 |
| `class News(Base)` — ORM 模型类 | 画货架图纸——仓库按这个格式建一排货架（数据库表） |
| `async def get_news(db)` — CRUD 函数 | 写标准菜谱——厨师照做，10 个服务员都用同一本菜谱 |
| `@router.get()` 里调 CRUD — 路由调用 | 服务员接单 → 喊厨师做菜 → 端统一盘子（JSON）上桌 |

## 是什么
接口实现流程是 FastAPI 项目的**通用开发模式**。任何一个接口（查询列表、获取详情、用户注册、添加收藏……）都遵循同样的四步：① 在 `routers/` 里用 `APIRouter` 定义路由地址 ② 在 `models/` 里用 SQLAlchemy 定义数据库表对应的 ORM 类 ③ 在 `crud/` 里封装数据库操作函数 ④ 在路由函数里调 crud 函数并返回 JSON。这四步构成了 FastAPI 从接收请求到返回响应的完整链路。

## 输入-输出空间（程序型必填）
- **输入**：HTTP 请求（GET/POST/PUT/DELETE + URL + 参数/请求体）
- **输出**：JSON 响应 `{"code": 200, "message": "...", "data": ...}`
- **前置条件**：已配置 ORM（`get_db` 依赖项）、已定义 Pydantic 模型（schemas）、已创建路由模块

## 核心代码 + 步骤表
```python
# ===== 第 ① 步：模块化路由 → API 接口规范文档 =====
# routers/news.py
from fastapi import APIRouter

router = APIRouter(prefix="/api/news", tags=["news"])
# prefix：所有接口共享的前缀
# tags：在 Swagger 文档中归入同一分组

# ===== 第 ② 步：定义模型类 → 数据库表（数据库设计文档） =====
# models/news.py
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from sqlalchemy import Integer, String

class Base(DeclarativeBase):
    pass

class Category(Base):
    __tablename__ = "news_category"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(50))

# ===== 第 ③ 步：封装 CRUD → 数据库操作方法 =====
# crud/news.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from models.news import Category

async def get_categories(db: AsyncSession, skip: int, limit: int):
    stmt = select(Category).offset(skip).limit(limit)
    result = await db.execute(stmt)
    return result.scalars().all()

# ===== 第 ④ 步：路由调用 CRUD → 响应结果 =====
# routers/news.py（接第①步）
from config.db_conf import get_db

@router.get("/categories")
async def get_categories(skip: int = 0, limit: int = 100, db: AsyncSession = Depends(get_db)):
    categories = await news.get_categories(db, skip, limit)  # 调 CRUD
    return {
        "code": 200,
        "message": "获取新闻分类成功",
        "data": categories  # CRUD 返回的数据放盘子里端出去
    }
```

| 步骤 | 文件位置 | 参照依据 | 做什么 |
|------|---------|---------|--------|
| ① 模块化路由 | `routers/xxx.py` | API 接口规范文档 | `APIRouter(prefix, tags)` 定义地址和分组 |
| ② 定义模型类 | `models/xxx.py` | 数据库表结构（DDL） | ORM 类映射数据库表，字段一一对应 |
| ③ 封装 CRUD | `crud/xxx.py` | 业务需求 | 写增删改查函数，传入 db session 执行 SQL |
| ④ 路由调用响应 | `routers/xxx.py` | FastAPI 路由规范 | `Depends(get_db)` 注入 → `await crud()` → `return` |

## 正例（≥2 个）
1. **获取新闻分类**：① `APIRouter(prefix="/api/news")` ② `class Category(Base)` 映射 `news_category` 表 ③ `crud/news.py` 的 `get_categories()` 封装 select 查询 ④ 路由调 `await news.get_categories(db, skip, limit)` → 返回 JSON。四步走完，接口上线。
2. **用户注册**：① `APIRouter(prefix="/api/user")` ② `class User(Base)` 映射 `user` 表 ③ `crud/users.py` 的 `create_user()` 封装密码加密 + INSERT ④ 路由先调 `get_user_by_username()` 判重，再调 `create_user()`，最后调 `create_token()` → 返回 token + 用户信息。四步心法完全一致，只是 CRUD 函数数量更多。
3. **所有增删改查接口**：获取新闻列表、收藏列表、浏览历史、修改密码、取消收藏……全部遵循此四步。学会一个，等于学会所有。

## 反例/边界（≥1 个）
1. **跳过 CRUD 层直接在路由里写 SQL**：`router` 函数里直接 `db.execute(select(Category))`——似乎少写了一个文件，但 10 个接口就有 10 段 SQL 散落各处。改一个字段名要改 10 处，封装到 crud 里只需改 1 处。
2. **模型类表名写错**：`__tablename__ = "news_categories"`（多写了个 s）→ 查询时报「表不存在」。必须和数据库实际表名完全一致。
3. **忘了在 main.py 挂路由**：`routers/news.py` 写好了但 `main.py` 没写 `app.include_router(news.router)` → 访问接口返回 404。路由文件不等于路由已注册。
4. **四步顺序搞反**：先写 CRUD 再写路由再写模型 → 写到一半发现模型没定义，CRUD 里的 `select(News)` 标红报错。顺序是：**路由结构 → 模型定义 → CRUD 实现 → 路由调用**，因为后面的步骤依赖前面的。

## 详细解释
**为什么是这四步？** 这是「关注点分离」原则在 Web 开发中的体现：

- **路由层（routers）**：只管「接什么请求、调什么服务、返回什么格式」——不碰 SQL
- **模型层（models）**：只管「数据库长什么样」——不碰业务逻辑
- **CRUD 层（crud）**：只管「怎么操作数据库」——暴露标准化函数供路由调用
- **校验层（schemas）**：只管「请求数据合不合法」——Pydantic 自动校验

**数据流向**：
```
HTTP 请求 → main.py → routers（服务员接单）
                      → schemas（验菜单格式）
                      → crud（厨师做菜）
                      → models（拿食材=操作数据库）
                      → 原路返回 JSON
```

**`@router.get()` 和 `return` 的关系**：`@router.get("/categories")` 是「挂牌」——告诉 FastAPI 这个 URL 归我管。`async def get_categories()` 里的 `return` 才是真正返回给客户端的数据。挂掉的牌（装饰器）不会自己做饭，函数体才是做饭的人。
