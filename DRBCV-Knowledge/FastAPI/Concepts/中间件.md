# 中间件（Middleware）

## 类型判定
discriminant — 中间件与依赖注入的关键区分：一个是"所有人强制执行"，一个是"谁需要谁声明"。

## 类比 ★
### 一句话比喻
中间件就像机场安检——不管你是飞头等舱还是经济舱、去北京还是纽约，所有人过安检门都得接受一样的检查。你不需要在每个登机口再查一遍，安检统一包办了。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 中间件（middleware） | 机场安检通道——所有旅客必经之路 |
| `@app.middleware("http")` | 安检门的电源开关——通电即生效 |
| 请求前代码 | 进入候机楼前的行李扫描——请求到达路由前执行 |
| 响应前代码 | 登机前的二次核验——响应发出前执行 |
| 自下而上执行顺序 | 从最里面的安检口往外走——代码顺序倒着来 |
| 依赖注入 | VIP 通道——只有办了 VIP 的人才走 |

## 是什么
中间件是 FastAPI 中**对所有请求和响应自动生效**的钩子函数。通过 `@app.middleware("http")` 装饰器定义，在每个请求到达路由处理函数之前、每个响应返回客户端之前自动执行。适合日志记录、跨域处理、身份认证、性能监控、响应头设置等全局统一逻辑。

## 正例（≥2 个）
1. **CORS 跨域处理**：前端在 `localhost:3000`，后端在 `localhost:8000`，浏览器会拦截跨域请求。用中间件统一添加 `Access-Control-Allow-Origin` 响应头，所有接口自动支持跨域——不用每个路由手动加。
2. **全局请求日志**：记录每个请求的路径、方法、耗时、状态码——中间件在请求到达时记开始时间，响应返回前算耗时并写入日志文件，所有接口零侵入。
3. **性能监控**：在响应头中统一注入 `X-Process-Time`，前端和运维都能看到每个接口的处理时长。

## 反例/边界（≥1 个）
1. **不是所有逻辑都适合放中间件**：如果只有部分接口需要分页参数（`skip/limit`），应该用依赖注入而不是中间件——中间件对所有接口生效，不合逻辑地给不需要分页的接口强行注入参数会浪费资源且语义混乱。
2. **中间件的 `call_next` 不能省略**：`await call_next(request)` 是请求向后传递的唯一通道——忘了写或注释掉，请求永远到不了路由，所有接口全部挂掉。
3. **多个中间件执行顺序是自下而上**：代码里写在下面的中间件反而先执行——容易搞反，调试时要注意看打印日志的顺序。

## 详细解释
### 执行流程
```
客户端 → 中间件N(请求前) → ... → 中间件1(请求前) → 路由处理函数
                                                         ↓
客户端 ← 中间件N(响应前) ← ... ← 中间件1(响应前) ← 响应结果
```

两个关键参数：
- **`request`**：当前请求对象，可读取路径、方法、请求头等
- **`call_next`**：向下传递请求的函数，必须 `await` 调用，返回响应对象

### 核心代码模板
```python
@app.middleware("http")
async def my_middleware(request: Request, call_next):
    # ===== 请求前：在这里写请求到达时的统一逻辑 =====
    print("请求来了")

    # ===== 传递请求到下一层 =====
    response = await call_next(request)

    # ===== 响应前：在这里写响应返回前的统一逻辑 =====
    print("响应走了")

    return response
```

### 中间件 vs 依赖注入
| | 中间件 | 依赖注入 |
|---|---|---|
| 生效范围 | 所有请求自动执行 | 只有声明了 Depends 的接口执行 |
| 控制权 | 框架做主（被动执行） | 程序员做主（按需注入） |
| 典型场景 | 日志、CORS、全局异常 | 分页参数、数据库会话、用户鉴权 |
