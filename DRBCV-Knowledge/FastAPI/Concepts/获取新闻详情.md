# 获取新闻详情

## 类型判定
procedure — 一次请求完成三件事：按 ID 查新闻详情 → 浏览量 +1 → 查询同类推荐新闻，最终响应全量数据。

## 类比 ★
### 一句话比喻
获取新闻详情就像点开报纸上的一篇文章——你不仅能看到正文（详情数据），报纸还会记录"这篇文章被翻看了多少次"（浏览量 +1），同时在文末推荐"你可能还喜欢"的同类文章（相关推荐）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 按 news_id 查详情 | 按文章编号从档案室调出全文 |
| 浏览量 views + 1 | 图书馆的借阅计数器——每被拿出来看一次 +1 |
| update + where + values | 找到这本书，在借阅次数那一栏盖个章 |
| 相关推荐（同类其他新闻） | "买了这本书的人还买了……"推荐栏 |
| order_by views DESC | 按畅销度排名——浏览量最高的排前面 |
| 列表推导式过滤字段 | 只展示书名和作者——不把出版社内部编号也暴露出来 |

## 是什么
获取新闻详情接口（GET `/api/news/detail?news_id=X`）返回单条新闻的完整信息，同时自动完成浏览量 +1 和同类新闻推荐。三个操作在一个请求中串行完成：先查详情 → 然后更新浏览量 → 最后查同分类的其他新闻（按浏览量和发布时间降序取前 5 条）。

## 输入-输出空间（程序型必填）
- **输入**：news_id: int（必填）
- **输出**：`{"code": 200, "data": {"id":1, "title":"...", "views":8905, "related_news":[{...}, ...]}}`
- **前置条件**：已定义 News 模型类、NewsCategory 模型类

## 核心代码 + 步骤表
```python
# ===== CRUD/news.py =====
# ① 按 ID 查新闻详情
async def get_news_detail(db: AsyncSession, news_id: int):
    stmt = select(News).where(News.id == news_id)
    result = await db.execute(stmt)
    return result.scalar_one_or_none()  # 有就返回，没有返回 None

# ② 浏览量 +1
async def increase_news_views(db: AsyncSession, news_id: int):
    stmt = (update(News)
            .where(News.id == news_id)
            .values(views=News.views + 1))
    result = await db.execute(stmt)
    await db.commit()
    return result.rowcount > 0  # 命中了返回 True，否则 False

# ③ 查询同类推荐新闻
async def get_related_news(db: AsyncSession, news_id: int, category_id: int, limit: int = 5):
    stmt = (select(News)
            .where(News.category_id == category_id, News.id != news_id)
            .order_by(News.views.desc(), News.publish_time.desc())
            .limit(limit))
    result = await db.execute(stmt)
    news_list = result.scalars().all()
    # 列表推导式：只提取前端需要的字段
    return [{"id": n.id, "title": n.title, "image": n.image,
             "views": n.views, "publish_time": n.publish_time} for n in news_list]

# ===== routers/news.py：路由调用 =====
@router.get("/detail")
async def get_news_detail(
    news_id: int = Query(..., alias="id"),
    db: AsyncSession = Depends(get_db)
):
    # ① 查详情
    news_detail = await news_crud.get_news_detail(db, news_id)
    if not news_detail:
        raise HTTPException(status_code=404, detail="新闻不存在")

    # ② 浏览量 +1
    await news_crud.increase_news_views(db, news_detail.id)

    # ③ 查同类推荐
    related = await news_crud.get_related_news(db, news_detail.id, news_detail.category_id)

    return {"code": 200, "data": {
        "id": news_detail.id, "title": news_detail.title,
        "content": news_detail.content, "author": news_detail.author,
        "views": news_detail.views + 1,  # 响应给前端看 +1 后的
        "related_news": related
    }}
```

| 步骤 | 方法 | 说明 |
|------|------|------|
| ① 查详情 | `select(News).where(News.id == news_id)` | scalar_one_or_none() 查不到返回 None |
| ② 浏览量+1 | `update(News).values(views=News.views+1)` | 用 rowcount 检查是否命中 |
| ③ 同类推荐 | `where(category_id相同, id≠当前).order_by(views.desc()).limit(5)` | 取同分类下浏览量最高的 5 条，排除自身 |

## 正例（≥2 个）
1. **正常进入详情**：news_id=2，该新闻存在 → 返回详情 + views 从 8904 变为 8905 + 5 条同类推荐新闻。
2. **新闻不存在**：news_id=10000 → scalar_one_or_none() 返回 None → 路由中 if not 抛 404"新闻不存在"。
3. **推荐按质量排序**：order_by(views.desc(), publish_time.desc()) → 推荐的是浏览量高 + 最新发布的优质新闻，而非随便 5 条。

## 反例/边界（≥1 个）
1. **ID 不存在未处理**：直接 news_detail.title 取值 → AttributeError，服务器 500 报错。必须 scalar_one_or_none() + if not 抛异常。
2. **浏览量更新未检查命中**：直接 execute 不管结果 → 万一 news_id 不存在，静默失败。必须检查 `result.rowcount > 0`。
3. **推荐新闻包含自身**：where 条件只写了 category_id 相同 → 详情页推荐里包含当前这条新闻（用户正在看它！）。必须加 `News.id != news_id` 排除自身。
4. **推荐返回全量字段**：把 password、created_at 等无关字段也返回 → 浪费带宽 + 安全隐患。用列表推导式只提取需要的字段。

## 详细解释
**scalar_one_or_none vs scalar**：
- `scalar_one_or_none()`：有唯一结果返回，没有返回 None。适合"查一条，可能不存在"的场景（如详情）
- `scalar()`：返回第一个结果。不检查是否多个结果，多条时只取第一条（隐患）
- `scalar_one()`：严格只能有一条，0 条或多条都抛异常

**order_by 排序规则**：
- 默认升序（ASC）：`order_by(News.views)` → 浏览量最小的在前面
- 降序（DESC）：`order_by(News.views.desc())` → 浏览量最大的在前面
- 多字段排序：`order_by(News.views.desc(), News.publish_time.desc())` → 先按浏览量降序，同浏览量再按时间降序

**列表推导式过滤字段**：ORM 返回的 News 对象包含所有数据库字段，但前端只需要 id/title/image/views/publish_time。用列表推导式 `[{key: val, ...} for n in news_list]` 提取子集，既安全（不暴露敏感字段）又省带宽。
