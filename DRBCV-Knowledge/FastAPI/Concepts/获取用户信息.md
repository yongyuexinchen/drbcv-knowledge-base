# 获取用户信息

## 类型判定
procedure — 三步标准流程：从请求头提取 Token → 验证 Token 有效性 → 查用户并返回信息。

## 类比 ★
### 一句话比喻
获取用户信息就像刷工牌查员工档案——你刷卡（请求头携带 Token），HR 系统先验证这张卡是不是真的、过期没过期（Token 校验），验证通过后从档案系统调出你的资料（查数据库），展示在屏幕上。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Authorization: Bearer xxx | 刷工牌——"这是我的身份凭证" |
| Header 参数提取 Token | 刷卡机读取工牌信息——从请求头拿数据 |
| Token 过期检查 | HR 系统查"这卡还在有效期内吗？" |
| `get_user_by_token()` | HR 拿工号去查档案——Token 关联到具体的人 |
| `Depends(get_current_user)` 依赖注入 | 公司门禁系统——进门自动刷一次，不用每次人工查 |

## 是什么
获取用户信息接口（GET `/api/user/info`），是用户模块第一个需要认证的接口。核心是把 Token 验证逻辑封装为可复用的依赖项 `get_current_user()`，通过 `Depends()` 注入到路由中。该接口从请求头 `Authorization: Bearer <token>` 提取 Token，验证其有效性和过期状态，然后查出对应用户返回个人信息。

## 输入-输出空间（程序型必填）
- **输入**：请求头 `Authorization: Bearer <token>`（前端自动携带）
- **输出**：`{"code": 200, "message": "获取个人信息成功", "data": {"id": 1, "username": "大秋", ...}}`
- **前置条件**：用户已登录（Token 有效且未过期）、已定义 `UserToken` 和 `User` 模型类

## 核心代码 + 步骤表
```python
# ===== CRUD/users.py：根据 Token 查询用户 =====
async def get_user_by_token(db: AsyncSession, token: str):
    # ① 查 token 表
    stmt = select(UserToken).where(UserToken.token == token)
    result = await db.execute(stmt)
    db_token = result.scalar_one_or_none()

    # ② 验证 Token 有效性
    if not db_token or db_token.expires_at < datetime.now():
        return None    # Token 不存在或已过期

    # ③ 查用户表
    stmt_user = select(User).where(User.id == db_token.user_id)
    result_user = await db.execute(stmt_user)
    return result_user.scalar_one_or_none()

# ===== utils/auth.py：整合为可复用的依赖项 =====
from fastapi import Header, Depends

async def get_current_user(
    authorization: str = Header(..., alias="Authorization"),  # 从请求头提取
    db: AsyncSession = Depends(get_db)
):
    # 去除 "Bearer " 前缀，拿到纯 Token
    token = authorization.replace("Bearer ", "")

    user = await users_crud.get_user_by_token(db, token)
    if not user:
        raise HTTPException(status_code=401, detail="无效的令牌或已过期的令牌")
    return user

# ===== routers/users.py：路由注入依赖 =====
@router.get("/info")
async def get_user_info(
    user: User = Depends(get_current_user)   # 依赖注入：自动获取当前用户
):
    return success_response(
        message="获取个人信息成功",
        data=UserInfoResponse.model_validate(user)
    )
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 提取 Token | `Header(..., alias="Authorization")` | 从请求头拿到 `Bearer xxx` |
| ② 去前缀 | `replace("Bearer ", "")` | `"Bearer a1b2..."` → `"a1b2..."` |
| ③ 查 token 表 | `select(UserToken).where(token==token)` | 看 Token 是否存在 |
| ④ 验过期 | `expires_at < datetime.now()` | 过期则返回 None |
| ⑤ 查用户 | `select(User).where(id==token.user_id)` | Token 关联到具体用户 |
| ⑥ 返回 | `return user` | 供路由使用 |

## 正例（≥2 个）
1. **正常获取信息**：用户已登录，请求头携带有效 Token → `get_current_user` 验证通过 → 路由拿到 user 对象 → 返回用户 ID、用户名、头像、简介等信息。
2. **依赖注入复用**：`get_current_user` 被多个接口复用——获取用户信息、修改用户信息、修改密码都通过 `Depends(get_current_user)` 验证登录状态，无需重复写 Token 验证代码。
3. **自动脱敏**：`model_validate(user)` 基于 `UserInfoResponse` 提取字段——password 不在模型类中，自动忽略，不会泄露密码。

## 反例/边界（≥1 个）
1. **Token 过期**：用户 8 天前登录，Token 的 `expires_at` 已过 → `db_token.expires_at < now()` → 返回 None → raise 401，提示"令牌已过期"。
2. **Token 伪造**：攻击者编造随机字符串放请求头 → `select(UserToken).where(token==...)` 查不到 → `scalar_one_or_none()` 返回 None → 401。
3. **交互式文档无法测试**：Swagger UI 不会自动带 `Authorization` 请求头 → info 接口在交互式文档里测试会报 401。必须用前端页面或 Postman 手动加 Header 测试。

## 详细解释
**Header 参数的语法**：
```python
authorization: str = Header(..., alias="Authorization")
```
- `Header()`：指定参数从 HTTP 请求头中提取
- `...`：表示必填（没有则 FastAPI 自动返回 422 校验错误）
- `alias="Authorization"`：HTTP 标准中首字母大写，与 Python 变量名 `authorization` 不同——用别名兼容

**为什么要抽取 `get_current_user`？**
- 获取用户信息、修改用户信息、修改密码都需要验证 Token
- 如果每个接口都复制粘贴 Token 验证代码 → 重复、难维护、易遗漏
- 抽取为依赖注入函数 → 接口只需 `Depends(get_current_user)` 一行，验证逻辑复用

**依赖注入在此处的威力**：
```python
# 不用每次手写：
token = request.headers["Authorization"].replace("Bearer ", "")
db_token = await db.execute(select(UserToken)...)
if not db_token or expires: raise HTTPException(401)
user = await db.execute(select(User)...)

# 只需一行：
user: User = Depends(get_current_user)
```
