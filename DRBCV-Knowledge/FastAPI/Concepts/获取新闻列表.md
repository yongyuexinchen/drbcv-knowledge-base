# 获取新闻列表

## 类型判定
procedure — 核心是分页查询 + 按分类过滤 + 聚合统计量 + 是否还有更多，四步数据计算后响应统一格式。

## 类比 ★
### 一句话比喻
获取新闻列表就像翻报纸的目录页——你指定看哪个栏目（category_id）、翻到第几页（page），报纸就给你那一页的 N 条新闻摘要（page_size），并告诉你总共多少条新闻（total）和后面还有没有更多（has_more）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| category_id 分类过滤 | 报纸的栏目：只看"体育版"还是"财经版" |
| page + page_size 分页 | 翻报纸：你不可能一页看完所有新闻 |
| offset = (page-1) × page_size | 翻页时跳过的厚度——前面页全翻过去 |
| total 总量 | 报纸编辑告诉你：这个栏目总共有多少篇 |
| has_more 是否还有 | 底部提示"下转第X版"——还有更多 |
| Function.count 聚合统计 | 快速数一下总共多少篇，不用全翻一遍 |

## 是什么
获取新闻列表接口（GET `/api/news/list`）按分类 ID 查询新闻，支持分页（page / page_size）、返回新闻列表（list）、该分类下新闻总数（total）和是否还有更多新闻（has_more）。响应中 has_more 用于前端判断是否显示"加载更多"按钮。

## 输入-输出空间（程序型必填）
- **输入**：category_id: int(必填)、page: int(默认1)、page_size: int(默认10, 最大100)
- **输出**：`{"code": 200, "data": {"list": [...], "total": 51, "has_more": true}}`
- **前置条件**：已定义 News 模型类、已配置 ORM、已有新闻数据

## 核心代码 + 步骤表
```python
# ===== CRUD/news.py：封装查询方法 =====
from sqlalchemy import select, func
from models.news import News

# 查询指定分类下的新闻列表（分页）
async def get_news_list(db: AsyncSession, category_id: int, skip: int = 0, limit: int = 10):
    stmt = (select(News)
            .where(News.category_id == category_id)
            .offset(skip)
            .limit(limit))
    result = await db.execute(stmt)
    return result.scalars().all()

# 统计指定分类下的新闻总数（聚合查询）
async def get_news_count(db: AsyncSession, category_id: int):
    stmt = select(func.count(News.id)).where(News.category_id == category_id)
    result = await db.execute(stmt)
    return result.scalar_one()   # 只能有一个结果，0个或多报错

# ===== routers/news.py：路由调用 =====
@router.get("/list")
async def get_news_list(
    category_id: int = Query(..., alias="categoryId"),
    page: int = Query(1, ge=1),
    page_size: int = Query(10, le=100, alias="pageSize"),
    db: AsyncSession = Depends(get_db)
):
    # ① 计算分页：跳过的数量
    offset = (page - 1) * page_size

    # ② 查询新闻列表
    news_list = await news_crud.get_news_list(db, category_id, offset, page_size)

    # ③ 统计总量
    total = await news_crud.get_news_count(db, category_id)

    # ④ 判断是否还有更多
    has_more = (offset + len(news_list)) < total

    return {"code": 200, "message": "success", "data": {
        "list": news_list, "total": total, "has_more": has_more
    }}
```

| 步骤 | 公式/代码 | 说明 |
|------|----------|------|
| ① 处理分页 | `offset = (page-1) × page_size` | 页码转跳过量 |
| ② 查询列表 | `select(News).where(...).offset(offset).limit(page_size)` | 分页 + 分类过滤 |
| ③ 统计总量 | `select(func.count(News.id)).where(...)` | 聚合计算总条数 |
| ④ 判断更多 | `offset + len(news_list) < total` | 当前已有的 < 总条数 → 还有更多 |

## 正例（≥2 个）
1. **标准分页场景**：category_id=1（头条），51 条新闻，page=3，page_size=10 → offset=20，返回第 21-30 条，total=51，has_more=true。
2. **最后一页**：category_id=1，51 条，page=6，page_size=10 → offset=50，返回第 51 条（只有 1 条），total=51，has_more=false。
3. **参数别名转换**：前端传驼峰 `categoryId`，后端 Python 用下划线 `category_id`，通过 `Query(alias="categoryId")` 无缝对接。

## 反例/边界（≥1 个）
1. **page=0 或负数**：`offset = (0-1)×10 = -10`—SQL offset 负数无效。必须用 `Query(ge=1)` 限制页码 ≥1。
2. **page_size 过大**：用户传 `page_size=100000`—一次查 10 万条，内存爆炸。必须用 `Query(le=100)` 限制上限。
3. **scalar_one vs scalar**：统计总量用 `scalar_one()`，如果误用 `scalars()` 返回列表，取 [0] 容易漏掉空列表报 IndexError。

## 详细解释
**has_more 的业务意义**：前端列表不可能一次加载全部新闻（体验差、流量大）。has_more 告诉前端"后面还有"，前端据此显示"加载更多"按钮。计算公式：`offset + 当前页条数 < total` → 说明还没加载完。

**索引优化**：新闻表对 `category_id` 和 `publish_time` 创建了联合索引：
```python
__table_args__ = (
    Index("idx_category_publish", "category_id", "publish_time"),
)
```
原因：按分类查新闻是高频操作（不用全表扫），按发布时间排序也是刚需（有序索引避免全表排序）。

**别名（alias）的必要性**：前端 JavaScript 习惯驼峰命名 `categoryId`，Python 习惯下划线 `category_id`。`Query(alias="categoryId")` 让参数名两边都舒服，无需前端改代码。
