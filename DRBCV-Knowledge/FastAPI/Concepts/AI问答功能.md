# AI问答功能（调用千问大模型）

## 类型判定
procedure — 三步完成大模型接入：获取 API 地址和密钥 → 配置到前端 → 发送消息验证。本质是调用阿里云百炼的千问模型实现对话功能。

## 类比 ★
### 一句话比喻
AI 问答功能就像给新闻 APP 配了一个 AI 客服——用户在输入框提问（"介绍一下 FastAPI"），前端把问题发给阿里云百炼的千问大模型，大模型"思考"后回复一段文字。整个流程就像打电话：需要知道对方的号码（API 地址）和验证身份（API-KEY），接通后你说一句它回一句。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 阿里云百炼模型广场 | AI 服务"超市"——选模型、看价格、拿使用说明 |
| API 请求地址（HTTP endpoint） | 客服电话号码——打到正确的号码才能接通 |
| API-KEY（密钥） | 身份验证——证明你是付费用户，不是陌生人 |
| 模型名称（如 `qwen-max`） | 指定找哪位客服——不同模型能力不同 |
| `message` 数组 `[{role, content}]` | 对话记录本——每句话记下是谁说的、说了什么 |
| `role: "user"` / `role: "assistant"` | "顾客说" / "客服回"——区分问答双方 |
| 前端 `config/api.js` | 电话本——把号码和密钥记在一个地方 |

## 是什么
AI 问答功能是在头条项目前端界面集成阿里云百炼的**千问大模型**，实现用户输入文字 → 大模型回复的对话功能。核心不是自己写模型调用代码，而是：① 在模型广场找到模型 → ② 获取 HTTP 请求地址 + API-KEY → ③ 配置到前端 `config/api.js`。

## 输入-输出空间（程序型必填）
- **输入**：用户在前端输入框键入的问题（字符串）
- **输出**：千问大模型返回的回复文本
- **前置条件**：阿里云百炼账号已注册并实名认证、API-KEY 已创建

## 核心步骤

| 步骤 | 操作 | 关键产出 |
|------|------|---------|
| ① 登录模型广场 | 访问阿里云百炼 → 模型广场 → 选择模型（如通义千问3）→ 点击"API 参考" | 查看模型能力、价格、API 文档 |
| ② 获取两大关键信息 | API 参考页 → 选择"对话"（OpenAI 兼容模式）→ 记录 HTTP 请求地址 + 点击"获取 API-KEY" | 请求地址 + API-KEY |
| ③ 创建/复制密钥 | 密钥管理页 → 右上角"创建密钥" → 选默认空间 → 确定 → 点复制图标 | 一串加密字符串 |
| ④ 配置到前端 | 打开前端项目 `src/config/api.js` → 粘贴 API-KEY 到 `apiKey` 字段 → 保存 → 重启前端 | 前端代码与模型打通 |
| ⑤ 测试 | 浏览器打开项目 → AI 问答页 → 输入"你好" → 点发送 | 收到大模型回复即成功 |

## 前端配置示例
```javascript
// src/config/api.js（简化示意）
export default {
  // 千问大模型 API 地址（阿里云百炼提供的 HTTP 端点）
  apiUrl: "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",

  // 你的 API-KEY（从密钥管理页复制）
  apiKey: "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",

  // 模型名称
  model: "qwen-max",
};
```

## 消息格式（OpenAI 兼容）
```json
{
  "model": "qwen-max",
  "messages": [
    {"role": "system", "content": "你是一个新闻助手"},
    {"role": "user", "content": "介绍一下 FastAPI"},
    {"role": "assistant", "content": "FastAPI 是一个..."},
    {"role": "user", "content": "它和 Flask 有什么区别？"}
  ]
}
```
每条消息是 `{role, content}` 字典：`role` 标识说话者，`content` 是文本内容。整个对话历史以数组形式传给模型，模型基于上下文生成回复。

## 正例（≥2 个）
1. **简单问候测试**：用户输入"你好" → 模型回复"你好！很高兴见到你" → 验证连通性 OK。
2. **知识问答**：用户输入"介绍一下 FastAPI 框架" → 模型回复带格式的介绍文字 → 验证模型确实能"理解"并回答。
3. **多轮对话**：用户连续问"什么是异步？"→"异步和同步的区别？"——每次请求把之前的 `messages` 数组完整带上，模型基于上下文回答，不"失忆"。

## 反例/边界（≥1 个）
1. **API-KEY 泄露到前端仓库**：把密钥直接 hardcode 在 `api.js` 里并提交到 GitHub → 任何人看到你的代码就能用你的额度。生产环境应该用后端代理，前端不暴露密钥。
2. **未实名认证**：新注册的阿里云账号跳过实名认证直接创建密钥 → 调用 API 时报错"未实名"→ 必须先完成实名认证。
3. **密钥超额**：一个账号最多 20 个密钥，用完不能再创建 → 需要先删除不用的旧密钥。
4. **messages 没有带历史**：每轮对话只发当前问题，不带之前的对话 → 模型每次都像"第一次见面"，无法实现多轮对话的连贯性。

## 详细解释
**为什么在阿里云百炼而不用 OpenAI 直连？**：课程目标是学会调用国内可访问的大模型 API。阿里云百炼提供 OpenAI 兼容接口（请求格式和 OpenAI 一样），未来换模型只需改 `model` 参数名。

**API 调用的本质**：前端发一个 HTTP POST 请求到千问的 API 地址，body 里带 `model` 和 `messages`，header 里带 `Authorization: Bearer {apiKey}`。模型处理完返回一个 JSON：`{"choices": [{"message": {"role": "assistant", "content": "回复内容"}}]}`，前端取出 `content` 显示。

**课程后续**：当前只是调用别人的模型。后续课程会涉及**模型训练**（用自己的数据 fine-tune）和**模型服务化**（训练完部署成 API 给别人调用）——从"调用者"变成"提供者"。
