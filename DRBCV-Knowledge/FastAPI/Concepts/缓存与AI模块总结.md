# 缓存与AI模块总结

## 类型判定
discriminant — 对头条项目缓存模块（Redis 四步走 + 旁路策略）和 AI 模块（调用千问大模型）的知识体系做全局梳理，明确各知识点之间的位置和关系。

## 类比 ★
### 一句话比喻
整个缓存模块就像给公司的档案查询系统做了一次"效率改造"——原来每次查档案都要跑到地下室档案库（数据库），现在在前台放了一块小黑板（Redis），把经常被查的档案目录抄上去。AI 模块则是给公司前台配了一个智能客服（千问大模型），用户不查档案而是直接问问题时，客服能回答。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Redis 四步走（装服务→配客户端→封装→定策略） | 装黑板→配粉笔→写手册→定规则 |
| 旁路策略 | 黑板维护规则：先看黑板→没有才翻档案→翻完抄上去 |
| 缓存雪崩（所有 key 同时过期） | 黑板上的字全同时消失→所有人涌向档案室→档案室瘫痪 |
| 错开过期时间 | 排班表 1h 擦、规章 1 周擦——错开维护，不会同时消失 |
| 千问模型 API | 外包客服热线——打通电话就能用，不用自己培训客服 |
| API-KEY | 热线身份验证密码——证明你付费了 |
| 头条项目一完结 | 第一个完整项目交付——从框架→数据库→缓存→AI 全链路打通 |

## 是什么
本章是头条项目（项目一）的收官模块，包含两大块：

**缓存模块（Redis）**：四个步骤递进——
1. **安装 Redis 服务端**：在服务器上装 Redis（Mac: `brew install redis`，Windows: 双击安装包），端口 6379
2. **安装配置 Redis 客户端**：`pip install redis` + 创建 `redis.asyncio.Redis()` 异步连接对象，配置 host/port/db/decode_responses
3. **封装缓存操作方法**：对 `setex`/`get` 做二次封装（异常处理 + JSON 序列化/反序列化），产出 `set_cache`/`get_cache`/`get_json_cache` 三个通用方法
4. **设计缓存策略（旁路策略）**：读——先查缓存，命中返回，未命中查库写回；写——先更库，再删/更缓存。应用：新闻分类缓存 + 新闻列表缓存

**AI 模块**：在模型广场获取千问大模型的 API 地址和 API-KEY → 配置到前端 `config/api.js` → 实现 AI 问答对话功能。

## 正例（≥2 个）
1. **缓存 + 数据库配合**：新闻分类缓存 2 小时，新闻列表缓存 10 分钟，新闻详情缓存 30 分钟——不同数据不同策略，数据库扛住高并发。
2. **旁路策略统一应用**：新闻分类、新闻列表、新闻详情、推荐内容——四个接口用同一套旁路策略模板改造，掌握了模式就能批量应用。
3. **AI 问答增强体验**：用户在新闻 APP 里不只是被动浏览，还能主动提问——从"看新闻"升级到"问新闻"，产品体验提升。

## 反例/边界（≥1 个）
1. **缓存不设过期时间**：数据永远留在 Redis 里 → 内存越占越多 → Redis OOM 崩溃。每个 `setex` 必须有 `expire` 参数。
2. **所有过期时间相同**：所有 key 同时过期 → 缓存雪崩，数据库瞬间被打爆。必须错开。
3. **API-KEY 泄露**：密钥提交到公开仓库 → 被人盗刷额度。生产环境用环境变量或后端代理。
4. **缓存和数据库不一致但没处理**：数据更新了但缓存没删 → 用户看到旧数据。旁路策略要求写操作必须同步处理缓存。

**缓存模块知识体系一览**：

```
Redis 四步走
├── ① 安装服务端 ──→ [[Redis缓存简介]]
│      └── 产出：运行中的 Redis（端口 6379）
├── ② 配置客户端 ──→ [[Redis客户端配置]]
│      └── 产出：redis_client 连接对象
├── ③ 封装操作方法 ──→ [[封装缓存操作方法]]
│      └── 产出：set_cache / get_cache / get_json_cache
└── ④ 设计缓存策略 ──→ [[缓存策略-旁路策略]]
       ├── 应用1：新闻分类缓存（Source 65 后半）
       └── 应用2：新闻列表缓存 → [[缓存新闻列表]]
```

**AI 模块**：
```
阿里云百炼模型广场
├── ① 登录 → 选模型（千问）→ API 参考
├── ② 获取 HTTP 请求地址 + API-KEY
└── ③ 配置到前端 config/api.js → 测试对话 → [[AI问答功能]]
```

**整个头条项目的技术栈全景**：

| 层级 | 技术 | 对应知识点 |
|------|------|-----------|
| Web 框架 | FastAPI + Uvicorn | 异步路由、Pydantic 校验、自动文档 |
| 数据层 | SQLAlchemy + MySQL | ORM 模型、CRUD、分页、聚合 |
| 缓存层 | Redis | 四步走 + 旁路策略 |
| AI 层 | 千问大模型 | API 调用 |
| 前端 | Vue.js | 页面渲染、API 对接 |
