# Redis缓存简介

## 类型判定
discriminant — 定义缓存是什么、为什么用 Redis、它和数据库的根本差异在哪。

## 类比 ★
### 一句话比喻
Redis 缓存就像公司前台的小黑板——高频信息（今日访客名单、会议室安排）抄在黑板上，前台抬头就能回答，不用每次都跑到档案室（数据库）翻资料。档案室负责"存得住"，小黑板负责"取得快"。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Redis 缓存（内存） | 前台小黑板——抬头就看，秒级响应 |
| 数据库（硬盘） | 公司档案室——翻箱倒柜，慢但存得久 |
| 先查缓存再查库 | 先看黑板，没有才去档案室翻 |
| 缓存命中（Cache Hit） | 问前台"今天谁来访"→黑板上有→直接回答 |
| 缓存未命中（Cache Miss） | 黑板上没有→去档案室查→查到后顺手抄黑板上 |
| 6379 端口 | 小黑板挂在"2号楼6379室"——要知道门牌号才能找到 |

## 是什么
缓存是一种**高速临时数据存储机制**，把频繁使用的数据或计算结果在内存中存一份。后续请求先查缓存，有则直接返回（不再查库），没有再查数据库。本质是：**数据库（硬盘）负责"存得住"，缓存（内存）负责"取得快"**——用空间换时间，降低数据库压力。

Redis 是开发中最常用的缓存实现，基于**内存的 key-value 存储**，读写速度远超硬盘。使用 Redis 的四个步骤：安装服务端 → 配置客户端 → 封装缓存操作 → 设计缓存策略。

## 正例（≥2 个）
1. **高并发新闻列表**：1000 人同时刷头条首页，如果每次查数据库→1000 次 SQL。加了缓存后，第一个人查库写入缓存，后面 999 人直接从 Redis 返回，数据库只扛 1 次。
2. **新闻分类数据**：分类基本不变（科技/体育/财经），缓存 2 小时。2 小时内所有请求走缓存，数据库在这段时间内 0 压力。
3. **验证码**：用户登录时生成的验证码存 Redis，设置 120 秒过期——过期自动清除，不占内存也不污染数据库。

## 反例/边界（≥1 个）
1. **所有数据都缓存**：如果把每一条冷门新闻都缓存，内存占用爆炸且命中率极低——缓存要存"热点数据"，不是"全量备份"。
2. **缓存和数据库不一致**：新闻编辑改了标题，但缓存还是旧标题——用户看到的是过时信息。必须设计更新/删除缓存的策略。
3. **不是替代数据库**：Redis 是内存存储，重启就丢（除非持久化配置）。重要数据必须落盘到数据库。

## 详细解释
**为什么内存比硬盘快？**：硬盘读写是机械寻道（HDD）或电子擦写（SSD），延迟在毫秒级；内存是电路级的随机存取，延迟在纳秒级。差距约 1000 倍。

**Redis 数据流**：
```
请求 → 查 Redis 缓存 → 有？→ 直接返回 ✓
                      → 没有 → 查数据库 → 写入 Redis → 返回
```

**端口号 6379**：Redis 默认端口。如果一台机器上跑多个 Redis 实例，用不同端口区分（6380、6381...）。
