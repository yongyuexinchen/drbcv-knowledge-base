# 会话工厂（async_sessionmaker）

## 类型判定
procedure — 一行 `async_sessionmaker` 调用创建工厂，之后每次 `get_db` 依赖项被触发时用工厂生产一个临时数据库会话。

## 类比 ★
### 一句话比喻
会话工厂就像医院挂号机——它不是医生本人（数据库），也不是诊室（单个会话），而是一台机器：病人（请求）来了按一下（调用工厂），出一个小票（返回一个 session），凭票进诊室看病（操作数据库），看完小票作废（close）。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| `create_async_engine`（异步引擎） | 医院大楼——基础设施，建好不动 |
| `async_sessionmaker`（会话工厂） | 挂号机——每次来都吐一张新号 |
| `bind=engine` | 挂号机接通医院系统——知道去哪层哪科 |
| `class_=AsyncSession` | 挂号机吐的是"就诊号"而非"体检号"——指定票的类型 |
| `expire_on_commit=False` | 看完病小票不立刻作废——还能再瞄一眼，不用重新挂号 |
| `get_db` 依赖项 | 护士站的标准流程——挂号→看病→结算→走人 |

## 是什么
会话工厂（`async_sessionmaker`）是 SQLAlchemy 异步扩展中用于**按需生产数据库会话**的工厂函数。它绑定异步引擎，每次调用返回一个 `AsyncSession` 对象。配合 `get_db` 依赖项实现"每个请求一个会话"的模式——请求进来创建会话，请求结束关闭会话。

## 输入-输出空间（程序型必填）
- **输入**：
  - `bind`：异步引擎 `AsyncEngine`
  - `class_`：会话类 `AsyncSession`
  - `expire_on_commit`：提交后是否过期（通常 `False`）
- **输出**：一个 `async_sessionmaker` 工厂对象
- **前置条件**：`from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession`，已有 `async_engine`

## 核心代码 + 步骤表

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

# ① 先有引擎
DATABASE_URL = "mysql+aiomysql://root:123456@localhost:3306/news_app"
async_engine = create_async_engine(DATABASE_URL, pool_size=10, max_overflow=5)

# ② 创建会话工厂（这一行就是本卡的核心）
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,          # 绑定引擎——知道连哪个库
    class_=AsyncSession,        # 指定会话类型——异步版
    expire_on_commit=False      # 提交后不过期——避免重复查库
)

# ③ 在依赖项中用工厂生产会话
async def get_db():
    async with AsyncSessionLocal() as session:
        try:
            yield session          # 交给路由处理函数
            await session.commit() # 无异常则提交
        except Exception:
            await session.rollback() # 有异常则回滚
            raise
        # async with 自动 close，不用手动 finally
```

| 步骤 | 代码 | 说明 |
|------|------|------|
| ① 导包 | `from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession` | 异步版工厂和会话类 |
| ② 创建工厂 | `async_sessionmaker(bind=engine, class_=AsyncSession, expire_on_commit=False)` | 三个参数绑定引擎 + 指定类型 + 关闭过期 |
| ③ 生产会话 | `async with AsyncSessionLocal() as session:` | 每次调用产出一个新会话，`async with` 自动关闭 |

## 三个参数详解

| 参数 | 含义 | 为什么这样设 |
|------|------|------------|
| `bind=async_engine` | 绑定到哪个数据库引擎 | 引擎里有连接池，工厂通过引擎借连接 |
| `class_=AsyncSession` | 生产的会话是什么类型 | `AsyncSession` 支持 `await` 异步操作 |
| `expire_on_commit=False` | 提交后会话不过期 | `True`（默认）会导致提交后再次访问属性时重新查库，性能差；`False` 则保留缓存 |

## 正例（≥2 个）
1. **FastAPI 标准模式**：项目启动时创建全局 `AsyncSessionLocal`，路由函数中通过 `Depends(get_db)` 获取会话 → 每次请求独立会话，请求结束自动归还连接。
2. **多个数据库**：主库一个 `AsyncSessionLocal_main`，只读从库一个 `AsyncSessionLocal_readonly`，绑定不同引擎，路由根据需要注入不同工厂。
3. **测试环境**：测试时把 `bind` 换成 SQLite 内存引擎 → `create_async_engine("sqlite+aiosqlite://")`，不碰生产库。

## 反例/边界（≥1 个）
1. **全局单例会话**：不要把 `session = await AsyncSessionLocal()` 存成全局变量复用——多个请求共用一个会话会导致数据串扰、事务混乱。
2. **忘记 close**：不用 `async with` 而手动 `session = AsyncSessionLocal()` 然后忘了 `await session.close()` → 连接泄漏，连接池耗尽后所有请求挂起。
3. **同步混用**：不要用 `sessionmaker`（同步版）搭配 `async_engine`——类型不匹配，运行时报错。

## 详细解释

### 为什么叫"工厂"？
工厂模式的核心思想：**不直接 new 对象，而是调用工厂方法生产对象**。这样做的好处——工厂统一管理创建逻辑（绑定哪个引擎、什么类型、什么配置），调用方只需 `AsyncSessionLocal()` 即可，不需要关心内部细节。

### `async with` 自动 close 的原理
```python
async with AsyncSessionLocal() as session:
    # 进入：__aenter__ 生产一个 session
    ...
# 退出：__aexit__ 自动调用 session.close()
```
等价于手动 try/finally 的简洁写法，不容易漏掉 close。

### 和数据库ORM配置的关系
```
create_async_engine  →  异步引擎（基础设施）
        ↓
async_sessionmaker   →  会话工厂（本卡）  ← 承上启下
        ↓
get_db 依赖项        →  生产 + 提交/回滚/关闭
        ↓
Depends(get_db)      →  注入到路由
```
会话工厂是引擎和路由之间的桥梁——没有它，`get_db` 就不知道从哪获取会话。


### 一句话

不是给请求一个 ID，而是**给每个请求一个独立的数据库连接/会话**。
请求1 进来 → get_db() → 工厂生产 session A → 路由用 A 查数据库 → 请求结束 → A 关闭
请求2 进来 → get_db() → 工厂生产 session B → 路由用 B 查数据库 → 请求结束 → B 关闭
请求3 进来 → get_db() → 工厂生产 session C → 路由用 C 查数据库 → 请求结束 → C 关闭
