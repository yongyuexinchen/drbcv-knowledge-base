# 二元决策树（Binary Decision Tree）

## 类型判定
程序 — PA Agent 阶段一+阶段二的执行骨架，定义"先问什么、后问什么、每一步只有是/否两个出口"

## 类比 ★
### 一句话比喻
**二元决策树 = 急诊室分诊台**——病人进来，护士不问"你觉得你得了什么病"，而是按固定流程逐项排查：量体温→听心肺→查血氧。每一项只有"正常/异常"两个答案，异常就分流到对应科室。PA Agent 对每根 K 线也这样做：先问"能识别周期吗？"→ 再问"有方向惯性吗？"→ 再找"有没有合格信号棒？"——中间任何一步卡住就 wait，不开药方。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 闸门节点（§1–§2）| 急诊台——先判断病人有没有生命危险，危重不进专科直接抢救（直接 wait） |
| 结构分支（§3–§8）| 分诊——根据症状分到内科/外科/骨科（spike/channel/range） |
| 交易者方程（§10.3）| 手术风险评估——必须三价齐全、盈亏比≥1.0、胜率×回报>败率×风险，才能开刀 |
> 14 个章节、28+ 个节点覆盖了从"能不能做"到"怎么做"到"做完怎么检查"的全流程。

## 是什么
PA Agent 的核心决策流程，以 Al Brooks 的二元判断方法组织：每一步只问一个"是/否"问题，答案决定了下一步走到哪个分支。分为两个阶段：阶段一（§0–§2）做诊断闸门——判断市场能不能分析；阶段二（§3–§11 + §14）做策略执行——找到入场信号、评估风险收益、确定下单方式，最后扫描禁止行为清单。

## 输入-输出空间
- **输入**: 阶段一的诊断 JSON（cycle_position、direction、detected_patterns）
- **输出**: 阶段二的决策 JSON（order_type、entry_price、stop_loss、take_profit、decision_trace）
- **前置条件**: 阶段一 `gate_result=proceed`，否则不进入阶段二

## 正例（≥2 个）
1. **阶段一识别为 normal_channel + bullish**：→ 走 §4 通道分支 → §9.0 找到 H2 回调信号棒 → §10.1 止损设在信号棒下方 1 跳 → §10.3 交易者方程通过 → §11 突破单
2. **阶段一识别为 extreme_tr**：→ `gate_result=wait` → 不进入阶段二 → 直接输出"不下单，等待市场选择方向"

## 反例/边界（≥1 个）
1. **最常见的 AI 错误**：阶段一 `gate_result=proceed`，但 §2.5 判断惯性不足——AI 错误地把 gate_result 改成 wait。**正确做法**：§2.5 答"否"仍应 proceed，只是阶段二提高门槛做谨慎入场，不能直接阻断。

## 详细解释

### 完整的节点路径

```
阶段一（诊断闸门）
§0 总原则
  ├─ 0.1 看得懂吗？
  ├─ 0.2 具备分析条件吗？
  └─ 0.3 交易者方程（原则提醒，不在此执行）
§1 是否可以决策
  ├─ 1.1 数据够吗？（程序判定）
  ├─ 1.2 能识别周期吗？
  └─ 1.3 极端混乱吗？
§2 多空方向
  ├─ 2.1 有明确惯性方向吗？
  ├─ 2.2 长程背景 vs 近期方向？
  ├─ 2.3 当前方向判断（程序判定为主）
  ├─ 2.4 Always In（程序判定）
  └─ 2.5 惯性强度

阶段二（策略与执行）
§3–§8 结构分支（按 cycle_position 走对应分支）
§9 入场信号
  ├─ 9.0 有合格信号棒吗？
  ├─ 9.0P 背景限价评估
  └─ 9.1–9.7 信号棒质量检查
§10 风险收益
  ├─ 10.1 止损明确吗？
  ├─ 10.2 止损过大吗？
  └─ 10.3 交易者方程通过吗？
§11 下单方式（程序判定）
§14 禁止行为扫描
```

### 关键执行顺序规则

1. **不得跳步**：§9.0=否 不能直接写 terminal=wait——必须先评估 §9.0P（背景限价），§9.0P 也是否才能 wait
2. **不得提前评估**：§10.3 交易者方程只能在三价（entry/stop/target）确定之后执行，阶段一绝对禁止触碰
3. **禁止行为是最后一道关**：即使 §10.3 通过了，§14 扫描触犯任一条→立即改成"不下单"
