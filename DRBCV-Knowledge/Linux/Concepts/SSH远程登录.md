# SSH远程登录

## 类型判定
这是一个过程型卡片——SSH 是有明确步骤的操作流程：获取登录指令 → 打开终端 → 粘贴指令 → 输入密码 → 成功登录远程服务器。

## 类比 ★
### 一句话比喻
SSH 就是一条看不见的传送带——你坐在家里的电脑前打字，指令通过这条带子瞬间传到千里之外的数据中心服务器上，服务器的回应再通过带子传回你屏幕上。就像你遥控一台远在另一个城市的机器人帮你干活。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| SSH 客户端（你的电脑） | 你手里的遥控器 |
| SSH 连接 | 无线电信号 |
| 远程云服务器 | 千里之外的机器人 |
| SSH 密钥对 | 遥控器和机器人的配对密码——只认这把钥匙 |
| 密码登录 | 喊一声暗号，对上了就让你遥控 |
| SSH 隧道/端口转发 | 让机器人把隔壁房间的画面也传给你看 |

## 是什么
SSH（Secure Shell）是一种加密的网络协议，用于安全地远程登录和管理服务器。通过 SSH，你可以在自己电脑的终端里直接操作远在数据中心的云服务器，就像坐在那台服务器面前一样。

## 正例（≥2 个）
1. 在 AutoDL 租了一台 GPU 服务器 → 复制 SSH 登录指令 → 在本地 CMD/PowerShell 粘贴回车 → 输入密码 → 成功登录，开始操作远程服务器。
2. 本地启动了一个 Web 项目，端口是 6006 → 用 SSH 隧道 `ssh -L 6006:localhost:6006 用户@服务器` 把远程端口映射到本地 → 在本地浏览器打开 `localhost:6006` 就能看到远程的项目界面。

## 反例/边界（≥1 个）
1. SSH 只能连接已经开启 SSH 服务（端口22）的服务器。如果云服务器安全组没开放22端口，SSH 指令会一直卡住连接不上——就像机器人关机了，遥控器再好也没用。

## 详细解释
SSH 的核心价值是「你的键盘在本地，但执行在远程」。在 AI 项目部署中，几乎所有操作都通过 SSH 完成：

**基本登录流程：**
```
ssh 用户名@服务器IP -p 端口号
# 例如: ssh root@123.456.789.0 -p 22
```
系统会提示输入密码（输入时不显示任何字符是正常的安全设计），验证通过后进入远程服务器的终端。

**SSH 隧道（端口转发）：**
当远程服务器上启动了一个 Web 服务（如 Gradio 的 `localhost:7860`），本机无法直接访问。SSH 隧道让本地端口「映射」到远程端口：
```
ssh -L 本地端口:localhost:远程端口 用户@服务器
```
这样在本地浏览器访问 `localhost:本地端口` 就等于访问远程服务。

**两种认证方式：**
- 密码认证：每次输入密码
- 密钥对认证：生成公钥/私钥对，服务器存公钥，本地持私钥，登录时自动匹配，更安全且免密
