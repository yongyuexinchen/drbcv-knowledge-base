# Git克隆

## 类型判定
这是一个过程型卡片——`git clone` 是一个有明确输入（仓库网址）和输出（本地项目文件夹）的操作步骤。

## 类比 ★
### 一句话比喻
`git clone` 就是把别人已经装修好的样板间，连家具带装修图纸，一模一样地复印一套到你自己家——你不需要从毛坯开始，拿过来就能用。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 远程仓库（GitHub/GitLab） | 开发商展示的样板间 |
| git clone 网址 | 复印样板间的一切到你家里 |
| 克隆后的本地文件夹 | 你家里多了一个精装房 |
| git LFS | 样板间里有个超大鱼缸，普通搬家车装不下，需要特种运输车 |
| git LFS pull | 专门把那个大鱼缸运过来 |

## 是什么
`git clone` 是将远程代码仓库（如 GitHub 上的项目）完整复制到本地计算机的命令。格式为 `git clone <仓库URL>`。复制后得到一个包含所有代码、提交历史、分支信息的本地文件夹。

## 正例（≥2 个）
1. `git clone https://github.com/用户/项目名.git` → 在当前目录下生成 `项目名/` 文件夹，包含全部代码。
2. 克隆大型AI项目时，先用 `git lfs install` 初始化 LFS，再用 `git clone` 克隆，最后用 `git lfs pull` 拉取大文件（如模型权重）。

## 反例/边界（≥1 个）
1. 只用 `git clone` 克隆含大模型文件的项目时，大文件（GB级别）不会被自动下载——只下载了「指针文件」。必须额外执行 `git lfs pull` 才能把大文件真正拉到本地。

## 详细解释
Git 是目前最流行的版本控制工具，GitHub 是最大的代码托管平台。`git clone` 是使用 Git 的第一步——把别人共享的代码拿到自己机器上。

对于包含大型文件（模型权重、数据集等）的项目，GitHub 使用 Git LFS（Large File Storage）扩展来管理。普通 `git clone` 只下载小文件和 LFS 指针，真正的 GB 级大文件需要用 `git lfs pull` 单独拉取。

完整流程：
```
git lfs install          # 安装并初始化 LFS 工具
git clone <仓库URL>       # 克隆项目（不含大文件）
cd <项目目录>             # 进入项目
git lfs pull             # 拉取大文件
```

用 `git lfs ls-files` 可以检查大文件是否下载完整：文件前缀为 `*` 表示完整，为 `-` 表示不完整需要重新拉取。
