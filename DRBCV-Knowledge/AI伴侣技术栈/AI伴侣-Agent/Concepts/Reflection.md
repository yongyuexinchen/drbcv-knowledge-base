# Reflection（反思机制）

## 类型判定
过程型 — Agent 执行行动后检查结果、评估质量、识别错误、并触发修正的循环反馈机制。

## 类比 ★
### 一句话比喻
Reflection 像你做菜时的「尝一口」——炒完菜盛出来，尝一下，「嗯太咸了」，回锅加点水再炒一下。如果没有尝这一口，你就把一盘咸死人的菜端上桌了。Agent 也是——执行完一步不检查就直接下一步，最后可能整条路都跑偏了。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Reflection（执行后检查） | 炒完菜尝一口——「太咸了」「火候不够」 |
| 触发修正（Re-planning） | 回锅加水——根据尝到的结果调整后再来 |
| 质量门控（不达标则重试） | 尝了一口发现糊了——直接倒掉重做，不端上桌 |

## 是什么
Reflection 是 Agent 循环中的**自我评估与修正环节**。在一个典型的 Agent 循环中：执行一步（如调用搜索 API）→ 拿到结果 → Reflection 检查结果质量（是否相关？是否完整？是否有错误？）→ 如果通过，进入下一步；如果不通过，触发修正（重新搜索、换关键词、换工具）。Reflection 让 Agent 从「盲目执行」变成「边做边检查」，是 Agent 可靠性的核心保障。

## 输入-输出空间
- **输入**: 工具调用的结果 + 当前步骤的预期目标 + 上一步的执行上下文
- **输出**: 评估结论（pass / fail / partial）+ 修正建议（如果 fail）
- **评估维度**: 相关性（结果是否符合当前任务）、完整性（信息是否充分）、准确性（无事实错误）、格式正确性
- **循环终止条件**: 连续失败 N 次 → 降级处理（告知用户、或跳过该步骤）

## 正例（≥2 个）
1. **Reflexion（Shinn et al.）**: Agent 执行失败后将失败经验以自然语言「反思笔记」的形式存入记忆，后续执行时参考之前的反思来避免重复犯错
2. **AI 伴侣搜索修正**: Agent 搜索「深圳AI公司」→ 返回结果全是美国公司 → Reflection 识别为「结果不相关」→ 自动修正为搜索「深圳人工智能公司招聘」→ 获取正确结果

## 反例/边界（≥1 个）
1. **无 Reflection 的盲目执行**: Agent 搜到一个不相关结果就基于它继续推理和行动——最终输出牛头不对马嘴。没有 Reflection 的 Agent 是危险的
2. **边界 — 过度反思**: 每个微小步骤都反复检查 → 延迟爆炸、用户体验差。需要在「检查开销」和「错误代价」间平衡——高风险操作（转账）需要严格检查，低风险操作（查天气）宽松检查

## 详细解释
Reflection 在 Agent 循环中的位置：

```
         ┌─────────────────────────────────────┐
         ↓                                     │
Planning → Tool Calling → 拿到结果             │
                              ↓                 │
                         Reflection            │
                        ↙    ↓    ↘            │
                     pass  partial  fail       │
                      ↓      ↓       ↓         │
                  下一步  补调用   修正重试 ────┘
                      ↓
                   最终输出
```

Reflection 的三种粒度：
- **步骤级**: 每步工具调用后立即检查（细粒度，适合高风险任务）
- **阶段级**: 完成一组相关步骤后统一检查（中等粒度，适合日常任务）
- **任务级**: 所有步骤完成后端到端验证（粗粒度，适合简单任务）

AI 伴侣推荐「步骤级 + 关键步骤强化」——日常交互轻量检查，关键操作（如修改用户记忆、发送外部消息）严格验证。
