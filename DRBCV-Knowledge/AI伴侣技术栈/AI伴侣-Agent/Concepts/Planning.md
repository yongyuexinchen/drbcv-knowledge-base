# Planning（规划能力）

## 类型判定
判别型 — Agent 将用户的模糊目标拆解为可执行步骤序列的能力，是 Agent 从「被动应答」走向「主动执行」的关键跃迁。

## 类比 ★
### 一句话比喻
Planning 像你把「我要搬家」这个模糊目标变成一张便签纸上的清单——「① 找搬家公司比价 ② 买打包箱 ③ 周三晚上打包厨房 ④ 周四打包卧室 ⑤ 周五早上8点搬家」。没有这张清单，你就站在满屋子的东西面前发呆。有了清单，每一步都清楚。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 目标→任务拆解 | 搬家清单——把「搬家」这个巨无霸目标切成5个小步骤 |
| 任务依赖关系 | 必须先买打包箱（步骤②）才能打包（步骤③④）——顺序不能乱 |
| 动态重规划 | 搬家公司涨价了——清单上步骤①被划掉，换一家重新比价 |

## 是什么
Planning 是 Agent 的**任务分解与排序能力**。给定用户的一个高层目标（如「帮我准备下周的AI方向面试」），Planning 模块将其分解为：收集岗位信息 → 搜索面经 → 整理常见问题 → 生成模拟问答 → 安排模拟面试时间 → 生成复习材料。它不仅分解任务，还要处理任务间的依赖关系（必须先搜面经才能整理问题）和优先级排序。在 AI 伴侣场景中，Planning 让 AI 能从「陪你焦虑」升级为「带你行动」。

## 输入-输出空间
- **输入**: 用户目标（自然语言描述）+ User Model（了解用户的水平和偏好）
- **输出**: 任务计划（有序步骤列表，每步含：任务描述、所需工具、预计耗时、依赖关系）
- **计划形式**: 可以是 ReAct（每步推理后行动）、Tree-of-Thought（多路径探索）、或 Hierarchical（分层计划）
- **关键挑战**: 计划不是一成不变的——执行过程中需根据反馈动态调整（Re-planning）

## 正例（≥2 个）
1. **Plan-and-Execute Agent**: LangChain 的 Plan-and-Execute 模式——先让 LLM 生成完整计划，再逐步执行每步
2. **AI 伴侣的「帮我规划转行」**: 用户说「我想从传统行业转 AI」→ Planning 拆解：① 评估现有技能 ② 确定目标岗位 ③ 制定学习路线 ④ 推荐资源 ⑤ 设定里程碑 ⑥ 模拟面试——从模糊焦虑变成清晰路线图

## 反例/边界（≥1 个）
1. **单步问答**: 用户问「AI是做什么的」→ AI 回答。这是问答，没有目标拆解——不是 Planning
2. **边界 — 过度规划**: 简单任务（「帮我查一下天气」）不需要生成 5 步计划——Planning 的开销大于收益。需要判断「何时规划、何时直接行动」

## 详细解释
Planning 的常见范式：

| 范式 | 描述 | 适用场景 |
|-----|------|---------|
| ReAct | 每步推理→行动→观察→下一步推理 | 探索性任务，不确定性高 |
| Plan-and-Execute | 先生成完整计划，再按计划逐步执行 | 确定性任务，步骤清晰 |
| Tree-of-Thought | 生成多个候选步骤，评估后选择最优路径 | 复杂决策，多解空间 |
| Hierarchical | 分两层规划：高层（里程碑）→ 低层（具体步骤） | 长期复杂目标 |

在 AI 伴侣中，Planning 通常采用 **Hierarchical + ReAct 混合**：先用分层规划生成路线图（给用户看的），执行时每步用 ReAct 灵活应对变化。
