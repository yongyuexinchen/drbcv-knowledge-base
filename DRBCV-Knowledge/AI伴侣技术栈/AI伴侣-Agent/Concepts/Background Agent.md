# Background Agent（后台智能体）

## 类型判定
判别型 — 持续在后台运行的 Agent，不需要用户即时交互，自主执行总结、整理、优化、监控等维护性任务。

## 类比 ★
### 一句话比喻
Background Agent 像你雇的夜间清洁工——白天你在办公室里跟客户开会、写文档、打电话（前台交互），晚上你下班走了，清洁工进来扫地、擦桌子、倒垃圾、给绿植浇水（后台维护）。第二天你到办公室，一切整整齐齐，但你从来没跟清洁工说过一句话——他的工作不需要你参与。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Background Agent | 夜间清洁工——你不在的时候自己干活，天亮前搞定 |
| 记忆整理与摘要 | 把白天散落的文件归档、标签、放回柜子——第二天更好找 |
| 定时触发器 | 清洁工每晚10点准时来——不需要你每天打电话叫他 |

## 是什么
Background Agent 是 AI 伴侣体系中的**异步自主维护层**。与前台 Agent（响应用户即时指令）不同，Background Agent 按定时或事件触发运行，执行不需要用户参与的后台任务：对话结束后自动摘要并归档、定期整理长期记忆（去重、合并、衰减清理）、生成用户周报（「这周你提到了3次面试焦虑」）、监控外部信息（「你关注的AI公司今天发了新的招聘」）。它让 AI 伴侣从「随叫随到」升级为「默默守护」。

## 输入-输出空间
- **输入**: 触发事件（定时 / 用户活动结束 / 外部信号变更）+ 记忆系统完整数据
- **输出**: 整理后的记忆状态、生成的摘要/洞察/提醒、更新的 User Model
- **触发方式**: Cron 定时（每晚整理）、事件驱动（对话结束后触发摘要）、条件触发（记忆量超过阈值时触发去重）
- **运行约束**: 必须静默运行（不打扰用户）、资源消耗可控、执行时间可预测

## 正例（≥2 个）
1. **Mem0 的异步记忆提取**: 每轮对话结束后，后台异步调用 LLM 从对话中提取关键事实写入记忆库——用户无感知，下次对话时 AI 已经「记住了」
2. **AI 伴侣的夜间整理**: 每天凌晨自动运行：① 摘要昨天的对话 ② 去重合并记忆 ③ 更新 User Model ④ 生成第二天的提示（如「明天是用户面试日，提前准备鼓励语」）

## 反例/边界（≥1 个）
1. **前台同步 Agent**: 用户说「帮我查天气」→ Agent 实时执行并返回结果。这不是 Background Agent——它需要用户等待结果，且只在有指令时运行
2. **边界 — 静默 vs 可见**: Background Agent 发现重要信息（如「用户关注的公司突然裁员」）时，是应该主动推送通知，还是等用户下次对话时再提？——需要在「不打扰」和「不错过」之间平衡

## 详细解释
Background Agent 在 AI 伴侣架构中的位置：

```
┌──────────────────────────────────────────┐
│              前台（Foreground）            │
│  用户 ↔ Agent ↔ LLM ↔ Memory（实时交互）    │
└──────────────────────────────────────────┘
                    ↕
┌──────────────────────────────────────────┐
│              后台（Background）            │
│  Background Agent（定时/事件触发）          │
│  ├─ 记忆摘要与归档                         │
│  ├─ 记忆去重与衰减管理                      │
│  ├─ User Model 更新                       │
│  ├─ 外部监控（RSS、API、新闻）               │
│  └─ 洞察生成（周报、里程碑提醒）              │
└──────────────────────────────────────────┘
```

Background Agent 让 AI 伴侣产生「主动感」——用户感觉 AI 不是在等着被问，而是在默默关注着自己。这种「被记得、被关心」的体验是 AI 伴侣区别于工具型 AI 的核心差异。
