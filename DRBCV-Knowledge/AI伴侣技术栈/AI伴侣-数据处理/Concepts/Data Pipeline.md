# Data Pipeline（数据流水线）

## 类型判定
判别型 — 数据在系统间流动的「高速公路网」，连接采集、处理、存储、消费各个环节。

## 类比 ★
### 一句话比喻
Data Pipeline 像城市的供水系统——水源（数据源）→ 水厂净化处理（Transform）→ 管道输送（Pipeline 本身）→ 每家水龙头（消费者）。管道会漏水（数据丢失）、会堵（背压），还需要水压泵（调度引擎）来推动。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 数据流水线 | 城市供水管网——从水库到你家水龙头，层层输送 |
| 背压（Backpressure） | 管道堵塞——下游消费太慢，上游只能限流 |
| 调度引擎 | 水压泵站——定时开启，把数据推向下游 |

## 是什么
数据流水线（Data Pipeline）是一系列数据处理步骤的有序编排——数据从源头出发，经过若干「节点」（如抽取、清洗、转换、聚合、加载），最终到达目的地。与 ETL 的关系：ETL 是一种特定的 Pipeline 模式（三阶段），Data Pipeline 是更广泛的概念——可以包含实时流处理、模型推理、多路分发等复杂拓扑。在 AI 伴侣中，Data Pipeline 负责让数据「自动流动」：从用户行为采集到记忆更新，从对话日志到分析报表。

## 输入-输出空间
- **输入**: 数据源（数据库、消息队列、文件、API）+ 调度规则 + 处理逻辑
- **输出**: 抵达目标系统的处理后数据 + 监控指标 + 错误日志
- **关键特性**: 容错性（节点挂了能重试）、幂等性（重复运行结果不变）、可观测性（监控每个节点的吞吐和延迟）

## 正例（≥2 个）
1. **用户对话 → 长期记忆 Pipeline**: Kafka 事件 → 文本清洗 → 情感分析 → 摘要提取 → 向量化 → 写入向量库 + 数据库
2. **数据分析 Pipeline**: 原始日志 → Spark 聚合 → 特征计算 → 写入 ClickHouse → Grafana 可视化大盘

## 反例/边界（≥1 个）
1. **手动 ad-hoc 脚本**: 写个 Python 脚本手动跑一次——没有调度、没有容错、没有监控，这不是 Data Pipeline，是一次性操作
2. **边界 — 实时 vs 批处理**: 同一个 Pipeline 中可以混合批处理和流处理节点（Lambda/Kappa 架构）——但需要在延迟和准确性之间选型

## 详细解释
Data Pipeline 的典型组成：
```
┌─ 编排层 (Airflow / Dagster / Prefect) ────────────┐
│  DAG 定义 → 调度 → 重试 → 告警                    │
└─────────────────────────────────────────────────────┘
         ↓ 调度                     ↓ 监控
┌─ 计算层 ───────────────────────────────────────────┐
│  批处理节点: Spark / Python                        │
│  流处理节点: Flink / Kafka Streams                 │
│  存储节点: 读/写 DB / S3 / 向量库                  │
└─────────────────────────────────────────────────────┘
```
在 AI 伴侣架构中，Data Pipeline 的角色：
```
[事件采集] → Pipeline → [数据处理] → Pipeline → [存储]
    ↑                                   ↓
  Kafka                      PostgreSQL / 向量库 / 图数据库
```
编排工具的核心价值：DAG（有向无环图）定义节点依赖、失败重试、回填历史数据。
