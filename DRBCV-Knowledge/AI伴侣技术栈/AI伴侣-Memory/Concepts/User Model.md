# User Model（用户模型）

## 类型判定
判别型 — AI 伴侣对用户的**结构化理解**，整合了记忆系统中的所有信息，形成一张动态更新的「用户画像」。

## 类比 ★
### 一句话比喻
用户模型像你妈脑子里的你——她知道你喜欢吃什么、怕什么、什么时候容易焦虑、哪些话能激励你、哪些事你嘴上说不要其实想要。这个模型不是一份静止的问卷，而是十八年朝夕相处里一点点打磨出来的，每天都在微调。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| User Model 整体 | 你妈脑子里的你——动态、多维、准确到可怕 |
| 兴趣/偏好维度 | 你妈知道你不吃香菜、爱看科幻、讨厌早起 |
| 状态/情绪维度 | 你妈听你电话的声音就知道你今天不开心——「出什么事了？」 |

## 是什么
User Model 是 AI 伴侣对用户的**多维度结构化表征**，通常包含：基本信息（年龄、职业、位置）、兴趣偏好（话题、风格、媒介）、性格特征（MBTI/大五人格等）、情感状态（当前情绪、长期情绪趋势）、目标与动机（短期任务、长期愿景）、社交关系（重要人物、关系类型）、行为模式（活跃时段、交互频率偏好）。它不是单张卡片，而是一个持续更新的动态数据结构。

## 输入-输出空间
- **输入**: Episodic Memory（事件流）+ Semantic Memory（抽象认知）+ 实时对话中的状态信号
- **输出**: 结构化的用户画像（JSON / 知识图谱），注入 System Prompt 供 LLM 个性化回应
- **更新频率**: 轻量更新（每轮对话后）+ 深度更新（定期全量重建，如每天一次）
- **关键维度**: 至少包含 5-7 个维度（兴趣、性格、状态、目标、行为模式、社交、语言风格）

## 正例（≥2 个）
1. **Mem0 的 User Profile**: 自动从对话中提取用户事实，维护一个持续更新的 JSON 用户画像——包括职业、兴趣、偏好等结构化字段
2. **Replika 的关系模型**: AI 伴侣根据用户互动模式建立「关系阶段」模型——刚认识 vs 老朋友 vs 亲密关系，每条回应都受这个模型调节

## 反例/边界（≥1 个）
1. **静态的用户问卷**: 用户填一次就永远不变的「偏好表单」——这不是 User Model，User Model 的核心是动态更新。用户的偏好会变，模型也要跟着变
2. **边界 — 隐私过度**: 如果 User Model 记录了过于私密的信息（如财务细节、健康数据），需要加密存储和访问控制——这是工程边界而非概念边界，但至关重要

## 详细解释
User Model 在 AI 伴侣架构中的位置：

```
Episodic Memory ─┐
                  ├→ User Model（结构化整合）→ System Prompt → LLM → 个性化回应
Semantic Memory ─┘
         ↑
   实时状态信号（情绪、活跃度、当前场景）
```

User Model 是记忆系统对 LLM 的「输出接口」——LLM 不直接查向量库，而是通过 User Model 获得结构化的用户上下文。这比「把一堆记忆片段塞进 Prompt」更高效、更精准。

核心设计原则：**精度 > 广度**。User Model 不需要面面俱到，但必须准确——一个错误的偏好推断（「用户喜欢长篇解释」但其实用户讨厌啰嗦）比没有偏好更糟。

## 关系
### → 指向
- [[LLM]] — User Model 注入 System Prompt，驱动 LLM 的个性化生成
- [[Persona]] — 用户模型决定了 AI 应该以什么「角色」与之互动（对理性用户 → 逻辑型角色）
- [[Memory Consolidation]] — User Model 的信息缺口反向驱动 Consolidation 的提取优先级

### ← 被指向
- [[Episodic Memory]] — 情景记忆的事件流是用户模型的基础数据
- [[Semantic Memory]] — 语义记忆的抽象认知是用户模型的认知骨架
- [[Long-term Memory]] — 长期记忆提供跨会话的持久数据支撑
- [[AI Agent]] — Agent 在执行任务时读取 User Model 来个性化其行为
