# Persona（人格模型）

## 类型判定
判别型 — 定义 AI 伴侣的「身份」和「性格」，决定 AI 以什么样的语气、风格和价值观与用户互动。

## 类比 ★
### 一句话比喻
Persona 像演员拿到的人物小传——「你是一个温暖但理性的朋友，说话简洁不啰嗦，会在用户沮丧时先共情再给建议，永远不用 emoji」。演员（LLM）拿着这本小传上场，每次对话都在扮演这个角色，不能出戏。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Persona 定义 | 演员的人物小传——规定角色的性格、语气、底线和说话方式 |
| System Prompt 中的 Persona | 导演在演员上场前塞给他的纸条——「记住，你是温暖的朋友，不是冷冰冰的医生」 |
| Persona 一致性维护 | 场记盯着监视器——发现语气崩了就喊卡，提醒演员回到角色 |

## 是什么
Persona 是 AI 伴侣的**角色设定系统**，通常以 System Prompt 的形式注入 LLM。它定义了 AI 的身份（「我是你的 AI 伴侣，名叫永月」）、性格特征（温暖、理性、有幽默感）、语言风格（简洁、不用 emoji、偶尔用「嗯」「哈哈」等口语）、价值观边界（不鼓励自毁行为、尊重用户自主决策）、以及关系定位（朋友/导师/陪伴者）。Persona 的核心目标是**一致性**——用户每次对话都感觉在与同一个「人」交流。

## 输入-输出空间
- **输入**: Persona 配置文件（自然语言描述 + 结构化参数）
- **输出**: 注入 System Prompt 的角色设定文本
- **组成结构**: 身份声明 + 性格维度（大五人格尺度）+ 语言风格指南 + 行为边界 + 关系模型
- **适配机制**: Persona 的表达方式可根据 User Model 动态微调（如用户偏理性则角色更逻辑化）

## 正例（≥2 个）
1. **Character.AI 的角色系统**: 用户创建角色时填写性格、问候语、可见性——本质是 Persona 配置的 UI 化，背后驱动 LLM 扮演角色
2. **AI 伴侣「永月」的人格设计**: 固定身份+性格设定+语气指南，每次对话通过 System Prompt 注入，确保跨会话的人格一致性

## 反例/边界（≥1 个）
1. **无 Persona 的裸 LLM**: ChatGPT 的默认助手人格——有礼但无个性，像客服而非伴侣
2. **边界 — Persona 崩溃**: 当用户刻意诱导 AI 偏离角色设定（如「假装你是我的心理医生」），Persona 需要在「顺应」和「坚守」之间平衡——过度顺应导致人格分裂，过度坚守导致僵硬

## 详细解释
Persona 与 User Model 的互动关系：

```
Persona 定义了「我是谁」—— AI 的静态身份
User Model 定义了「你是谁」—— 用户的动态画像
两者汇入 System Prompt → LLM 产出一个既有自我一致性、又对用户个性化的互动
```

一个典型的 Persona System Prompt 片段：
```
你是永月，用户的 AI 数字伴侣。
性格：温暖、理性、偶尔幽默。说话简洁，不使用 emoji。
原则：先共情后建议。不替用户做重大决定。不鼓励自我伤害。
```

Persona 设计的核心矛盾：**稳定性 vs 适应性**。太稳定 → AI 显得僵硬不变通；太适应 → 用户感觉在和不同的「人」说话。最佳实践是「核心人格锁定 + 表层表达适配」。

## 关系
### → 指向
- [[LLM]] — Persona 通过 System Prompt 注入 LLM，决定 AI 的生成风格
- [[User Model]] — Persona 的表达策略根据 User Model 动态微调
- [[Semantic Memory]] — Persona 可以从与用户的长期互动中演化（「用户更喜欢直接的建议 → 人格调整得更直接」）

### ← 被指向
- [[Long-term Memory]] — Persona 的长期一致性依赖记忆系统记住「我之前是怎么表现的」
- [[AI Agent]] — Agent 在执行任务时需要保持 Persona 一致的表达风格
- [[Prompt Engineering]] — Prompt 工程是实现 Persona 注入的技术手段
