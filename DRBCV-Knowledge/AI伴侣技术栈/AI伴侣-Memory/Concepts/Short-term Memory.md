# Short-term Memory（短期记忆）

## 类型判定
判别型 — AI 伴侣的「当前对话缓存」，保存本轮会话的上下文和临时状态。

## 类比 ★
### 一句话比喻
短期记忆像你和朋友聊天时桌上的便签纸——你说过的每句话都记在上面，翻来覆去地参考。但一旦散场各自回家，便签纸就被揉成团扔进垃圾桶——下次见面桌子上又是空的。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Short-term Memory | 聊天桌上的便签纸——记着刚才说了什么，散场就扔 |
| Context Window 溢出 | 便签纸写满了——要往上写新东西，只能擦掉最早写的 |
| 对话状态跟踪 | 用荧光笔标出当前话题——「我们在聊她失业的事」 |

## 是什么
短期记忆是 AI 伴侣在当前会话中维护的对话上下文（context）。它通常以消息数组的形式存在——System Prompt + 历史对话轮次 + 最新用户输入。短期记忆的生命周期 = 一次会话（从用户打开对话到关闭或超时）。它是三层记忆体系中「最表层、最易失」的一层——直接喂给 LLM 的 Working Memory，但本身不持久化。

## 输入-输出空间
- **输入**: 用户每条新消息 + LLM 每次生成的回应
- **输出**: 完整的对话上下文数组（messages），注入 Prompt 供给 Working Memory
- **容量限制**: 受 LLM Context Window 约束（如 128K tokens）——超出时需裁剪（truncation）或摘要（summarization）
- **管理策略**: 滑动窗口（保留最近 N 轮）、重要性采样（保留关键转折点）、自动摘要（压缩旧对话）

## 正例（≥2 个）
1. **ChatGPT 对话线程**: 每次对话就是一个短期记忆实例——能看到刚才说了什么，但换个新对话就清零
2. **AI 伴侣的「刚才说到哪了」**: 用户说「接着说」，AI 从短期记忆中定位上一个话题的断点——这依赖短期记忆

## 反例/边界（≥1 个）
1. **用户偏好（「我喜欢猫」）**: 靠短期记忆只能在本轮会话生效——关了对话 AI 就忘了你爱猫，这需要 Long-term Memory
2. **边界 — Context Window 溢出**: 超长对话中，最早的几轮对话被裁剪——短期记忆容量有限，旧信息会丢失

## 详细解释
短期记忆在 AI 伴侣的认知管道中处于「入口」位置：

```
用户输入 → Short-term Memory（追加到消息数组）
              ↓
         Working Memory（LLM 处理消息数组中的信息）
              ↓
         Memory Consolidation（提取有价值信息 → Long-term Memory）
```

短期记忆的核心挑战是 **容量管理**：
- 对话超过 100 轮时，消息数组可能超出 Context Window
- 解决策略：滑动窗口 + 自动摘要（用 LLM 把旧对话压缩成一段摘要保留）
- 关键取舍：保留完整对话（精确但占空间）vs 摘要压缩（省空间但丢细节）

## 关系
### → 指向
- [[Working Memory]] — 短期记忆为工作记忆提供当前对话的完整上下文
- [[Memory Consolidation]] — 短期记忆中的有价值信息被提取后进入巩固流程
- [[Long-term Memory]] — 短期记忆是长期记忆的「信息入口」
- [[LLM]] — 短期记忆的内容是 LLM 推理的直接输入材料

### ← 被指向
- [[Working Memory]] — 工作记忆处理完信息后将结果写回短期记忆（更新对话状态）
- [[AI Agent]] — Agent 的多轮工具调用依赖短期记忆维持操作上下文
