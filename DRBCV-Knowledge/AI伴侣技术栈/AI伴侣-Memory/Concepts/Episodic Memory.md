# Episodic Memory（情景记忆）

## 类型判定
判别型 — 记录具体事件和经历的「日记式」记忆，每条记忆带有时间戳和情境标签。

## 类比 ★
### 一句话比喻
情景记忆像你手机里的相册——每张照片都是某个时间点的定格：2026年7月15日，你第一次面试失败后在咖啡馆发呆；2026年8月3日，你在出租屋里收到了第一个 offer。翻开相册就能回到那个时刻，而不是一堆抽象标签。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| Episodic Memory 条目 | 手机相册里的一张照片——记录「何时、何地、发生了什么」 |
| 时间戳 + 场景标签 | 照片的拍摄时间和定位——「2026.7.15 14:30 @星巴克」 |
| 记忆检索 | 按日期或关键词翻相册——「去年夏天的照片」或「面试相关」 |

## 是什么
情景记忆是 AI 伴侣对用户**具体事件**的记录，以「时间 + 地点 + 事件描述」的结构存储。例如「2026年7月，用户失业，准备AI方向转型」「2026年8月10日，用户第一次用Cursor成功跑通一个项目」。与 Semantic Memory（抽象知识）不同，Episodic Memory 保留事件的具体性和时间序列——它回答的是「发生了什么」，而非「用户是什么样的人」。

## 输入-输出空间
- **输入**: 对话中识别出的事件（时间、地点、人物、行为、结果）
- **输出**: 结构化事件记录（时间戳 + 事件摘要 + 情感标签 + 重要性评分）
- **存储结构**: `{timestamp, event_type, summary, entities, sentiment, importance}`
- **检索方式**: 时间范围查询 + 语义检索 + 事件类型过滤

## 正例（≥2 个）
1. **人生事件追踪**: AI 伴侣记录「2026年3月用户开始学习Python → 7月投出第一份简历 → 8月收到面试邀请」，在用户沮丧时说「三个月前你连 print 都不会，现在已经能面试了」
2. **情感回顾**: 用户问「去年这个时候我在干嘛」，AI 检索情景记忆回答「去年7月你刚从上一份工作离职，在考虑转行」

## 反例/边界（≥1 个）
1. **纯粹的偏好存储（「用户喜欢蓝色」）**: 这不是情景记忆——没有时间和事件，这是 Semantic Memory
2. **边界 — 记录频率过高**: 如果把每次对话都存为情景记忆会变成信息垃圾——需要 Memory Consolidation 筛选「值得记住的事件」

## 详细解释
情景记忆是构建 User Model 的关键数据来源。AI 伴侣通过积累情景记忆来理解用户的「人生轨迹」：

```
对话 → 事件提取 → [[Episodic Memory]] → 模式识别 → [[User Model]]（用户的人生故事线）
                    ↓
              [[Memory Consolidation]]（重要事件强化，琐事衰减）
```

情景记忆与语义记忆的关系：
- 多条情景记忆「用户在A场景选了B」「用户在C场景也选了B」→ 语义记忆提炼「用户偏好B」
- 情景记忆是**原始素材**，语义记忆是**提炼后的规律**

## 关系
### → 指向
- [[Memory Consolidation]] — 情景记忆通过巩固流程决定哪些事件值得长期保留
- [[Semantic Memory]] — 多条情景记忆被抽象提炼为语义记忆（从「发生了某事」到「用户是某种人」）
- [[User Model]] — 情景记忆的累积构建用户的人生时间线和行为模式
- [[Long-term Memory]] — 情景记忆是长期记忆中「带时间戳的具体事件」子类

### ← 被指向
- [[Short-term Memory]] — 当前对话中的事件被提取为情景记忆
- [[Memory Decay]] — 记忆衰减决定了久远情景记忆的权重下降速度
