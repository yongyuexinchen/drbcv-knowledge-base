# Embedding

## 类型判定
判别型 — 文本到向量的「翻译官」，让计算机用数学理解语义。

## 类比 ★
### 一句话比喻
Embedding 像给每本书贴 GPS 坐标——「喜欢旅行」放在 (23.5, 51.2, -8.1...)，「热爱旅游」紧挨着它 (23.4, 50.9, -8.0...)，而「量子力学」远远地在 (-90.3, 12.7, 45.6...)。语义越近，坐标越近。

### 生活映射
| 概念世界 | 现实世界 |
|---------|---------|
| 向量（Embedding） | 每本书的 GPS 坐标——一个 N 维数字串，代表它在语义宇宙中的位置 |
| 语义相似 = 向量距离近 | 「北京」和「首都」的坐标紧挨着，「北京」和「香蕉」相隔千里 |
| Embedding Model | 训练好的地图测绘员——给任意文本一个准确的坐标 |

## 是什么
Embedding 是将文本（或图像、音频）映射为固定长度的高维向量（通常 768/1024/1536 维）的技术。这个向量捕获了文本的语义信息——语义相近的文本，它们的向量在空间中距离更近。这是 RAG、语义搜索、推荐系统的基础技术。在 AI 伴侣中，用户的每段对话、每条记忆、每个知识片段都被 Embedding 变成向量，存入向量数据库供检索。

## 输入-输出空间
- **输入**: 文本字符串（任意长度，但通常有 token 上限如 512/8192）
- **输出**: 固定维度的浮点数向量，如 `[0.023, -0.451, 0.789, ..., 0.112]`（1536维）
- **距离度量**: 余弦相似度（Cosine Similarity）最常用，范围 [-1, 1]，越接近 1 越相似

## 正例（≥2 个）
1. **AI 伴侣记忆检索**: 「用户喜欢吃什么」→ Embedding → 在向量库中找最接近的记忆 → 找到「用户爱吃日料特别是三文鱼刺身」
2. **文档语义搜索**: 用户上传 50 篇笔记，全部 Embedding 存入向量库 → 搜「机器学习」能找出「深度学习」「神经网络」相关的笔记，即使没有精确关键词匹配

## 反例/边界（≥1 个）
1. **关键词搜索（Elasticsearch BM25）**: 搜「苹果」只能找到含「苹果」二字的文档——Embedding 能找到「水果」「iPhone」等语义相关的但无关键词的文档
2. **边界 — 多语言不对齐**: 中文「猫」和英文「cat」在同一个 Embedding 空间中距离可能很远——除非用多语言模型（如 multilingual-e5）

## 详细解释
Embedding 的原理可视化：
```
「机器学习」       → [0.8, 0.3, -0.1, ...]
「深度学习」       → [0.7, 0.4, -0.2, ...]  ← 很近！
「人工智能」       → [0.6, 0.5, -0.3, ...]  ← 也近
...
「今天天气不错」   → [-0.9, 0.1, 0.8, ...]  ← 很远
```

在 RAG 管道中的位置：
```
文档 → Chunking（切片）→ Embedding → 向量数据库
查询 → Embedding → 相似度搜索 → top-k 结果
```

常用 Embedding 模型：
- OpenAI `text-embedding-3-small/large`（商业化，1536/3072 维）
- BGE `bge-large-zh-v1.5`（中文优选，1024 维）
- Cohere `embed-multilingual-v3`（多语言）
