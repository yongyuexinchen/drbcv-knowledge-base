**DeepSeek Tavern V1：两张 5090，300 小时，我为酒馆玩家炼了一个专属模型**

_送给所有在深夜调预设、写世界书、雕琢角色卡的酒馆玩家。_

### 一、为什么不用 [Claude Opus](https://zhida.zhihu.com/search?content_id=274157423&content_type=Article&match_order=1&q=Claude+Opus&zhida_source=entity)？

玩酒馆的朋友一定经历过这种时刻——

你花了一整个周末，调好了预设，选了一张绝美的角色卡，把世界书写得比毕业论文还认真。然后你满怀期待地按下发送键。对面回了一句“好的呢”。

那种想砸键盘的感觉，我太懂了。

所以我花了 300 个小时，用两张 RTX 5090，把 [DeepSeek V4 Flash](https://zhida.zhihu.com/search?content_id=274157423&content_type=Article&match_order=1&q=DeepSeek+V4+Flash&zhida_source=entity) 做成了一个专为酒馆玩家优化的文字模型。结果出乎意料：AI 味少了，人味多了，上下文遵循甚至逼近 Claude Opus，而且——居然破限了。

Opus 4.6 是目前公认文字创作最强的模型。100 万上下文，酒馆里的神。但问题也很明显——贵。重度使用一个月，API 费用够买半张显卡。而且它不是你的模型。你不能改、不能调、不能部署在自己的服务器上。你永远在租别人的脑子。

### 二、为什么不用本地小模型？

“用 7B、13B 的本地小模型啊，免费，跑自己电脑上。”听起来很美。但玩过酒馆的人都知道——酒馆不是简单的聊天工具。它是极其复杂的提示词工程。预设系统、世界书、角色卡、上下文管理，这些设计思路后来被大量借鉴到 Agent 工程和学术论文里。小模型根本驾驭不了这种级别的提示词结构。

### 三、284B 全量微调？不可行

那把整个 DeepSeek V4 全量微调呢？284B 参数，全量微调。你知道需要多少算力吗？这么说吧——够你交十年 Opus API 的钱。根本不是个人开发者能碰的东西。

### 四、答案藏在 [MoE 架构](https://zhida.zhihu.com/search?content_id=274157423&content_type=Article&match_order=1&q=MoE+%E6%9E%B6%E6%9E%84&zhida_source=entity)里

DeepSeek V4 Flash 用的是 MoE（Mixture of Experts，混合专家）架构。总参数 284B，每次推理只激活 13B。里面有多个专家各管各的——数学、代码、逻辑推理、翻译……还有一个专家，专门负责文字创作。这个文字专家的参数量大约在 50B 左右。

思路就很简单了：284B 我训不起，50B 我还训不起吗？两张 RTX 5090，300 个小时，够了。

这就是整个项目的核心逻辑——用有限的算力，精准打击一个专家模块，而不是盲目轰炸整个模型。

![](https://picx.zhimg.com/v2-0f7cb470c39ca46615ee84ece0b541d3_1440w.jpg)

这就好比改造一栋大楼。全量微调是把整栋楼拆了重建，需要工程队、起重机、几千万预算。我的做法是——只重新装修其中一个房间。效果一样好，成本不到百分之一。

### 五、训练数据从哪儿来？

我没有去网上扒通用语料。我的训练数据，全部来自酒馆本身。具体做法：1. 配置一个真实酒馆环境，挂上经典预设和各类角色卡；2. 挂载 Claude Opus 4.6；3. 让 Opus 在酒馆里进行文字创作、角色对话；4. 选了上千张角色卡，数百种预设，让 Opus 大量输出；5. V4 Flash 的文字专家去学习 Opus 的输出。

这就是[知识蒸馏](https://zhida.zhihu.com/search?content_id=274157423&content_type=Article&match_order=1&q=%E7%9F%A5%E8%AF%86%E8%92%B8%E9%A6%8F&zhida_source=entity)（Knowledge Distillation），也叫强化监督学习。Opus 是老师，V4 是学生。而且是最顶级的老师。

![](https://pic1.zhimg.com/v2-248fea45cd75f1d7989f93a3f08bb8ba_1440w.jpg)

### 六、训练效果：出乎意料

**训练前 vs 训练后**

训练前：V4 Flash 写出来的东西，“AI 味”很重。什么是 AI 味？就是那种客客气气、不咸不淡、永远在端水的感觉。

训练后：人味明显多了。不是那种刻意的“像人”，而是自然地像人。幻觉显著减少，上下文遵循大幅提升。

![](https://picx.zhimg.com/v2-4a198d2580914c867e7502ce2554431b_1440w.jpg)

**上下文遵循：MoE 学到了稠密模型的能力**

这是一个很技术但很重要的点。Claude Opus 是稠密模型——每次推理激活全部参数，上下文的每一段都被充分处理。DeepSeek V4 是 MoE 专家模型——只激活部分专家，上下文信息可能在“路由”过程中丢失。

但经过 Opus 的训练蒸馏后，V4 Flash 的上下文遵循变得非常强。它学会了 Opus 是怎么“阅读”和“遵循”上下文的。这是意料之中——但程度出乎意料。

### 七、最大的意外：破限了

我从一开始就没打算去破解 DeepSeek V4 的安全锁。那个太难了，不是我的目标。但微调完文字专家后——居然破限了。

![](https://pic1.zhimg.com/v2-98c8546ec0d9309b9bb54b536c4eb13a_1440w.jpg)

我有一个大胆的推测：V4 的文字专家，本身就没有被做很大的安全限制。安全锁很可能在别的专家那里——比如逻辑推理专家，或者价值观对齐专家。文字专家就老老实实管文字创作。懂的都懂。

### 八、算力对比

全量微调 284B：几十张 H100，够交十年 Opus API 的钱

专家微调 50B：两张 RTX 5090，放家里就能跑

差距：50-100 倍

### 九、送给所有酒馆玩家

你花一周末调酒馆，按下发送键。对面回的不是“对不起我无法回答这个问题”，而是一段让你拍大腿的文字。你觉得对面坐着一个有灵魂的创作者，而不是一个概率分布。

这就是我想做的事。酒馆玩家是一群很有趣的人。你们花大把时间打磨角色、设计世界、雕琢提示词。你们在做的事，本质上就是最前沿的 AI 工程实践——只是你们叫它“玩”。

我想给这群人开一个专属的模型。不是租来的，不是凑合的，是真正为酒馆而生的。
